이번 검색에서는 **이전에 알리지 않았고 현재도 공식 채용 페이지에서 지원 가능한 공고 1건**을 알림 대상으로 남겼습니다. 다만 정확히 구분하면 오늘 새로 게시된 공고가 아니라, **7월 30일부터 모집 중이었으나 이번 검색에서 새롭게 포착한 미보고 공고**입니다. 현재도 삼일PwC 공식 채용 목록과 개별 JD가 모두 활성 상태입니다. ([PwC][1])

**종합 적합도: 9.3/10 · 지원 현실성: 9.4/10 · 현재 바로 지원할 가치가 높은 편**

이 포지션은 상당히 잘 맞습니다. 실제 업무가 **LLM 기반 AI Agent 설계 → RAG/검색 → Tool Calling → 멀티모달 문서 처리 → 답변 품질 평가 → regression test → 데이터 파이프라인**까지 이어집니다. 특히 테스트 데이터와 사용자 피드백을 이용한 **답변 품질 평가·회귀 테스트 체계 구축**, 그리고 **최신 AI Agent 및 Harness Engineering 기술 조사·검증**이 공식 JD에 직접 포함돼 있습니다. ([PwC][2])

요구 역량도 신입·전환 지원자가 접근하기 좋은 편입니다. Python·SQL 기반 데이터 처리와 API 사용, LLM의 token/context·RAG·검색·Tool Calling 이해, **AI 결과를 분석해 가설을 만들고 실험으로 검증한 경험**, Git과 테스트 코드에 대한 기본 이해를 요구합니다. 모델 평가·benchmark·prompt optimization, LLM/Agent/RAG 프로젝트, cloud/container 환경 경험은 우대사항입니다. ([PwC][2])

현재 갖춘 Python 기반 개발 경험과 Git/GitHub 사용, LLM·Agent·benchmark에 대한 관심을 직접 활용할 수 있고, 연구 과정에서 해왔던 **가설 설정 → 실험 → 결과 분석** 경험도 이 JD가 요구하는 실험 방식과 연결하기 좋습니다. 특히 최근 다뤄온 Agent Harness나 evaluation 개념을 포트폴리오로 전환하기 쉬워, 별도의 오랜 LLM 경력을 요구하는 정규직 공고보다 실제 서류 경쟁력이 나올 가능성이 높습니다.

다만 이 역할은 **PyTorch/Hugging Face 기반 모델 학습 자체가 중심은 아닙니다.** 모델 Training/Inference Engineer보다는 `Applied LLM + Agent Engineering + Evaluation`에 더 가깝습니다. 또한 SQL, RDBMS/NoSQL, 기업 데이터 파이프라인, Docker/Cloud, Knowledge Graph 경험이 상대적으로 약하다면 이 부분이 간극이 될 수 있습니다. ([PwC][2])

지원 전에는 새로운 대형 프로젝트보다 기존 Agent 프로젝트 하나를 **평가 가능한 시스템**으로 마감하는 것이 효과적입니다. `문서 → RAG → Agent → Tool Calling → 답변/근거 생성` 흐름을 만들고, 50~100개 고정 테스트셋에서 **answer correctness, citation correctness, tool-call accuracy, hallucination rate**를 측정하세요. 이후 prompt나 workflow를 변경했을 때 성능 저하를 자동 감지하는 `pytest` 기반 regression test와 GitHub Actions를 붙이면 이 JD의 **Harness Engineering + 품질 평가 + Git/테스트 코드** 요구사항에 상당히 정확하게 대응됩니다.

공식 페이지에는 현재도 **채용 시 마감**으로 활성화돼 있고, 외부 채용 정보에서는 **경력무관·3개월 인턴**으로 확인됩니다. ([PwC][2])
