현재 목표와 잘 맞는 지점은 상당히 명확합니다. Python 기반 ML 실험, Linux, Git/GitHub, LLM benchmark·evaluation에 관심이 있다면 **모델을 만드는 쪽과 모델을 평가·운영하는 ML Infra 사이를 연결하는 경험**을 만들 수 있습니다. 게다가 모든 기술 요건을 반드시 갖춰야 한다기보다, 새로운 기술을 빠르게 습득한 증거를 더 중요하게 본다고 공식 JD에서 명시합니다. ([Lever][1])

가장 큰 부족 요소는 **C/C++/Rust 같은 low-level programming**, React/TypeScript 기본 경험, 그리고 AWS·Terraform/Pulumi·Kubernetes 운영입니다. 특히 METR은 단순히 `lm-eval`을 실행하는 연구 인턴이 아니라 **평가 플랫폼 자체의 reliability와 infrastructure를 다루는 Platform Engineer**를 찾고 있다는 점을 감안해야 합니다. ([Lever][1])

지원 전에는 새 모델을 파인튜닝하는 것보다 `LLM Evaluation Platform` 하나를 만드는 것이 효과적입니다. Hugging Face 모델 3~4개를 동일 benchmark에서 평가하고, seed·generation config를 고정해 reproducibility를 확보한 뒤 accuracy와 함께 TTFT·TPOT·throughput·VRAM을 저장하세요. 여기에 Docker, CI regression test, Prometheus 계열 모니터링을 붙이고 가능하면 AWS나 작은 Kubernetes 환경에 배포하면 JD와 직접 대응됩니다.

이 공고는 **지금까지 추적한 글로벌 포지션 중 사용자 조건에서 NVIDIA New Grad 계열보다 실제 지원 제약이 훨씬 적습니다.** 특히 학위 졸업연도 제한이 없고 비자 가능성까지 열어둔 점 때문에 도전 가치가 높습니다. ([Lever][1])

### 2. Multiverse Computing — Machine Learning Engineer Intern (LLM)

**기술 적합도: 8.9/10 · 지원 현실성: 7.6/10**

* **근무지:** San Sebastián, Gipuzkoa, Spain
* **근무 방식:** **Hybrid**
* **고용 형태:** **6개월 Internship**
* **경력:** LLM/NLP 경험 + **개인 LLM 프로젝트 최소 1개**
* **학력:** AI·CS·Data Science 또는 related field의 Bachelor/Master
* **게시일:** **2026년 8월 10일**
* **Relocation:** relocation package 제공 가능
* **마감:** 별도 기한 미표기
* **지원:** Multiverse Computing 공식 Teamtailor 공고 ([Tech Jobs][2])

이 공고는 **어제인 8월 10일 새롭게 게시된 실제 신규 공고**입니다. LLM을 대상으로 prototype을 구현하고 실험을 설계하며, 모델 성능에 대한 **rigorous evaluation·benchmark**, fine-tuning, 정확도·robustness·efficiency optimization을 수행합니다. Python 능력이 핵심 요구사항이고 AWS·Docker 경험도 요구합니다. ([Tech Jobs][2])

특히 좋은 부분은 **“benchmark → 약점 분석 → fine-tuning/optimization → 다시 평가”**라는 업무 구조입니다. 사용자가 우선하고 있는 모델 튜닝과 벤치마크를 하나의 프로젝트 사이클로 보여주기 좋습니다. 산업·연구 환경 경험은 우대사항일 뿐이고, 개인 ML 프로젝트도 평가한다고 명시되어 있어 인턴 지원자에게 비교적 현실적인 조건입니다. ([MULTIVERSE COMPUTING][3])

가장 큰 리스크는 두 가지입니다. 첫 번째는 학위가 AI·CS·Data Science 또는 관련 분야여야 한다는 조건이고, 두 번째는 회사의 핵심 기술에 **quantum·quantum-inspired ML**이 포함된다는 점입니다. 또한 PyTorch/Hugging Face가 JD에 직접 명시되지는 않고 Python과 TensorFlow·scikit-learn·Pandas 등이 예시로 제시됩니다. ([MULTIVERSE COMPUTING][3])

지원 전에는 기존 LLM 프로젝트 하나를 다음 형태로 정리하는 것으로 충분합니다. `baseline model → benchmark → error analysis → LoRA/SFT 또는 quantization → benchmark 재실행` 구조를 만들고, accuracy뿐 아니라 latency·VRAM·throughput을 기록하세요. Docker로 재현 환경을 만들고 실험 결과를 GitHub README에 표와 그래프로 정리하면 이 공고의 평가·최적화 업무와 직접 연결됩니다.
