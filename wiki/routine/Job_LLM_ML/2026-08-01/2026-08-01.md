* **고용 형태:** 정규직

* **마감:** 공식 페이지에 별도 기한 미표기, 2026년 8월 1일 현재 지원 페이지 활성

산업 현장의 문제를 정의하고 LLM·VLM을 활용해 지능형 분석과 자동화 시스템을 만드는 역할입니다. 주요 업무에는 AI Agent 개발, RAG와 fine-tuning을 통한 모델 성능 개선, 산업 데이터 분석, 실제 적용 사례 확대가 포함됩니다. Python 능력과 최신 AI·LLM 연구 동향에 대한 이해를 요구하며, LLM 학습·평가, RAG 파이프라인 평가, 데이터 파이프라인, 코드 리뷰 경험을 우대합니다. ([Makina Rocks][1])

**잘 맞는 이유**

사용자의 Python·PyTorch·Hugging Face 경험, 논문과 최신 기술을 지속적으로 학습하는 습관, LLM 서빙·파인튜닝·에이전트 개발 관심을 직접 활용할 수 있습니다. 목재물리 연구에서 실제 데이터를 분석하고 문제를 수치적으로 정의한 경험도 **도메인 문제 정의 → 데이터 분석 → 모델 적용**이라는 FDE 업무 흐름과 연결하기 좋습니다.

특히 이 포지션은 특정 알고리즘 연구 실적보다, 다양한 도메인의 문제를 이해하고 LLM 기술을 실제 시스템으로 구현하는 능력을 중시합니다. 순수 NLP 연구직보다 현재 경력을 설득력 있게 전환하기 쉬운 포지션입니다.

**부족할 수 있는 부분**

* 실제 사용자를 대상으로 운영한 RAG·Agent 시스템 사례
* LLM 평가 지표와 회귀 테스트를 자동화한 경험
* 고객 또는 현업 담당자의 모호한 요구사항을 기술 문제로 구조화한 사례
* Docker·API·배포·모니터링을 포함한 프로덕션 수준 프로젝트

**지원 전 준비**

공지문·기술문서·연구자료를 입력받아 행동 항목을 추출하는 에이전트를 포트폴리오로 구성하는 것이 좋습니다. 이전에 구상한 **공지 → 행동카드 변환 에이전트**를 활용하면 직무 연관성이 높습니다.

구체적으로는 다음 결과가 필요합니다.

1. 문서 수집과 청킹, embedding, retrieval 파이프라인
2. 해야 할 일·담당자·기한·우선순위 구조화
3. 변경된 공지를 입력했을 때 기존 카드 업데이트
4. 추출 정확도·누락률·hallucination 평가
5. FastAPI와 Docker 기반 실행 환경
6. 실패 사례와 개선 내용을 포함한 README

외부 채용 플랫폼에는 과거 **2026년 7월 21일 마감**으로 표시된 기록도 있지만, 회사 공식 지원 페이지는 현재 활성 상태입니다. 재공고 또는 상시채용 전환 가능성이 있으므로 공식 페이지를 기준으로 빠르게 지원하는 편이 안전합니다. ([Makina Rocks][1])

* **지원:** Nuance Labs 공식 채용 공고 ([Greenhouse][2])

LLM·음성·Diffusion 모델의 end-to-end 추론 최적화, KV-cache 압축과 eviction, memory-efficient attention, batching, 양자화, latency·throughput 프로파일링을 담당합니다. vLLM·SGLang·TensorRT-LLM 경험을 연구·개인 프로젝트 수준에서도 인정하며, Python·PyTorch를 핵심 요건으로 두고 CUDA·Triton과 오픈소스 기여를 우대합니다. ([Greenhouse][2])

**잘 맞는 이유**

사용자가 계획한 B200 멀티 GPU 실험, vLLM 서빙, tensor parallelism, quantization, TTFT·TPOT·throughput·VRAM 벤치마킹이 공고 업무와 거의 일치합니다. 프로덕션 경험이 없어도 연구나 개인 프로젝트 수준의 vLLM·SGLang 경험을 인정한다고 명시한 점도 유리합니다. ([Greenhouse][2])

**가장 큰 위험**

공고는 CS·ML 관련 학위의 졸업 예정자 또는 최근 졸업자를 대상으로 합니다. 사용자의 석사 졸업 시점이 2019년이고 전공도 목재물리이므로, 형식적인 New Grad 기준에서는 불리할 가능성이 큽니다. 다만 공고가 학위보다 시스템 직관과 기술 역량을 강조하므로, 강한 추론 최적화 프로젝트가 있다면 도전 지원 가치는 있습니다. ([Greenhouse][2])

**지원 전 준비**

* 동일 LLM을 Transformers·vLLM·SGLang으로 서빙
* 1·2·4 GPU에서 TTFT, TPOT, tokens/s, p95 latency 측정
