이 포지션은 꽤 수준 높은 RAG를 다룹니다. 단순 `chunk → vector search → answer`가 아니라 **Query Understanding → 질의 분해·재구성 → Retrieval → Re-ranking → Context Construction → Answer Generation → 근거 검증**으로 이어지는 Agentic RAG를 연구합니다. 문서 관계와 출처 신뢰도·다양성까지 고려해 의료 정보 탐색 Agent를 만드는 역할입니다. ([온다][2])

이번 검색 조건과 특히 잘 맞는 부분은 **평가**입니다. 공고가 정량·정성 evaluation을 이용해 Agent/RAG의 문제를 찾아 개선 방향을 도출하는 역량과 **Git 기반 협업·코드 리뷰 경험**을 명시적으로 요구합니다. LangGraph·LangChain·LlamaIndex, GraphRAG/Knowledge Graph, 실제 Agent 배포 경험은 우대합니다. ([온다][2])

따라서 기존 Agent 프로젝트를 단순 데모가 아니라 **benchmark 가능한 시스템**으로 만든 경험을 보여주는 것이 핵심입니다. 부족할 수 있는 부분은 Information Retrieval 자체의 깊이입니다. embedding과 vector DB 사용 경험만으로는 부족할 수 있으며, BM25/dense retrieval, cross-encoder reranker, Recall@k, MRR/NDCG 같은 IR 평가와 query decomposition의 효과를 설명할 수 있으면 훨씬 유리합니다.

지원 전에는 50~100개의 고정 질문으로 `Basic RAG → Reranker 추가 → Agentic Query Decomposition` 세 버전을 비교해 보세요. **Recall@k, answer correctness, citation correctness, hallucination rate, 평균 retrieval/tool step 수, latency**를 동일 조건에서 측정하고 실패 사례를 retrieval/reasoning/context 문제로 분류하면 이 JD와 거의 정확히 맞습니다.
