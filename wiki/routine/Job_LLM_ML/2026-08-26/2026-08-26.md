## 신규 고적합 공고 — 2026년 8월 26일

어제 **8월 25일 새로 게시된 국내 공고 중 2건**이 조건에 걸렸습니다. 둘 다 채용사가 공개되지 않은 Robert Walters 의뢰 공고이고, 명목상 신입 포지션은 아닙니다. 다만 **경력 연수를 숫자로 제한하지 않으면서 LLM Serving·GPU Infra 또는 Agent·Evaluation을 직접 다루는 공고**라서 도전 지원 가치가 있습니다. ([로버트 월터스][1])

**기술 적합도 9.6/10 · 현재 지원 현실성 7.0/10**

업무가 상당히 정확하게 ML Infra 쪽입니다. ML 연구자의 학습·실험 인프라를 구축하고, 자체 모델을 프로덕션에 서빙하며 **추론 비용과 latency를 최적화**합니다. 여기에 cloud/on-prem 배포 표준화, **GPU cluster 구축·운영과 GPU resource scheduling**까지 포함됩니다. 우대사항에는 Argo Workflows·Airflow, batching·quantization, Slurm/HPC, GPU model serving이 직접 들어갑니다. ([로버트 월터스][2])

현재의 Python·PyTorch·Hugging Face·Linux 기반에 vLLM 서빙과 멀티 GPU benchmark 경험을 확장하려는 방향이라면 업무 축이 매우 잘 맞습니다. 특히 **“모델을 학습해봤다”보다 “GPU 위에서 모델을 어떻게 안정적·효율적으로 운영할 것인가”**를 보는 자리라 장기적인 ML Infrastructure/LLMOps 방향과 연결성이 높습니다.

문제는 JD가 사실상 프로덕션 경험을 요구한다는 점입니다. 특히 **Kubernetes에서 GPU workload를 실제 운영한 경험과 production LLM serving**이 필수라 개인 GPU 실험만으로는 직접적인 대체가 어렵습니다. 직급도 `대리(실무자)`로 표시돼 있어 순수 신입 경쟁은 아닙니다. ([로버트 월터스][2])

지원 전에는 포트폴리오를 `vLLM → Docker → Kubernetes → GPU monitoring → benchmark`까지 연결하는 것이 가장 효과적입니다. 1·2·4 GPU에서 TTFT, TPOT, tokens/s, p95 latency, VRAM을 측정하고 FP16과 quantized 모델을 비교하세요. 여기에 Kubernetes deployment와 GPU scheduling, Airflow 또는 Argo 기반 benchmark job 자동화를 붙이면 현재 간극을 가장 직접적으로 줄일 수 있습니다.

**기술 적합도 9.2/10 · 현재 지원 현실성 6.8/10**

이쪽은 모델 학습보다는 **Agent + Evaluation**에 강하게 치우쳐 있습니다. 핵심 업무가 Agent core 개발, 평가체계 구축/R&D, production optimization이고, 지원자에게 **다단계 LLM workflow를 직접 설계하고 문제를 정량적 metric으로 정의해 실험으로 개선 여부를 검증한 경험**을 요구합니다. ([로버트 월터스][3])

우대사항도 흥미롭습니다. Multi-Agent, 서로 다른 검색엔진·저장소를 결합한 IR pipeline, 여러 LLM provider의 비교 평가, **hallucination 감소·citation verification·guardrail** 구현 경험을 봅니다. 법률·금융·의료처럼 근거 정확성이 중요한 도메인 경험도 우대합니다. ([로버트 월터스][3])

벤치마크를 설계하고 외부 조건을 통제하면서 모델이나 시스템의 변화를 비교하는 경험, 그리고 Agent workflow에 대한 관심을 활용하기 좋은 공고입니다. 반면 PyTorch/Hugging Face fine-tuning 자체가 중심은 아니어서 **LLM Model Engineer보다는 Applied AI/Agent Evaluation Engineer** 쪽에 더 가깝습니다.

가장 큰 간극 역시 production입니다. JD가 단순 Agent 데모가 아니라 **실제 사용자가 쓰는 LLM 서비스를 출시해본 경험**을 명시적으로 요구합니다. 따라서 LangGraph 예제 하나보다 서비스 품질을 수치로 관리한 증거가 중요합니다. ([로버트 월터스][3])

지원한다면 공개 판례나 다른 근거 기반 문서를 대상으로 `Hybrid Retrieval → Reranker → Agent → Citation Verification` 시스템을 만들고, **Recall@k, citation correctness, hallucination rate, task success rate, latency, cost**를 고정 evaluation set에서 측정하는 편이 좋습니다. 여러 LLM을 동일 조건에서 비교하고 prompt/model 변경 시 regression test를 돌리면 이 JD의 평가체계 구축 요구와 거의 그대로 대응됩니다.

### 이번 우선순위

**MLOps Engineer → AI Engineer (Agent Core)** 순으로 봅니다. 첫 번째는 현재 목표인 **GPU·LLM Serving·ML Infrastructure**와 훨씬 직접적으로 연결됩니다. 두 번째도 기술적으로 좋은 공고지만 production Agent 경험 요구가 강하고 모델 학습·PyTorch 비중은 상대적으로 낮습니다.

글로벌 시장의 8월 25일 신규 후보도 확인했지만, 강하게 맞는 포지션들은 **3년 이상 경력**, 최근 졸업자 전용 또는 현재 학위과정 재학 조건이 붙어 있어 이번 알림에서는 제외했습니다. 예를 들어 Protege의 신규 FDE는 3년 이상의 엔지니어링 경험을 요구합니다. ([hotfix.jobs][4])
