### 왜 잘 맞는가

이 JD는 상당히 구체적입니다. 업무에 **LLM 기반 AI Agent의 설계·개발·배포·운영**, Multi-Agent, Tool Calling, **MCP**, RAG, embedding·Vector DB·reranking, 그리고 응답 속도·토큰 비용·정확도 최적화가 포함됩니다. 모델 측면에서도 **PyTorch/TensorFlow 기반 학습, 모델 서빙, MLOps pipeline, 성능 평가, 실험 관리, parameter tuning**을 직접 명시합니다. :chatgpt-content-reference{index="2"}

현재 경험을 기준으로 보면 **기술 적합도는 약 9.7/10** 정도로 볼 만합니다. 지금까지 진행한 `Python/PyTorch/Hugging Face → Local LLM → vLLM serving → benchmark/evaluation` 흐름과 거의 같은 축입니다. 특히 B200에서 진행한 TP별 **TTFT·TPOT·throughput·latency·GPU utilization** 측정은 다날이 요구하는 모델 서빙과 서비스 성능 최적화에 바로 연결할 수 있습니다.

현재 악성코드 분석 프로젝트도 활용도가 높습니다. `정적 분석 → 결과 집계 → Local LLM 분석 → 보고서`에서 Agent/MCP 구조로 확장해온 경험을 **“LLM API를 붙인 프로젝트”가 아니라 실제 도구와 데이터를 연결한 AI workflow**로 설명할 수 있기 때문입니다. 다날은 실제로 Multi-Agent, Tool Calling, MCP 기반 업무 지원 서비스를 업무 범위에 명시하고 있습니다. :chatgpt-content-reference{index="3"}

또 하나 좋은 부분은 **연차보다 문제 해결 능력과 성장 가능성을 중요하게 본다고 명시**했다는 것입니다. 공고 자체가 경력 무관이고, 관련 석사 학위뿐 아니라 “이에 준하는 AI/ML 연구·개발 경험”도 우대 대상으로 인정합니다. 따라서 전공이 CS/AI가 아니라는 점도 최근 LLM 프로젝트와 연구형 실험 결과로 보완할 여지가 있습니다. :chatgpt-content-reference{index="4"}

### 부족할 수 있는 부분

가장 큰 간극은 **production Agent/RAG 운영 경험**입니다. 현재 강점은 로컬 GPU 환경, 모델 학습·평가, inference benchmark와 prototype 설계 쪽인데, 다날은 그 이후의 **배포·운영·검색 품질 개선·비용 최적화**까지 요구합니다.

두 번째는 RAG의 깊이입니다. 단순 vector search만으로는 부족하고, 공고가 직접 **embedding → Vector DB → reranking → 검색 품질 개선**까지 언급합니다. 따라서 retrieval 품질을 Recall@K, MRR 같은 지표로 비교한 경험이 있다면 더 강해집니다. :chatgpt-content-reference{index="5"}

반대로 CUDA/Triton이나 대규모 distributed training처럼 지금 당장 없는 역량을 새로 만들 필요는 없습니다. 이 포지션은 HyperAccel이나 FuriosaAI AI System Researcher처럼 low-level ML Systems 연구가 중심인 자리가 아니라 **Applied LLM + Agent + MLOps** 역할에 더 가깝습니다.

### 지원 전에 무엇을 준비할 것인가

지금은 새 프로젝트를 만드는 것보다 **현재 악성코드 분석 시스템을 이 JD에 맞게 한 번 정리하는 것이 가장 효율적**입니다. 구조를 `파일/코드 입력 → 정적 분석 Tool → LLM Agent → 근거 검증 → 결과 생성 → evaluation`으로 표현하고, MCP 또는 Tool Calling이 실제 어느 단계에서 쓰이는지 명확히 보여주는 것이 좋습니다.

여기에 고정 evaluation set을 두고 **false positive/negative, 근거 일치율, unsupported claim, task success rate, latency**를 측정하세요. 그러면 다날이 요구하는 `모델 성능 평가·실험 관리`를 실제 숫자로 증명할 수 있습니다.

B200 포트폴리오는 별도의 **LLM Serving Performance** 섹션으로 두는 것이 좋습니다. TP1/TP2와 concurrency 변화에 따른 TTFT·TPOT·throughput·p99 latency를 비교하고, “왜 이 조건에서 성능이 달라졌는가”까지 한두 문단으로 해석하면 **모델 서빙과 성능 최적화를 이해하는 Applied AI Engineer**라는 차별점이 생깁니다.

현재 기준으로는 **실제 지원 우선순위 상위권에 넣을 만한 공고**입니다. 특히 최근 추적했던 스캐터랩·FuriosaAI가 Research/Training 쪽이라면, 다날은 **`LLM 모델 이해 + Agent 시스템 구현 + Serving/MLOps`를 한 직무에서 활용할 수 있는 현실적인 국내 Applied LLM 카드**라는 점에서 가치가 있습니다. :chatgpt-content-reference{index="6"}
