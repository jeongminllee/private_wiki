## 신규 고적합 공고 — 2026년 8월 10일

이전에 알린 공고는 제외했습니다. 오늘은 **새롭게 확인된 공고 중 알림 가치가 높은 2건**을 선별했습니다. 하나는 지원 현실성이 높은 **6개월 이상 AI 개발 인턴**, 다른 하나는 경력 조건은 다소 높지만 **Agent Benchmark·Codex·Agent Harness**라는 키워드가 매우 정확하게 맞는 도전 지원 포지션입니다.

### 1. 베링랩(Bering Lab) — AI 개발 인턴 (6개월 이상)

**적합도: 9.3/10 · 이번 회차 최우선 지원 권장**

* **근무지:** 서울
* **원격 여부:** 미표기
* **고용 형태:** 풀타임 인턴
* **근무 조건:** **6개월 이상 근무 필수**
* **경력:** 별도 연차 요구 없음. 컴퓨터공학·AI/ML·데이터사이언스 관련 전공자 **또는 이에 준하는 개발 경험** 인정
* **게시일:** **2026년 8월 9일경** — LinkedIn에서 8월 10일 기준 `1일 전`으로 표시
* **마감:** 별도 마감일 미표기
* **지원 링크:** 베링랩 LinkedIn 채용 공고 ([LinkedIn][1])

업무는 **Python 기반 AI Agent workflow 개발, RAG 파이프라인, prompt engineering, LLM·agent framework·orchestration tool PoC 및 성능 평가**입니다. 우대사항에 LangGraph·n8n 같은 agent framework 경험과 **프롬프트 평가·LLM benchmarking 경험**이 직접 들어가 있습니다. ([LinkedIn][1])

이 공고가 특히 좋은 이유는 모델 연구 경력을 요구하는 인턴이 아니라 **“직접 Python으로 프로토타입을 만들 수 있느냐”와 “AI 시스템을 평가하고 제품화할 수 있느냐”**에 초점을 둔다는 점입니다. 현재의 Python·LLM 개발 경험과 에이전트/RAG 관심을 바로 연결할 수 있고, 비전산 전공도 `이에 준하는 개발 경험`으로 대체할 여지가 있어 지금까지 확인한 인턴 중 지원 장벽이 비교적 낮습니다. ([LinkedIn][1])

다만 **PyTorch·Hugging Face 기반 모델 학습이나 fine-tuning이 주업무는 아닙니다.** 베링랩의 JD는 모델 레벨보다 LLM API, Agent orchestration, RAG, evaluation 쪽에 더 가깝습니다. 따라서 장기적으로 모델 학습·ML Infra를 최우선으로 본다면 약간 application-layer 쪽으로 치우친다는 점은 감안해야 합니다. ([LinkedIn][1])

지원 전에는 새 프로젝트를 만들기보다 기존 **공지 → 행동카드 에이전트**를 포트폴리오 수준으로 끌어올리는 것이 효율적입니다. `공지 수집 → RAG → 행동 항목 추출 → tool execution → 변경 공지 반영`까지 연결하고, 단순 데모에서 끝내지 말고 **추출 정확도, 누락률, hallucination rate, latency, API cost**를 측정하세요. 여기에 LangGraph 버전과 단순 single-call baseline을 비교하면 베링랩이 요구하는 *PoC + 성능 평가*를 매우 직접적으로 보여줄 수 있습니다. ([LinkedIn][1])

### 2. KRAFTON — [AI Research Div.] AI Agent Engineer (2년 이상)

**기술 적합도: 9.5/10 · 지원 현실성: 7.0/10 · 강한 도전 지원 후보**

* **근무지:** 서울 강남구 역삼 센터필드 West 타워
* **원격 여부:** 미표기
* **고용 형태:** 정규직·풀타임
* **요구 경력:** **공고 제목상 2년 이상**
* **게시일:** **2026년 8월 7일경** — LinkedIn에서 8월 10일 기준 `3일 전`
* **마감:** 상시채용, 채용 완료 시 조기 마감 가능
* **지원 링크:** KRAFTON 공식 채용 공고 ([Krafton][2])

이 포지션은 상당히 눈여겨볼 만합니다. 핵심 업무가 **AI Agent 개발 → Agent Harness 고도화 → Benchmark 설계·구축 → 반복적 성능 개선**이며, Planning, Memory, Tool Use, Loop, Evaluation, Meta-Harness를 직접 연구합니다. 필수요건에는 심지어 **Claude Code·Codex 등 coding agent 활용 능력**이 명시돼 있고, 우대사항에는 Openclaw·Hermes 같은 오픈소스 agent 분석과 **Agent Benchmark 구축 경험**이 들어가 있습니다. ([LinkedIn][3])

특이한 점은 제목에는 `2년 이상`이라고 되어 있지만 LinkedIn 직급 분류는 **신입**이며, 채용 안내에서도 “신입일 경우 자기소개서, 경력일 경우 경력기술서”라고 별도로 안내하고 있다는 것입니다. 그렇다고 2년 조건을 무시할 수는 없지만, 완전히 경력직만을 대상으로 닫힌 공고처럼 보이지는 않습니다. 포트폴리오는 필수 제출입니다. ([LinkedIn][3])

현재 Codex를 실제 개발 workflow에 활용하고 있고, 에이전트 구조·평가·벤치마크에도 관심이 있다는 점은 이 포지션과 아주 강하게 연결됩니다. 반면 **실제 제품에서 Agent를 개발한 경험**을 필수로 두고 있고, production LLM/Agent 시스템과 Harness engineering 경험을 우대하기 때문에 단순 개인 데모만으로는 경쟁력이 부족할 수 있습니다. ([LinkedIn][3])

지원 전 준비의 핵심은 “에이전트를 하나 더 만드는 것”이 아니라 **Agent Harness를 보여주는 것**입니다. 기존 에이전트에 Planning, Memory, Tool Use, retry/recovery, evaluator를 분리해서 넣고, 50~100개 정도의 고정 benchmark task를 만들어 **task success rate, tool-selection accuracy, 평균 step 수, failure recovery rate, latency·cost**를 측정하세요. 동일 과제를 단순 ReAct 방식과 개선된 Harness 방식으로 비교하고 regression test까지 GitHub에 넣으면 KRAFTON의 JD와 매우 직접적으로 대응됩니다. ([LinkedIn][3])
