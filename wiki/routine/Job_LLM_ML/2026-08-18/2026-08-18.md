### DeepAuto.ai — [전환형 인턴] AI Engineer

**종합 적합도: 9.6/10 · 지원 현실성: 9.2/10 · 이번 회차 최우선 지원 후보**

* **근무지:** 서울. 잡코리아 공고에는 **서울 강남구 테헤란로 216**으로 안내되어 있습니다.
* **원격 여부:** 공식 JD에서 원격/하이브리드 별도 명시 없음
* **고용 형태:** **3개월 인턴 → 정규직 전환 가능**
* **모집 인원:** 2명
* **경력:** **신입 지원 가능**
* **학력:** 관련 분야 학사 이상 또는 **그에 준하는 프로그래밍 역량** 인정
* **공고 시작:** **2026년 8월 13일**
* **마감:** 회사·잡코리아에서는 상시채용으로 표시됩니다. 사람인에는 **2026년 9월 11일** 마감으로 표시되어 채널 간 차이가 있으므로 공식 페이지가 열려 있는 동안 조기 지원하는 편이 안전합니다. ([잡코리아][2])
* **지원:** DeepAuto 공식 Careers의 **`AI Engineer 인턴 → Apply Now`**에서 지원할 수 있습니다. ([DeepAuto][3])

이 포지션은 일반적인 “LLM API 연결 인턴”과 꽤 다릅니다. 산업 현장의 **CAD·PDF·이미지·CSV·이메일 등 비정형 데이터를 AI가 사용할 수 있는 데이터셋으로 변환하고**, 모델 학습·분산 학습 및 Agent가 사용할 수 있는 **Data Lakehouse architecture**를 구축합니다. 그 위에서 근거를 추적할 수 있는 보고서 생성 Agent와 **멀티에이전트 시뮬레이션·의사결정 시스템**까지 구현합니다. 회사는 이 역할을 VLM/LLM, 강화학습, 데이터 아키텍처를 결합하는 AI Engineering 포지션으로 설명합니다. ([BeBee][4])

필수요건도 이번 검색 조건과 거의 정확하게 겹칩니다. **Python과 PyTorch 등의 딥러닝 프레임워크를 능숙하게 사용할 것**, 최신 AI 논문의 핵심 아이디어를 빠르게 이해해 직접 코드로 구현할 것, 정답이 없는 문제에서 가설을 세우고 실험으로 검증할 수 있을 것을 요구합니다. 관련 전공 학위가 아니더라도 이에 준하는 프로그래밍 역량을 인정합니다. ([BeBee][4])

우대사항에는 **LangChain·LlamaIndex·AutoGen, 분산 데이터 처리, Hadoop·Spark·Databricks, Knowledge Graph/GraphRAG, RAG 문서 생성, LLM Tool Calling, Multi-Agent simulation**이 포함됩니다. 따라서 LLM 모델 자체만 다루는 자리가 아니라 **LLM/Agent와 Data/ML Infrastructure 사이를 연결하는 포지션**에 가깝습니다. ([BeBee][4])

### 왜 잘 맞는가

사용자의 **Python·PyTorch·Linux·Git/GitHub 기반 개발 경험과 최신 논문을 읽고 실험하는 방향**을 직접 활용할 수 있습니다. 특히 석사 연구에서 가설을 세우고 수치적으로 검증했던 경험은 이 JD가 요구하는 `가설 설정 → 실험 → 검증 → 분석`과 연결하기 좋습니다. LLM·Agent 쪽 관심과 프로젝트 경험도 보고서 생성 Agent와 multi-agent workflow 쪽으로 연결할 수 있습니다.

또 하나 중요한 점은 **진입 장벽**입니다. 최근 알린 Scatter Lab·카카오·LG Efficient AI처럼 좋은 공고들은 기술 적합도는 높아도 LLM training 경력이나 전공 조건이 상당히 강했습니다. DeepAuto는 이번에 확인된 공고 중 드물게 **3개월 전환형 인턴이며, 신입과 재학·휴학·졸업생까지 열어 두고 동등한 프로그래밍 역량을 인정**합니다. ([BeBee][4])

### 부족할 수 있는 부분

가장 큰 간극은 **Data Lakehouse와 대규모 데이터 엔지니어링**입니다. Python/PyTorch나 LLM 경험만으로는 충분하지 않고, Spark/Databricks 계열 분산 처리, 데이터 provenance, structured/unstructured data ingestion을 설명할 수 있으면 훨씬 유리합니다. GraphRAG·Knowledge Graph나 실제 multi-agent simulation을 완결된 시스템으로 만든 경험도 우대 수준에서는 경쟁력이 될 수 있습니다. ([BeBee][4])

반대로 **CUDA/Triton, 대규모 LLM pre-training, vLLM inference optimization이 핵심인 포지션은 아닙니다.** 따라서 장기 목표가 순수 ML Systems/Inference Engineer라면 DEEPX나 LG Efficient AI가 더 직접적입니다. DeepAuto의 축은 **Agentic AI + Data/ML Platform + Enterprise AI** 쪽입니다. ([BeBee][4])

### 지원 전에 가장 효과적인 준비

이번 공고에는 모델 하나를 더 파인튜닝하기보다 **`Document → Lakehouse → Agent → Evaluation` 미니 프로젝트 하나**가 훨씬 강합니다. PDF·CSV·이메일 몇 종류를 입력으로 받아 구조화하고, PySpark + Delta Lake 또는 동급의 로컬 lakehouse에 적재한 뒤, 각 데이터에 `source_id`를 남겨 **답변과 보고서의 근거를 원본까지 역추적**할 수 있게 만드는 방식입니다.

그 위에 RAG/Tool Calling Agent를 올려 `데이터 조회 → 분석 → 보고서 생성`을 수행하고, 마지막으로 50~100개 정도의 고정 테스트를 만들어 **retrieval accuracy, citation/provenance accuracy, hallucination rate, task success rate**를 측정하면 좋습니다. 가능하면 single-agent와 multi-agent 버전을 동일 benchmark로 비교하세요. 이 하나의 저장소만으로 DeepAuto JD의 **비정형 데이터 처리 → Lakehouse → RAG → Agent → Multi-Agent → Evaluation**을 거의 그대로 증명할 수 있습니다. ([BeBee][4])

이번 공고는 **지원하는 쪽이 좋습니다.** 특히 현재 단계에서는 “대규모 LLM을 얼마나 많이 학습해봤느냐”보다 **연구적 문제 해결 능력 + Python/PyTorch + 실제 AI 시스템 구현 능력**으로 평가받을 여지가 큰 전환형 인턴이라는 점이 매력적입니다. 공식 Careers에는 현재도 해당 포지션이 활성화되어 있으므로 서류가 어느 정도 준비되어 있다면 오래 미루지 않는 편이 좋습니다. ([DeepAuto][3])
