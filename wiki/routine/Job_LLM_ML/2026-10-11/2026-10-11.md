### 현재 경험과의 적합성

이 공고를 우선 추천하는 이유는 현재 준비한 기술을 여러 방향으로 활용할 수 있기 때문입니다.

**첫째, LLM 연구 경험입니다.**

Transformer부터 최신 LLM 아키텍처까지 분석하고, 보안 특화 LLM 구조를 연구하는 과정이 회사에서 요구하는 최신 AI 기술 연구와 직접 연결됩니다.

**둘째, PyTorch와 모델 실험입니다.**

A6000 및 B200 환경에서 수행해온 LLM 실험, LoRA/QLoRA 파인튜닝, 평가 및 추론 벤치마크 경험을 활용할 수 있습니다.

**셋째, AI Harness Engineering입니다.**

현재 Codex 기반의 다중 에이전트 연구 환경을 설계하고 활용하고 있다는 점이 특히 중요합니다.

엔세이피아는 실제로 공고에서 **Context & Harness Engineering, Codex, Claude Code**를 직접 명시하고 있습니다. [ENSAPIA group recruit_about](https://recruit.cocone.co.kr/job_posting/xGnZyTs4)

따라서 일반적인 AI 도구 사용 경험이 아니라, 연구 작업을 수행하기 위한 도구와 에이전트 구조를 직접 설계하고 개선한 경험을 보여줄 수 있습니다.

### 부족할 수 있는 부분

이 공고의 가장 큰 간극은 특정 라이브러리보다는 **독립적으로 완결한 연구개발 결과물의 증거**입니다.

회사가 기대하는 것은 AI 기술을 알고 있다는 사실보다 실제 문제를 정의하고, 해결 방법을 설계한 뒤, 구현과 검증까지 완료할 수 있는 능력입니다.

또한 Diffusion 모델 최적화와 World Model 등 현재 주력 연구에서 벗어난 과제를 담당할 가능성도 있습니다.

### 지원 전 준비

**가장 효과적인 방법은 현재 Codex 연구 Harness와 LLM 프로젝트를 연결한 포트폴리오입니다.**

기존 AI Harness 프로젝트를 다음과 같이 정리하는 것을 권합니다.

`연구 문제 정의 → Harness 설계 → Agent 역할 분담 → 실험 실행 → 결과 검증 → 실패 분석 → 개선`

특히 자동화 이전과 이후를 비교할 수 있는 지표를 추가하면 좋습니다.

예를 들어 작업 완료율, 검증 통과율, 반복 수정 횟수, 실행 비용 등을 측정할 수 있습니다.

LLM 프로젝트에서는 모델 학습이나 평가 결과를 연결해 **Harness가 실제 연구 생산성이나 품질을 개선했는지** 보여주는 것이 좋겠습니다.

이 공고는 장기 목표인 LLM Research Engineer와 현재 진행 중인 AI Harness 연구를 함께 활용할 수 있는 지원 대상입니다.

### 채용 정보

노타의 NetsPresso 팀은 최신 LLM·VLM을 다양한 NPU/GPU/CPU 환경에서 실행하기 위한 모델 최적화 기술을 개발합니다.

이번 인턴십의 주요 업무는 다음과 같습니다.

- **PyTorch → ONNX → Compiler → Device Runtime** 변환 파이프라인
- Transformer·Attention·KV Cache 구조 분석
- 모델 Quantization 및 Graph Optimization
- AI 모델 정확도·추론 지연·메모리 사용량 비교
- 디바이스별 추론 성능 프로파일링
- Python 기반 최적화·평가 작업 자동화

특히 우대사항에 **vLLM, TensorRT-LLM, ONNX Runtime**, 추론 지연과 메모리 프로파일링 경험이 포함됩니다. [더팀스](https://www.theteams.kr/recruit_big/detail/1076002)

근무기간은 6개월이며, 서울 강남구 테헤란로 521에서 근무합니다. 공개 채용 정보에는 대면근무로 분류돼 있습니다. [커리어리](https://careerly.co.kr/job/15742794)

### 현재 경험과의 적합성

이 직무는 현재 B200에서 진행해온 vLLM 추론 벤치마크와 직접 연결됩니다.

특히 Tensor Parallel 구성, 동시 요청 수, 추론 지연, 처리량 및 GPU 메모리 사용량을 비교하는 실험은 모델 최적화와 성능 평가 역량을 보여주는 근거가 될 수 있습니다.

현재 연구 중인 Transformer, Attention, KV Cache 구조에 대한 이해도 도움이 됩니다.

다만 이 회사는 vLLM을 활용하는 사람보다 **모델과 추론 프레임워크를 하드웨어에 맞게 수정할 수 있는 엔지니어**를 찾고 있습니다.

따라서 지금의 벤치마크 경험만으로 자격요건을 충분히 충족한다고 보기는 어렵습니다.

### 부족할 수 있는 부분

가장 중요한 간극은 **ONNX 기반 모델 변환·디버깅 경험**입니다.

노타는 해당 경험과 Quantization·Pruning·Fusion 등의 모델 경량화 경험을 필수사항으로 제시합니다. [더팀스](https://www.theteams.kr/recruit_big/detail/1076002)

현재의 PyTorch 및 vLLM 경험과는 기술적으로 연결되지만, 다음 요소는 추가적인 실습이 필요합니다.

- PyTorch 모델의 ONNX Export 및 변환 결과 검증
- ONNX Graph 수정 및 최적화
- 양자화 전후 정확도와 추론 성능 비교
- ONNX Runtime 기반 실제 추론 수행

### 지원 전 준비

기존 프로젝트를 확장하는 방식이 가장 효율적입니다.

우선 작은 Transformer 모델을 사용해 다음 실험을 수행하는 것을 권합니다.

`PyTorch 모델 → ONNX Export → ONNX Runtime 추론 → 정확도 검증 → 최적화 → 성능 재측정`

실험 결과에는 출력 오차, latency, memory footprint를 기록하고 최적화 전후 차이를 비교합니다.

이후 지원서에는 B200/vLLM 벤치마크와 ONNX 변환 실험을 구분해서 기술하면 됩니다.

**이 포지션은 현재 역량과의 간극이 존재하는 도전 지원 대상**이지만, 장기적으로 LLM Serving 및 ML Systems Engineer로 전문성을 확장하는 데 적합합니다.
