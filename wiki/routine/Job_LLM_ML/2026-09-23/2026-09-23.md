### SAP Fioneer — Graduate AI Engineer

이 포지션은 **GenAI를 기업 시스템에 실제로 넣는 Applied AI Engineer** 성격입니다. AI 기반 banking feature를 설계·개발·테스트·배포하고, 아이디어 탐색과 prototype 단계에서 시작해 production-ready solution까지 AI lifecycle 전체에 참여합니다. 특히 **LLM을 enterprise solution에 통합하는 여러 접근법에 대한 이해**와 Python을 포함한 프로그래밍 역량을 직접 요구하며, 새로운 AI 기술을 지속적으로 파악하고 제품에 적용하는 것도 업무에 포함됩니다. :chatgpt-content-reference{index="2"}

학력 조건이 눈에 띕니다. Computer Science만 제한하는 것이 아니라 **Physics와 Engineering 학위도 명시적으로 인정**합니다. 따라서 비전산 계열 석사 배경이 형식적으로 큰 장애물이 되지 않는 몇 안 되는 글로벌 Graduate AI 포지션입니다. 또한 경력 연수를 요구하지 않고 experienced engineer의 mentorship 아래 일하는 **early-career role**로 설명하고 있습니다. :chatgpt-content-reference{index="3"}

현재 경험과의 **기술 적합도는 약 8.9/10**으로 보겠습니다. Python 기반 Local LLM 시스템, 모델 API/Agent 통합, Linux·GitHub 환경, 그리고 vLLM 기반 GPU serving/benchmark 경험을 `모델 → API → 서비스 → 평가` 관점으로 묶기 좋습니다. 특히 B200 실험에서 latency·throughput·GPU resource를 정량적으로 측정해 온 경험은 “AI 기능을 만들 줄 안다”를 넘어 **성능과 운영 특성까지 고려한다**는 증거가 됩니다.

다만 이전의 Mistral이나 FuriosaAI 공고와 달리 **PyTorch, Hugging Face, fine-tuning 자체가 JD의 중심은 아닙니다.** 여기서는 LLM 연구보다 **enterprise integration + cloud-native development**의 비중이 큽니다. 필수요건에 Azure/AWS/GCP 중 하나에 대한 초기 cloud-native 경험과 **Docker·Kubernetes**가 명시되어 있습니다. 따라서 현재 가장 큰 간극은 모델 연구가 아니라 **cloud deployment와 container orchestration을 실제로 해본 증거**입니다. :chatgpt-content-reference{index="4"}

지원 전에는 새 LLM 프로젝트를 만드는 것보다 기존 시스템 하나를 production 형태로 마무리하는 편이 좋습니다. 현재 Local LLM/보안 분석 시스템을 `FastAPI → LLM → evaluation → Docker`까지 고정하고, 가능하면 AWS·Azure·GCP 중 하나에 작은 인스턴스로 배포해 **CI → container build → deployment → logging** 흐름을 GitHub README에 남기세요. Kubernetes는 대규모 cluster를 만들 필요 없이 manifest나 작은 local cluster에서 deployment/service 구조를 이해했다는 정도까지 확보하면 이 Graduate 포지션에서는 충분히 의미가 있습니다.

포트폴리오에서는 B200 benchmark를 별도 **Performance Engineering** 섹션으로 두는 것이 좋습니다. `TP1 vs TP2`, concurrency 변화에 따른 TTFT·TPOT·throughput·p99 latency·GPU utilization을 정리하면, SAP Fioneer가 직접 요구하지 않는 PyTorch/vLLM 역량도 **추가적인 기술 깊이**로 보여줄 수 있습니다.
