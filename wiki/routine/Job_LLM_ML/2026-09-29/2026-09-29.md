### 1. DeepAuto — AI Engineer 인턴

DeepAuto 공식 Careers에서 현재 `AI Engineer 인턴`을 **활성 채용 포지션**으로 확인했습니다. 회사 자체가 “research-powered” 조직을 표방하고 있고, NeurIPS·ICML·ICLR·CVPR·EMNLP 연구진과 함께 Agentic AI를 실제 기업 workflow에 배포하고 있다고 설명합니다. [deepauto.ai](https://deepauto.ai/careers)

[DeepAuto AI Engineer 인턴 공식 지원 페이지](https://deepauto.ai/careers/detail?job=AI+Engineer)

세부 직무를 보면 이번 공고가 특히 강합니다. 인턴은 **3개월 후 정규직 전환형**이며, 트랙 중 하나가 아예 `LLM 파인튜닝 및 강화학습 기반 모델 학습`입니다. 여기에서 오픈소스 모델 **SFT**, DPO 등의 최신 RL/post-training 실험, 그리고 **자동화 benchmark/evaluation framework 구축**을 수행합니다. 다른 트랙에서는 LLM/VLM Agent의 Planning·Memory·Tool-use, 비정형 데이터 처리, 분산 학습용 데이터 구조를 다룹니다. [Wanted](https://www.wanted.co.kr/wd/353066?utm_source=chatgpt.com)

필수 역량도 현재 방향과 상당히 정확하게 겹칩니다. **Python + PyTorch**, 최신 AI 논문의 핵심 아이디어를 읽고 코드로 구현하는 능력, 그리고 **가설을 세우고 실험으로 검증하는 문제 해결 방식**을 명시적으로 요구합니다. Agentic AI, RAG, Tool-calling, 멀티에이전트 경험도 우대합니다. [Wanted](https://www.wanted.co.kr/wd/353066?utm_source=chatgpt.com)

이건 현재 포트폴리오를 거의 그대로 활용할 수 있습니다. `B200/vLLM benchmark → LoRA/QLoRA fine-tuning → fixed evaluation → error analysis`를 하나의 실험 사이클로 묶고, 악성코드 분석 프로젝트는 `Static Analyzer → evidence → LLM reasoning → evaluation → report/Agent` 구조로 보여주면 됩니다. **모델 실험과 실제 Agent 시스템을 둘 다 가지고 있다는 점**이 특히 좋습니다.

여기서 가장 부족할 가능성이 높은 부분은 **실제 post-training 결과물**입니다. LoRA/QLoRA를 “할 계획”인 것과 실제로 `base → training → evaluation → ablation` 결과를 가지고 있는 것은 차이가 큽니다. 또한 DPO/RL 계열을 직접 구현해본 경험과 논문 실적은 경쟁자 대비 약점일 수 있습니다. 다만 논문 게재는 우대사항이고, 필수 조건은 최신 논문을 이해하고 구현하는 역량입니다. [Wanted](https://www.wanted.co.kr/wd/353066?utm_source=chatgpt.com)

따라서 **지원 전에 가장 먼저 끝낼 것은 LoRA/QLoRA 실험 하나**입니다. 모델을 크게 잡을 필요는 없습니다. 동일한 eval set에서 `Base vs SFT/LoRA`, category별 성능, 실패 사례, inference latency를 비교하고 README에 실험 가설과 결과를 남기세요. 그리고 B200 benchmark는 `TP1/TP2가 어느 workload에서 유리했으며 왜 그런가`까지 설명하면 좋습니다.

장기 목표가 **LLM Research Engineer → Research 역량 확대**라면 이번 공고는 상당히 중요합니다. 단순 Agent API 개발 인턴이 아니라 **학습·RL·benchmark/evaluation 트랙을 직접 선택할 수 있다는 점** 때문입니다.

### 2. 안랩 — [신입] ML/MLOps 엔지니어

두 번째는 상당히 흥미로운 조합입니다. 안랩에서 현재 **신입 ML/MLOps 엔지니어**를 모집하고 있고, 공식 채용 페이지도 활성 상태입니다. 근무지는 **경기 성남시 분당구 판교역로 220 안랩 본사**, 신입 포지션이며 정규직으로 확인됩니다. 현재 공식 공고 기준 마감은 **2026년 12월 31일 23:59**입니다. [JOBS.ac.kr](https://jobs.ac.kr/recruit-detail/1947257?utm_source=chatgpt.com)

[안랩 [신입] ML/MLOps 엔지니어 공식 지원 페이지](https://ahnlab.recruiter.co.kr/career/jobs/99907?utm_source=chatgpt.com)

업무는 간결하지만 요구사항이 매우 잘 맞습니다. **AI 모델 개발 + 모델 개발·운영 프로세스 구축**이 핵심이며, 필수 역량으로 **Python/Scala, PyTorch 등의 ML framework, Spark 기반 대규모 데이터 처리, Git/SVN, AI/ML 모델 설계·개발 경험**을 요구합니다. 그리고 우대사항이 **MLOps 경험 + 석사 또는 연구 경험 + 보안 관련 지식과 경험**입니다. [직행](https://zighang.com/recruitment/14393d42-497a-4ba2-929d-971a1d45b19a)

이 조합 때문에 현재 기준 적합도가 상당히 올라갑니다. 일반적인 신입 MLOps 지원자는 보안 프로젝트가 없고, 일반적인 보안 지원자는 **PyTorch 모델 학습과 LLM serving benchmark**를 깊게 보여주기 어렵습니다. 반면 현재 진행 중인 악성코드 분석 프로젝트와 GPU/LLM 실험을 합치면 **`Security + ML + MLOps`**라는 꽤 희소한 포지셔닝이 가능합니다.

특히 B200에서 진행한 vLLM TP benchmark는 이 공고에서 단순 부가 경험이 아닙니다. `모델 개발 → inference serving → 성능 측정 → 운영 조건 결정`으로 설명하면 **모델 개발/운영 프로세스를 직접 다뤄본 증거**가 됩니다. 여기에 Linux 서버, GitHub, Python/PyTorch 환경도 그대로 연결됩니다.

현재 가장 큰 부족점은 **Spark와 정식 MLOps pipeline**입니다. PyTorch·Linux·Git·serving은 강하지만, `training pipeline → experiment tracking → model registry → deployment → monitoring → retraining` 전체를 MLflow/Kubeflow/Airflow 같은 도구로 운영해본 증거는 상대적으로 약합니다. Spark 역시 직접적인 대규모 처리 경험을 보여주기 어려울 수 있습니다. [직행](https://zighang.com/recruitment/14393d42-497a-4ba2-929d-971a1d45b19a)

다만 여기서는 새 MLOps 프로젝트를 하나 더 만드는 것보다 현재 파인튜닝 작업에 **MLflow 정도만 추가하는 것이 효율적**입니다. 예를 들어 `dataset version → training config → metric → checkpoint → evaluation result`를 MLflow로 추적하고, inference 서버의 latency와 model version을 연결하면 충분히 좋은 이야기가 됩니다. Spark는 기본적인 DataFrame 처리와 partition 개념을 작은 실습으로 보완하되, 지금 주력 시간을 많이 쓰지는 않는 편이 좋습니다.

그리고 이 공고에는 한 가지 특별한 이점이 있습니다. **석사·연구 경험과 보안 경험을 둘 다 우대**합니다. 따라서 석사 연구에서의 가설 설정·수치 분석 경험을 “연구 방법론”, 현재 악성코드 분석 프로젝트를 “도메인 전문성”, LLM 실험을 “최신 AI engineering 역량”으로 분리해 설명하면 상당히 깔끔한 지원서가 나옵니다. [직행](https://zighang.com/recruitment/14393d42-497a-4ba2-929d-971a1d45b19a)

이번 회차의 우선순위는 명확합니다. **Research/Training 방향으로 가려면 DeepAuto를 먼저**, **ML Systems/MLOps + 보안이라는 안정적인 병렬 커리어까지 고려하면 안랩을 바로 다음에** 두는 것이 좋겠습니다. 둘 다 단순히 “지원 가능” 수준보다는 **현재까지 만들어 온 프로젝트를 거의 버리지 않고 그대로 증거로 활용할 수 있는 공고**라 실제 지원 대상으로 올릴 가치가 높습니다.
