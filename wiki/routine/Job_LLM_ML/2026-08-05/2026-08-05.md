### 1. NAVER Cloud — Foundation Model 학습데이터 파이프라인 연구

**적합도: 9.8/10 · 현재 가장 현실적인 최우선 지원 후보**

* **근무지:** 경기도 성남시 분당구 그린팩토리
* **고용 형태:** 체험형 인턴, 채용 연계형 아님
* **지원 대상:** 학사 재학생 또는 기졸업자
* **근무 기간:** 2026년 9~12월 중 약 3개월, 주 5일 풀타임
* **게시일:** **2026년 8월 3일**
* **마감:** **2026년 8월 12일 18:00**
* **지원:** NAVER Cloud 공식 채용 공고 ([NAVER Cloud Careers][1])

수학·과학·코드 영역의 LLM 성능을 높이기 위한 학습 데이터 전략을 수립하고, 데이터 수집·정제 파이프라인과 성능 검증 체계를 구축하는 역할입니다. Python, PyTorch, Transformers 활용 경험과 최신 AI·ML 논문을 읽고 구현하는 역량을 직접 요구합니다. HyperCLOVA X 벤치마크 분석, 취약 도메인 진단, 합성·정제 파이프라인 자동화까지 경험할 수 있습니다. ([NAVER Cloud Careers][1])

**잘 맞는 이유**

이번에 확인된 공고 중 사용자의 현재 경력과 가장 자연스럽게 연결됩니다.

* Python·PyTorch·Hugging Face Transformers가 명시적 요구사항
* Kaggle·AutoML·벤치마크 분석 경험을 활용 가능
* 석사 연구에서 수행한 실험 설계·수치 분석·결과 해석을 데이터 중심 LLM 연구로 전환 가능
* Codex를 실제 프로젝트에 적극 활용한 경험도 우대사항과 일치
* AI 관련 전공은 필수가 아니라 우대사항이므로 비전산 전공 리스크가 상대적으로 작음

**부족할 수 있는 부분**

대규모 텍스트 데이터의 품질 평가, contamination·deduplication·data mixture 분석을 실제로 수행한 포트폴리오가 부족할 수 있습니다. Kaggle 경험도 단순 참가보다 실험 설계와 성능 개선 근거를 명확히 보여줘야 합니다.

**지원 전 준비**

새로운 대형 프로젝트를 시작하기보다, 지금까지의 실험을 다음 구조로 빠르게 재정리하는 것이 효과적입니다.

1. 공개 LLM 벤치마크에서 취약 태스크를 식별
2. 실패 응답을 유형별로 분류
3. 취약 유형에 맞는 합성 학습 데이터를 생성·필터링
4. SFT 전후 성능과 다른 태스크의 성능 저하 여부 비교
5. 데이터 생성·중복 제거·품질 필터링 기준을 README에 기록

이력서에서는 **“모델을 사용했다”보다 “벤치마크로 병목을 찾고 데이터를 개선해 성능을 올렸다”**는 흐름을 강조해야 합니다.

### 2. NAVER Cloud — HyperCLOVA X Omni-modal Backbone Model 개발

**적합도: 9.4/10 · 대규모 GPU 경험을 가장 강하게 활용할 수 있는 후보**

* **근무지:** 경기도 성남시 분당구
* **고용 형태:** 체험형 인턴
* **지원 대상:** 학사 재학생 또는 기졸업자
* **게시일:** **2026년 8월 3일**
* **마감:** **2026년 8월 12일 18:00**
* **지원:** NAVER Cloud 채용 공고 연결 페이지 ([JLab][2])

대규모 GPU 클러스터에서 멀티모달 Backbone을 학습하고, Vision·Audio 기능을 추가하는 프레임워크 엔지니어링을 수행합니다. Pre-training recipe와 데이터 curation을 연구하며, FSDP·ZeRO·Megatron·sequence packing·sequence parallel 등 분산 학습 효율화 기술을 직접 적용합니다. Python과 LLM/VLM 학습 구조 이해, DeepSpeed·PyTorch FSDP 이해를 요구합니다. ([JLab][2])

**잘 맞는 이유**

현재 사용할 수 있는 B200 다중 GPU 환경을 가장 직접적으로 포트폴리오로 전환할 수 있는 공고입니다. 사용자가 계획한 모델 학습·서빙 실험과 GPU 수에 따른 처리량·메모리 비교도 분산 학습 역량으로 연결할 수 있습니다.

**부족할 수 있는 부분**

가장 큰 간극은 VLM·멀티모달 학습 경험입니다. LLaVA, Qwen-VL, DeepSeek-VL 같은 모델의 아키텍처와 데이터·loss 구성도 설명할 수 있어야 합니다. Slurm·Kubernetes 기반 멀티노드 경험과 FSDP·DeepSpeed 실험 결과도 경쟁 지원자보다 약할 수 있습니다.

**지원 전 준비**

* 소형 VLM 하나를 Hugging Face로 실행하고 학습 데이터 형식 분석
* 단일 GPU와 FSDP 2·4 GPU의 처리량·VRAM·학습 시간 비교
* gradient checkpointing, mixed precision, sequence packing 적용 전후 측정
* 텍스트 전용 LLM과 VLM 학습 파이프라인의 차이 정리
* OOM 또는 통신 병목을 해결한 과정 문서화

시간이 부족하다면 완전한 VLM 학습보다 **FSDP 벤치마크와 멀티모달 데이터 파이프라인 분석**을 우선하는 편이 좋습니다.

* **게시 시점:** LinkedIn 기준 **2026년 8월 4일경**
* **마감:** 별도 기한 미표기

* **지원:** DeepLearning.AI 공식 채용 공고 ([Lever][3])

RAG, fine-tuning, agentic workflow, evaluation, guardrail을 이용해 AI 교육 제품과 콘텐츠 제작 도구를 개발합니다. Python 백엔드와 관계형·NoSQL·그래프·벡터 데이터베이스 역량을 요구하며, Claude Code·Codex·Gemini CLI 같은 코딩 에이전트를 프로토타이핑과 프로덕션 코드 개발에 모두 활용하는 경험도 명시적으로 평가합니다. ([Lever][3])

**잘 맞는 이유**

Codex 기반 개발 경험, LLM 에이전트 관심, Python·FastAPI와 RAG 프로젝트 방향을 활용할 수 있습니다. 특히 사용자가 구상한 공지 행동카드 에이전트는 tool calling, RAG, evaluation을 모두 보여줄 수 있어 직무와 연결성이 높습니다.

**부족할 수 있는 부분**

React·TypeScript·Tailwind 등 프런트엔드 역량과 실제 클라우드 배포 경험이 필요합니다. 가장 큰 현실적 장벽은 미국 대면 근무와 취업 허가이며, 공고에는 비자 스폰서십이 명시돼 있지 않습니다. ([Lever][3])

**지원 전 준비**

* Python·FastAPI 백엔드
