# Day 42 — Explaining Precision–Recall Trade-offs and Decision Thresholds

오늘 목표는 **모델의 정확도를 하나의 숫자로만 보지 않고, 어떤 오류를 더 줄여야 하는지에 따라 precision과 recall의 우선순위가 달라진다는 점**을 설명하는 것입니다. 오늘은 **error type → precision/recall → threshold → application risk → decision** 구조로 말하는 연습을 합니다.

## 1. Speaking Prompt — 2분

다음 질문에 60–90초 동안 영어로 답해보세요.

> You are building a malware detection system. One model catches almost every malicious file, but it also incorrectly flags many safe files. Another model produces fewer false alarms but misses more malicious files. Which model would you prefer?

답변에는 **false positive와 false negative의 차이, 어떤 오류가 더 위험한지, precision과 recall 중 무엇을 우선할지, threshold를 어떻게 조정할지**를 포함하세요.

시작은 이렇게 해보세요.

> The better model depends on which type of error is more costly in the deployment environment.

## 2. Reusable Speaking Templates — 3분

첫 번째는 **오류 비용을 비교할 때** 사용합니다.

> The key question is whether **[false positives]** or **[false negatives]** are more costly.

예:

> The key question is whether false positives or false negatives are more costly in the security setting.

두 번째는 **precision과 recall의 우선순위를 설명**할 때 유용합니다.

> If missing a positive case is especially costly, I would prioritize **[recall]** over **[precision]**.

예:

> If missing malware is especially costly, I would prioritize recall over precision.

세 번째는 **threshold 조정을 말할 때** 씁니다.

> We can adjust the decision threshold to trade **[metric A]** for **[metric B]**.

예:

> We can lower the decision threshold to increase recall at the cost of precision.

## 3. Useful Words & Expressions — 4분

**false positive**는 실제로는 음성인데 모델이 양성이라고 잘못 판단한 경우입니다.

> A false positive occurs when a safe file is incorrectly classified as malicious.

일반 영어로 바꾸면:

> The system raised an unnecessary alarm.

**false negative**는 실제 양성을 놓친 경우입니다.

> A false negative occurs when malware is incorrectly classified as benign.

보안이나 의료에서는 false negative의 비용이 특히 클 수 있습니다.

**precision**은 모델이 양성이라고 판단한 것 중 실제 양성의 비율입니다.

> High precision means that most flagged cases are truly positive.

실무적으로는 `few false alarms`와 연결해서 이해하면 쉽습니다.

**recall**은 실제 양성 중에서 모델이 얼마나 많이 찾아냈는지를 의미합니다.

> High recall means that the model misses relatively few positive cases.

보안 탐지에서는 `detection rate`와 비슷한 맥락으로 자주 설명됩니다.

**decision threshold**는 모델이 양성으로 분류하기 위한 기준값입니다.

> Lowering the decision threshold usually increases recall but may reduce precision.

자주 쓰는 표현은 `threshold tuning`, `threshold selection`, `operating point`입니다.

## 4. Correction Exercise — 3분

먼저 직접 고쳐본 뒤 정답을 확인하세요.

### 1

> This model has many false positive.

정답:

> This model has many false positives.

설명: `false positive`는 셀 수 있는 명사이므로 여러 건이면 복수형을 써야 합니다.

- many false positive ❌
- many false positives ✅

### 2

> Recall is more important than precision in this case because missing malware is more dangerous.

이 문장은 거의 맞습니다. 조금 더 자연스럽게 다듬으면:

> Recall is more important than precision in this case because missing malware is more costly.

설명: `dangerous`도 가능하지만 모델 오류의 영향이나 비용을 말할 때는 `costly`가 더 전문적입니다.

### 3

> If we decrease threshold, recall will go high.

정답:

> If we lower the threshold, recall will increase.

설명:

- decrease threshold △
- lower the threshold ✅
- recall goes high △
- recall increases ✅

수치나 기준값에는 `lower`가 자연스럽습니다.

### 4

> High precision means model rarely makes false positive.

정답:

> High precision means that the model makes relatively few false positives.

설명: 세 가지를 고쳤습니다.

- `the model`처럼 관사 필요
- `false positives` 복수형
- `few`가 `rarely makes`보다 더 자연스러움

### 5

> We should choose threshold depends on business requirement.

정답:

> We should choose the threshold based on the deployment requirements.

또는:

> The threshold should depend on the deployment requirements.

설명:

- depends on을 바로 동사 뒤에 붙일 수 없음
- `business requirement`보다 여기서는 `deployment requirements`가 더 정확함

## 5. 60–90 Second Speaking Practice — 2분

다음 흐름으로 말해보세요.

> Model A achieves higher recall, but …  
> Model B produces fewer false positives, but …  
> The more important error in this setting is …  
> Therefore, I would prioritize …  
> We could also adjust …  
> If we lower the threshold, …  
> Based on the deployment risk, I would choose …

초급식 표현:

> Model A is better because it catches more malware.

더 정확한 표현:

> Model A catches more malware, but it also produces more false positives.

C1에 가까운 표현:

> In a security-sensitive environment, I would generally favor higher recall if the cost of missing malicious files outweighs the operational burden of investigating additional false positives.

## Compact Model Answer — 1분

> I would probably prefer the model with higher recall if the system is used for malware detection. In this setting, a false negative means that a malicious file is classified as safe, which could lead to a serious security incident. A false positive is also costly because analysts may waste time investigating benign files, but the consequences are usually easier to contain. I would therefore prioritize recall while keeping the false-positive rate within an operationally acceptable range. I would also tune the decision threshold rather than relying on the default value. Lowering the threshold could improve recall, although it would likely reduce precision. The final operating point should be selected based on the relative cost of each error type and the available review capacity.

오늘 입에 붙일 세 문장은 이것입니다: **“The key question is which type of error is more costly.” → “I would prioritize recall if missing a positive case is especially costly.” → “The decision threshold should reflect the deployment requirements.”**
