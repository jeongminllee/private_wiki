# Day 35 — Explaining Robustness: Does the Model Still Work When Conditions Change?

오늘 목표는 **평가 환경이 조금 바뀌었을 때도 모델 성능이 유지되는지 설명하는 것**입니다. 오늘은 **standard performance → distribution shift → robustness → failure analysis → deployment confidence** 구조로 말하는 연습을 합니다.

## 1. Speaking Prompt — 2분

다음 질문에 60–90초 동안 영어로 답해보세요.

> A model performs very well on the test set, but its accuracy drops significantly when the input format, writing style, or domain changes slightly. Would you consider the model robust enough for deployment?

답변에는 **기본 테스트 성능과 실제 환경의 차이, robustness가 왜 중요한지, 어떤 변화에 취약한지, 배포 전 어떤 추가 평가가 필요한지**를 포함하세요.

시작은 이렇게 해보세요.

> Strong performance on a standard test set does not necessarily mean that the model is robust to changes in real-world inputs.

## 2. Reusable Speaking Templates — 3분

첫 번째는 **환경 변화에 따른 성능 저하를 설명**할 때 사용합니다.

> The model performs well under **[condition A]**, but its performance degrades when **[condition B]**.

예:

> The model performs well on clean inputs, but its performance degrades when the writing style becomes less structured.

두 번째는 **robustness를 정의하거나 평가할 때** 유용합니다.

> A robust model should maintain reasonably stable performance across **[different conditions]**.

예:

> A robust model should maintain reasonably stable performance across domains, input formats, and noise levels.

세 번째는 **배포 전 추가 검증을 제안할 때** 씁니다.

> Before deployment, I would evaluate the model under **[stress condition]** to identify **[failure mode]**.

예:

> Before deployment, I would evaluate the model under distribution shifts to identify conditions that cause systematic failures.

## 3. Useful Words & Expressions — 4분

**robust**는 조건이 조금 바뀌어도 성능이 크게 무너지지 않는다는 뜻입니다.

> The model is accurate, but it is not robust to noisy inputs.

논문에서는 `robustness`, `robust evaluation`, `robust performance`라는 표현이 자주 나옵니다.

**distribution shift**는 학습이나 평가 데이터의 분포와 실제 입력 데이터의 분포가 달라지는 상황입니다.

> Performance dropped under distribution shift.

예:

> A model trained on formal text may struggle when evaluated on informal conversations.

**degrade**는 성능이 저하되다는 뜻입니다.

> Accuracy degrades as input noise increases.

일반 영어에서도 가능합니다.

> Image quality degraded after compression.

**sensitivity**는 특정 변화에 얼마나 민감한지를 뜻합니다.

> The experiment revealed high sensitivity to prompt wording.

자주 쓰는 표현:

> sensitivity to noise  
> sensitivity to hyperparameters  
> sensitivity analysis

**failure mode**는 시스템이 특정 조건에서 반복적으로 실패하는 방식입니다.

> We identified several failure modes during stress testing.

실무와 연구 모두에서 매우 유용합니다.

> Understanding failure modes is essential before deployment.

## 4. Correction Exercise — 3분

먼저 직접 고쳐본 뒤 정답을 확인하세요.

### 1

> The model is strong for noisy data.

더 자연스럽게:

> The model is robust to noisy data.

설명: 기술적으로 “변화나 노이즈에 잘 견딘다”는 의미에는 `strong`보다 `robust to`가 훨씬 정확합니다.

- strong for noisy data △
- robust to noisy data ✅

### 2

> The accuracy became very down when domain changed.

정답:

> The accuracy dropped significantly when the domain changed.

설명: `became down`은 자연스럽지 않습니다.

- accuracy went down ✅
- accuracy dropped ✅
- accuracy decreased ✅

연구 영어에서는 `dropped significantly`가 매우 자연스럽습니다.

### 3

> The model is sensitive about prompt format.

정답:

> The model is sensitive to prompt format.

설명:

- sensitive about → 감정적으로 예민하다는 의미에서 자주 사용
- sensitive to → 어떤 변화나 자극에 민감함

따라서 기술 문맥에서는 `sensitive to`를 사용합니다.

### 4

> We should test model in many different situation.

정답:

> We should test the model under many different conditions.

설명: 특정 모델을 말하므로 `the model`이 필요합니다. 또한 실험 문맥에서는 `situations`보다 `conditions`가 더 자연스럽습니다.

### 5

> If performance is dropped easily, deployment is dangerous.

더 자연스럽게:

> If performance degrades easily under small input changes, deployment may be risky.

설명: `is dropped`는 수동태라서 여기서는 어색합니다. 성능 자체가 떨어지는 것이므로 능동형을 씁니다.

- performance is dropped ❌
- performance drops ✅
- performance degrades ✅

또한 연구·실무 영어에서는 `dangerous`보다 `risky`가 더 적절한 경우가 많습니다.

## 5. 60–90 Second Speaking Practice — 2분

다음 흐름으로 한 번에 말해보세요.

> The model performs well on …  
> However, its performance degrades when …  
> This suggests that the model may be sensitive to …  
> A robust system should …  
> Before deployment, I would evaluate …  
> I would also analyze failure modes related to …  
> Based on the current evidence, I would …

오늘은 특히 **“test accuracy가 높다”와 “실제 환경에서도 안정적으로 작동한다”를 구분해서 말하는 것**에 집중하세요.

초급식 표현:

> The model is good because the test accuracy is high.

더 정확한 표현:

> The model performs well on the test set, but its robustness under changing conditions is still unclear.

C1에 가까운 표현:

> Although the model achieves strong in-distribution performance, its sensitivity to relatively minor input shifts raises concerns about its robustness in real-world deployment.

## Compact Model Answer — 1분

> I would not consider the model fully robust if its performance drops substantially after relatively small changes in input format, writing style, or domain. Strong test-set performance is useful, but real-world inputs rarely follow exactly the same distribution as the evaluation data. If the model is highly sensitive to these shifts, its reliability in deployment may be limited. I would therefore evaluate the system across multiple domains, noisy inputs, alternative formats, and different writing styles. I would also analyze the failure modes to determine whether the degradation is random or systematic. If performance remains reasonably stable across these conditions, I would have greater confidence in deployment. Otherwise, additional training or robustness-oriented evaluation would be necessary.

오늘 입에 붙일 세 문장은 이것입니다: **“The model’s performance degrades under distribution shift.” → “A robust model should remain stable across changing conditions.” → “We need to identify failure modes before deployment.”**
