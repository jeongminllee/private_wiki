# Day 2 — Explaining a Technical Problem Clearly

오늘 목표는 **문제–원인–해결–결과** 구조로 60–90초 동안 설명하는 것입니다. 면접, 회의, 논문 발표에서 그대로 활용할 수 있는 패턴입니다.

## 1. Speaking Prompt — 2분

다음 질문에 영어로 답해보세요.

> Describe a technical problem you encountered recently. What caused it, and how did you solve it?

아래 네 가지 정보만 순서대로 말하면 됩니다.

1. 어떤 문제가 발생했는가
2. 원인이 무엇이었는가
3. 무엇을 시도했는가
4. 결과적으로 무엇을 배웠는가

---

## 2. 재사용 가능한 말하기 템플릿 — 3분

### Template 1: 문제 설명

> I ran into an issue where **[problem]**.

예:

> I ran into an issue where the model returned an empty response.

`run into an issue`는 `meet a problem`보다 훨씬 자연스럽습니다.

### Template 2: 원인 분석

> After investigating the issue, I found that **[cause]**.

예:

> After investigating the issue, I found that the endpoint configuration was incorrect.

### Template 3: 해결과 교훈

> I resolved the issue by **[solution]**, which taught me that **[lesson]**.

예:

> I resolved the issue by updating the configuration, which taught me that environment settings should always be verified first.

이 구조는 매우 강력합니다.

> problem → investigation → solution → lesson

---

## 3. 오늘의 핵심 표현 5개 — 4분

### 1. run into an issue

**문제에 부딪히다**

> I ran into an issue while deploying the model.

자연스러운 대체 표현:

> I encountered an issue during deployment.

---

### 2. identify the root cause

**근본 원인을 파악하다**

> It took some time to identify the root cause of the error.

`root cause`는 단순한 증상이 아니라 문제의 근본 원인을 뜻합니다.

---

### 3. reproduce the problem

**문제를 재현하다**

> I reproduced the problem in a separate environment.

디버깅에서는 문제를 먼저 재현할 수 있어야 합니다.

---

### 4. resolve

**문제를 해결하다**

> The issue was resolved after I changed the dependency version.

`solve`도 가능하지만, 기술적 문제에는 `resolve an issue`가 자주 사용됩니다.

---

### 5. robust

**견고한, 쉽게 실패하지 않는**

> We need a more robust error-handling mechanism.

논문 예문:

> The proposed method is robust to noisy input data.

주의:

* `robust for noise`보다는
* `robust to noise`가 자연스럽습니다.

---

## 4. 교정 연습 — 3분

먼저 직접 고친 후 정답을 확인하세요.

### 1

> An error was happened during training.

정답:

> An error occurred during training.

또는:

> An error happened during training.

설명:

`happen`과 `occur`는 자동사이므로 수동태를 쓰지 않습니다.

* was happened ❌
* happened ✅
* occurred ✅

---

### 2

> I searched the reason of the error.

더 자연스러운 표현:

> I investigated the cause of the error.

또는:

> I tried to identify the cause of the error.

설명:

기술적 원인을 분석할 때 `search the reason`보다 `investigate the cause`가 자연스럽습니다.

---

### 3

> Finally, I could solve the problem.

더 자연스러운 표현:

> Eventually, I was able to solve the problem.

설명:

과거의 특정 상황에서 “해낼 수 있었다”는 의미라면 `was able to`가 더 자연스럽습니다.

* I could understand the explanation.
  일반적인 능력이나 가능성
* I was able to fix the error.
  실제로 한 번 성공한 결과

---

### 4

> This problem made me to check the configuration again.

정답:

> This problem made me check the configuration again.

설명:

`make + 사람 + 동사원형` 구조에서는 `to`를 쓰지 않습니다.

* made me to check ❌
* made me check ✅

---

### 5

> The method is robust for unexpected inputs.

정답:

> The method is robust to unexpected inputs.

설명:

`robust`는 일반적으로 `to`와 함께 사용합니다.

---

## 5. 60–90초 말하기 — 2분

아래 구조를 따라 소리 내어 말하세요.

> Recently, I ran into an issue where …
> At first, I thought …
> After investigating the issue, I found that …
> I tried several approaches, including …
> Eventually, I resolved the issue by …
> This experience taught me that …

오늘은 `because`만 반복하지 말고 아래 연결어를 사용해보세요.

* At first
* After that
* Eventually
* As a result
* This experience taught me that

---

## Model Answer — 1분

> Recently, I ran into an issue while setting up a machine learning environment. A package listed in the project configuration was not available when I ran the code. At first, I assumed that the installation had failed completely. After investigating the issue, however, I found that I was using a different Python environment from the one managed by the project. I reproduced the problem, checked the interpreter path, and compared the installed packages in both environments. Eventually, I resolved the issue by selecting the correct interpreter and reinstalling the dependencies. This experience taught me that environment consistency is essential for building robust machine learning systems.

## 한 단계 높은 표현

기본:

> I fixed the problem.

발전:

> I identified the root cause and resolved the issue by verifying the environment configuration.

기본:

> I tried many things.

발전:

> I tested several possible solutions and ruled them out one by one.

오늘의 핵심 교정:

> An error was happened. ❌
> An error occurred. ✅

> It made me to check it again. ❌
> It made me check it again. ✅
