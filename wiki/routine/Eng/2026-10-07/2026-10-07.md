# Day 53 — Explaining Robustness: Does the Model Still Work When the Input Changes?

오늘 목표는 **정상적인 평가 데이터에서는 잘 작동하는 모델이 입력이 조금 변했을 때도 안정적으로 동작하는지** 설명하는 것입니다. 오늘은 **clean performance → perturbation → robustness → failure mode → stronger evaluation** 구조를 연습합니다.

## 1. Speaking Prompt — 2분

다음 질문에 60–90초 동안 영어로 답해보세요.

> A model performs very well on clean test data, but its accuracy drops sharply when small changes are made to the input. Would you consider the model robust?

답변에는 **clean accuracy만으로 충분한지, 작은 입력 변화가 왜 중요한지, robustness를 어떻게 평가할지, 실제 배포에서 어떤 문제가 생길 수 있는지**를 포함하세요.

시작은 이렇게 해보세요.

> I would not consider the model fully robust if small input changes cause a large drop in performance.

## 2. Reusable Speaking Templates — 3분

첫 번째는 **정상 조건과 변화된 조건을 비교할 때** 사용합니다.

> The model performs well under **[normal conditions]**, but its performance deteriorates when **[condition changes]**.

예:

> The model performs well under clean conditions, but its performance deteriorates when the input contains noise.

두 번째는 **robustness의 의미를 설명할 때** 유용합니다.

> A robust model should maintain relatively stable performance even when **[input/environment]** changes slightly.

예:

> A robust model should maintain relatively stable performance even when the input distribution changes slightly.

세 번째는 **추가 평가를 제안할 때** 씁니다.

> I would evaluate the model under **[several perturbations / stress conditions]** before concluding that it is reliable.

예:

> I would evaluate the model under several perturbations before concluding that it is reliable enough for deployment.

## 3. Useful Words & Expressions — 4분

**robustness**는 조건이 조금 변해도 성능이 크게 무너지지 않는 성질입니다.

> Robustness is important for models deployed in unpredictable environments.

자주 나오는 표현은 `model robustness`, `robustness evaluation`, `robustness benchmark`입니다.

**perturbation**은 입력에 가해지는 작은 변화나 교란입니다.

> Small perturbations caused a significant drop in accuracy.

연구에서는 다음처럼 자주 씁니다.

> input perturbation  
> adversarial perturbation

**deteriorate**는 상태나 성능이 악화된다는 뜻입니다.

> Model performance deteriorated under noisy conditions.

일반 영어에서도 유용합니다.

> The road conditions deteriorated because of the heavy rain.

**sensitive to**는 어떤 변화에 영향을 많이 받는다는 뜻입니다.

> The model is highly sensitive to small changes in the input.

일상 영어에서도 자주 씁니다.

> This device is sensitive to temperature changes.

**stress test**는 정상 조건보다 까다로운 환경에서 시스템의 한계를 확인하는 평가입니다.

> We should stress-test the model before deployment.

일반 시스템 엔지니어링에서도 매우 자주 쓰입니다.

> The service passed the load stress test.

## 4. Correction Exercise — 3분

먼저 직접 고쳐보세요.

### 1

> The model performance dropped a lot by small changes.

정답:

> The model’s performance dropped significantly because of small input changes.

또는:

> Small input changes caused a significant drop in model performance.

설명: 연구 영어에서는 `a lot`보다 `significantly`가 더 자연스럽습니다.

### 2

> The model is weak for noisy data.

더 자연스럽게:

> The model is sensitive to noisy data.

또는:

> The model performs poorly on noisy data.

설명: `weak for`는 자연스럽지 않습니다.

- weak for noisy data ❌
- sensitive to noisy data ✅
- performs poorly on noisy data ✅

### 3

> We need test robustness with many condition.

정답:

> We need to test robustness under multiple conditions.

설명:

- need test ❌
- need to test ✅
- many condition ❌
- multiple conditions ✅

그리고 실험 조건은 보통 `under conditions`라고 합니다.

### 4

> Small perturbation should not makes big difference.

정답:

> Small perturbations should not cause a large difference.

설명:

`should` 뒤에는 동사원형을 사용합니다.

- should not makes ❌
- should not make ✅

연구 문맥에서는 `cause a large difference`가 더 자연스럽습니다.

### 5

> High clean accuracy doesn't guarantee the model works good in real world.

정답:

> High accuracy on clean data does not guarantee that the model will perform well in the real world.

설명:

- works good ❌
- performs well ✅

`good`은 형용사이고, 동사를 수식할 때는 `well`을 사용합니다.

또한 `in real world`보다는 `in the real world`가 자연스럽습니다.

## 5. 60–90 Second Speaking Practice — 2분

다음 흐름으로 한 번에 말해보세요.

> The model performs well on clean data, but …  
> Its performance drops when …  
> This suggests that …  
> A robust model should …  
> I would therefore test …  
> I would also examine whether …  
> Based on these results, …

초급식 표현:

> The model is good on normal data but bad when data changes.

더 정확한 표현:

> The model performs well on clean data, but its performance degrades when the input changes slightly.

C1에 가까운 표현:

> Although the model achieves strong clean-set performance, its sensitivity to minor perturbations suggests that the learned representation may not be sufficiently robust for real-world deployment.

## Compact Model Answer — 1분

> I would not consider the model fully robust if small input changes lead to a large performance drop. Strong accuracy on clean test data shows that the model works well under controlled conditions, but robustness requires stable performance under realistic variation. For example, noise, formatting differences, or slight distribution changes may occur after deployment. I would therefore evaluate the model under several types of perturbations and compare the performance degradation with the clean-data baseline. I would also examine whether the failures are random or concentrated in particular input patterns. If the model remains accurate across these stress conditions, I would have greater confidence that it is robust enough for real-world use.

오늘 입에 붙일 세 문장은 이것입니다: **“High clean accuracy does not guarantee robustness.” → “The model is sensitive to small input perturbations.” → “A robust model should maintain stable performance under changing conditions.”**
