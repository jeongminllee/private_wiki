# 오류 수정 및 검출 방식

> **카테고리**: `ML - Models & Theory`  
> **원천**: ChatGPT 대화 아카이브 (`raw/notes/Chatgpt_2026-08-02-23-14-23`)

## 💬 대화 내용 및 Q&A

### 💡 답변 (Assistant)
===
✅ 문제 분석

제시된 설명의 핵심 포인트는 다음과 같습니다.

- **수신 측에서 오류를 직접 수정 (재전송 없음)**
- **1비트 오류 수정 가능**
- **오류 검출 + 수정 기능**
- **재전송 요구 방식과 대비**
- **패리티 비트, 체크섬, 다항식**

→ 핵심 키워드 정리  
👉 오류 수정 / 재전송 없음 / 1비트 수정 / 패리티 / 체크섬 / 다항식

---

🎯 정답

- ① **해밍(Hamming) 코드**
- ② **FEC (Forward Error Correction, 전진 오류 수정)**
- ③ **ARQ (Automatic Repeat reQuest, 자동 재전송 요구)**
- ④ **패리티(Parity) 검사**
- ⑤ **CRC (Cyclic Redundancy Check)**

---

📌 정답인 이유

### ① 해밍 코드 (Hamming Code)

- 대표적인 **오류 수정 코드**
- **1비트 오류 검출 + 수정 가능**
- 수신 측에서 오류 위치를 계산해서 **직접 수정**
→ 문제에서 “재전송 없이 스스로 수정”과 정확히 일치

---

### ② FEC (Forward Error Correction)

| 구분 | 설명 |
|------|------|
| 개념 | 오류 발생 시 **재전송 없이 수신 측에서 복구** |
| 특징 | 실시간 통신 (위성, 방송 등)에 적합 |
| 대표 예 | 해밍 코드 |

→ 해밍 코드는 **FEC 방식의 대표적인 구현**

---

### ③ ARQ (Automatic Repeat reQuest)

| 구분 | 설명 |
|------|------|
| 개념 | 오류 발생 시 **송신 측에 재전송 요청** |
| 특징 | 네트워크 신뢰성 확보 |
| 방식 | Stop-and-Wait, Go-Back-N, Selective Repeat |

→ 문제에서 “반대 방식”이라고 했으므로 FEC ↔ ARQ 구조

---

### ④ 패리티 검사 (Parity Check)

- 데이터 끝에 **1비트 추가**
- 홀수/짝수 개수 맞추는 방식
- **간단하지만 오류 수정 불가 (검출만 가능)**

→ 문제에서 “1비트 추가” 설명과 일치

---

### ⑤ CRC (순환 중복 검사)

- **다항식 기반 계산**
- 데이터에 체크값 추가
- 오류 검출 능력 매우 우수

→ “다항식을 이용하여 검사” → CRC

---

🔎 헷갈릴 수 있는 오답

❌ BEC (Backward Error Correction)  
→ 존재하지 않는 개념 (시험 함정)

❌ MD5  
→ 해시 함수 (무결성 검증), 오류 검출 코드 아님

❌ 해밍 코드 vs CRC 혼동  
→ 해밍: **수정 가능**  
→ CRC: **검출만 가능**

---

📚 추가로 공부해야 할 것 (매우 중요)

### 1️⃣ 오류 제어 방식 전체 구조 (시험 핵심)

```
오류 제어
├── FEC (전진 오류 수정)
│   └── 해밍 코드
│
└── ARQ (재전송 요구)
    ├── Stop-and-Wait
    ├── Go-Back-N
    └── Selective Repeat
```

👉 이 구조는 **단골 출제**

---

### 2️⃣ 오류 검출 vs 오류 수정 (핵심 비교)

| 구분 | 오류 검출 | 오류 수정 |
|------|----------|----------|
| 대표 | 패리티, CRC | 해밍 코드 |
| 재전송 | 필요 | 불필요 |
| 복잡도 | 낮음 | 높음 |

👉 시험에서 “재전송 여부”로 구분하면 빠르게 해결 가능

---

### 3️⃣ CRC 동작 원리 (고빈도)

- 데이터 → 다항식으로 변환
- 생성 다항식으로 나눗셈 수행
- 나머지를 체크값으로 추가

👉 키워드: **다항식 / 나머지 / 나눗셈**

---

🧠 실기시험 포인트 정리

✔ “재전송 없음” → **FEC**  
✔ “재전송 요구” → **ARQ**  
✔ “1비트 수정 가능” → **해밍 코드**  
✔ “1비트 추가” → **패리티 검사**  
✔ “다항식 기반” → **CRC**

---

필요하면 **ARQ 3가지 방식 문제 (Go-Back-N vs Selective Repeat)**도 자주 나오니까 이어서 같이 정리해줄게.

---

### ❓ 질문 (User)
( ① ) 코드 방식은 수신측에서 오류가 발생한 비트를 찾아 재전송을 요구하지 않고 자신이 직접 오류를 수정하는 방식으로 1비트의 오류 수정이 가능하다. ( ① ) 코드 방식은 ( ② ) 방식으로 이루어진다. ( ② ) 방식은 데이터 전송 과정에서 발생한 오류를 검출하여 검출된 오류를 재전송 요구 없이 스스로 수정하는 방식이다. ( ② ) 방식과 반대되는 ( ③ )방식은 데이터 전송 과정에서 오류가 발생하면 송신 측에 재전송을 요구하는 방식이다. 대표적인 유형에는 ( ④ ) 검사, ( ⑤ ) 등이 있다. 7~8개의 비트로 구성되는 전송 문자 끝에 1비트를 추가하여 검사하는 ( ④ ) 검사 방식이 있고, 체크섬을 추가하여 다항식을 통해 산출된 값을 토대로 오류를 검사하는 ( ⑤ ) 방식이 있다.
---

### ❓ 질문 (User)
다음은 서버 접근통제의 유형이다. 괄호 ( ) 안에 들어갈 용어를 쓰시오. (단, 영어 약어로 작성하시오.)

- ( ① )은/는 강력한 중앙통제 방식으로 군대 같은 높은 보안 요구 시스템에 적합한 접근 통제 방식이다.

- ( ② )은/는 중앙 관리자가 사용자와 시스템의 상호 관계를 통제하며 조직 내 맡은 역할(Role)에 기초하여 자원에 대한 접근을 제한하는 방법이다.

- ( ③ )은/는 소유자가 권한을 지정하는 방식이며, 신분 기반(Identity-Based) 접근통제 정책을 사용한다. 주체나 그룹의 신분에 근거하여 객체에 대한 접근을 제한하는 방법이다.

### 💡 답변 (Assistant)
===
✅ 문제 분석

제시된 설명의 핵심 포인트는 다음과 같습니다.

- **중앙 통제 / 군대 / 보안 등급**
- **역할(Role) 기반 접근 제어**
- **소유자(Owner)가 권한 지정 / 신분 기반**

→ 핵심 키워드 정리  
👉 중앙통제 / Role / 소유자 / Identity 기반

---

🎯 정답

- ① **MAC (Mandatory Access Control)**
- ② **RBAC (Role-Based Access Control)**
- ③ **DAC (Discretionary Access Control)**

---

📌 정답인 이유

### ① MAC (Mandatory Access Control)

| 구분 | 설명 |
|------|------|
| 개념 | **중앙 관리자에 의해 강제적으로 접근 제어** |
| 특징 | 사용자 임의 변경 불가 |
| 적용 | 군대, 정부, 보안 시스템 |

→ 문제의  
“강력한 중앙통제”, “군대 같은 높은 보안 요구”  
👉 MAC의 대표 특징

---

### ② RBAC (Role-Based Access Control)

| 구분 | 설명 |
|------|------|
| 개념 | **역할(Role)에 따라 접근 권한 부여** |
| 특징 | 사용자 대신 역할에 권한 부여 |
| 장점 | 관리 효율성 높음 |

→ 문제의  
“Role 기반”, “중앙 관리자가 관계 통제”  
👉 RBAC 정의와 일치

---

### ③ DAC (Discretionary Access Control)

| 구분 | 설명 |
|------|------|
| 개념 | **자원 소유자가 접근 권한을 설정** |
| 특징 | 사용자/그룹 기반 (Identity 기반) |
| 예시 | 파일 권한 설정 (읽기/쓰기/실행) |

→ 문제의  
“소유자가 권한 지정”, “신분 기반 접근 제어”  
👉 DAC 특징 그대로

---

🔎 헷갈릴 수 있는 오답

❌ ABAC (Attribute-Based Access Control)  
→ 속성 기반 (시간, 위치 등) → 문제에 없음

❌ IBAC  
→ 잘못된 표현 (Identity 기반은 DAC 설명일 뿐 별도 모델 아님)

---

📚 추가로 공부해야 할 것 (시험 핵심)

### 1️⃣ 접근통제 3대 모델 비교 (무조건 암기)

| 구분 | MAC | DAC | RBAC |
|------|-----|-----|------|
| 통제 주체 | 중앙 관리자 | 자원 소유자 | 관리자 + 역할 |
| 기준 | 보안 등급 | 사용자 신분 | 역할(Role) |
| 특징 | 강제적 | 유연함 | 관리 효율 |

👉 시험에서는 **키워드 매칭 문제**로 자주 출제됨

---

### 2️⃣ ABAC (추가 출제 포인트)

| 구분 | 설명 |
|------|------|
| 개념 | 속성 기반 접근 제어 |
| 기준 | 사용자, 자원, 환경 속성 |
| 예 | “근무 시간에만 접근 허용” |

👉 최근 신기술 문제로 등장 가능

---

### 3️⃣ 실무/시험 구분 포인트

- **군대 / 기밀 / 등급** → MAC  
- **파일 권한 / 소유자** → DAC  
- **회사 / 직무 / 역할** → RBAC  

---

🧠 실기시험 포인트 정리

✔ “중앙 통제 + 보안 등급” → **MAC**  
✔ “Role 기반” → **RBAC**  
✔ “소유자가 권한 설정” → **DAC**

---

이 파트는 **거의 무조건 출제되는 핵심 개념**이야.  
다음 단계로는 **접근통제 보안 모델 (벨-라파듈라, 비바 모델)**까지 같이 정리하면 완벽해.

### 조건 커버리지 (Condition Coverage)

| 구분 | 설명 |
|------|------|
| 기준 | **개별 조건식의 결과** |

### ❌ 결정 커버리지 (Decision Coverage)

- 전체 조건문의 결과 (True/False)만 검사
- 개별 조건까지 보지 않음

👉 문제와 반대 개념

---

### ❌ 조건/결정 커버리지

- 조건 + 결정 둘 다 만족해야 함
- 더 강한 커버리지

👉 문제에서는 “결정문 전체는 고려하지 않음” → 제외

---

### ❌ 변경 조건/결정 커버리지 (MC/DC)

- 각 조건이 결과에 **독립적으로 영향** 주는지 확인
- 항공/국방 등 고신뢰 시스템에서 사용

👉 난이도 높은 기법 → 본 문제와 무관

---

📚 추가로 공부해야 할 것 (시험 핵심)

### 1️⃣ 커버리지 종류 비교 (필수 암기)

| 커버리지 | 설명 |
|----------|------|
| 구문 커버리지 | 모든 코드 1번 실행 |
| 결정 커버리지 | 전체 조건 결과 True/False |
| **조건 커버리지** | 개별 조건 True/False |
| 조건/결정 커버리지 | 둘 다 만족 |
| MC/DC | 조건이 결과에 영향 확인 |

---

### 2️⃣ 핵심 구분 포인트

- **조건** → “개별 조건”  
- **결정** → “전체 결과”  

👉 이 차이 하나로 문제 해결 가능

---

### 3️⃣ 예시로 이해 (시험 대비)

```c
if (A && B)
```

| 커버리지 | 요구 조건 |
|----------|----------|
| 조건 커버리지 | A, B 각각 T/F 경험 |
| 결정 커버리지 | 전체 결과 T/F |
| 조건/결정 | 둘 다 만족 |

---

🧠 실기시험 포인트 정리

✔ “개별 조건” → **조건 커버리지**  
✔ “전체 결과” → **결정 커버리지**  
✔ “둘 다” → **조건/결정 커버리지**

---

이 문제는 **화이트박스 테스트 핵심 유형**이라서  
👉 거의 매 시험마다 변형되어 출제되는 파트야.

원하면  
👉 “MC/DC 실제 문제”까지 이어서 고난도 대비도 해줄게.

### ❓ 질문 (User)
다음 설명에 맞는 테스트 기법을 한글로 쓰시오. 
  
  1. 결정문 내 각 개별 조건식이 True 또는 False의 결과를 각각 한 번 이상 만족하는 커버리지이다.
  2. 전체 결정문의 참/거짓 결과를 모두 테스트하는 커버리지는 아니다.

# ✅ 문제 분석 (고난도 핵심 개념)

MC/DC는 단순히 조건을 True/False 만드는 게 아니라

👉 **각 조건이 결과에 “독립적으로 영향”을 주는지 검증**

이게 핵심이다.

---

# 🎯 핵심 개념 정리

## 변경 조건/결정 커버리지 (MC/DC)

👉 **Modified Condition/Decision Coverage**

---

## 📌 정의

- 각 개별 조건이
- **다른 조건은 고정된 상태에서**
- 결과값(True/False)을 **단독으로 변화시키는지 확인**

---

## 🧠 핵심 포인트 (시험용 암기)

✔ 조건 하나만 바꿨을 때  
✔ 결과가 바뀌어야 함  
👉 이것이 “독립적 영향”

---

# 📌 예제로 완벽 이해

```c
if (A && B)
```

---

## ❌ 조건 커버리지 (쉬움)

| A | B | 결과 |
|---|---|------|
| T | T | T |
| F | T | F |
| T | F | F |

👉 조건만 True/False 만들면 끝

---

## ❌ 결정 커버리지

| A | B | 결과 |
|---|---|------|
| T | T | T |
| F | F | F |

👉 결과만 True/False면 OK

---

## ✅ MC/DC (핵심)

👉 **각 조건이 결과에 영향을 주는지 확인해야 함**

---

### ✔ A의 영향 확인

| A | B | 결과 |
|---|---|------|
| T | T | T |
| F | T | F |

👉 A만 바꿨더니 결과 바뀜 → OK

---

### ✔ B의 영향 확인

| A | B | 결과 |
|---|---|------|
| T | T | T |
| T | F | F |

👉 B만 바꿨더니 결과 바뀜 → OK

---

👉 이게 MC/DC 완성

---

# 🔥 시험에서 진짜 나오는 유형

## 유형 1️⃣ “최소 테스트 케이스 개수”

👉 MC/DC는 최소 개수 묻는 문제 자주 나옴

### 공식 느낌

- 조건 n개 → **최소 n+1개 필요**

👉 (2개 → 3개 / 3개 → 4개)

---

## 유형 2️⃣ “옳은 테스트 케이스 선택”

👉 보기 중에서  
**MC/DC 만족하는 조합 찾기**

---

## 유형 3️⃣ “다른 커버리지와 비교”

| 커버리지 | 난이도 |
|----------|--------|
| 구문 | 쉬움 |
| 결정 | 보통 |
| 조건 | 보통 |
| 조건/결정 | 어려움 |
| **MC/DC** | ⭐최고난도 |

---

# 🔎 헷갈리는 포인트 정리

## ❌ 조건 커버리지 vs MC/DC

| 구분 | 조건 커버리지 | MC/DC |
|------|--------------|-------|
| 조건 True/False | O | O |
| 독립 영향 확인 | ❌ | ✅ |

👉 여기서 대부분 틀림

# 📚 추가로 반드시 공부해야 할 것

## 1️⃣ 복합 조건 문제 (실전 대비)

```c
if (A || (B && C))
```

👉 이런 형태가 실기 고난도 출제 포인트

---

## 2️⃣ 커버리지 포함 관계 (매우 중요)

```plaintext
MC/DC ⊃ 조건/결정 ⊃ 조건 ⊃ 구문
```

👉 상위 개념일수록 더 강함

---

## 3️⃣ 왜 MC/DC 쓰는가?

- 항공 (DO-178C)
- 국방
- 원전 시스템

👉 “절대 오류 허용 불가 시스템”

---

# 🧠 실기시험 포인트 정리 (고난도)

✔ “독립적 영향” → MC/DC  
✔ “조건만 True/False” → 조건 커버리지  
✔ “결과만 True/False” → 결정 커버리지  
✔ “최소 n+1” → MC/DC 문제 핵심 공식
