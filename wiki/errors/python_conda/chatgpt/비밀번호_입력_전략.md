# 비밀번호 입력 전략

> **카테고리**: `Errors - Python & Conda`

## 💬 대화 내용 및 Q&A

### ❓ 질문 (User)
문제
I have a really long password, and sometimes I make a mistake when I type it. Right now I've typed part of my password, but I might have made some mistakes. In particular, I might have pressed the wrong key while typing one or more of the previous characters. Given how likely I was to get each character right, what should I do?

I have three options:

Finish typing the password, then press "enter". I know I'll type the rest of the characters perfectly. If it turns out that one of the earlier characters was wrong, I'll have to retype the whole thing and hit "enter" again -- but I know I'll get it right the second time.
Hit "backspace" some number of times, deleting the last character(s) I typed, and then complete the password and press "enter" as in option 1. If one of the characters I didn't delete was wrong, I'll have to retype the whole thing and press "enter", knowing I'll get it right the second time.
Give up by pressing "enter", retyping the password from the start, and pressing "enter" again. I know I'll get it right this time.
 

I want to minimize the expected number of keystrokes needed. Each character in the password costs 1 keystroke; each "backspace" costs 1 keystroke; pressing "enter" to complete an attempt or to give up costs 1 keystroke.

Note: The "expected" number of keystrokes is the average number of keystrokes that would be needed if the same situation occurred a very large number of times. See the example below.

Example
Suppose my password is "guest" and I have already typed the first two characters, but I had a 40% chance of making a mistake when typing each of them. Then there are four cases:

I typed "gu" without error. This occurs with probability 0.6 * 0.6 = 0.36.
I typed the 'g' correctly but I made a mistake typing the 'u'. Then I have two letters typed still, but the second one is wrong: "gX". (Here, the 'X' character represents a mistyped letter.) This occurs with probability 0.6 * 0.4 = 0.24.
I typed the 'u' correctly but I made a mistake typing the 'g': "Xu". This occurs with probability 0.4 * 0.6 = 0.24.
I made a mistake typing both letters, so I have two incorrect letters: "XX". This occurs with probability 0.4 * 0.4 = 0.16.
 

I don't know how many mistakes I actually made, but for any strategy, I can calculate the expected number of keys required to use it. This is shown in the table below:

 

 	"gu"   	"gX"   	"Xu"   	"XX"   	Expected
Probability	0.36	0.24	0.24	0.16	-
Keystrokes if I keep typing	4	10	10	10	7.84
Keystrokes if I press backspace once	6	6	12	12	8.4
Keystrokes if I press backspace twice  	8	8	8	8	8
Keystrokes if I press enter right away	7	7	7	7	7
 

If I keep typing, then there is an 0.36 probability that I will need 4 keystrokes, and an 0.64 probability that I will need 10 keystrokes. If I repeated the trial many times, then I would use 4 keystrokes 36% of the time, and 10 keystrokes the remaining 64% of the time, so the average number of keystrokes needed would be 0.36 * 4 + 0.64 * 10 = 7.84. In this case however, it is better to just press enter right away, which requires 7 keystrokes.

입력
The first line of the input gives the number of test cases, T. T test cases follow. Each test case begins with a line containing two integers, A and B. A is the number of characters that I have already typed, and B is the total number of characters in my password.

This is followed by a line containing A real numbers: p1, p2, ..., pA. pi represents the probability that I correctly typed the ith letter in my password. These real numbers will consist of decimal digits and at most one decimal point. The decimal point will never be the first or the last character in a number.

Limits
1 ≤ T ≤ 20.
0 ≤ pi ≤ 1 for all i.
1 ≤ A ≤ 99999.
A < B ≤ 100000.
출력
For each test case, output one line containing "Case #x: y", where x is the case number (starting from 1) and y is the expected number of additional keystrokes I need, not counting the letters I have typed so far, and assuming I choose the optimal strategy. y must be correct to within an absolute or relative error of 10-6.

예제 입력 1 
3
2 5
0.6 0.6
1 20
1
3 4
1 0.9 0.1
예제 출력 1 
Case #1: 7.000000
Case #2: 20.000000
Case #3: 4.500000

### 💡 답변 (Assistant)
이 문제는 비밀번호를 입력할 때, 이미 입력한 글자들 중에 실수로 잘못 입력한 문자가 있을 확률을 고려하여 앞으로 추가로 입력해야 할 키의 총 횟수를 최소화하는 “전략”을 고르는 문제입니다. 즉, 지금까지 입력한 내용이 완벽하지 않을 수 있는데, 이를 보완하기 위해 어떻게 행동하는 것이 전체 키 입력 수(노력)를 줄일 수 있는지를 계산하는 것입니다.

### 상황 설명

- **비밀번호의 길이:** 총 \( B \)개의 문자  
- **이미 입력한 문자 수:** \( A \)개  
- **각 문자에 대한 확률:** \( p_1, p_2, \dots, p_A \)  
  → \( p_i \)는 \( i \)번째 문자를 올바르게 입력했을 확률입니다.  
- **남은 입력:** 앞으로 입력할 \( B - A \)개의 문자는 확실히 올바르게 입력할 수 있다고 가정합니다.

하지만, 이미 입력한 \( A \)개 문자 중 단 하나라도 틀리면, 전체 비밀번호를 처음부터 다시 입력해야 합니다.

### 선택할 수 있는 전략

1. **계속 입력하기 (Keep Typing):**  
   - **동작:** 남은 \( B - A \)개의 문자를 입력하고, 엔터키를 눌러 제출합니다.
   - **결과:**  
     - 만약 지금까지 입력한 \( A \)개의 문자가 모두 맞다면, 추가로 필요한 키 수는 남은 문자 입력 \( (B - A) \)회와 엔터키 1회, 즉 **\( B - A + 1 \)**회입니다.  
     - 만약 오타가 하나라도 있었다면, 비밀번호가 틀렸으므로 추가로 전체 비밀번호 \( B \)개와 엔터키 1회를 입력해야 하므로 **\( B - A + 1 + B + 1 \)**회가 필요합니다.
   - **기대 추가 키 입력수:**  
     \[
     (B - A + 1) + (1 - P_{\text{correct}}) \times (B + 1)
     \]
     여기서 \( P_{\text{correct}} = p_1 \times p_2 \times \cdots \times p_A \)입니다.

2. **백스페이스 사용하기 (Press Backspace):**  
   - **동작:** 백스페이스 키를 \( K \)번 눌러 마지막 \( K \)개의 문자를 지운 후, 그 부분과 남은 문자를 다시 입력하고 엔터키를 누릅니다.
   - **결과:**  
     - 이렇게 하면, 지우지 않은 처음 \( A - K \)개의 문자에 대해만 올바르게 입력했는지 의문을 갖게 됩니다.
     - 올바르게 입력했다면, 필요한 키 수는:
       - **백스페이스:** \( K \)회  
       - **다시 입력:** 지운 \( K \)개 문자 재입력 + 남은 \( B - A \)개 문자 입력  
       - **엔터키:** 1회  
       - 총: \( K + (B - (A - K) + 1) \)회
     - 만약 처음 \( A - K \)개의 문자 중 하나라도 틀렸다면, 그 후 전체 비밀번호 \( B \)개와 엔터키 1회를 추가로 입력해야 하므로 \( B + 1 \)회가 더 필요합니다.
   - **기대 추가 키 입력수:**  
     \[
     K + \bigl(B - (A - K) + 1\bigr) + \bigl(1 - P_{\text{correct}}(A-K)\bigr) \times (B + 1)
     \]
     여기서 \( P_{\text{correct}}(A-K) = p_1 \times p_2 \times \cdots \times p_{A-K} \) 입니다.

3. **바로 포기하기 (Give Up):**  
   - **동작:** 지금까지 입력한 것을 모두 무시하고, 엔터키를 눌러 시도한 뒤, 비밀번호 입력이 실패하면 처음부터 다시 입력합니다.
   - **결과:**  
     - 먼저 엔터키 1회,  
     - 이후 전체 비밀번호 \( B \)개 입력,  
     - 그리고 엔터키 1회가 필요하므로 총 **\( B + 2 \)**회의 키 입력이 요구됩니다.
   - **기대 추가 키 입력수:** 이 경우 확률과 상관없이 항상 \( B + 2 \)회입니다.

### 예제

예를 들어, 비밀번호가 `"guest"` (\( B = 5 \))이고, 지금까지 `"gu"` (\( A = 2 \))를 입력했다고 합시다. 각 문자를 제대로 입력할 확률이 \( 0.6 \)이라고 할 때:

- **계속 입력하기 (Option 1):**  
  \( P_{\text{correct}} = 0.6 \times 0.6 = 0.36 \)  
  기대 키 입력수는:  
  \[
  (5 - 2 + 1) + (1 - 0.36) \times (5 + 1) = 4 + 0.64 \times 6 = 4 + 3.84 = 7.84
  \]

- **백스페이스 1번 (Option 2, \( K = 1 \)):**  
  \( P_{\text{correct}}(1) = 0.6 \) (첫 글자만 남음)  
  기대 키 입력수는:  
  \[
  1 + (5 - (2-1) + 1) + (1 - 0.6) \times 6 = 1 + (5 - 1 + 1) + 0.4 \times 6 = 1 + 5 + 2.4 = 8.4
  \]

- **백스페이스 2번 (Option 2, \( K = 2 \)):**  
  \( P_{\text{correct}}(0) \) = (아무것도 남지 않으므로, 이를 1로 취급)  
  기대 키 입력수는:  
  \[
  2 + (5 - (2-2) + 1) + (1 - 1) \times 6 = 2 + 6 + 0 = 8
  \]

- **바로 포기하기 (Option 3):**  
  기대 키 입력수는:  
  \[
  5 + 2 = 7
  \]

이 예제에서는 옵션 3, 즉 바로 포기하고 다시 입력하는 것이 평균 \( 7 \)회로 가장 적은 키 입력을 필요로 하므로 최선의 선택입니다.

### 결론

문제의 핵심은 **이미 입력한 글자가 맞을 확률**을 이용해서,  
- **계속 입력**하는 경우,  
- **백스페이스를 눌러 일부를 지우고 수정**하는 경우, 그리고  
- **바로 포기하고 다시 시작**하는 경우  
각각에 대해 추가로 입력해야 할 키의 “기대값(평균)”을 계산한 뒤, 그 중 가장 적은 기대값을 주는 전략을 선택하는 것입니다.

이렇게 문제의 상황과 각 옵션의 비용(키 입력 횟수)을 이해하면, 주어진 확률 정보를 바탕으로 최적의 전략을 결정할 수 있게 됩니다.

## **테스트 케이스 1: \(A=2\), \(B=5\), 확률: 0.6, 0.6**

#### **상황 정리**
- **이미 입력한 문자:** 2개  
- **전체 문자:** 5개 → 남은 문자는 \(5 - 2 = 3\)개  
- **각 문자가 올바를 확률:**  
  - 1번째: 0.6  
  - 2번째: 0.6  
- **전체가 맞을 확률:** \(0.6 \times 0.6 = 0.36\)

#### **옵션별 전략**

1. **계속 입력하기 (Keep Typing):**
   - **정상인 경우:**  
     남은 3개 문자를 정확히 입력하고 엔터 → \(3 + 1 = 4\) 키  
   - **오타가 있을 경우:**  
     남은 3개 + 엔터(4키) 후, 비밀번호 전체 5개와 엔터 다시 입력 → \(4 + (5+1)=10\) 키  
   - **기대 키 수:**  
     \[
     0.36 \times 4 + 0.64 \times 10 = 1.44 + 6.4 = 7.84
     \]

2. **백스페이스 사용하기 (Backspace):**  
   - **예를 들어, 백스페이스 1번(\(K=1\))를 선택하면:**  
     - 남겨지는 문자는 \(A-K = 2-1 = 1\)개  
     - 첫 글자가 맞을 확률은 0.6  
     - **정상인 경우:**  
       비용 = 백스페이스 1번 + 남은 1개 문자를 재입력하고, 그 후 남은 \(5 - (2-1)=4\)개 문자를 입력 + 엔터  
       → \(1 + 4 + 1 = 6\) 키  
     - **오타가 있을 경우:**  
       위 6키에 더해 전체 재입력 \(5+1=6\)키 → \(6 + 6 = 12\) 키  
     - **기대 키 수:**  
       \[
       0.6 \times 6 + 0.4 \times 12 = 3.6 + 4.8 = 8.4
       \]
   - **백스페이스 2번(\(K=2\))의 경우:**  
     - 남겨지는 문자는 \(2-2=0\)개 (즉, 아무것도 남지 않으므로 확률 1로 취급)  
     - 비용 = 2(백스페이스) + \(5 - 0 = 5\) (전체 문자 입력) + 엔터 1 → \(2+5+1=8\) 키  
     - **기대 키 수:** 8

3. **바로 포기하기 (Give Up):**
   - **동작:**  
     지금 바로 엔터를 누른 후, 비밀번호 전체 5개와 엔터 재입력  
   - **비용:**  
     \(1\) (엔터) + \(5+1 = 6\) → 총 \(7\) 키

#### **최적 선택**
- 계속 입력: 7.84 키  
- 백스페이스 1번: 8.4 키  
- 백스페이스 2번: 8 키  
- 바로 포기: **7 키**

따라서 **최적 전략은 바로 포기하기**이며, 기대 추가 키 수는 **7.000000**회.

## **테스트 케이스 2: \(A=1\), \(B=20\), 확률: 1**

#### **상황 정리**
- **이미 입력한 문자:** 1개  
- **전체 문자:** 20개 → 남은 문자는 \(20 - 1 = 19\)개  
- **입력한 문자는 확실히 맞음 (\(p_1 = 1\))**

#### **옵션별 전략**

1. **계속 입력하기:**
   - 남은 19개 문자와 엔터 → \(19+1 = 20\) 키  
   - 오타 발생 확률이 0이므로 재입력 없음  
   - **기대 키 수:** 20

2. **백스페이스 사용하기:**
   - 예를 들어, 백스페이스 1번을 누르면:  
     - 남겨지는 문자는 \(1-1=0\)개  
     - 비용 = 1(백스페이스) + \(20 - 0=20\) (전체 문자 입력) + 엔터 1 → \(1+20+1=22\) 키  
   - 다른 백스페이스 옵션도 더 많은 키를 요구함

3. **바로 포기하기:**
   - 비용 = 엔터 1 + 전체 비밀번호 20개와 엔터 1 → \(1+21=22\) 키

#### **최적 선택**
- 계속 입력: **20 키**  
- 백스페이스나 포기: 22 키 이상

따라서 **최적 전략은 계속 입력하기**이며, 기대 추가 키 수는 **20.000000**회.

## **테스트 케이스 3: \(A=3\), \(B=4\), 확률: 1, 0.9, 0.1**

#### **상황 정리**
- **이미 입력한 문자:** 3개  
- **전체 문자:** 4개 → 남은 문자는 \(4 - 3 = 1\)개  
- **각 문자 올바를 확률:**  
  - 1번째: 1  
  - 2번째: 0.9  
  - 3번째: 0.1  
- **전체가 맞을 확률:** \(1 \times 0.9 \times 0.1 = 0.09\)

#### **옵션별 전략**

1. **계속 입력하기:**
   - **정상인 경우:**  
     남은 1개 문자와 엔터 → \(1+1=2\) 키  
   - **오타가 있을 경우:**  
     \(2\) 키 사용 후, 전체 비밀번호 4개와 엔터(5키) 재입력 → \(2+5=7\) 키  
   - **기대 키 수:**  
     \[
     0.09 \times 2 + 0.91 \times 7 = 0.18 + 6.37 = 6.55
     \]

2. **백스페이스 사용하기:**  
   - **백스페이스 1번 (\(K=1\)):**
     - 남겨지는 문자는 \(A-K = 3-1 = 2\)개  
     - 이때 남은 두 문자(1번째와 2번째)가 모두 맞을 확률은 \(1 \times 0.9 = 0.9\)
     - **정상인 경우:**  
       비용 = 1(백스페이스) + 입력해야 하는 문자 수:  
       재입력한 1글자(백스페이스한 문자)와 남은 \(B - (A-K)=4 - 2 = 2\)글자, 그리고 엔터  
       → \(1 + (1+2) + 1 = 1+3+1=5\) 키  
       (※ 문제 설명의 예제에서는 6키로 계산했으나 여기서 재계산하면:  
       백스페이스 1번 → 비용 = 백스페이스 1 + (4 - (3-1) + 1) = 1 + (4-2+1)=1+3=4.  
       다만, 위 문제 설명 예제에서는 6키로 되어 있으므로 다시 확인해 보겠습니다.)
       
       **정확한 계산:**  
       백스페이스 \(K\)번을 할 경우, 남은 확신하는 문자는 \(A-K\)개이므로  
       추가로 입력할 키 = \(K\) (백스페이스) + \([B - (A-K)]\) (재입력해야 할 문자들) + 1 (엔터)  
       여기서 \(K=1\)이면,  
       추가 키 = \(1 + [4 - (3-1)] + 1 = 1 + [4-2] + 1 = 1 + 2 + 1 = 4\) 키  
       - **오타가 있을 경우:**  
         위 4키에 더해 전체 비밀번호 재입력 \(B+1=5\) 키  
         → \(4 + 5 = 9\) 키  
       - **기대 키 수:**  
         \[
         0.9 \times 4 + 0.1 \times 9 = 3.6 + 0.9 = 4.5
         \]
     
   - **백스페이스 2번 (\(K=2\)):**
     - 남겨지는 문자는 \(3-2=1\)개 → 첫 문자는 1 (확실히 맞음)
     - 추가 키 = \(2\) (백스페이스) + \([4 - (3-2)] + 1 = 2 + [4 - 1] + 1 = 2+3+1 = 6\) 키  
     - 오타 발생 확률 0 → 기대 키 수 = 6
     
   - **백스페이스 3번 (\(K=3\)):**
     - 남겨지는 문자는 0개  
     - 추가 키 = \(3\) (백스페이스) + \([4 - 0] + 1 = 3+4+1=8\) 키  
     - 기대 키 수 = 8

3. **바로 포기하기 (Give Up):**
   - 비용 = 엔터 1 + 전체 비밀번호 4개와 엔터 1 → \(1 + 5 = 6\) 키

#### **최적 선택**
- 계속 입력: 6.55 키  
- 백스페이스 1번: **4.5 키**  
- 백스페이스 2번: 6 키  
- 백스페이스 3번: 8 키  
- 포기하기: 6 키

따라서 **최적 전략은 백스페이스 1번**이며, 기대 추가 키 수는 **4.500000**회.

### 💡 답변 (Assistant)
다음은 위 문제를 파이썬으로 구현한 코드입니다.

```python
def solve():
    import sys
    input_data = sys.stdin.read().strip().split()
    if not input_data:
        return
    t = int(input_data[0])
    index = 1
    results = []
    for case in range(1, t + 1):
        # A: 이미 입력한 문자 수, B: 전체 문자 수
        A = int(input_data[index])
        B = int(input_data[index + 1])
        index += 2

        # 입력된 각 문자가 올바를 확률
        probs = list(map(float, input_data[index:index + A]))
        index += A

        # 누적 확률: p[i]는 처음 i개의 문자가 모두 올바를 확률 (p[0] = 1)
        p = [1.0]
        for i in range(A):
            p.append(p[-1] * probs[i])
        
        # 최적의 전략에 대한 최소 기대 키 입력수 계산
        best = float('inf')
        
        # 1) 백스페이스 k번 (k = 0이면 "계속 입력하기"와 동일)
        for k in range(0, A + 1):
            # 남은 문자를 입력하는 횟수: (B - (A - k))개
            # k번 백스페이스, 남은 문자 입력, 엔터 1회 => 기본 비용: k + (B - (A - k) + 1)
            # 만약 (A - k)개의 문자가 올바르지 않으면 (B+1) 추가 비용(전체 재입력 및 엔터)
            strokes = k + (B - (A - k) + 1) + (1 - p[A - k]) * (B + 1)
            if strokes < best:
                best = strokes
        
        # 2) 포기하고 처음부터 다시 입력
        give_up = 1 + B + 1  # 현재 시도: 엔터 1회, 그 후 B글자 입력 + 엔터 1회
        best = min(best, give_up)
        
        results.append(f"Case #{case}: {best:.6f}")
    
    sys.stdout.write("\n".join(results))


if __name__ == '__main__':
    solve()
```

### 코드 설명

1. **입력 처리:**
   - 전체 입력을 한 번에 읽어 `input_data` 리스트에 저장합니다.
   - 첫 번째 값은 테스트 케이스의 수 \( T \)입니다.

2. **누적 확률 계산:**
   - `p[0]`를 1.0으로 시작하고, 입력된 확률을 차례대로 곱하여 `p[i]`에는 처음 \( i \)개의 문자가 올바를 확률을 저장합니다.

3. **각 전략에 따른 기대 키 입력수 계산:**
   - **백스페이스 \( k \)번:**  
     - 기본 비용: \( k \) (백스페이스 키) + \( [B - (A - k) + 1] \) (남은 문자 입력과 엔터키)  
     - 만약 남은 \( A - k \)개 문자 중 하나라도 틀렸다면 \( (B+1) \) 키를 추가로 입력해야 하므로, 해당 확률에 따라 추가 비용을 계산합니다.
   - **포기하고 처음부터:**  
     - \( 1 \) (현재 시도에서 엔터) + \( B + 1 \) (전체 비밀번호 입력과 엔터)를 비용으로 계산합니다.

4. **최적의 전략 선택:**
   - 위의 모든 경우 중 최소의 기대 키 입력수를 선택하여 결과에 저장하고, 최종적으로 출력합니다.

### ❓ 질문 (User)
1) 백스페이스 k번에서 strokes 계산하는거에 대해서 자세하게 설명해줘
위의 식을 보기에는 strokes = k + p * (B - (A - k) + 1) + (1 - p) * (B + 1) 이어야 할 거 같은데 왜 그렇게 되는지 이해가 잘 안돼.

### 💡 답변 (Assistant)
백스페이스 \( k \)번을 선택했을 때, 우리가 치러야 하는 키 입력 횟수(“strokes”)는 두 가지 상황을 모두 고려한 **기대값**입니다.

여기서 상황은 다음과 같습니다:

1. **남은 \( A - k \)개의 문자 모두 올바르게 입력된 경우**  
2. **남은 \( A - k \)개 중 적어도 한 글자라도 틀린 경우**

이제 각각의 경우를 살펴봅시다.

---

### 1. **공통으로 발생하는 “기본 비용”**

백스페이스 \( k \)번을 누르면, 그 비용 \( k \)는 **무조건** 발생합니다.

그 다음에는, 지워진 문자들을 다시 입력하고, 남은 \( B - (A - k) \)글자와 엔터키(1회)를 입력해야 합니다.  
즉, 이 비용도 조건과 상관없이 항상 발생합니다.

따라서 **기본 비용**은  
\[
\text{기본 비용} = k + \bigl(B - (A - k) + 1\bigr)
\]
여기서  
- \( k \)는 백스페이스 횟수  
- \( B - (A - k) \)는 다시 입력해야 할 문자 수  
- \( +1 \)은 엔터키 입력

---

### 2. **조건부 추가 비용: 재입력 비용**

만약 남은 \( A - k \)개의 문자 중 하나라도 틀렸다면, 전체 시도가 실패합니다. 이 경우 **추가 비용**으로 비밀번호 전체를 다시 입력해야 합니다.  
비밀번호 전체를 다시 입력하는 비용은 \( B \)개의 문자 입력 + 엔터키 1회, 즉  
\[
B + 1
\]
입니다.

남은 \( A - k \)개 문자가 모두 맞을 확률을 \( P = p[ A-k ] \)라고 합시다. 그러면 오타가 있을 확률은 \( 1 - P \)입니다.

따라서 **조건부 추가 비용**은  
\[
(1 - P) \times (B + 1)
\]

---

### 3. **최종 기대 비용(키 입력 횟수)**

두 가지 비용을 합하면 최종 기대값은  
\[
\text{strokes} = \underbrace{k + \bigl(B - (A - k) + 1\bigr)}_{\text{기본 비용}} + \underbrace{(1 - P) \times (B + 1)}_{\text{오타 시 추가 비용}}
\]
가 됩니다.

---

### 왜 \( p \)를 기본 비용에 곱하지 않을까요?

기본 비용 \( k + (B - (A - k) + 1) \)은 **오류가 있든 없든 항상 치러야 하는 비용**입니다.  
즉, 백스페이스를 누르고 나서 입력하는 키와 엔터키는 **조건에 상관없이 반드시** 입력합니다.

반면, 추가 비용 \( (B+1) \)은 **오류가 발생한 경우에만** 발생하므로, 그 부분에만 오타가 날 확률 \( (1-P) \)를 곱해줍니다.

만약 기본 비용에 \( p \)를 곱하게 되면, "오타가 없을 때만 비용을 지불한다"는 의미가 되어버리는데, 이는 사실과 다릅니다.  
기본 비용은 항상 지불하는 비용이고, 오타가 발생했을 때만 추가 비용을 지불합니다.

---

### 예시로 다시 확인해봅시다.

예를 들어,  
- \( A = 5 \), \( B = 10 \),  
- 백스페이스 \( k = 2 \)번 선택하면, 남은 문자는 \( A - k = 3 \)개이고,
- \( P \) (남은 3개 모두 맞을 확률)이 \( 0.8 \)라고 가정해봅니다.

**기본 비용:**  
\[
2 \ (\text{백스페이스}) + \bigl(10 - (5-2) + 1\bigr) = 2 + (10 - 3 + 1) = 2 + 8 = 10
\]

**오타가 있을 경우 추가 비용:**  
\[
(1 - 0.8) \times (10+1) = 0.2 \times 11 = 2.2
\]

**최종 기대 비용:**  
\[
10 + 2.2 = 12.2
\]

즉, **12.2** 키를 입력하는 것이 기대되는 비용입니다.

---

이와 같이,  
- 기본 비용은 **무조건** 발생하는 비용이므로 그대로 더하고,  
- 오타 발생 시에만 추가 비용 \( (B+1) \)를 오타 확률 \( (1-P) \)에 따라 더해주기 때문에  
\[
\text{strokes} = k + \bigl(B - (A - k) + 1\bigr) + (1 - P) \times (B+1)
\]
라는 식이 성립합니다.

점화식 대로 하면 p(B - A + k + 1) + (1-p)(B-A+k+1+B+1) 이니까 (B-A+k+1)은 공통 부분이니 
정리하면 B-A+k+1 + (1-p)(B+1) 이 되는거지?

### 💡 답변 (Assistant)
네, 맞습니다.  
  
자세히 설명하면, 백스페이스 \(k\)번을 선택했을 때 두 가지 경우가 있습니다.  
  
1. **오류 없이 모두 맞은 경우**:  
   - **백스페이스:** \(k\)번  
   - **남은 문자 입력:** \(B - (A - k)\)개  
   - **엔터:** 1회  
   - 따라서 이 경우 총 비용은  
     \[
     k + \bigl(B - (A - k)\bigr) + 1 = k + (B - A + k) + 1 = B - A + 2k + 1
     \]
     입니다.
  
2. **오타가 있어서 전체를 다시 입력해야 하는 경우**:  
   - 위에서 계산한 비용에 추가로 전체 비밀번호 재입력 비용 \(B + 1\)이 더해집니다.  
   - 따라서 이 경우 총 비용은  
     \[
     B - A + 2k + 1 + B + 1 = B - A + 2k + 1 + B + 1
     \]
     입니다.
  
이제, \(p\)를 남은 \(A-k\)개의 문자가 모두 올바를 확률이라고 하면,  
전체 기대 비용은  
\[
p\bigl(B - A + 2k + 1\bigr) + (1-p)\bigl(B - A + 2k + 1 + B + 1\bigr)
\]
로 쓸 수 있습니다.

여기서 \(B - A + 2k + 1\)은 양쪽에 공통으로 들어 있으므로, 이를 묶으면  
\[
\bigl(B - A + 2k + 1\bigr) + (1-p)(B + 1)
\]
가 됩니다.

다만, 질문에서 제시한 식  
\[
p(B - A + k + 1) + (1-p)(B - A + k + 1 + B + 1)
\]
는 이미 \(k\)번의 백스페이스 비용을 포함한 **공통 부분**을 \(B - A + k + 1\)로 정의한 경우에 해당합니다.  
  
즉, 만약 백스페이스 키 \(k\)번을 누르는 비용과 재입력 비용을 합쳐서  
\[
\text{공통 비용} = B - A + k + 1
\]
라고 정의했다면,  
- 오류 없이 맞았을 때의 비용은 \(\text{공통 비용}\)  
- 오타가 있었을 때는 \(\text{공통 비용} + (B+1)\)  
  
이고, 이 경우 기대 비용은  
\[
p\cdot (\text{공통 비용}) + (1-p)\cdot (\text{공통 비용} + (B+1)) = \text{공통 비용} + (1-p)(B+1)
\]
가 되어, 말씀하신 식과 일치합니다.
  
**요약하면:**  
- 만약 공통 비용을 \(B-A+k+1\)로 두고 계산한다면,  
  \[
  p(B-A+k+1) + (1-p)(B-A+k+1+B+1) = B-A+k+1 + (1-p)(B+1)
  \]
로 정리되는 것이 맞습니다.
  
- 단, 앞서 설명한 바와 같이, 백스페이스 \(k\)번의 비용을 별도로 포함하면 실제로는 \(B-A+2k+1 + (1-p)(B+1)\)가 되는데, 이는 **공통 비용**을 어떻게 정의하느냐에 따라 달라지는 문제입니다.

따라서, 질문하신 방식대로 공통 비용을 \(B-A+k+1\)로 정의한 경우라면 정리한 식이 맞습니다.
