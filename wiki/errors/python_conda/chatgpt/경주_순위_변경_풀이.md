# 경주 순위 변경 풀이

> **카테고리**: `Errors - Python & Conda`

## 💬 대화 내용 및 Q&A

### ❓ 질문 (User)
문제 설명
얀에서는 매년 달리기 경주가 열립니다. 해설진들은 선수들이 자기 바로 앞의 선수를 추월할 때 추월한 선수의 이름을 부릅니다. 예를 들어 1등부터 3등까지 "mumu", "soe", "poe" 선수들이 순서대로 달리고 있을 때, 해설진이 "soe"선수를 불렀다면 2등인 "soe" 선수가 1등인 "mumu" 선수를 추월했다는 것입니다. 즉 "soe" 선수가 1등, "mumu" 선수가 2등으로 바뀝니다.

선수들의 이름이 1등부터 현재 등수 순서대로 담긴 문자열 배열 players와 해설진이 부른 이름을 담은 문자열 배열 callings가 매개변수로 주어질 때, 경주가 끝났을 때 선수들의 이름을 1등부터 등수 순서대로 배열에 담아 return 하는 solution 함수를 완성해주세요.

제한사항
5 ≤ players의 길이 ≤ 50,000
players[i]는 i번째 선수의 이름을 의미합니다.
players의 원소들은 알파벳 소문자로만 이루어져 있습니다.
players에는 중복된 값이 들어가 있지 않습니다.
3 ≤ players[i]의 길이 ≤ 10
2 ≤ callings의 길이 ≤ 1,000,000
callings는 players의 원소들로만 이루어져 있습니다.
경주 진행중 1등인 선수의 이름은 불리지 않습니다.
입출력 예
players	callings	result
["mumu", "soe", "poe", "kai", "mine"]	["kai", "kai", "mine", "mine"]	["mumu", "kai", "mine", "soe", "poe"] 
파이썬 코드로 풀이해줘

### 💡 답변 (Assistant)
문제를 효율적으로 해결하려면, 선수들의 순위를 빠르게 업데이트할 수 있는 자료 구조를 사용하는 것이 중요합니다. 아래는 문제를 해결하기 위한 Python 코드입니다. `players`와 `callings`를 입력받아 최종 결과를 반환하는 `solution` 함수입니다.

### 코드

```python
def solution(players, callings):
    # 선수 이름을 키로, 순위를 값으로 저장하는 딕셔너리 생성
    rank = {player: i for i, player in enumerate(players)}

    # 호출을 처리하며 순위 변경
    for call in callings:
        # 호출된 선수의 현재 순위
        current_rank = rank[call]
        
        # 앞선 선수와 자리를 바꿈
        if current_rank > 0:  # 호출된 선수가 1등이 아닌 경우에만
            # 앞선 선수의 이름
            prev_player = players[current_rank - 1]
            
            # 순위 정보 업데이트
            rank[call] -= 1
            rank[prev_player] += 1
            
            # players 배열에서 두 선수의 위치를 교환
            players[current_rank - 1], players[current_rank] = call, prev_player

    return players
```

### 코드 설명
1. **`rank` 딕셔너리 생성**:  
   선수의 이름과 현재 순위를 매핑하는 딕셔너리를 만들어 호출된 선수의 현재 순위를 O(1) 시간에 조회합니다.
   
2. **호출 처리**:  
   `callings` 배열을 순회하며 호출된 선수와 그 바로 앞선 선수의 순위를 업데이트하고, `players` 배열에서도 두 선수의 위치를 교환합니다.

3. **효율성**:  
   - `rank` 딕셔너리를 이용해 순위를 O(1) 시간에 조회합니다.
   - 순위 변경은 리스트와 딕셔너리 업데이트로 O(1) 시간에 처리됩니다.
   - 따라서 `callings`의 길이를 \(n\), `players`의 길이를 \(m\)라고 할 때, 전체 시간 복잡도는 \(O(n)\)입니다.

### 입출력 예시

```python
# 테스트
players = ["mumu", "soe", "poe", "kai", "mine"]
callings = ["kai", "kai", "mine", "mine"]
result = solution(players, callings)
print(result)  # ["mumu", "kai", "mine", "soe", "poe"]
```

```
def solution(players, callings):
    ans = players[:]
    for call in callings :
        player1 = ans.index(call)       # call 된 선수
        player2 = ans.index(call) - 1   # call 된 선수에 추월당한 선수

        player1 -= 1                    # 추월
        player2 += 1                    # 추월 당함

        ans[player1] = call             # 추월한 선수 위치 
        ans[player2] = players[player1] # 추월 당한 선수 위치
        players = ans[:]                # 현재 위치 저장

    return ans
```

### 주어진 코드의 문제점과 비효율성
1. **비효율적인 순위 조회**:
   - `ans.index(call)`로 호출된 선수의 인덱스를 찾는 과정이 매번 O(m) 시간복잡도를 가집니다. (m은 `players` 배열의 길이)
   - `callings`의 길이를 \(n\)이라고 할 때, 전체 시간복잡도는 \(O(n \cdot m)\)이 됩니다. 이는 \(m\)이 크고 \(n\)이 길 경우 성능 저하를 초래합니다.

2. **중복된 리스트 복사**:
   - `players = ans[:]`로 매번 리스트를 복사합니다. 이는 불필요한 연산으로, 코드의 효율성을 낮춥니다.

3. **순위 업데이트의 논리적 오류**:
   - `player1 -= 1`과 `player2 += 1`은 변수를 업데이트하지만, 실제로 `ans[player1]`과 `ans[player2]`를 수정하는 방식이 잘못되었습니다.
   - `players[player1]`을 사용하여 값을 변경하려 하지만, `player1`과 `player2`는 이미 변형된 상태이므로 올바르지 않은 값이 참조될 가능성이 있습니다.

---

### 개선한 코드의 장점
1. **딕셔너리를 이용한 O(1) 조회**:
   - `rank` 딕셔너리를 사용하여 호출된 선수의 현재 순위를 즉시 조회합니다.
   - 호출된 선수가 추월할 때, 딕셔너리와 리스트를 동기화하여 O(1) 시간에 위치를 업데이트합니다.

2. **불필요한 리스트 복사 제거**:
   - 리스트를 매번 복사하지 않고 `players`와 `rank`를 동기화하며 처리합니다.

3. **명확한 순위 변경 로직**:
   - `rank`와 `players`를 함께 업데이트하면서, 순위 변경을 명확하고 간결하게 처리합니다.
   - 호출된 선수와 추월당한 선수를 직접 교환하여, 데이터 무결성을 유지합니다.

---

### 시간복잡도 비교
- **주어진 코드**:  
  \(O(n \cdot m)\) — `callings`의 길이 \(n\)과 `players`의 길이 \(m\)의 곱에 비례하여 실행 시간 증가.
- **개선한 코드**:  
  \(O(n)\) — 딕셔너리와 리스트를 이용해 각 호출을 상수 시간에 처리.
