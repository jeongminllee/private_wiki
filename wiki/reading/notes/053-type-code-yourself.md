# 한눈에 보기

글은 코드를 손으로 입력하는 행위 자체보다, 예제를 보지 않고 기억과 이해를 바탕으로 다시 만드는 `freecoding`을 강조한다. 복사한 코드는 실행될 수 있지만 어떤 이름, 타입, 제약이 필요한지 스스로 복원하지 못하면 실제 이해는 약할 수 있다.

# 왜 도움이 되는가

문법, 타입과 정확한 API 이름은 저수준 잡음만은 아니다. 프로그램의 제약을 압축해 표현하는 수단이기 때문에 직접 써 보면 자신이 모르는 경계가 빨리 드러난다. 타입과 스키마 이해가 약한 상태에서 AI 결과만 이어 붙이면 `any` 캐스팅, 중복 모델, 예외 처리 누락을 리뷰하기 어려워진다.

읽거나 생성된 코드를 닫고 핵심 함수를 다시 구현한 뒤 원본과 비교하면 수동적인 인식과 능동적인 회상을 구분할 수 있다. 실패한 부분은 다음 학습 범위를 알려준다.

# AI와 함께 쓰는 방법

- 새 언어와 핵심 도메인 로직은 짧은 구간을 직접 재구성한다.
- AI가 만든 코드 중 중요한 알고리즘이나 권한 경계는 설명하고 다시 쓸 수 있는지 확인한다.
- boilerplate는 생성하되, 생성된 타입과 실패 조건을 사람이 검토한다.
- 복습에서는 완성 코드를 베끼기보다 테스트만 보고 구현해 본다.

# 주의할 점

모든 코드를 손으로 타이핑하는 것이 생산성이나 실력을 자동으로 높이지는 않는다. 반복적인 설정과 기계적 변환까지 수동으로 할 이유는 적다. 목표는 타자량이 아니라 회상, 예측, 오류 교정이 포함된 연습이다.
