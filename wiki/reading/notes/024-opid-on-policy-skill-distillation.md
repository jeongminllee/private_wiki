# 한 줄 요약

OPID는 에이전트가 방금 수행한 on-policy 궤적에서 재사용 가능한 스킬을 추출하고, 그 스킬을 보았을 때 기존 정책이 각 토큰의 확률을 얼마나 바꾸는지를 추가 학습 신호로 사용한다.

# 문제

에이전트 강화학습은 보통 에피소드 끝의 성공·실패 보상에 의존한다. 이 결과 보상은 어떤 중간 판단이 좋았는지 알려주지 않아 신호가 희소하고, 긴 도구 사용 과정에서 학습 효율이 떨어진다. 별도 교사 모델로 고품질 추론을 만들 수 있지만 비용과 정책 불일치 문제가 생긴다.

# 방법

OPID는 완료된 현재 정책의 궤적을 다시 읽어 두 수준의 스킬을 만든다.

- 에피소드 수준 스킬은 전체 워크플로, 성공 패턴, 피해야 할 실패를 요약한다.
- 단계 수준 스킬은 결과에 큰 영향을 준 결정 시점에서 필요한 국소 판단을 추출한다.
- critical-first routing은 중요한 시점에는 단계 스킬을, 나머지에는 에피소드 스킬을 선택한다.
- 선택한 스킬을 대화 이력에 넣고 **같은 기존 정책**이 이미 샘플링한 응답을 다시 채점한다.
- 원래 문맥과 스킬 문맥 사이의 토큰별 로그확률 차이를 self-distillation advantage로 만들고, 기존 outcome advantage와 결합한다.

즉 외부 정답을 새로 생성하는 대신, 정책이 자기 궤적에서 정리한 지식이 기존 행동의 확률 분포를 어떻게 교정하는지 이용한다.

# 결과와 의미

논문은 ALFWorld, WebShop, 검색 기반 질의응답 환경에서 성능, 표본 효율, 강건성이 대체로 개선됐다고 보고한다. 중요한 아이디어는 스킬을 단순 프롬프트 메모로 남기는 데 그치지 않고, 토큰 수준 학습 신호로 변환했다는 점이다. 결과 보상과 과정 지식을 연결하는 한 방식으로 볼 수 있다.

# 활용 아이디어

도구 사용 에이전트의 실패 로그에서 `전체 전략`과 `결정 지점의 규칙`을 따로 추출하고, 새 실행에서 어떤 규칙이 실제 선택을 바꾸는지 평가할 수 있다. 학습까지 하지 않더라도 스킬 저장소를 만들 때 전역 플레이북과 국소 복구 규칙을 분리하는 설계에 참고할 만하다.

# 주의할 점

추출된 스킬 자체가 LLM의 해석이므로 잘못된 인과관계를 담을 수 있다. 성공한 궤적의 우연한 행동을 규칙으로 굳힐 위험도 있다. 벤치마크와 시뮬레이터에서의 개선이 실제 브라우저·업무 환경으로 그대로 이전되는지는 별도 검증이 필요하다.
