# 한눈에 보기

온톨로지를 절대적으로 참인 지식의 목록이 아니라 특정 목적의 지식 공유를 위해 사람이 설계한 명시적 개념 체계로 본다. 1995년 Gruber의 설계 원칙에서 시작해 현대적인 URI, 명명, 버전 관리, 문서화와 유지보수 실무로 확장한다.

# 핵심 내용

- 좋은 온톨로지는 의미가 명확하고 내부적으로 일관되며, 기존 정의를 깨지 않고 확장할 수 있어야 한다.
- 특정 구현 언어나 저장 형식에 과도하게 종속되는 표현 편향을 줄이고, 꼭 필요한 주장만 정의해 사용자의 해석 범위를 불필요하게 제한하지 않는다.
- 안정적인 URI를 식별자로 사용하면 화면의 라벨이나 언어가 바뀌어도 개념의 정체성을 유지할 수 있다.
- 클래스, 객체 속성, 데이터 속성, 개체의 명명 규칙을 일관되게 유지하고 사람이 읽을 라벨과 정의를 함께 제공한다.
- 시맨틱 버전, 변경 이력, 시각화와 문서를 두고 지속적으로 품질을 검사해야 재사용할 수 있다.

# 왜 읽을 만한가

지식 그래프를 만들 때 도구 선택보다 개념 경계와 재사용 조건을 먼저 생각하게 한다. LLM과 RAG가 있어도 잘못 설계된 온톨로지 위에서는 일관된 추론을 기대하기 어렵다는 점이 중요하다.

# 적용 아이디어

- wiki 태그와 문서 유형의 의미를 짧은 정의와 예시로 고정한다.
- 파일명이나 표시 제목이 바뀌어도 유지되는 식별 전략을 검토한다.
- 새 개념을 추가할 때 기존 개념과의 중복, 모순, 확장 가능성을 체크한다.

# 주의할 점

자동 생성 자막에는 전문 용어 오인식이 있다. 원칙명과 세부 정의를 인용할 때는 영상이 소개한 원 논문과 온톨로지 개발 방법론을 다시 확인해야 한다.
