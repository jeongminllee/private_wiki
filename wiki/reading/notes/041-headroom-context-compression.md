# 한눈에 보기

Headroom은 코딩 에이전트가 도구 출력, 로그, 파일, RAG 결과를 컨텍스트에 그대로 쌓아 토큰을 낭비하는 문제를 줄이는 오픈 소스 도구다. 단순히 앞뒤를 잘라내기보다 자료의 종류를 판별해 의미 있는 부분을 남기고, 압축 전에 보관한 원문을 필요할 때 다시 조회할 수 있게 한다.

# 동작 방식

- JSON, 로그, 코드, 검색 결과처럼 입력 형식에 맞는 압축 전략을 고른다.
- 라이브러리, OpenAI 호환 프록시, MCP 서버 형태로 기존 에이전트에 연결할 수 있다.
- 원문을 로컬 저장소에 남기고 압축 결과에 참조 정보를 넣어 손실된 세부 내용을 다시 가져오게 한다.
- 프로젝트는 JSON에서 60~95%, 코딩 에이전트에서 15~20%의 토큰 절감을 주장한다. 이는 워크로드와 설정에 따라 달라지는 프로젝트 측 수치다.

# 적용 판단

긴 테스트 로그, 대형 JSON 응답, 반복되는 도구 출력 때문에 모델의 실제 작업 공간이 줄어드는 에이전트에 적합하다. 공유 메모리를 쓰는 다중 에이전트에서도 원문과 압축 표현을 분리하는 계층으로 검토할 수 있다. 반대로 짧은 작업이나 모델의 기본 compaction만으로 충분한 흐름에서는 운영 요소와 지연만 늘 수 있다.

도입 실험에서는 같은 작업 세트로 성공률, 입력 토큰, 지연 시간, 원문 재조회 횟수를 함께 비교해야 한다. 토큰 감소만 보고 선택하면 오류 메시지의 한 줄이나 코드의 경계 조건처럼 결과를 좌우하는 정보가 사라질 수 있다.

# 주의할 점

압축은 본질적으로 정보 손실 가능성이 있다. 원문 복구가 실제로 동작하는지, 비밀 값이 로컬 저장소나 프록시 로그에 남지 않는지, 프록시 인증과 보존 기간이 적절한지 확인해야 한다. 설치 스크립트와 네트워크 경로도 운영 환경에 넣기 전에 검토한다.
