# 한눈에 보기

이 글은 개인정보보호위원회의 자료를 바탕으로 생성형 AI 서비스 이용자가 확인할 사항을 실무 언어로 정리한다. 핵심은 “학습 사용 끄기” 하나로 안전이 보장되는 것이 아니라, **입력 데이터의 민감도, 서비스 계약 형태, 기록 보존, 외부 연동, 권한, 삭제 절차**를 함께 봐야 한다는 것이다.

# 개인 사용 점검표

- 입력 내용이 모델 개선이나 학습에 쓰이는지, 대화 기록을 끌 수 있는지, 임시 대화가 어떤 방식으로 보존되는지 확인한다.
- 외부 앱, 플러그인, 커넥터를 연결했다면 어떤 데이터에 접근하고 제3자에게 무엇을 전달하는지 살핀다.
- 해외 이전, 보존 기간, 계정 삭제와 대화 삭제의 차이를 서비스의 최신 개인정보 처리방침에서 확인한다.
- 학습 사용을 껐더라도 보안 점검이나 남용 방지를 위한 제한적 보존이 있을 수 있다. 따라서 민감 정보를 넣어도 된다는 뜻으로 해석하면 안 된다.
- 비밀번호, API 키, 인증 토큰, 주민등록번호, 계좌·카드 정보, 의료·상담 기록, 고객·직원 명단, 비공개 계약 및 소스 코드는 입력하지 않는 것이 기본이다.

# 조직과 데이터베이스 활용

조직 데이터에 AI를 연결할 때는 무료냐 유료냐보다 **개인용 소비자 서비스인지, 기업용 계약 또는 API 환경인지**가 더 중요하다. 먼저 데이터 목록을 만들고 민감도를 분류한 뒤, 이용 목적과 적법 근거를 확인해야 한다. 이후 최소 권한, 테스트 데이터 분리, 입출력 로그, 보존·삭제 기간, 사고 대응 책임자를 정한다.

데이터는 필요한 필드만 선택하고 가능한 경우 가명·익명 처리한다. RAG나 DB 조회를 붙일 때도 모델이 데이터베이스 전체를 볼 수 있게 하지 말고, 사용자 권한과 문서 권한이 검색 단계부터 이어지게 해야 한다. 결과에 개인정보가 재노출되는지도 별도 테스트한다.

# 이 wiki에 적용하기

- 웹 원문을 가져올 때 계정 식별자, 추적 파라미터, 개인 메모가 공개 문서에 남지 않는지 검사한다.
- `raw/`에는 원본을 보존하되 공개 전 민감 정보 검사를 수행한다.
- 외부 AI로 자료를 보낼 때 개인 문서와 회사 내부 자료를 분리한다.
- 커넥터가 필요한 작업은 최소 범위로 연결하고, 작업 종료 뒤 불필요한 권한을 정리한다.

# 주의할 점

이 노트는 법률 자문이 아니다. 서비스 정책과 국내 지침은 바뀔 수 있으므로 실제 개인정보 처리 업무에서는 최신 서비스 약관과 개인정보보호위원회 원문을 다시 확인해야 한다. 저장된 글은 이용자 관점의 2026년 가이드를 주로 다루지만, AI를 직접 개발하거나 운영하는 조직은 개발·활용 생애주기 지침도 함께 봐야 한다.
