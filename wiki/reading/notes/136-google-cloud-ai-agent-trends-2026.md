# 다섯 흐름

1. 직원은 구체적 절차보다 목표를 주고 agent의 결과를 감독하는 방식으로 이동한다.
2. 여러 agent가 end-to-end workflow를 나눠 수행하는 “digital assembly line”이 늘어난다.
3. 기업 data로 grounding한 concierge형 고객 경험이 단순 chatbot을 대체한다.
4. 보안 agent가 alert 분류를 넘어 조사와 대응을 보조하며 인간 분석가는 고위험 결정을 맡는다.
5. 기술 도입보다 위임, 검증, data policy와 비판적 판단을 가르치는 upskilling이 병목이 된다.

# 기술적 기반

A2A는 서로 다른 agent의 협업을, MCP는 model과 data·tool의 연결을 표준화하려는 흐름으로 제시된다. 표준 연결이 생겨도 identity, per-tool authorization, data lineage, prompt injection 방어와 action rollback은 자동 해결되지 않는다.

# 조직에 적용할 질문

- 처음부터 모든 workflow를 바꾸지 말고 측정 가능한 한 과정을 선택했는가?
- agent가 할 수 있는 action과 사람이 승인할 action을 구분했는가?
- 시간 절감뿐 아니라 오류, 고객 영향과 review cost를 함께 측정하는가?
- 실패 시 책임자, audit log와 복구 절차가 있는가?

# 비판적으로 볼 점

Google Cloud가 자사 ecosystem의 수요를 전망하는 vendor report다. 도입률, ROI와 고객 사례 수치는 조사 표본·정의와 자사 제품 맥락을 확인해야 하며 2026년 전체 시장의 확정 사실로 볼 수 없다.
