# 문제

Coding agent가 답을 만드는 2~10분은 그냥 기다리기에는 길고 새 project에 몰입하기에는 짧다. 이때 즉흥적으로 다른 복잡한 일을 시작하면 원래 작업으로 돌아올 때 context switching 비용이 더 커진다.

# 대기 시간 메뉴

글은 시작과 중단이 쉽고 작은 흔적을 남기는 일을 미리 정해 두라고 제안한다.

- **생각·확장**: 현재 구조를 다섯 개 이하의 box로 그리거나 다음 prompt에 필요한 질문 세 개를 만든다.
- **수집·소통**: 나중에 볼 자료에 한 줄 이유와 tag를 붙이고 짧은 진행 상황을 정리한다.
- **보여 주기·번역**: 방금 만든 code나 결정의 의미를 다른 독자에게 설명할 짧은 기록으로 바꾼다.
- **회복**: 화면에서 눈을 떼고 움직이거나 호흡을 가다듬는다.

# 적용 원칙

대기 시간에 mini project를 만들지 않는다. Agent가 끝나면 즉시 닫을 수 있어야 하며, bookmark·질문·diagram처럼 다음 작업에 재사용되는 결과가 있으면 좋다. 생산성 항목과 회복 항목을 함께 두어 모든 빈 시간을 output으로 채우지 않는다.
