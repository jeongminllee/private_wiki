# 한눈에 보기

AI 네이티브 팀은 기존 개발자가 채팅 도구를 하나 더 쓰는 팀이 아니다. 이슈 작성, 계획, 구현, 리뷰, 테스트, 유지보수의 각 단계가 에이전트에게 명확한 맥락과 검증 수단을 제공하도록 바뀐 팀이다. 문서 작성, 테스트 초안, 의존성 갱신 같은 반복 작업은 더 많이 위임하되, 모호한 요구와 고위험 변경의 소유권은 엔지니어가 유지한다.

# 개발 흐름의 변화

- 이슈는 배경, 범위, 제약, 완료 조건을 포함해 에이전트가 실행 가능한 단위로 다듬는다.
- 계획 단계에서 영향 파일, 인터페이스, 마이그레이션과 검증 방법을 먼저 드러낸다.
- 구현은 작은 변경과 빠른 피드백 루프로 나누고 테스트·린트·실행 결과를 증거로 남긴다.
- 리뷰는 생성된 코드의 문체보다 동작, 보안 경계, 실패 시나리오와 운영 영향을 본다.
- 유지보수 작업은 자동화하기 쉽지만, 위험 수준에 따라 사람의 승인과 롤백 조건을 둔다.

# 팀이 먼저 준비할 것

에이전트가 성공하려면 저장소가 테스트 가능하고 명령이 재현 가능해야 한다. `AGENTS.md` 같은 저장소 지침, 좁은 작업 범위, 빠른 테스트, 관찰 가능한 실패, 최신 문서가 중요하다. “AI를 얼마나 많이 썼는가”보다 리드 타임, 재작업률, 결함, 리뷰 부담, 운영 사고 같은 결과를 측정해야 한다.

초기에는 위험이 낮고 완료 조건이 분명한 작업군을 선택한다. 성공 사례의 프롬프트만 복사하지 말고 필요한 저장소 맥락과 검증 장치를 표준화한다. 이후 독립 실행 범위를 넓히되 데이터 변경, 권한, 배포는 별도 정책으로 관리한다.

# 주의할 점

가이드는 OpenAI 제품을 전제로 한 공급자 자료다. “주 단위 작업이 일 단위가 된다”는 표현은 보편적인 보장이 아니다. 팀의 코드베이스, 테스트 성숙도와 업무 특성에 따라 효과가 달라지므로 소규모 비교 실험으로 확인해야 한다.
