# 성장 경로

글쓴이는 멋쟁이사자처럼에서 Django와 첫 hackathon을 경험하고, UMC에서 Spring Boot·JPA를 접했다. 이후 월간 사용자 약 8,000명의 국제 서비스를 운영했지만 학부생이 자유롭게 실험하기 어려운 mission-critical 환경과 팀 방향이 맞지 않아 나왔다.

2024년 하반기 카카오테크 부트캠프에서는 Java·POJO, Spring의 IoC·DI부터 JDBC·transaction, JPA, design pattern, MySQL replication, TDD와 infrastructure를 프로젝트에 연결했다. 팀은 98% test coverage와 45개가량의 기술 글을 남겼다.

# 글쓴이가 강조한 학습법

- 기술 이름보다 내부 동작과 “왜 필요한가”를 파고든다.
- 이론을 실제 project와 troubleshooting에 연결한다.
- 다른 사람이 읽을 기술 글을 써서 이해의 빈틈을 드러낸다.
- Coverage 숫자 자체보다 refactoring feedback loop로 test를 쓴다.
- 서비스 운영 여부를 취업의 필수 badge로 보지 않는다.

# LINE 채용 경험

신입이지만 경력 서버 개발 수시채용에 지원했다. Resume에는 읽는 사람이 자신을 빨리 이해하도록 글쓰기 강점을 활용했다. 기술 면접은 정형 암기보다 예상 밖의 장애 상황을 깊게 파고드는 방식이었고, JDBC transaction synchronization, Nginx graceful shutdown과 HTTP connection까지 low-level 설명을 연결했다. 마지막 면접은 culture fit 중심이었다.

# 읽을 때 주의할 점

이는 한 사람의 성공 회고이지 채용 공식은 아니다. “깊게 공부하면 대기업에 간다”, coverage 98%나 특정 bootcamp가 필수라는 인과로 일반화하면 안 된다. 재사용할 부분은 project마다 검증 가능한 산출물, 설명 가능한 technical depth와 독자를 고려한 기록을 남긴 과정이다.
