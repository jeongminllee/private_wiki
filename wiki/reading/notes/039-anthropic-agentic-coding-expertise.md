# 한 줄 요약

코딩 에이전트는 구현 능력의 진입 장벽을 낮추지만, 무엇을 만들어야 하고 무엇이 맞는지 판단하는 과제별 도메인 전문성의 가치는 계속 남는다는 관찰 연구다.

# 데이터와 방법

Anthropic은 2025년 10월부터 2026년 4월 사이 약 23만 5천 명의 사용자가 만든 약 40만 개의 대화형 Claude Code 세션을 프라이버시 보존 집계 방식으로 분석했다. CLI, Claude.ai, 데스크톱 앱의 대화형 사용을 포함하고, headless 실행과 제3자 IDE·SDK 사용은 제외했다.

분류기는 세션의 의사결정을 계획과 실행으로 나누고 사람과 Claude 중 누가 결정했는지 추정했다. 사용자의 전문성은 직업이나 일반 코딩 경력이 아니라 지시의 정확성, 검증 요청, 오류를 누가 교정하는지에 따라 과제별로 평가했다. 성공은 대화 내용의 판정과 테스트 통과, 커밋, 사용자 확인 같은 구체적 신호를 결합했다.

# 주요 발견

- 사람은 계획 결정의 약 70%를, Claude는 실행 결정의 약 80%를 맡는 경향이 있었다.
- 전문성이 높은 사용자의 한 프롬프트는 더 긴 에이전트 행동 연쇄를 촉발했다. 도메인 지식이 에이전트에게 더 많은 일을 정확히 위임하게 한 것으로 해석할 수 있다.
- 중급 이상 세션은 초보 세션보다 verified success와 부분 성공 비율이 높았고, 가장 큰 차이는 초보에서 중급으로 넘어갈 때 나타났다.
- 코드를 생성하는 과제에서는 여러 직업군이 소프트웨어 직군과 비슷한 성공률을 보였다. 코딩 직업 여부보다 해당 업무의 성공 조건을 아는지가 중요하다는 신호다.
- 관찰 기간 동안 디버깅 비중은 줄고 운영·배포, 분석, 비코드 문서 작성 같은 종단 작업이 늘었다.

# 실무적 의미

좋은 지시는 구현 방법을 세세히 대신 쓰는 것보다 목표, 제약, 경계 사례, 완료 증거를 제공한다. 도메인 전문가는 월말 정산 규칙, 환자 데이터의 금지 조건, 교육 평가 기준처럼 모델이 스스로 알기 어려운 성공 기준을 줄 수 있다. 에이전트의 결과도 “완료했습니다”라는 문장보다 테스트, 실행 화면, 산출물, 커밋으로 확인해야 한다.

# 한계

이는 무작위 대조 실험이 아니라 특정 제품 사용 로그의 관찰 연구다. 전문성, 직업, 성공, 과제 가치 모두 모델 기반 분류와 추정이 포함되며 실제 업무 성과를 직접 측정하지 않는다. 전문성이 성공을 만들었다고 인과적으로 단정할 수 없고, 제외된 자동화·IDE 사용에는 결과가 다를 수 있다.
