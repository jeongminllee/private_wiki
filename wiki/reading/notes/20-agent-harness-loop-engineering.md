# 한눈에 보기

좋은 LLM 하나가 곧 좋은 에이전트는 아니라는 점을 20분 안에 설명하는 영상이다. 하니스는 모델 주변의 프롬프트, 메모리, 검색, 도구와 가드레일을 묶고, 루프는 목표가 끝날 때까지 선택·실행·관찰을 반복하되 멈출 조건을 통제한다.

# 핵심 내용

- 시스템 프롬프트는 역할과 행동 경계를 정의하고, 메모리는 이전 대화와 실행 사건을 다음 판단에 제공한다.
- RAG는 모든 데이터를 넣는 대신 현재 질문과 관련된 정보를 검색해 컨텍스트를 구성한다.
- 도구 호출은 한 번으로 끝나지 않을 수 있어 계획, 호출, 결과 관찰, 재시도의 반복 구조가 필요하다.
- 종료 조건, 최대 반복, 시간·비용 한도와 실패 승격이 없으면 루프가 멈추지 않거나 잘못된 행동을 반복할 수 있다.
- tracing은 한 실행의 단계와 도구 결과를 남기고, evaluation은 결과와 과정을 판정한다. 이 피드백으로 프롬프트, 모델, 검색과 도구 설정을 개선한다.

# 왜 읽을 만한가

에이전트 개발을 프롬프트 작성이 아니라 제어 시스템과 운영 시스템의 문제로 보는 최소 개념 지도를 제공한다. 하니스, 루프, tracing, eval이 왜 한 묶음인지 빠르게 이해하기 좋다.

# 적용 아이디어

- 모든 에이전트 작업에 성공·실패·중단 조건과 예산을 명시한다.
- 한 실행을 입력, 모델 판단, 도구 인자, 도구 결과, 최종 응답 단위로 추적한다.
- 모델의 자기 평가와 별도로 테스트, 스키마 검사, 사람 승인 같은 외부 판정을 둔다.

# 주의할 점

입문 영상이라 각 구성 요소의 구현과 보안 위협은 깊게 다루지 않는다. 프레임워크를 고르기 전에 현재 작업에 실제로 필요한 상태, 도구, 루프와 평가 범위를 먼저 정해야 한다.
