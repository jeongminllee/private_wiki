# 한눈에 보기

이 주의 논문은 에이전트의 상태와 워크플로를 어디에 둘 것인지라는 설계 질문을 보여준다. Harness-1과 AdaCoM처럼 메모리·도구·제어를 모델 밖에서 관리하는 접근이 있는 반면, Latent Agents와 Subterranean 계열은 반복되는 워크플로를 모델 가중치나 잠재 표현에 내재화하려 한다. 이와 함께 attention 구조의 효율화와 공격·실패에 대한 복구 연구가 묶여 있다.

# 주요 흐름

## 외부 상태와 내부 정책

외부 하네스는 진행 상태, 파일, 도구 결과, 검증 기록을 명시적으로 보존해 관찰과 복구가 쉽다. 반대로 자주 쓰는 절차를 모델에 내재화하면 실행 시 프롬프트와 도구 호출을 줄일 수 있지만, 규칙을 수정하거나 실패 원인을 추적하기 어렵다. 실무적으로는 복구 가능한 장부와 권한 관리는 외부에 두고, 의미 판단과 패턴 인식은 모델에 맡기는 혼합 설계가 합리적이다.

## Attention 재설계

`SISA Forget Attention`은 모든 과거 토큰을 동일하게 유지하기보다 불필요한 정보를 잊는 메커니즘을 탐구한다. QKV projection 공유 연구는 attention의 표현력과 파라미터·메모리 비용 사이의 균형을 다시 본다. 긴 컨텍스트의 문제를 단순히 길이 확장으로만 풀지 않고 선택과 구조 변경으로 접근한다.

## 강건성, 안전, 복구

MOSS는 문제가 생긴 소스 코드를 실행 피드백과 함께 다시 쓰는 방향을 다룬다. `FuzzingBrain V2`는 생성 모델을 퍼징 입력 탐색에 활용하고, `AdvGame`은 비협조적 안전 게임을 통해 공격과 방어를 모델링한다. `Plan, Watch, Recover`는 계획을 세운 뒤 실행을 감시하고 이상이 생기면 복구하는 구조를 강조한다.

# 실무 적용

- 진행률, 출처, 권한, 실패 사유는 모델 기억이 아니라 파일이나 데이터베이스에 남긴다.
- 긴 작업은 계획자와 실행자만 두지 말고 감시·복구 경로를 별도 설계한다.
- 컨텍스트를 늘리기 전에 오래된 로그를 요약하고 현재 결정에 필요한 사실을 선택한다.
- 자동 코드 수정은 퍼징, 테스트, 정적 분석처럼 모델과 독립된 실패 탐지기를 붙인다.

# 주의할 점

모델에 워크플로를 내재화한 결과는 벤치마크에는 빠를 수 있지만 정책 변경과 감사가 어려워질 수 있다. 외부 하네스도 복잡성이 커지면 자체 버그와 지연이 생기므로 각 상태가 실제 복구나 검증에 쓰이는지 확인해야 한다.
