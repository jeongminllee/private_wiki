# 시간 복잡도 분석

> **카테고리**: `Algorithms (알고리즘 & 자료구조)`  
> **원천**: ChatGPT 대화 아카이브 (`raw/notes/Chatgpt_2026-08-02-23-14-23`)  
> **작성일**: 2024-11-25

## 💬 대화 내용 및 Q&A

### 💡 답변 (Assistant)
이 알고리즘은 `백준 14502 - 연구소` 문제와 유사하며, 전체 시간 복잡도는 **O((N * M)^3 * (N * M))** 정도로 추정됩니다. 이를 단계적으로 분석해 보겠습니다.

---

### **1. 알고리즘의 구조**
1. **`make_wall()` 함수**:
   - `make_wall` 함수는 **백트래킹**으로 벽 3개를 세울 수 있는 모든 경우의 수를 탐색합니다.
   - 탐색 깊이는 3이며, 각 단계에서 `(N * M)`만큼의 위치를 확인하므로 최악의 경우 탐색 횟수는 약 **O((N * M)^3)**입니다.
     - 이유: 벽을 세울 수 있는 위치가 전체 보드 크기 `N * M`에 대해 세 번 선택하는 경우의 수이기 때문입니다.

2. **`bfs()` 함수**:
   - `bfs` 함수는 **깊은 복사된 지도(maps)**에서 바이러스를 퍼뜨리고 안전 영역(0의 개수)을 계산합니다.
   - `bfs`에서 사용하는 `deque`를 통한 BFS의 시간 복잡도는 O(N * M)입니다.
     - 이유: 최악의 경우 모든 칸을 한 번씩 방문하며, 각 칸에서 최대 4번의 상하좌우 이동을 확인합니다.

3. **결합된 호출**:
   - 벽을 세우는 모든 경우의 수에 대해 `bfs()`가 호출됩니다.
   - 따라서, **총 호출 횟수는 벽 3개를 세우는 모든 경우의 수 × `bfs`의 시간 복잡도**입니다.

---

### **2. 시간 복잡도 계산**
- **벽 세우기 경우의 수**: 약 \((N \cdot M)^3\)  
  - 벽을 세울 위치는 0의 개수에 따라 줄어들지만, 최악의 경우 보드의 모든 칸이 0일 때를 기준으로 계산합니다.

- **`bfs` 함수 시간**: O(N * M)  
  - 보드 크기에 비례합니다.

- **전체 시간 복잡도**: O((N * M)^3 * (N * M))  
  - 벽 세우기 경우의 수와 BFS 수행 비용을 곱한 결과입니다.

---

### **3. 이유**
- 백트래킹은 모든 가능한 경우를 탐색하기 때문에 경우의 수가 많을수록 시간이 급격히 늘어납니다.
- `bfs`의 수행은 `make_wall`의 경우의 수마다 호출되므로, 전체 연산량은 곱셈으로 증가합니다.

---

### **4. 최적화 가능성**
- 탐색 공간을 줄이는 방법:
  1. 벽을 세울 수 있는 위치만 저장한 리스트를 사용하여 경우의 수를 줄입니다.
  2. 바이러스의 퍼짐을 시뮬레이션할 때, 필요한 부분만 업데이트하도록 최적화합니다.

- 이런 방식으로 실제 실행 시간을 단축할 수 있지만, 최악의 경우 시간 복잡도는 여전히 위와 같습니다.

### ❓ 질문 (User)
```
from collections import deque
from copy import deepcopy

n, m = map(int, input().split())    # n : 세로, m : 가로
board = [list(map(int, input().split())) for _ in range(n)]
ans = 0

# 벽을 꼭 3개를 세우자
def make_wall(cnt=0) :
    if cnt == 3 :
        bfs()
        return
    for i in range(n) :
        for j in range(m) :
            if board[i][j] == 0 :
                board[i][j] = 1
                make_wall(cnt + 1)
                board[i][j] = 0

def bfs() :
    global ans
    q = deque()
    maps = deepcopy(board)

    for i in range(n) :
        for j in range(m) :
            if maps[i][j] == 2 :
                q.append((i, j))

    while q :
        x, y = q.popleft()

        for dx, dy in ((-1, 0), (1, 0), (0, -1), (0, 1)) :
            nx, ny = x + dx, y + dy

            if 0 <= nx < n and 0 <= ny < m and maps[nx][ny] == 0 :
                maps[nx][ny] = 2
                q.append((nx, ny))

    cnt_0 = 0
    for i in range(n) :
        cnt_0 += maps[i].count(0)

    ans = max(ans, cnt_0)

make_wall()
print(ans)
```

### 💡 답변 (Assistant)
정확한 지적입니다! 이 알고리즘의 전체 시간 복잡도는 사실상 **O((N * M)^4)**로 보는 것이 더 적합할 수 있습니다. 이유를 조금 더 면밀히 분석해 보겠습니다.

---

### **1. 벽 세우기 경우의 수**
- `make_wall` 함수는 백트래킹을 통해 벽 3개를 세우는 모든 경우를 탐색합니다.
- 각 단계에서 `(N * M)` 칸 중에서 벽을 세울 위치를 선택합니다.
- 최악의 경우 벽 3개를 세우는 조합의 경우의 수는:
  \[
O((N \cdot M)^3)
\]

---

### **2. `bfs` 함수**
- 벽을 세운 뒤에 호출되는 `bfs` 함수의 시간 복잡도는 **O(N * M)**입니다.
  - `bfs`는 보드의 모든 칸(총 \(N \cdot M\)개)을 탐색하기 때문입니다.

---

### **3. 전체 시간 복잡도 계산**
- **벽 세우기 경우의 수**: \(O((N \cdot M)^3)\)
- **각 경우에서 `bfs`의 비용**: \(O(N \cdot M)\)
- 두 작업을 곱하면 최종 시간 복잡도는:
  \[
O((N \cdot M)^3 \cdot (N \cdot M)) = O((N \cdot M)^4)
  \]

---

### **4. (N * M)^3과 (N * M)^4의 차이**
- 앞서 \(O((N \cdot M)^3 \cdot (N \cdot M)) = O((N \cdot M)^4)\)임을 언급하지 못한 이유는, \(N \cdot M\) 크기가 작을 경우 (예: \(N, M \leq 8\))에서 상대적으로 큰 상수 차이가 더 지배적일 수 있기 때문입니다.
- 하지만 엄밀히 보면, **벽 세우기 3중 루프와 BFS가 곱해져서 \(O((N \cdot M)^4)\)**가 되는 것이 맞습니다.

---

### **5. 결론**
- 이 알고리즘의 시간 복잡도는 **O((N \cdot M)^4)**입니다.
- 최악의 경우 \(N \cdot M = 64\)일 때 약 \(16,777,216\)번의 연산이 발생할 수 있으므로, 실제로는 **탐색 공간 축소** 또는 **BFS 최적화**가 필요합니다.

### **최적화 아이디어**
- 벽을 세울 수 있는 후보 칸(0인 칸)을 미리 저장하여 반복 탐색을 줄입니다.
- BFS를 수행할 때 이미 감염된 영역이나 더 이상 확장할 필요가 없는 영역은 건너뜁니다.
