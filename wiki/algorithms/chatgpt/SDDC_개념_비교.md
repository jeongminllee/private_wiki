## 문제

**소프트웨어 정의 데이터센터(SDDC)** 에 대한 설명으로  
**가장 거리가 먼 것**은?

1. 입력 개입 없이 소프트웨어 조작만으로 제어한다.  
2. 컴퓨팅, 네트워킹, 스토리지 등을 모두 소프트웨어로 정의한다.  
3. 모든 하드웨어들이 가상화된다.  
4. 응용 프로그램이나 데이터를 자신의 컴퓨터에 설치할 필요없이 이용가능하다.

---

## 정답

👉 **4번**

---

## 1️⃣ 문제 해설 (출제 의도 & 풀이 전략)

이 문제의 핵심은 다음을 **구분**하는 것입니다.

* **SDDC (Software Defined Data Center)**
  * 데이터센터 **인프라 관점**
  * 자원 제어·관리의 **자동화/소프트웨어화**
* **클라우드 서비스(SaaS)**
  * 사용자 **이용 형태 관점**
  * 설치 없이 서비스 사용

👉 즉,  
**“데이터센터 내부 기술” vs “사용자 서비스 방식”**  
이 경계를 흐리는 보기가 오답입니다.

---

## 2️⃣ 정답인 이유 (4번)

### ❌ 4번

> 응용 프로그램이나 데이터를 자신의 컴퓨터에 설치할 필요없이 이용가능하다.

이 설명은 **SDDC가 아니라 SaaS(Software as a Service)** 의 특징입니다.

### 왜 틀렸는가?

* **SDDC**
  * 데이터센터 내부에서
    * 서버
    * 네트워크
    * 스토리지
  * 를 **소프트웨어로 정의하고 자동 제어**
* **설치 필요 없음**
  * SaaS의 핵심 키워드
  * (예: Google Docs, Office 365)

👉 사용자 관점의 서비스 설명  
→ **SDDC 개념과 직접적 관련 없음**  
→ 가장 거리가 먼 설명 → **정답**

---

## 3️⃣ 나머지 선지 분석 (왜 옳은가)

### 1번 ✔

> 입력 개입 없이 소프트웨어 조작만으로 제어한다.

* SDDC의 핵심 특징
  * 자동화
  * 정책 기반 관리
  * 중앙 집중 제어

👉 **소프트웨어에 의한 자동 제어** ⭕

---

### 2번 ✔

> 컴퓨팅, 네트워킹, 스토리지 등을 모두 소프트웨어로 정의한다.

* SDDC의 정의 문장 그대로
  * SDN (네트워크)
  * SDS (스토리지)
  * 서버 가상화

👉 **교과서 문장** ⭕

---

### 3번 ✔

> 모든 하드웨어들이 가상화된다.

* SDDC의 전제 조건
  * 물리 자원을
  * 가상 자원으로 추상화

👉 **완전 가상화 기반 인프라** ⭕

---

## 4️⃣ 틀렸다면 무엇을 추가로 공부해야 하나?

이 문제를 틀렸다면 **SDDC와 클라우드 서비스 모델의 구분이 약한 상태**입니다.

### 반드시 정리할 것 (시험 단골)

#### 📌 SDDC vs 클라우드 서비스 모델

| 구분 | SDDC | SaaS |
|----|----|----|
| 관점 | 데이터센터 인프라 | 사용자 서비스 |
| 대상 | 서버·네트워크·스토리지 | 응용 프로그램 |
| 핵심 | 자동화·가상화·소프트웨어 제어 | 설치 없이 사용 |
| 예 | SDN, SDS | Google Docs |

---

## 5️⃣ 시험장에서 바로 쓰는 판별 요령

* **“설치할 필요 없음”**
  → SaaS ❌
* **“데이터센터 자원 제어”**
  → SDDC ⭕
* **“가상화 + 자동화”**
  → SDDC ⭕

## 문제

**OSI 7계층**에서 **상위 계층에 해당하지 않는 것**은?

1. Presentation Layer  
2. Session Layer  
3. Application Layer  
4. Data Link Layer  

---

## 정답

👉 **4번**

---

## 1️⃣ 문제 해설 (출제 의도 & 풀이 전략)

출제자는 다음을 정확히 알고 있는지를 확인합니다.

* **상위 계층 (Upper Layer)**  
  → 사용자와 직접 연관
* **하위 계층 (Lower Layer)**  
  → 물리적 데이터 전송 담당

👉 핵심 전략  
**“사용자 서비스 제공 계층인가?”**  
이 기준으로 분류하면 됩니다.

---

## 2️⃣ 정답인 이유 (4번)

### ❌ 4번 – Data Link Layer

* Data Link Layer(데이터 링크 계층)는
  * 프레임 전송
  * 오류 제어
  * 흐름 제어
  * MAC 주소 사용

👉 **물리적 전송과 밀접한 하위 계층**  
→ 상위 계층 아님 → **정답**

---

## 3️⃣ 나머지 선지 분석 (왜 옳은가)

### 1번 ✔ Presentation Layer

* **표현 계층**
  * 데이터 형식 변환
  * 압축, 암호화

👉 사용자 데이터를 **어플리케이션이 이해할 수 있게 변환**  
→ 상위 계층 ⭕

---

### 2번 ✔ Session Layer

* **세션 계층**
  * 세션 설정
  * 유지
  * 종료

👉 통신 **논리적 연결 관리**  
→ 상위 계층 ⭕

---

### 3번 ✔ Application Layer

* **응용 계층**
  * 사용자 인터페이스 제공
  * FTP, HTTP, SMTP 등

👉 사용자와 **직접 접촉하는 계층**  
→ 상위 계층 ⭕

---

## 4️⃣ 틀렸다면 무엇을 추가로 공부해야 하나?

이 문제를 틀렸다면 **OSI 7계층의 상·하위 구분이 약한 상태**입니다.

### 반드시 정리할 것 (기출 핵심)

#### 📌 OSI 계층 분류

| 구분 | 계층 |
|----|----|
| **상위 계층** | Application, Presentation, Session |
| **하위 계층** | Transport, Network, Data Link, Physical |

---

## 5️⃣ 시험장에서 바로 쓰는 판별 요령

* **Application / Presentation / Session**
  → 무조건 상위 계층 ⭕
* **Data Link / Physical**
  → 무조건 하위 계층 ⭕
* **Transport / Network**
  → 중간이지만 시험에서는 하위로 분류 ⭕

---

이제 이어서 **OSI 계층별 기능 + 프로토콜 매칭 문제** 나오면  
실수 없이 정리해 드리겠습니다.

### ❓ 질문 (User)
양방향 암호화 알고리즘 종류에 해당하지 않는 것은?

### 💡 답변 (Assistant)
이 문제는 **보기가 반드시 있어야 정확한 풀이가 가능한 유형**입니다.  
양방향 암호화(대칭/비대칭) 문제는 **보기 중에 무엇이 섞여 있느냐**가 핵심이기 때문입니다.

👉 **선택지(보기)를 알려주세요.**  
그러면 아래 형식 그대로,

* 문제 해설  
* 정답  
* 왜 정답인지  
* 나머지 선지 분석  
* 틀렸다면 추가로 공부할 내용  

까지 **정보처리기사 시험 기준으로 정확히** 풀어드리겠습니다.

---

### 참고로, 시험에서 자주 쓰이는 기준 힌트만 미리 알려주면

* **양방향 암호화 ❌**
  * 해시 함수 (단방향)
    * MD5
    * SHA-1 / SHA-256
    * HAS-160
* **양방향 암호화 ⭕**
  * 대칭키: DES, AES, SEED
  * 비대칭키: RSA, ECC

하지만 **정답은 보기 없이는 확정할 수 없습니다.**

👉 **보기를 그대로 적어주세요.**  
바로 실전 풀이 들어가겠습니다.

### 💡 답변 (Assistant)

**양방향(대칭·비대칭) 암호화와 비암호 개념을 구분하는지**를 묻는 **기초 개념 판별 문제**입니다.

## 문제

**양방향 암호화 알고리즘**의 종류에 **해당하지 않는 것**은?

1. RSA  
2. DES  
3. DoS  
4. AES  

---

## 정답

👉 **3번**

---

## 1️⃣ 문제 해설 (출제 의도 & 풀이 전략)

출제자의 의도는 단순합니다.

* **양방향 암호화**
  * 암호화 ↔ 복호화 가능
  * 대칭키 + 공개키 방식 포함
* **암호와 전혀 무관한 용어**
  * 보안 공격 개념

👉 핵심 전략  
**“암·복호화에 쓰이는 알고리즘인가?”**  
이 질문 하나면 바로 걸러집니다.

---

## 2️⃣ 정답인 이유 (3번)

### ❌ 3번 – DoS

* **DoS (Denial of Service)**
  * 서비스 거부 공격
  * 서버 자원을 고갈시켜 정상 서비스 방해

👉 **암호화 알고리즘 아님**  
👉 공격 기법의 한 종류  
→ 양방향 암호화와 무관 → **정답**

---

## 3️⃣ 나머지 선지 분석 (왜 옳은가)

### 1번 ✔ RSA

* **비대칭키(공개키) 암호화 알고리즘**
* 공개키로 암호화, 개인키로 복호화

👉 양방향 암호화 ⭕

---

### 2번 ✔ DES

* **대칭키 암호화 알고리즘**
* 동일한 키로 암·복호화

👉 양방향 암호화 ⭕

---

### 4번 ✔ AES

* **대칭키 암호화 알고리즘**
* DES를 대체한 표준 알고리즘

👉 양방향 암호화 ⭕

---

## 4️⃣ 틀렸다면 무엇을 추가로 공부해야 하나?

이 문제를 틀렸다면 **암호화 기법과 보안 공격 용어가 섞여 있는 상태**입니다.

### 반드시 정리할 것 (시험 단골)

#### 📌 암호화 vs 공격 기법 구분

| 구분 | 예시 |
|----|----|
| 암호화 알고리즘 | DES, AES, RSA |
| 공격 기법 | DoS, DDoS, 스니핑 |
| 해시(단방향) | MD5, SHA |

---

## 5️⃣ 시험장에서 바로 쓰는 판별 요령

* **알고리즘 이름**
  → 암호화 가능성 ⭕
* **Service / Attack 포함**
  → 공격 기법 ⭕

---

다음 문제 주세요.  
이제 이어서 **대칭키 vs 공개키 + 해시 알고리즘** 묶음 문제 나오면  
시험장에서 헷갈리지 않게 정리해 드리겠습니다.

## 문제

**계정(Account)에 적용되는 시스템 보안 범위**에  
**해당하지 않는 것**은?

1. 주기별 사용자 현행화  
2. 업무 내용  
3. 개발자 계정 삭제  
4. Default 계정 사용 제한  

---

## 정답

👉 **2번**

---

## 1️⃣ 문제 해설 (출제 의도 & 풀이 전략)

출제자는 **계정 보안(Account Security)** 이 무엇을 포함하고 무엇을 포함하지 않는지를 구분하는지를 봅니다.

* **계정 보안의 핵심 범위**
  * 계정 생성·변경·삭제
  * 사용 여부 점검
  * 불필요 계정 제거
  * 기본 계정 통제

👉 핵심 전략  
**“계정 자체의 생성·유지·통제와 직접 관련 있는가?”**  
이 기준으로 판단하면 됩니다.

---

## 2️⃣ 정답인 이유 (2번)

### ❌ 2번 – 업무 내용

* **업무 내용**
  * 직무, 역할, 담당 업무에 대한 설명
  * **계정 관리 대상이 아님**

👉 계정 보안은  
**‘누가 어떤 계정을 쓰는가’**이지  
**‘무슨 일을 하는가’**를 직접 통제하는 것이 아닙니다.

→ 시스템 보안 범위에서 벗어남  
→ **정답**

---

## 3️⃣ 나머지 선지 분석 (왜 옳은가)

### 1번 ✔ 주기별 사용자 현행화

* 미사용 계정 점검
* 퇴사·부서 이동 반영

👉 계정 관리의 핵심 보안 통제 ⭕

---

### 3번 ✔ 개발자 계정 삭제

**행위(Behavioral) 패턴의 개념을 정확히 이해하고 있는지**를 묻는 **대표적인 구분 문제**입니다.

## 문제

**행위 패턴(Behavioral Pattern)** 의 개념에 대한 설명으로  
**가장 거리가 먼 것**은?

1. 기능의 구체적인 알고리즘을 정의하는 패턴이다.  
2. 큰 작업을 여러 개의 객체로 분리한 방법을 제공한다.  
3. 반복적으로 사용하는 객체들의 상호작용을 패턴화한 것이다.  
4. 객체에 접근할 수 있는 인터페이스와 새로운 기능을 제공한다.  

---

## 정답

👉 **4번**

---

## 1️⃣ 문제 해설 (출제 의도 & 풀이 전략)

출제자는 **디자인 패턴 3대 분류**를 구분하는지를 확인합니다.

* **생성 패턴(Creational)**  
  → 객체 생성 방식
* **구조 패턴(Structural)**  
  → 객체 구조, 기능 확장
* **행위 패턴(Behavioral)**  
  → 객체 간 **책임 분담**, **알고리즘**, **상호작용**

👉 핵심 전략  
**“알고리즘/상호작용인가, 구조/기능 확장인가?”**  
이 기준으로 선지를 판별합니다.

---

## 2️⃣ 정답인 이유 (4번)

### ❌ 4번

> 객체에 접근할 수 있는 인터페이스와 새로운 기능을 제공한다.

이 설명은 **행위 패턴이 아니라 구조 패턴**에 대한 설명입니다.

### 왜 틀렸는가?

* 해당 설명은
  * **Proxy 패턴** (접근 제어)
  * **Decorator 패턴** (기능 확장)
* 모두 **구조 패턴(Structural Pattern)** 에 해당

👉 객체의 **행동이나 알고리즘 흐름**이 아니라  
**구조와 기능 확장**에 초점  
→ 행위 패턴과 가장 거리가 멂 → **정답**

---

## 3️⃣ 나머지 선지 분석 (왜 옳은가)

### 1번 ✔

> 기능의 구체적인 알고리즘을 정의하는 패턴이다.

* Strategy, Template Method 패턴
* 알고리즘 캡슐화

👉 행위 패턴의 핵심 ⭕

---

### 2번 ✔

> 큰 작업을 여러 개의 객체로 분리한 방법을 제공한다.

* 책임 분산
* 객체 간 협력

👉 행위 패턴의 목적에 부합 ⭕

---

### 3번 ✔

> 반복적으로 사용하는 객체들의 상호작용을 패턴화한 것이다.

* 행위 패턴의 **정의 문장**
* 객체 간 메시지 흐름 규칙화

👉 교과서 표현 ⭕

---

## 4️⃣ 틀렸다면 무엇을 추가로 공부해야 하나?

이 문제를 틀렸다면 **디자인 패턴 분류 기준이 명확하지 않은 상태**입니다.

### 반드시 정리할 것 (기출 핵심)

#### 📌 디자인 패턴 분류 요약

| 분류 | 핵심 키워드 | 예 |
|----|----|----|
| 생성 | 객체 생성 | Factory, Singleton |
| 구조 | 구조, 기능 확장 | Adapter, Decorator, Proxy |
| 행위 | 알고리즘, 상호작용 | Strategy, Observer, Command |

---

## 5️⃣ 시험장에서 바로 쓰는 판별 요령

* **알고리즘 / 상호작용 / 책임 분리**
  → 행위 패턴 ⭕
* **인터페이스 제공 / 기능 추가**
  → 구조 패턴 ❌
* **객체 생성 방식**
  → 생성 패턴 ❌

## 문제

**해당하지 않는 것**은?

1. 가장 높은 결합도를 가지며 모듈의 품질을 하락시킨다.  
2. 가장 좋지 않은 결합으로 모듈의 설계를 다시 할 필요가 있다.  
3. 모듈이 다른 모듈의 내부 기능과 데이터를 직접적으로 사용하는 경우이다.  
4. 모듈이 다른 모듈의 내부 데이터를 참조하는 경우이다.  

---

## 정답

👉 **4번**

---

## 1️⃣ 문제 해설 (출제 의도 & 풀이 전략)

출제자는 **내용 결합도의 ‘정확한 범위’**를 알고 있는지를 확인합니다.

* **내용 결합도(Content Coupling)**
  * 다른 모듈의 **내부 로직(기능)** 을 직접 참조하거나 수정
  * 다른 모듈의 **코드 일부를 직접 제어**
* 헷갈리기 쉬운 것
  * **공통 결합도(Common Coupling)**  
    → 내부 데이터(전역 변수) 참조

👉 핵심 전략  
**“내부 데이터만 참조인가, 내부 기능/로직까지 침범하는가?”**  
이 기준으로 구분합니다.

---

## 2️⃣ 정답인 이유 (4번)

### ❌ 4번

> 모듈이 다른 모듈의 내부 데이터를 참조하는 경우이다.

이 설명은 **내용 결합도**가 아니라  
👉 **공통 결합도(Common Coupling)** 에 해당합니다.

### 왜 틀렸는가?

* **공통 결합도**
  * 전역 변수, 공유 데이터 참조
* **내용 결합도**
  * 다른 모듈의 내부 처리 로직 직접 사용
  * 코드나 기능을 침범

👉 단순히 **내부 데이터만 참조**  
→ 내용 결합도까지는 아님  
→ 가장 거리가 먼 설명 → **정답**

---

## 3️⃣ 나머지 선지 분석 (왜 옳은가)

### 1번 ✔

> 가장 높은 결합도를 가지며 모듈의 품질을 하락시킨다.

* 결합도 최악의 형태
* 유지보수성 급격히 저하

👉 내용 결합도의 대표 특징 ⭕

---

### 2번 ✔

> 가장 좋지 않은 결합으로 모듈의 설계를 다시 할 필요가 있다.

* 내용 결합 발생 시
  * 구조적 결함
  * 재설계 필요

👉 정확한 설명 ⭕

---

### 3번 ✔

> 모듈이 다른 모듈의 내부 기능과 데이터를 직접적으로 사용하는 경우이다.

* 내부 기능(로직) 직접 접근
* 내용 결합도의 정의 문장

👉 교과서 표현 ⭕

---

## 4️⃣ 틀렸다면 무엇을 추가로 공부해야 하나?

이 문제를 틀렸다면 **결합도 단계별 차이 정리가 부족한 상태**입니다.

#### 📌 결합도 단계 정리 (나쁨 → 좋음)

| 결합도 | 특징 |
|----|----|
| **내용 결합도** | 내부 로직 직접 침범 (최악) |
| 공통 결합도 | 전역 데이터 공유 |
| 외부 결합도 | 외부 장치 공유 |
| 제어 결합도 | 제어 정보 전달 |
| 스탬프 결합도 | 자료 구조 전달 |
| 자료 결합도 | 단순 데이터 전달 (최선) |

### 💡 답변 (Assistant)
주어진 산술식:

> **A * B + C − D / E**

연산자 우선순위에 따라 먼저 구조를 정리하면 다음과 같습니다.

- `A * B`
- `D / E`
- 전체 식: **(A * B) + C − (D / E)**

---

## 1️⃣ Prefix 표기법 (전위 표기법)

**연산자 → 피연산자들 순서**

1. `A * B` → `* A B`
2. `(A * B) + C` → `+ * A B C`
3. 전체 식 `(A * B + C) − (D / E)` → `- + * A B C / D E`

### ✅ Prefix 결과
```
- + * A B C / D E
```

---

## 2️⃣ Postfix 표기법 (후위 표기법)

**피연산자들 → 연산자 순서**

1. `A * B` → `A B *`
2. `(A * B) + C` → `A B * C +`
3. `D / E` → `D E /`
4. 전체 식 → `A B * C + D E / -`

### ✅ Postfix 결과
```
A B * C + D E / -
```

---

## ✍️ 최종 정답 정리 (시험 답안용)

- **Prefix** : `- + * A B C / D E`  
- **Postfix** : `A B * C + D E / -`

---

이 유형은 **자료구조(스택) 주관식 단골 문제**라  
연산자 우선순위 + 괄호 구조만 정확히 잡으면 안정적으로 맞힐 수 있습니다.

- 의도적으로 **중복 허용**, **테이블 통합**, **속성 분리** 등을 수행하는 기법

- 중복 컬럼 추가
- 집계 테이블 추가
- 진행 테이블 추가

👉 문제의 설명과 **완벽히 일치**

### 1번 ❌ 인덱스 정규화

### 3번 ❌ 집단화

- 일부 문맥에서 묶는다는 의미로 쓰일 수 있으나  
  👉 반정규화의 정의와는 다름

---

### 4번 ❌ 머징(Merging)

- 일반적으로 **테이블 병합**을 의미하는 영어 표현
- 반정규화의 **한 방법**일 수는 있으나  
  👉 데이터 모델링 기법의 공식 명칭은 아님

### 반드시 정리할 핵심

#### 📌 정규화

- 목적: 데이터 무결성, 중복 제거
- 특징: 테이블 분해
- 단점: 조인 증가 → 성능 저하 가능

#### 📌 반정규화

- 목적: 성능 향상
- 특징: 중복 허용, 테이블 통합
- 대상: 이미 정규화된 모델

1. 연쇄 복귀

## 정답

👉 **2번 (분실된 갱신)**

---

## 1️⃣ 문제 해설 (출제 의도 & 풀이 전략)

출제자는 병행 처리에서 발생하는 **고전적인 3대 이상 현상** 중  
어떤 유형인지 구분할 수 있는지를 묻고 있습니다.

👉 핵심 키워드  
- **“같은 데이터”**
- **“동시에 갱신”**
- **“결과가 기대와 다름”**

이 3가지가 동시에 나오면 거의 자동으로 **분실된 갱신(Lost Update)** 입니다.

---

## 2️⃣ 정답인 이유 (2번)

### ✅ 2번. 분실된 갱신 (Lost Update)

분실된 갱신이란,

- 두 개 이상의 트랜잭션이
- **같은 데이터를 동시에 수정**
- 한 트랜잭션의 갱신 결과가  
  **다른 트랜잭션에 의해 덮어써져 사라지는 현상**

👉 결과적으로 **한쪽 갱신이 “분실”**되어  
사용자가 기대한 최종 결과와 달라짐

→ 문제 설명과 정확히 일치

---

## 3️⃣ 나머지 선지 분석 (왜 오답인가)

### 1번 ❌ 연쇄 복귀 (Cascading Rollback)

- 하나의 트랜잭션이 롤백되면서  
  이를 참조한 다른 트랜잭션도 함께 롤백되는 현상

👉 “동시 갱신”과 직접 관련 없음

---

### 3번 ❌ 모순성 (Inconsistency)

- 트랜잭션 수행 중  
  데이터의 **논리적 일관성이 깨진 상태**
- 보다 포괄적인 개념

👉 시험에서는 보통  
“부분 완료”, “불일치 상태”로 출제됨

---

### 4번 ❌ 비완료 의존성 (Dirty Read)

- 완료되지 않은 트랜잭션의 데이터를  
  다른 트랜잭션이 읽는 현상

👉 “갱신”이 아니라 **읽기 문제**

---

## 4️⃣ 틀렸다면 무엇을 추가로 공부해야 하나?

이 문제를 틀렸다면  
👉 **병행 처리 이상 현상의 정의 구분이 약한 상태**입니다.

### 반드시 정리할 병행 처리 3대 이상 현상

| 현상 | 핵심 키워드 |
|---|---|
| 분실된 갱신 | 동시에 수정, 덮어씀 |
| 비완료 의존성 | Dirty Read, 미완료 데이터 읽기 |
| 모순성 | 중간 상태 조회, 불일치 |

---

## 5️⃣ 시험장에서 바로 쓰는 판별 요령

- **“동시에 갱신”**
  → 분실된 갱신 ⭕

- **“롤백 연쇄”**
  → 연쇄 복귀

## 1️⃣ 문제 해설 (출제 의도 & 풀이 전략)

### ✅ 3번. ALTER TABLE

`ALTER TABLE`은

- 기존 테이블의 구조를 변경할 때 사용하는 DDL
- 컬럼 추가 / 삭제 / 수정 모두 가능

### 예시 SQL (시험 참고용)

```sql
ALTER TABLE 인사
MODIFY 주소 VARCHAR(20);
```

👉 컬럼 길이 확장 → **ALTER TABLE 사용이 정답**

---

## 3️⃣ 나머지 선지 분석 (왜 오답인가)

### 1번 ❌ MODIFY FIELD

- SQL 표준 명령 아님
- 시험에서 사용하는 공식 구문 아님

---

### 2번 ❌ MODIFY TABLE

- SQL 문법에 존재하지 않음
- `MODIFY`는 `ALTER TABLE` 내부에서만 사용

---

### 4번 ❌ ADD TABLE

- 테이블을 추가하는 명령은 `CREATE TABLE`
- 컬럼 수정과 전혀 무관

### 반드시 정리할 DDL 핵심

| 작업 | 명령 |
|---|---|
| 테이블 생성 | CREATE TABLE |
| 테이블 구조 변경 | ALTER TABLE |
| 테이블 삭제 | DROP TABLE |
| 컬럼 추가 | ALTER TABLE ADD |
| 컬럼 수정 | ALTER TABLE MODIFY |

---

- 해시 함수 결과값 기준 분할
- 데이터 분산에 유리

---

### 4번 ✔ 조합 분할 (Composite Partitioning)

- 범위 + 해시 또는 범위 + 리스트 등
- 두 가지 이상 파티션 기법을 결합

---

## 1️⃣ 문제 해설 (출제 의도 & 풀이 전략)

출제자는 **SOLID 원칙 중 ‘의존성 관리’와 관련된 설명**을 제시했습니다.

👉 핵심 키워드 정리

- **하위 클래스 변경이 상위 클래스에 영향 ❌**
- **복잡한 컴포넌트 관계 단순화**
- **컴포넌트 간 효율적 커뮤니케이션**

이 키워드 조합은 전형적인 **의존성 뒤집기 원칙(DIP)** 설명입니다.

※ 실제 교과서 표현은  
> “하위 모듈의 변경이 상위 모듈에 영향을 주지 않도록 한다”

→ 문제에서 이를 **하위 클래스 / 상위 클래스**로 표현한 것

---

## 2️⃣ 정답인 이유 (3번)

### ✅ 3번. 의존성 뒤집기 원칙 (Dependency Inversion Principle)

의존성 뒤집기 원칙이란,

- 상위 모듈이 하위 모듈에 의존 ❌
- **둘 다 추상화(인터페이스)에 의존 ⭕**
- 세부 구현 변경이 전체 구조에 영향을 주지 않도록 설계

### 효과

- 하위 클래스(구현체) 변경 시  
  → 상위 클래스 영향 최소화
- 컴포넌트 간 결합도 감소
- 시스템 구조 단순화

👉 문제의 두 설명과 정확히 일치

---

## 3️⃣ 나머지 선지 분석 (왜 오답인가)

### 1번 ❌ 개방 폐쇄 원칙 (OCP)

- 확장에는 열려 있고
- 변경에는 닫혀 있어야 함

👉 “의존성 관계 단순화”와는 직접적 관련 ❌

---

### 2번 ❌ 단일 책임 원칙 (SRP)

- 하나의 클래스는 하나의 책임만 가져야 함

👉 책임 분리 개념이지  
컴포넌트 의존성 관리 원칙 아님

---

### 4번 ❌ 인터페이스 분리 원칙 (ISP)

- 하나의 큰 인터페이스보다
- 여러 개의 작은 인터페이스가 좋다

👉 인터페이스 크기 문제이지  
상·하위 모듈 의존성 문제 아님

---

## 4️⃣ 틀렸다면 무엇을 추가로 공부해야 하나?

이 문제를 틀렸다면  
👉 **SOLID 원칙 간 핵심 키워드 정리가 부족한 상태**입니다.

### 반드시 정리할 SOLID 핵심 키워드

| 원칙 | 핵심 키워드 |
|---|---|
| SRP | 책임 하나 |
| OCP | 확장 O / 변경 X |
| LSP | 하위 객체 대체 가능 |
| ISP | 인터페이스 분리 |
| DIP | 추상화 의존, 결합도 감소 |

---

## 5️⃣ 시험장에서 바로 쓰는 판별 요령

- **“하위 변경이 상위에 영향 없음”**

- **“확장 / 변경”**

- 스레드를 **어디에서 관리하느냐**

## 2️⃣ 정답인 이유 (4번 ❌)

### ❌ 4번. 프로세스 레벨 스레드

- **프로세스(Process)** 는  
  → 스레드를 포함하는 **상위 개념**
- 스레드는 프로세스 **내부에서 동작**
- 따라서  
  👉 *“프로세스 레벨 스레드”*라는 모델은  
  **운영체제 이론에서 존재하지 않음**

➡️ 멀티스레드 모델 ❌ → 정답

---

## 3️⃣ 나머지 선지 분석 (왜 옳은가)

### 2번 ✔ 사용자 레벨 스레드 (User-Level Thread)

- 사용자 영역 라이브러리에서 관리
- 커널 개입 없음
- 문맥 교환 빠름, 병렬성 제한

👉 대표적인 멀티스레드 모델

---

### 3번 ✔ 커널 레벨 스레드 (Kernel-Level Thread)

- 운영체제가 직접 스레드 관리
- 병렬 처리 가능
- 오버헤드 존재

👉 대표적인 멀티스레드 모델

---

### 1번 ✔ 멀티 레벨 스레드

- 사용자 레벨 + 커널 레벨을 결합한 구조
- 일반적으로 **혼합형(M:N, 다대다 모델)** 을 의미

👉 시험에서는 **멀티 레벨 스레드 = 혼합형 모델**로 인정

---

## 4️⃣ 틀렸다면 무엇을 추가로 공부해야 하나?

이 문제를 틀렸다면  
👉 **프로세스와 스레드의 계층 관계가 혼동된 상태**입니다.

### 반드시 정리할 개념 구조

```
프로세스
 └─ 스레드
     ├ 사용자 레벨 스레드
     ├ 커널 레벨 스레드

```

## 해설

**소프트웨어 관련 신기술**에 해당하지 않는 것을 고르는 문제입니다.

### ① Bluetooth ❌ **(정답)**
- 근거리 **무선 통신 기술**
- 하드웨어·통신 기술에 해당
- 소프트웨어 신기술로 분류되지 않음

### ② Software Escrow ⭕
- 소프트웨어 소스코드를 제3의 기관에 보관하는 제도
- 공급사 문제 발생 시 사용자 보호 목적
- **소프트웨어 관련 기술/제도**

### ③ Grayware ⭕
- 악성코드와 정상 소프트웨어의 중간 성격
- 사용자에게 불편이나 보안 위협을 주는 프로그램
- **소프트웨어 보안 관련 개념**

### ④ Complex Event Processing (CEP) ⭕
- 대량의 이벤트 스트림을 실시간 분석·처리하는 기술
- 빅데이터, 실시간 분석 분야의 **소프트웨어 기술**

---

## 최종 정답

✅ **1번 Bluetooth**

### 암기 포인트
- **Bluetooth** → 무선 통신 기술
- **CEP / Grayware / Software Escrow** → 소프트웨어 신기술 or 소프트웨어 관리·보안 개념
