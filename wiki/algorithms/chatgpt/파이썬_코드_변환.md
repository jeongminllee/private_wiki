import sys
input = sys.stdin.readline

# 입력
arrSize, sel = map(int, input().split())
arr = [0] * arrSize
for i in range(arrSize):
    arr[i] = int(input())

is_used = [False] * arrSize      # 각 인덱스의 원소 사용 여부
selected = [0] * sel             # 선택된 수를 담을 배열

def func(k: int):
    """
    k번째 자리를 어떤 수로 채울지 결정하는 재귀 함수
    k == sel 이 되면 하나의 순열이 완성됨

    global cnt
    if k == sel:
        print(*selected)
        cnt += 1
        return

    # arr의 0 ~ arrSize-1 인덱스를 돌며 사용 가능한 수 선택
    for i in range(arrSize):

            func(k + 1)               # 다음 자리 결정
            is_used[i] = False        # 상태 복구 (백트래킹)

func(0)
print(cnt)

### ❓ 질문 (User)
순열과 조합을 하나의 템플릿으로 외우고 싶은데 파이썬 코드로 구현해줘

### 💡 답변 (Assistant)
아예 “복붙용 템플릿” 느낌으로, **순열 / 조합을 한 파일 안에서 같이 외워둘 수 있게** 정리해볼게.  
(백트래킹 기본 뼈대는 똑같고, 달라지는 건 딱 두 군데야.)

```python
import sys
input = sys.stdin.readline

# 입력 예시
# N: 숫자의 개수, M: 뽑을 개수
# numbers: 사용할 숫자들
#
# 예)
# 4 2
# 1 3 5 7
#
# N=4, M=2, numbers=[1,3,5,7]

N, M = map(int, input().split())
numbers = list(map(int, input().split()))

# 공통으로 쓰는 배열들
selected = [0] * M      # 현재까지 선택한 수들
used = [False] * N      # 순열에서만 사용 (해당 인덱스 사용 여부)


# -----------------------------
# 1️⃣ 순열 (Permutation)
#  - 순서 O
#  - 중복 X
# -----------------------------
def perm(k: int):
    """
    k : 현재 선택할 자리 (0 ~ M-1)
    """
    if k == M:
        # M개를 다 골랐으면 출력
        print(*selected)
        return

    for i in range(N):          # numbers의 i번째 원소를 쓸지 말지
        if not used[i]:         # 아직 사용 안 했다면
            used[i] = True      # 사용 표시
            selected[k] = numbers[i]
            perm(k + 1)         # 다음 자리 고르러 감
            used[i] = False     # 되돌리기 (백트래킹)


# -----------------------------
# 2️⃣ 조합 (Combination)
#  - 순서 X
#  - 중복 X
# -----------------------------
def comb(k: int, start: int):
    """
    k     : 현재 선택할 자리 (0 ~ M-1)
    start : numbers에서 다음에 고를 수 있는 최소 인덱스
            (앞에서 고른 것보다 항상 뒤에서만 고름)
    """
    if k == M:
        print(*selected)
        return

    for i in range(start, N):
        selected[k] = numbers[i]
        comb(k + 1, i + 1)   # i 이후의 것들만 고름


# =============================
# 사용 예시
# =============================

# 순열 출력
# perm(0)

# 조합 출력
# comb(0, 0)
```

### 어떻게 외우면 좋냐면

둘 다 같은 틀이라고 생각하면 돼:

1. **공통 구조**
   - `selected[k]`에 뭔가 하나 넣고
   - 재귀로 `k+1` 호출
   - 끝까지 다 채우면 (`k == M`) 출력

2. **순열 vs 조합의 차이는 딱 두 가지**

   #### 순열
   - `for i in range(N):`
   - 이미 쓴 건 `used[i]`로 체크

   ```python
   for i in range(N):
       if not used[i]:
           used[i] = True
           selected[k] = numbers[i]
           perm(k+1)
           used[i] = False
   ```

   #### 조합
   - `for i in range(start, N):`
   - `used` 필요 없음, 대신 `start` 파라미터로 “앞에 쓴 것보다 뒤에서만 고른다” 보장

   ```python
   for i in range(start, N):
       selected[k] = numbers[i]
       comb(k+1, i+1)
   ```

이 파일 하나를 그냥 `template_perm_comb.py` 같은 이름으로 저장해 두고,  
대회/백준 풀 때는:

- 순열 문제 → `perm(0)`만 호출
- 조합 문제 → `comb(0, 0)`만 호출

이렇게 쓰면 딱 “하나의 템플릿”으로 몸에 익힐 수 있을 거야.

### ❓ 질문 (User)
```
class Solution:
    def combine(self, n: int, k: int) -> List[List[int]]:
        nums = [i for i in range(n+1)]
        visited = [False for _ in range(n+1)]
        res = []
        self.combinations(1, k, nums, visited, [], 0, res)

        return res

    def combinations(self, bgn, end, nums, visited, buildings, depth, res) :
        if depth == end :
            res.append(buildings[:])
            return

        for idx in range(bgn, len(nums)) :
            if visited[idx] :
                continue

            visited[idx] = True
            self.combinations(bgn+1, end, nums, visited, buildings + [nums[idx]], depth + 1, res)
            visited[idx] = False
```
리트코드 combination 문제를 내 방식대로 풀어봤는데 정답이 아니란 말이지. 어디서 실수했는지 지적해줘.

### 💡 답변 (Assistant)
핵심만 먼저 말하면:

👉 **재귀 호출에서 `bgn+1`을 넘긴 게 가장 큰 버그**야.  
그 자리는 **항상 `idx+1`**이 들어가야 해.

---

네 코드에서 조합을 만드는 부분만 다시 보자:

```python
for idx in range(bgn, len(nums)) :
    if visited[idx] :
        continue

    visited[idx] = True
    self.combinations(bgn+1, end, nums, visited, buildings + [nums[idx]], depth + 1, res)
    visited[idx] = False
```

여기서 논리가 이렇게 돼야 해:

- 지금 `idx`번째 숫자를 골랐으니  
  **다음 재귀에서는 `idx` 뒤에 있는 숫자들만** 골라야 한다.
- 그래서 다음 시작 인덱스는 **`idx+1`** 이 되어야 함.

근데 네 코드는 `bgn+1`을 넘기고 있어서,  
매 단계에서 “현재 고른 위치”랑 상관없이  
그냥 `bgn+1`부터 다시 도는 문제가 생겨.

---

### 실제로 어떻게 망가지는지 예시 (n=4, k=2)

`nums = [0,1,2,3,4]` 이고 (idx 0은 안 써서 무시),
첫 호출은 `combinations(1, 2, ...)` 이라고 하자.

1. 첫 깊이(`depth=0`, `bgn=1`)에서  
   `idx = 1` 선택 → 숫자 1을 골랐다고 치자.
   - 재귀 호출: `combinations(bgn+1=2, ...)`
   - 여기서는 `idx = 2,3,4`만 돌고,  
     방문체크 때문에 1은 안 고른다.
   - 결과: `[1,2], [1,3], [1,4]` → OK

2. 다시 `depth=0`으로 돌아와서 `idx = 2` 선택 (숫자 2):
   - 재귀 호출: **여전히** `combinations(bgn+1=2, ...)`
   - 여기서 `idx=2`는 visited라 skip,
   - `idx=3,4` 선택해서 `[2,3], [2,4]` → 이것도 괜찮아 보이지?

3. 문제는 `idx = 3`일 때 터진다.

   - `depth=0`, `bgn=1`, `idx=3` 선택 (숫자 3)
   - 재귀 호출: 또 `combinations(bgn+1=2, ...)`
   - 이제 `depth=1`, `bgn=2`에서 `idx`는 2~4를 도는데,
     - `idx=2`는 아직 visited가 아니니까 선택 가능해짐

   → `buildings = [3]`인 상태에서 `idx=2`를 골라서  
   **[3,2] 같은 조합이 튀어나와 버려.**  
   (조합은 순서가 중요 없으니까 [2,3]과 중복되는 셈)

이게 바로 `bgn+1`을 쓴 탓이야.  
“현재 고른 위치(idx)”를 기준으로 **그 뒤로만** 탐색해야 하는데,  
항상 같은 `bgn+1`을 넘기니까 이전에 나오던 인덱스도 다시 섞이게 됨.

---

## 고친 버전 (네 스타일 최대한 유지)

1) **핵심 수정:** `bgn+1` ➜ `idx+1`  
2) 사실 `visited`는 조합에서는 필요 없지만, 네 스타일 살려서 그대로 둘게.

```python
class Solution:
    def combine(self, n: int, k: int) -> List[List[int]]:
        nums = [i for i in range(n+1)]  # nums[1..n] 사용
        visited = [False for _ in range(n+1)]
        res = []
        self.combinations(1, k, nums, visited, [], 0, res)
        return res

    def combinations(self, bgn, end, nums, visited, buildings, depth, res):
        if depth == end:
            res.append(buildings[:])
            return

        for idx in range(bgn, len(nums)):
            if visited[idx]:
                continue

            visited[idx] = True
            # ✅ 다음 시작점은 항상 idx+1
            self.combinations(idx + 1, end, nums, visited, buildings + [nums[idx]], depth + 1, res)
            visited[idx] = False
```

이렇게 바꾸면:

- 항상 **오름차순 인덱스**로만 뽑게 되고  
- `[2,3]`이 나온 뒤에 `[3,2]` 같은 역순 쓰레기는 안 생겨.

## 더 깔끔한 “조합 템플릿” 버전 (visited 없이)

LeetCode에서 그냥 쓰기 좋은 정석 버전도 같이 남길게:

```python
class Solution:
    def combine(self, n: int, k: int) -> List[List[int]]:
        res = []

        def dfs(start: int, path: List[int]):
            if len(path) == k:
                res.append(path[:])
                return

            for num in range(start, n + 1):
                dfs(num + 1, path + [num])

        dfs(1, [])
        return res
```

- `start`가 네 `bgn`
- `k`가 네 `end == depth 조건`
- `path`가 네 `buildings`

그래서 요약하면:

> ❗ 네 코드의 핵심 실수:  
> **재귀 호출의 시작 인덱스를 `bgn+1`로 넘긴 것.  
> 올바른 건 `idx+1`.**

이거 한 번 머릿속에 “트리 펼치기”로 시뮬 돌려보면  
조합/순열 문제들 훨씬 빨리 감 잡을 수 있을 거야.

### ❓ 질문 (User)
내가 이렇게 공부하는 이유는 니가 지적한 idx+1 부분을 0으로(혹은 1로) end 부분을 len(nums) 부분으로 하면 순열이 되기 때문이야.

### 💡 답변 (Assistant)
아하, 이제 왜 그렇게 짰는지 완전 이해했어.  
**“idx+1 쓰면 조합, 0(또는 1) / len(nums) 쓰면 순열”** 이 패턴을 몸에 새기려는 거였구나 👍

정리해보면, 네 머릿속은 대충 이런 그림이지?

- **공통 틀:**
  - `depth` : 지금까지 몇 개 골랐냐
  - `visited` : 이미 쓴 숫자인지
  - `buildings` : 지금까지 고른 숫자들
- 그리고
  - “다음에 어디서부터 탐색하냐(start/bgn)”를 어떻게 주느냐에 따라  
    → **조합 / 순열이 갈린다**

이 아이디어 자체는 **완전 맞는 방향**이야.  
다만, 네 코드에서 깨졌던 건 “조합 모드에서 start를 잘못 넘긴 것(bgn+1 → idx+1)”이고,  
“순열 모드” 관점에서 보면 네 말이 맞아.

---

## 1. 한 줄로 요약하면

- **조합(combination)**  
  → *“앞에서 고른 것보다 뒤의 인덱스만 고른다”*  
  → `for i in range(start, n):` + 재귀에서 `start = i+1`

- **순열(permutation)**  
  → *“매 깊이마다 전체 후보 중 ‘아직 안 쓴 것’을 고른다”*  
  → `for i in range(0, n):` + 재귀에서도 `start` 의미 없음 (항상 0 또는 1)

그래서 네 말처럼:

> 조합: `start = idx+1`  
> 순열: `start = 0(또는 1)` / `end = len(nums)` 고정 + visited로 중복 방지

이게 맞는 감각이야.

---

## 2. 너가 생각하는 “하나의 틀”을 코드로 찍어보자

네 스타일 존중해서,  
**같은 DFS 뼈대에 플래그만 다르게 주는 버전**을 만들어볼게.

```python
from typing import List

def backtrack(nums: List[int], k: int, use_start: bool) -> List[List[int]]:
    """
    use_start = True  -> 조합 모드 (combination)
    use_start = False -> 순열 모드 (permutation)
    """
    n = len(nums)
    res = []
    visited = [False] * n

    def dfs(depth: int, start: int, path: List[int]):
        if depth == k:
            res.append(path[:])
            return

        # ✅ 다음에 탐색할 인덱스 범위 결정
        if use_start:
            # 조합 모드: 항상 start ~ n-1
            rng = range(start, n)
        else:
            # 순열 모드: 항상 0 ~ n-1 (start는 의미 없음)
            rng = range(0, n)

        for idx in rng:
            if visited[idx]:
                continue

            visited[idx] = True
            # 조합이면 다음 start는 idx+1, 순열이면 0 그대로
            next_start = idx + 1 if use_start else 0
            dfs(depth + 1, next_start, path + [nums[idx]])
            visited[idx] = False

    dfs(0, 0, [])
    return res


# 사용 예시
nums = [1, 2, 3]

# 조합: 3개 중 2개 고르기 -> [1,2], [1,3], [2,3]
comb_res = backtrack(nums, k=2, use_start=True)

# 순열: 3개 중 2개 순서 있게 -> [1,2], [2,1], [1,3], [3,1], [2,3], [3,2]
perm_res = backtrack(nums, k=2, use_start=False)
```

여기서 보면:

- **조합 모드**
  - `rng = range(start, n)`  
  - `next_start = idx + 1`  
  → 항상 증가하는 인덱스 순서로만 뽑음 → (i1 < i2 < ...)

- **순열 모드**
  - `rng = range(0, n)`  
  - `next_start = 0`  
  → 매 깊이마다 “전체에서 아직 안 쓴 것” 아무거나 골라서 순서 있는 나열이 됨

네가 머릿속으로 생각한:

> “`idx+1` 부분을 0/1로, `end`를 len(nums)로 고정하면 순열이 된다”

를 코드로 딱 형태화한 게 이거야.

---

## 3. 네 LeetCode 코드에서만 문제였던 포인트

다시 한 번 짚자면, 네 기존 조합 코드는:

```python
for idx in range(bgn, len(nums)) :
    ...
    self.combinations(bgn+1, end, ...)
```

여기서 **조합 모드로 굴리고 싶었다면**  
→ `bgn+1`이 아니라 `idx+1`이어야 했고,

**순열 모드로 굴리고 싶었다면**  
→ 애초에 `for idx in range(1, len(nums))` 돌리고,
→ 재귀에서 `bgn`은 항상 1로 고정하거나, 그냥 파라미터에서 빼버렸어야 했지.

즉, 네 아이디어(“start를 어떻게 넘기느냐로 순열/조합을 통합해서 이해하기”)는 맞는데,  
**조합 쪽 구현에서만 start 갱신을 틀리게 쓴 거**고,  
순열/조합을 하나의 틀로 묶어보려는 공부 방향은 아주 좋다 👍

- 지금 네 스타일을 그대로 살려서  
  `combine` + `permute`를 같은 클래스 / 같은 템플릿으로 정리해 줄 수도 있고,
- 거기에 `중복 허용 조합`, `중복 허용 순열`까지

### 💡 답변 (Assistant)
좋은 코드 비교였다 이거 😂  
두 코드는 “겉보기 로직”은 거의 같은데, **조합 뽑는 부분에서의 차이 때문에 BFS를 몇 번 돌리냐가 완전히 달라져서** 위 코드는 TLE, 아래 코드는 통과가 나는 거야.

## 1. 가장 큰 차이: 이건 조합이 아니라 거의 순열

### 위 코드의 조합 함수

```python
def combine(arr, k) :
    visited = [False for _ in range(len(arr))]
    res = []
    combinations(0, k, arr, visited, [], 0, res)
    return res

def combinations(bgn, end, nums, visited, buildings: list, depth, res) :
    if depth == end :
        res.append(buildings[:])
        return

    for idx in range(len(nums)) :   # ❌ bgn 안 씀
        if visited[idx] :
            continue

        visited[idx] = True
        combinations(idx+1, end, nums, visited, buildings + [nums[idx]], depth + 1, res)
        visited[idx] = False
```

문제 포인트:

- `for idx in range(len(nums))`  
  → **항상 0 ~ len(nums)-1 전체를 돈다. `bgn`은 완전히 무시됨.**
- `visited[idx]`로 “같은 원소를 두 번 뽑지 않게”는 막았지만,
- 순서를 고려하지 않게 막지는 못함.

즉, 이건 조합이 아니라 사실상:

> **길이 k인 “순열” (order O, 중복 X)** 를 전부 생성하는 꼴

예를 들어 `nums = [a, b, c]`, `k = 2`면:

- 진짜 **조합**이라면: `[a, b]`, `[a, c]`, `[b, c]` → 3개
- 지금 코드에선: `[a, b]`, `[a, c]`, `[b, a]`, `[b, c]`, `[c, a]`, `[c, b]` → 6개

즉, **각 조합을 순서만 바꿔서 여러 번 뽑고 있는 것**이야.

---

### 아래 코드의 조합 함수

```python
def combination(lst, k) :
    def backtrack(start, output) :
        if len(output) == k :
            result.append(output[:])
            return

        for i in range(start, len(lst)) :
            output.append(lst[i])
            backtrack(i+1, output)
            output.pop()

    result = []
    backtrack(0, [])
    return result
```

여기는:

- `for i in range(start, len(lst))`
- 재귀에서 `backtrack(i+1, output)`

즉,

> 항상 **앞에서 고른 인덱스보다 뒤에 있는 인덱스만** 고르기 때문에  
> (i₁ < i₂ < … < iₖ),  
> **딱 진짜 조합만** 만들어짐.

---

## 2. 이 차이가 성능에 미치는 영향

연구소 3(추측)에서:

- 바이러스 후보 개수 = V (최대 10쯤)
- 활성화할 개수 = M

**아래 코드(정답 코드)는:**

- 조합 개수 = `C(V, M)` 만큼만 BFS 수행

**위 코드(TLE 코드는):**

- 순열 개수 = `P(V, M) = V! / (V-M)!` 만큼 BFS 수행

예시로 V=10, M=5면:

- 조합: `C(10, 5) = 252`
- 순열: `P(10, 5) = 30,240`

→ **BFS를 120배 더 많이 돌리고 있는 셈** 😅  
50×50 격자에서 BFS 한 번도 꽤 비싼데, 이걸 120배 더 돌리면… 당연히 TLE.

여기서 중요한 건:

> **BFS 결과가 바이러스 선택 “순서”에 전혀 의존 안 한다**는 점  
> (멀티 소스 BFS라 `(v1, v2, v3)`나 `(v2, v1, v3)`나 결과 똑같음)

그런데 위 코드는 그 **순서가 다른 경우까지 모조리 중복 계산**하고 있는 거지.

---

## 3. 나머지 차이들은 부차적인 수준

두 코드 BFS 자체도 조금씩 다르긴 한데, 이건 성능 차이의 주범은 아님:

### 위 코드 BFS

```python
visited = [[INF for _ in range(N)] for _ in range(N)]
...
if visited[ni][nj] > visited[ci][cj] + 1 :
    ...
```

### 아래 코드 BFS

```python
v = [[-1] * N for _ in range(N)]
...
if 0<=ni<N and 0<=nj<N and v[ni][nj] == -1 and arr[ni][nj] != 1 :
    ...
```

- 위는 `INF`와 `>` 비교
- 아래는 `-1` 이면 한번만 방문

BFS 특성상, 첫 방문이 이미 최단 거리라 **두 방식 모두 논리적으로는 문제 없음**.  
비교 연산 조금 더 들어가는 정도고, 이게 TLE를 만들 정도는 아님.

실제 지배적인 차이는 **조합 vs 순열 개수** 때문에 발생하는  
BFS 호출 횟수의 차이야.

## 4. 위 코드를 “진짜 조합”으로 고치려면

너의 `combine` 템플릿을 유지하면서,  
딱 한 줄만 바꾸면 돼:

```python
def combinations(bgn, end, nums, visited, buildings: list, depth, res) :
    if depth == end :
        res.append(buildings[:])
        return

    # ❌ for idx in range(len(nums)) :
    for idx in range(bgn, len(nums)):   # ✅ bgn부터 시작!
        if visited[idx] :
            continue

        visited[idx] = True
        combinations(idx+1, end, nums, visited, buildings + [nums[idx]], depth + 1, res)
        visited[idx] = False
```

사실 이 상태에선 `visited`도 필요 없긴 해(인덱스가 항상 증가하니까 중복이 안 생김).  
그래도 네 “순열/조합 하나의 틀로 이해하기” 관점 유지하려면 놔둬도 돼.

## 요약

1. **위 코드의 `combine`이 조합이 아니라 사실상 순열을 만들고 있다.**  
   - `for idx in range(len(nums))` 때문에 순서 다른 경우까지 몽땅 탐색.
2. 그래서 BFS를 `C(V, M)`번이 아니라 `P(V, M)`번 돌리게 되고,  
   → **필요한 것보다 수십~수백 배 더 많이 BFS**를 돌려서 TLE.
3. 아래 코드는 `for i in range(start, len(lst))` + `backtrack(i+1, ...)`로  
   → 진짜 조합만 생성해서 통과.

네 “하나의 틀로 순열/조합 이해하기” 방향은 완전 좋아.  
지금 이 케이스는 그냥 **“조합 모드에서 start를 안 쓴 실수”** 때문에  
순열처럼 동작해버려서 시간만 조짐 😂
