# 응집도 결합도 품질 관계

> **카테고리**: `Algorithms (알고리즘 & 자료구조)`

## 💬 대화 내용 및 Q&A

### ❓ 질문 (User)
결합도와 품질과 관련된 내용을 공부하게 되었어. 이것과 같이 응집도랑 연계해서 공부하면 좋을꺼 같아서 물어보고 싶어. 응집도, 결합도, 품질 관계에 대해서 정리해줘.

### 💡 답변 (Assistant)
좋아, 이건 **정보처리기사 실기에서 매우 자주 출제되는 핵심 개념 3종 세트**야.  
👉 *응집도 + 결합도 + 소프트웨어 품질*은 반드시 **한 덩어리로 이해**해야 한다.

아래 형식으로 정확하게 정리해줄게.

---

# ✅ 문제 분석

제시된 개념의 핵심 포인트는 다음과 같습니다.

- 모듈 내부 구성 요소 간의 관련성 → **응집도**
- 모듈 간 상호 의존성 → **결합도**
- 소프트웨어의 구조적 품질 판단 기준

→ 핵심 키워드  
**모듈 내부 / 모듈 간 / 독립성 / 유지보수성 / 품질**

---

# 🎯 핵심 정리 (한 줄 요약)

👉 **응집도는 높을수록 좋고, 결합도는 낮을수록 좋다 → 소프트웨어 품질 향상**

---

# 📌 응집도 (Cohesion)

👉 **모듈 내부 요소들이 얼마나 “하나의 목적”으로 잘 뭉쳐 있는가**

### 특징
- 하나의 기능만 수행할수록 높음
- 모듈 내부 집중도

### 응집도 종류 (중요: 시험 출제 포인트)

낮음 → 높음 순서

| 종류 | 설명 |
|------|------|
| 기능적 응집도 | 하나의 기능만 수행 (최고 👍) |
| 순차적 응집도 | 출력 → 다음 입력 |
| 통신적 응집도 | 동일 데이터 사용 |
| 절차적 응집도 | 실행 순서 중심 |
| 시간적 응집도 | 특정 시간에 수행 |
| 논리적 응집도 | 유사 기능 묶음 |
| 우연적 응집도 | 아무 관련 없음 (최악 👎) |

---

# 📌 결합도 (Coupling)

👉 **모듈 간 얼마나 강하게 연결되어 있는가**

### 특징
- 서로 의존성이 적을수록 좋음
- 독립성 중요

### 결합도 종류 (중요)

높음 → 낮음 순서

| 종류 | 설명 |
|------|------|
| 내용 결합도 | 내부 데이터 직접 접근 (최악 👎) |
| 공통 결합도 | 전역 변수 공유 |
| 외부 결합도 | 외부 장치/환경 공유 |
| 제어 결합도 | 제어 정보 전달 |
| 스탬프 결합도 | 자료 구조 전달 |
| 자료 결합도 | 필요한 데이터만 전달 (최고 👍) |

---

# 📌 품질과의 관계 (핵심!)

👉 시험에서 가장 중요하게 묻는 부분

### 공식처럼 외워라

```
응집도 ↑  → 품질 ↑
결합도 ↓  → 품질 ↑
```

---

# 📊 구조적 관계 정리

| 항목 | 상태 | 결과 |
|------|------|------|
| 응집도 높음 | 내부 집중 | 유지보수 쉬움 |
| 응집도 낮음 | 기능 분산 | 오류 증가 |
| 결합도 높음 | 의존성 큼 | 수정 영향 큼 |
| 결합도 낮음 | 독립성 높음 | 재사용성 ↑ |

---

# 🔎 쉽게 이해하는 비유

- **응집도 = 팀워크**
  - 한 팀이 하나의 목표만 수행 → 좋음

- **결합도 = 팀 간 의존성**
  - 다른 팀 도움 없이 일 가능 → 좋음

👉 즉,
> “각 팀은 자기 일만 잘하고, 서로 간섭은 최소화”  
→ 좋은 시스템 구조

---

# 🔎 헷갈리는 포인트

❌ “응집도 낮고 결합도 낮으면 좋다?”  
→ ❌ 틀림

👉 반드시 같이 기억해야 함

- 응집도: 높을수록 좋다  
- 결합도: 낮을수록 좋다

---

# 📚 추가로 공부해야 할 것 (틀렸다면)

1️⃣ 응집도 vs 결합도 비교 문제  
→ “내부냐 / 외부냐” 기준으로 구분

2️⃣ 유형 순서 문제 (자주 출제됨)

👉 응집도:  
우논시절통순기 (우연 → 기능)

👉 결합도:  
내공외제스자 (내용 → 자료)

3️⃣ 설계 원칙과 연결

- 모듈화 (Modularity)
- 정보 은닉 (Information Hiding)
- 추상화 (Abstraction)

---

# 🧠 실기시험 포인트 정리

✔ “모듈 내부” → 응집도  
✔ “모듈 간 관계” → 결합도  
✔ “좋은 구조” → 응집도↑ 결합도↓  
✔ “유지보수성” → 구조 품질의 핵심 기준

# ✅ 문제 분석

제시된 설명의 핵심 포인트는 다음과 같습니다.

- **응집도**: 하나의 모듈 내부 요소들이 얼마나 밀접하게 관련되어 있는가
- **결합도**: 서로 다른 모듈끼리 얼마나 강하게 의존하고 있는가
- **좋은 소프트웨어 구조**: 응집도는 높고, 결합도는 낮아야 함

→ 핵심 키워드:  
**모듈 내부 / 모듈 간 / 독립성 / 연관성 / 유지보수성 / 재사용성**

---

# 🎯 정리

👉 **응집도(Cohesion)** = 모듈 내부의 뭉침 정도  
👉 **결합도(Coupling)** = 모듈과 모듈 사이의 연결 정도

---

# 📌 응집도(Cohesion)란?

응집도는 **하나의 모듈 안에 들어 있는 구성 요소들이 얼마나 같은 목적을 위해 함께 동작하는가**를 의미해.

쉽게 말하면,

- 한 모듈이 **하나의 일만 깔끔하게 하면 응집도가 높다**
- 한 모듈이 **이 일도 하고 저 일도 하면 응집도가 낮다**

즉,  
**“모듈 내부가 얼마나 잘 뭉쳐 있느냐”**를 보는 개념이야.

---

## ✅ 응집도가 높은 것이 왜 좋은가?

응집도가 높으면:

- 모듈의 역할이 분명함
- 이해하기 쉬움
- 수정하기 쉬움
- 재사용하기 쉬움
- 테스트하기 쉬움

예를 들어,

- `회원 로그인 처리 모듈`이 로그인 기능만 담당하면 좋음
- 그런데 그 모듈이 로그인, 회원가입, 결제, 게시글 작성까지 다 하면 나쁨

즉,  
**모듈 하나 = 하나의 책임** 이 되면 응집도가 높다고 보면 돼.

---

# 📌 응집도 종류

시험에서는 보통 **낮은 것 → 높은 것** 순서로 많이 외워.

## 1) 우연적 응집도 (Coincidental Cohesion)

👉 **서로 관련 없는 기능들이 우연히 한 모듈에 묶여 있는 상태**

예:
- 파일 저장
- 회원 삭제
- 화면 출력
- 날짜 계산

이런 전혀 다른 기능들이 한 모듈에 들어 있음.

### 특징
- 가장 낮은 응집도
- 이유 없이 묶여 있음
- 유지보수 매우 어려움

### 시험 포인트
문제에서  
**“관련 없는 기능이 한 모듈에 모여 있다”**  
라고 나오면 우연적 응집도야.

---

## 2) 논리적 응집도 (Logical Cohesion)

👉 **비슷한 성격의 기능들을 논리적으로 묶은 상태**

예:
- 입력 처리 모듈
  - 키보드 입력
  - 마우스 입력
  - 음성 입력

비슷하긴 하지만 실제로는 각각 다른 기능임.

### 특징
- 유사한 기능끼리 묶였지만 하나의 명확한 기능은 아님
- 보통 조건에 따라 다른 기능이 수행됨

### 시험 포인트
**“유사한 성격”, “선택에 따라 다른 처리”**  
이런 표현이 나오면 논리적 응집도일 가능성이 높아.

---

## 3) 시간적 응집도 (Temporal Cohesion)

👉 **특정한 시점에 함께 수행되는 기능들을 묶은 상태**

예:
- 시스템 시작 시 초기화
- 프로그램 종료 시 정리 작업

초기화 작업들은 비슷한 목적이 아니라  
**“같은 시간에 실행된다”**는 이유로 모여 있음.

### 특징
- 수행 시점이 같아서 묶임
- 기능 자체가 꼭 밀접한 것은 아님

### 시험 포인트
**“초기화”, “종료 처리”, “동시에 수행”**  
이런 표현이 보이면 시간적 응집도.

---

## 4) 절차적 응집도 (Procedural Cohesion)

👉 **실행 순서가 정해져 있어서 묶인 상태**

예:
1. 데이터 읽기
2. 데이터 검사
3. 결과 출력

기능들이 같은 목적을 위해 완전히 밀접한 것은 아니지만  
**정해진 순서대로 처리되기 때문에** 한 모듈에 있음.

### 특징
- 순서 중심
- 처리 흐름 중심

### 시험 포인트
**“순서대로 수행”, “절차에 따라 실행”**  
이면 절차적 응집도.

---

## 5) 통신적 응집도 (Communicational Cohesion)

👉 **같은 데이터를 사용하거나 같은 결과를 산출하는 기능들이 묶인 상태**

예:
- 같은 고객 정보를 조회
- 같은 고객 정보를 출력
- 같은 고객 정보를 수정

모두 동일한 데이터와 관련되어 있음.

### 특징
- 동일한 입력/출력 데이터 공유
- 데이터 중심으로 묶임

### 시험 포인트
**“동일한 자료 사용”, “같은 데이터 처리”**  
라고 나오면 통신적 응집도.

---

## 6) 순차적 응집도 (Sequential Cohesion)

👉 **한 기능의 출력이 다음 기능의 입력이 되는 상태**

예:
1. 자료 입력
2. 입력 자료 정렬
3. 정렬 결과 출력

앞 단계 결과가 다음 단계로 바로 이어짐.

### 특징
- 기능 간 연결성이 강함
- 처리 흐름이 자연스럽게 이어짐

### 시험 포인트
**“앞의 출력이 뒤의 입력”**  
이 문장은 거의 순차적 응집도라고 보면 돼.

---

## 7) 기능적 응집도 (Functional Cohesion)

👉 **모듈이 오직 하나의 기능만 수행하는 상태**

예:
- 로그인 검증 모듈
- 급여 계산 모듈
- 주민번호 유효성 검사 모듈

### 특징
- 가장 이상적인 응집도
- 하나의 목적만 수행
- 이해/테스트/수정/재사용이 가장 쉬움

### 시험 포인트
**“단일 기능”, “하나의 명확한 목적”**  
이면 기능적 응집도.

---

# 📌 응집도 순서 정리

낮음 → 높음

**우연적 → 논리적 → 시간적 → 절차적 → 통신적 → 순차적 → 기능적**

암기팁:  
**우논시절통순기**

---

# 🎯 정답인 이유

응집도가 높다는 것은  
**한 모듈이 하나의 책임에 집중하고 있다는 뜻**이야.

그래서 결과적으로:

- 구조가 명확해지고
- 이해가 쉬워지고
- 테스트가 편해지고
- 변경 영향이 줄어들고
- 재사용성이 높아져

즉, **소프트웨어 품질이 좋아진다.**

---

# 📌 결합도(Coupling)란?

결합도는 **모듈과 모듈 사이가 얼마나 강하게 연결되어 있는가**를 의미해.

쉽게 말하면,

- 한 모듈이 다른 모듈에 거의 의존하지 않으면 결합도가 낮음
- 한 모듈이 다른 모듈 내부까지 알아야 하면 결합도가 높음

즉,  
**“모듈끼리 얼마나 얽혀 있느냐”**를 보는 개념이야.

---

## ✅ 결합도가 낮은 것이 왜 좋은가?

결합도가 낮으면:

- 한 모듈 수정 시 다른 모듈 영향이 적음
- 독립적인 개발 가능
- 오류 전파가 적음
- 재사용 쉬움
- 유지보수 쉬움

반대로 결합도가 높으면:

- 한 곳 수정했는데 여러 곳이 깨짐
- 테스트가 어려움
- 구조가 복잡해짐

---

# 📌 결합도 종류

시험에서는 보통 **높은 것 → 낮은 것** 순서로 외워.

## 1) 내용 결합도 (Content Coupling)

👉 **한 모듈이 다른 모듈의 내부 내용까지 직접 참조하거나 수정**

예:
- A 모듈이 B 모듈의 내부 변수 직접 변경
- A가 B의 내부 로직으로 직접 점프

### 특징
- 가장 강한 결합
- 독립성 거의 없음
- 최악의 결합도

### 시험 포인트
**“다른 모듈 내부 직접 참조”**,  
**“내부 데이터 수정”**  
이면 내용 결합도.

---

## 2) 공통 결합도 (Common Coupling)

👉 **여러 모듈이 전역 변수를 함께 사용하는 상태**

예:
- 여러 함수가 하나의 전역 변수 `count`를 같이 사용

### 특징
- 하나 바꾸면 전체에 영향
- 디버깅이 어려움

### 시험 포인트
**“공유 데이터”, “전역 변수”, “공통 영역 사용”**  
이면 공통 결합도.

---

## 3) 외부 결합도 (External Coupling)

👉 **모듈들이 외부 환경이나 외부 장치, 외부 파일 형식 등에 같이 의존하는 상태**

예:
- 여러 모듈이 같은 프린터 장치 사용
- 같은 통신 프로토콜 사용

### 특징
- 외부 환경에 의해 연결됨

### 시험 포인트
**“외부 장치”, “통신 인터페이스”, “외부 파일 형식”**  
이 나오면 외부 결합도.

---

## 4) 제어 결합도 (Control Coupling)

👉 **한 모듈이 다른 모듈의 처리 방식까지 제어하는 정보를 전달**

예:
- `process(mode)`에서 mode 값에 따라 상대 모듈 동작이 달라짐

```c
processData(data, 1); // 1이면 저장, 2이면 삭제
```

### 특징
- 단순 데이터 전달이 아니라
- 상대방의 내부 로직 선택까지 제어함

### 시험 포인트
**“제어 플래그”, “처리 경로를 결정하는 값 전달”**  
이면 제어 결합도.

---

## 5) 스탬프 결합도 (Stamp Coupling)

👉 **필요한 값만 쓰면 되는데 자료구조 전체를 넘기는 상태**

예:
- 회원 이름만 필요하지만 회원 객체 전체 전달

```java
printName(Member member)
```

실제로는 `member.name`만 필요할 수도 있음.

### 특징
- 구조체, 레코드, 객체 전체를 넘김
- 필요한 것보다 큰 단위 전달

### 시험 포인트
**“자료구조 전체 전달”**, **“레코드 전체 전달”**  
이면 스탬프 결합도.

---

## 6) 자료 결합도 (Data Coupling)

👉 **모듈 간에 필요한 데이터만 매개변수로 전달하는 상태**

예:

```java
calculateTax(price, rate)
```

필요한 값만 넘김.

### 특징
- 가장 바람직한 결합
- 모듈 독립성 높음

### 시험 포인트
**“단순 자료 전달”, “필요한 데이터만 전달”**  
이면 자료 결합도.

---

# 📌 결합도 순서 정리

높음 → 낮음

**내용 → 공통 → 외부 → 제어 → 스탬프 → 자료**

암기팁:  
**내공외제스자**

---

# 📌 응집도와 결합도의 관계

이 둘은 항상 같이 나와.

## 좋은 구조
- **응집도 높음**
- **결합도 낮음**

## 나쁜 구조
- **응집도 낮음**
- **결합도 높음**

왜냐하면,

- 모듈 내부는 한 가지 일에 집중해야 하고
- 모듈끼리는 서로 덜 의존해야 하기 때문이야.

---

# 📊 응집도 vs 결합도 비교

| 구분 | 응집도 | 결합도 |
|------|--------|--------|
| 의미 | 모듈 내부 요소 간 관련성 | 모듈 간 의존성 |
| 대상 | 한 모듈 내부 | 모듈과 모듈 사이 |
| 바람직한 방향 | 높을수록 좋음 | 낮을수록 좋음 |
| 품질 영향 | 높을수록 품질 향상 | 낮을수록 품질 향상 |
| 핵심 키워드 | 집중, 단일 기능 | 독립, 최소 의존 |

---

# 🔎 쉽게 이해하는 예시

## 예시 1: 좋은 구조

- `로그인검사모듈`
- `회원조회모듈`
- `결제처리모듈`

각각 자기 기능만 수행하고,  
필요한 값만 서로 주고받음.

👉 응집도 높음 / 결합도 낮음

---

## 예시 2: 나쁜 구조

하나의 모듈이

- 로그인
- 회원가입
- 주문
- 결제
- 게시판
- 통계출력

까지 다 처리하고,

다른 모듈들이 이 모듈 내부 변수까지 직접 참조함.

👉 응집도 낮음 / 결합도 높음

---

# 📌 품질과의 관계

소프트웨어 품질, 특히 구조적 품질은  
응집도와 결합도에 큰 영향을 받는다.

## 응집도 높음
- 이해성 향상
- 변경 용이
- 시험 용이
- 재사용성 향상

## 결합도 낮음
- 영향 범위 감소
- 장애 전파 감소
- 유지보수성 향상
- 독립적 개발 가능

결론:

👉 **응집도는 높을수록 좋고, 결합도는 낮을수록 좋다**  
👉 이것이 **좋은 모듈 설계의 핵심 원칙**이다.

---

# 🔎 헷갈릴 수 있는 오답

## ❌ “비슷한 기능들을 묶었으니 무조건 기능적 응집도다”
아님.

비슷하다고 해서 다 기능적 응집도는 아니야.

- 비슷한 성격만 모음 → 논리적 응집도
- 같은 시점에 수행 → 시간적 응집도
- 진짜 하나의 기능만 수행 → 기능적 응집도

---

## ❌ “객체 전체를 넘기면 자료 결합도다”
아님.

필요한 값만 넘겨야 자료 결합도고,  
객체나 레코드 전체를 넘기면 **스탬프 결합도**야.

---

## ❌ “제어 정보도 데이터니까 자료 결합도다”
아님.

단순 값 전달이 아니라  
상대 모듈의 동작을 결정하는 값이면 **제어 결합도**야.

---

# 📚 추가로 공부해야 할 것 (만약 틀렸다면)

1️⃣ **응집도/결합도 순서 암기**
- 응집도: 우논시절통순기
- 결합도: 내공외제스자

2️⃣ **키워드 구별**
- 내부 / 단일 기능 / 연관성 → 응집도
- 전역변수 / 제어플래그 / 외부장치 / 자료전달 → 결합도

3️⃣ **소프트웨어 설계 원칙과 연결**
- 모듈화
- 정보 은닉
- 추상화
- 독립성 확보

---

# 🧠 실기시험 포인트 정리

✔ **응집도**는 모듈 내부의 관련성  
✔ **결합도**는 모듈 간 의존성  
✔ **응집도는 높을수록 좋다**  
✔ **결합도는 낮을수록 좋다**  
✔ **기능적 응집도**가 가장 좋고, **우연적 응집도**가 가장 나쁨  
✔ **자료 결합도**가 가장 좋고, **내용 결합도**가 가장 나쁨  
✔ 품질 향상 공식은  
**응집도↑ / 결합도↓**
