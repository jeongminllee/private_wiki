## 💬 대화 내용 및 Q&A

### ❓ 질문 (User)
문제
You are one of the people on-call for a high-availability service that offers users to solve programming tasks. As an organized team, you have an on-call schedule specifying who is responsible for the service at which time. A colleague sends you a new schedule, and you want to make sure that everyone has the same amount of on-call time as before, or print any differences.

The on-call schedule is specified with lines of form 
$s_ie_it_i$, where 
$s_i$ and 
$e_i$ represent the start and end offsets of the on-call shift for a teammate 
$t_i$ from some start hour.

Given a sample schedule

0 7 jan
7 14 tomaz
14 20 jure
20 24 jan
24 25 tomaz
25 26 jure
we can see that jan is on-call for the first 7 hours (hour 0, 1, 2, 3, 4, 5, and 6), tomaz for next 7, ... In total, jan is on-call for 11 hours, tomaz for 8 and jure for 7.

입력
The input contains two schedules separated by a horizontal line ------. Each schedule contains one or more lines of form 
$s_ie_i t_i$, where integers 
$s_i$ and 
$e_i$ specify that teammate 
$t_i$ is on-call for hours from 
$s_i$ up to and excluding 
$e_i$. A final line ====== is printed after the second schedule.

출력
Output the differences between two schedules, in form 
$t_i \pm\! d_i$, where 
$d_i$ is the difference between the second and the first schedule for the teammate 
$t_i$. The output should be sorted alphabetically by teammates' names and teammates with no differences should be omitted, otherwise the difference should be printed with a + or a - sign. If no differences are found, print "No differences found." (without the quotes).

제한
For each schedule, the following holds:

 
$s_1 = 0$ 
 
$s_i < e_i$ 
 
$s_{i+1} = e_i$ 
 
$e_i \leq 1000$ 
Name 
$t_i$ will consist of lowercase letters from the English alphabet.
 
$3 \leq |t_i| \leq 20$ 
예제 입력 1 
0 7 jan
7 14 tomaz
14 20 jure
20 24 jan
24 25 tomaz
25 26 jure
------
0 9 tomaz
9 20 jan
20 26 jure
======
예제 출력 1 
jure -1
tomaz +1
예제 입력 2 
0 7 nino
7 14 bgs
14 21 ines
------
0 7 ines
7 14 nino
14 21 bgs
======
예제 출력 2 
No differences found.
예제 입력 3 
0 3 vid
3 6 maks
6 9 janez
------
0 1 vid
1 2 vid
2 3 vid
3 4 maks
4 5 maks
5 6 maks
6 7 janez
7 8 janez
======
예제 출력 3 
janez -1
---
```
from collections import defaultdict
schedules = [[] for _ in range(2)]
d = 0
while True :
    try :
        schedule = input()
        if schedule == "======" :
            break
        if schedule == "------" :
            d = 1
            continue

        schedules[d].append(schedule)

    except :
        break

first = defaultdict(int)
second = defaultdict(int)
for i in range(2) :
    for sche in schedules[i] :
        s, e, name = sche.split()
        if i == 0 :
            first[name] += int(e) - int(s)
        else :
            second[name] += int(e) - int(s)

res = defaultdict(int)
diff_val = 0

for idx, val in first.items() :
    res[idx] = second[idx] - val
    diff_val += abs(second[idx] - val)

ans = list(res.items())
ans.sort()

for a in ans :
    if diff_val == 0 :
        print("No differences found.")
        break

    if a[1] == 0 :
        continue
    elif a[1] > 0 :
        print(f"{a[0]} +{a[1]}")
    else :
        print(f"{a[0]} {a[1]}")
```

## 1. 문제 접근 및 알고리즘 설계 평가

### 핵심 요구사항 정리
- 두 개의 스케줄을 입력으로 받음
- 각 스케줄에서 **이름별 총 근무 시간 합산**
- 두 번째 스케줄 − 첫 번째 스케줄 차이를 계산
- 차이가 있는 사람만 출력
- 이름 사전순 정렬
- 차이가 전혀 없으면 `"No differences found."` 출력

### 접근 방식 평가
- `defaultdict(int)`을 사용해 **이름 → 총 시간** 누적  
  → 문제 요구에 정확히 부합
- 구간 `(e - s)` 계산 방식도 정확
- 스케줄 구간이 연속적이라는 제약을 굳이 활용하지 않아도 되는데, 잘 단순화함

📌 **알고리즘 복잡도**
- 입력 줄 수를 `N`이라 하면  
  - 시간 복잡도: `O(N)`
  - 공간 복잡도: `O(M)` (이름 수)
- 제한(`e_i ≤ 1000`) 대비 충분히 효율적

➡️ **알고리즘 설계 자체는 매우 적절하며 정답 접근입니다.**

## 2. 구현상 문제점 및 개선 포인트

### ① 두 번째 스케줄에만 등장하는 이름 처리 누락 ❌

현재 로직:

```python
for idx, val in first.items():
    res[idx] = second[idx] - val
```

문제:
- **첫 번째 스케줄에 없는 사람**이
- 두 번째 스케줄에만 등장하면
- `res`에 아예 포함되지 않음

📌 문제 조건상 스케줄이 완전히 달라질 수 있으므로, 이는 **논리적 결함**입니다.

#### 예시 (현재 코드 오답)
```
첫 번째: 없음
두 번째: alex 5시간
```

정답:
```
alex +5
```

현재 코드 출력:
```
(아무것도 출력 안 함)
```

✅ **개선 방법**
- 이름의 합집합을 기준으로 처리해야 함

```python
all_names = set(first.keys()) | set(second.keys())
for name in all_names:
    res[name] = second[name] - first[name]
```

---

### ② diff_val 계산 방식이 불필요하게 복잡 ⚠️

```python
diff_val += abs(second[idx] - val)
```

그리고 출력 시:

```python
if diff_val == 0 :
    print("No differences found.")
    break
```

문제점:
- `diff_val`은 루프 이전에 이미 계산 가능
- 현재는 출력 루프 안에서 검사 → 가독성 저하
- 논리 흐름이 자연스럽지 않음

✅ **권장 방식**
```python
non_zero = [(name, diff) for name, diff in res.items() if diff != 0]

if not non_zero:
    print("No differences found.")
else:
    for name, diff in sorted(non_zero):
        ...
```

---

### ③ 출력 제어 흐름 개선 필요 ⚠️

현재 구조:

```python
for a in ans :
    if diff_val == 0 :
        print("No differences found.")
        break
```

문제:
- 루프를 도는 중에 전체 결과 여부를 판단
- 한 번만 출력하면 되는데 루프 내부에 있음
- 유지보수 시 실수 유발 가능

➡️ **결과 판단 → 출력은 분리**하는 것이 바람직

## 3. 스타일 및 코드 품질 평가

### 👍 잘한 점
- 변수명 직관적 (`first`, `second`)
- `defaultdict` 적절한 사용
- 불필요한 정렬/중복 계산 없음
- 입력 파싱 안정적 (`------`, `======` 처리)

### ⚠️ 아쉬운 점
- `except:` 사용 → 너무 광범위  
  (EOFError만 잡는 것이 이상적)
- `diff_val`이라는 전역 상태 사용
- 테스트 케이스 확장 시 취약한 부분 존재
