### 💡 답변 (Assistant)
지금 코드만 보면 `fit_predict(...)` 줄 자체가 문법적으로 문제인 건 아닙니다.  
오히려 **그 전에 데이터 준비 부분**에서 헷갈릴 만한 지점이 있습니다.

가장 먼저 짚을 부분은 이겁니다:

```python
df1 = df
df1[TARGET_NAME] = df1[TARGET_NAME].map({"good":1, "bad":0})
```

이건 **복사본을 만든 게 아니라 같은 DataFrame을 가리키는 별칭**입니다.  
즉 `df1`을 바꾸면 `df`도 같이 바뀝니다. 그래서 아래의 `train_test_split(df, ...)`는 사실상 이미 변환된 타깃을 쓰게 됩니다.

이 자체가 반드시 에러는 아니지만, 코드 의도와 다르게 보일 수 있습니다.

그리고 OpenML의 `credit-g`는 설명상 타깃이 `good` / `bad`인 이진 분류 데이터셋입니다. citeturn197566search2  
LightAutoML에서 `Task('binary')`는 이진 분류 작업을 의미하고 기본 metric은 ROC-AUC입니다. 또한 `fit_predict(train_data, roles=...)` 형태로 DataFrame과 target role을 넘기는 방식이 맞습니다. citeturn183514search5turn183514search1turn183514search4

다만 지금 코드에서 제가 가장 강하게 권하는 수정은 아래 3가지입니다.

### 1) 명시적으로 복사해서 target 변환하기
```python
df = pd.concat([X, y], axis=1).copy()
df[TARGET_NAME] = df[TARGET_NAME].map({"good": 1, "bad": 0})
```

### 2) split도 변환된 `df` 기준으로 하기
지금도 사실상 그렇게 되고 있지만, 코드 가독성상 이렇게 명확히 쓰는 게 좋습니다.

```python
train_data, test_data = train_test_split(
    df,
    test_size=TEST_SIZE,
    stratify=df[TARGET_NAME],
    random_state=RANDOM_STATE
)
```

### 3) report 폴더 이름도 현재 데이터셋에 맞추기
지금은 `credit-g`를 쓰는데 output path는 `australian`으로 되어 있습니다.

```python
RD = ReportDeco(output_path='tabularAutoML_model_report_credit_g')
```

전체적으로 정리하면 이렇게 쓰는 편이 깔끔합니다.

```python

pd.set_option('display.max_columns', None)
pd.set_option('display.max_rows', None)

total_dataset = [
    'australian', 'blood-transfusion-service-center', 'credit-g', 'kc1', 'jasmine',
    'kr-vs-kp', 'sylvine', 'phoneme', 'christine', 'guillermo', 'riccardo',
    'amazon_employee_access', 'nomao', 'bank-marketing', 'adult',
    'kddcup09_appetency', 'apsfailure', 'numerai28.6', 'higgs', 'MiniBooNE',
    'car', 'cnae-9', 'connect-4', 'dilbert', 'fabert', 'fashion-mnist',

dataset = openml.datasets.get_dataset(total_dataset[2])

    target=TARGET_NAME
)

df = pd.concat([X, y], axis=1).copy()
df[TARGET_NAME] = df[TARGET_NAME].map({"good": 1, "bad": 0})

# 혹시 매핑 실패한 값이 있는지 확인
print(df[TARGET_NAME].value_counts(dropna=False))

train_data, test_data = train_test_split(

            'random_state': RANDOM_STATE

    train_data,
```

- `credit-g` 정도 크기면 10-fold도 가능하긴 하지만, 환경에 따라 꽤 오래 걸릴 수 있습니다.

원하시면 제가 다음 답변에서 이 코드를 기준으로 **LightAutoML + OpenML용 디버깅 체크리스트**를 아주 실전적으로 정리해드릴게요.

AssertionError: Pipeline finished with 0 models for some reason.

### 💡 답변 (Assistant)
이 에러는 `fit_predict` 마지막 줄이 문제라기보다, **LightAutoML 내부 후보 모델들이 전부 실패해서 살아남은 모델이 0개가 됐다**는 뜻입니다. GitHub 이슈에서도 같은 AssertionError가 보고되어 있고, 원인은 보통 개별 모델 실패가 누적된 경우입니다. citeturn120225search0turn120225search1

당장 가장 중요한 건 **숨겨진 실제 에러를 보이게 만드는 것**입니다. LightAutoML 문서상 `verbose>=4`면 각 알고리즘별 학습 로그까지 출력됩니다. 지금 `verbose=1`이라 내부 실패 원인이 거의 안 보였을 가능성이 큽니다. citeturn841703search9

먼저 이렇게 바꿔서 다시 돌려보세요.

```python
out_of_fold_predictions = automl_rd.fit_predict(
    train_data,
    roles=roles,
    verbose=4
)
```

## 지금 코드에서 특히 의심되는 지점

### 1) 실제 target 값이 정말 0/1로 잘 바뀌었는지
`Task('binary')`는 이진 분류용이고, 기본 metric은 ROC-AUC입니다. 이때 타깃이 사실상 2클래스여야 합니다. citeturn841703search2turn841703search3

바로 확인:

```python
print(df[TARGET_NAME].dtype)
print(df[TARGET_NAME].value_counts(dropna=False))
print(df[TARGET_NAME].isna().sum())
```

여기서 기대 결과는 대충 이런 형태입니다.

```python
0    ...
1    ...
NaN  0
```

혹시 `NaN`이 생기면 매핑이 일부 실패한 겁니다.  
더 안전하게는 이렇게 쓰세요.

```python
df = pd.concat([X, y], axis=1).copy()
df[TARGET_NAME] = df[TARGET_NAME].replace({"good": 1, "bad": 0}).astype("int8")
```

---

### 2) `df1 = df`는 복사가 아님
이건 에러의 직접 원인일 수도 있고 아닐 수도 있지만, 코드가 헷갈리게 됩니다.

```python
df1 = df
df1[TARGET_NAME] = ...
```

이건 `df1`만 바꾸는 게 아니라 **df도 같이 바뀝니다**.  
그래서 그냥 명시적으로 아래처럼 쓰는 편이 낫습니다.

```python
df = pd.concat([X, y], axis=1).copy()
df[TARGET_NAME] = df[TARGET_NAME].replace({"good": 1, "bad": 0}).astype("int8")
```

---

### 3) CV fold에서 클래스 구성이 깨지는 경우
LightAutoML 이슈 중에는 **5-fold CV에서 어떤 fold의 train/test에 클래스 구성이 달라져서 실패**한 사례도 있습니다. 지금은 `stratify`를 train/test split에만 적용했고, 내부 CV는 `reader_params={'cv': 10}`로 별도로 돕니다. 데이터나 버전에 따라 내부 CV 쪽에서 특정 모델이 실패할 수 있습니다. citeturn120225search1

그래서 먼저 `cv=10`을 줄여서 확인해보는 게 좋습니다.

```python
reader_params = {
    'n_jobs': N_THREADS,
    'cv': 5,
    'random_state': RANDOM_STATE
}
```

## 가장 실전적인 진단 순서

### 1단계: 데이터 검증
```python
print(df.shape)
print(df.dtypes)
print(df[TARGET_NAME].value_counts(dropna=False))
print(df.isna().sum().sort_values(ascending=False).head(20))
```

### 2단계: 최소 구성으로 돌리기
후보 모델을 줄여서 어떤 계열이 죽는지 확인합니다.

```python
automl = TabularAutoML(
    task=Task('binary'),
    timeout=TIMEOUT,
    cpu_limit=N_THREADS,
    reader_params={'n_jobs': N_THREADS, 'cv': 5, 'random_state': RANDOM_STATE},
    general_params={'use_algos': [['lgb']]}
)

oof_pred = automl.fit_predict(train_data, roles=roles, verbose=4)
```

이렇게 해서 돌아가면, 원래 설정에서 다른 모델이 죽었던 겁니다.

문서상 `TabularAutoML`은 여러 레벨/파이프라인으로 모델을 구성하는 preset이라, 특정 알고리즘만 남겨가며 원인 분리가 가능합니다. citeturn841703search10turn841703search11

### 3단계: report 데코레이터 빼고 본체만 돌리기
`ReportDeco`가 원인인 경우는 흔하진 않지만, 디버깅은 단순할수록 좋습니다.

```python
automl = TabularAutoML(
    task=Task('binary'),
    timeout=TIMEOUT,
    cpu_limit=N_THREADS,
    reader_params={'n_jobs': N_THREADS, 'cv': 5, 'random_state': RANDOM_STATE},
    general_params={'use_algos': [['lgb']]}
)

oof_pred = automl.fit_predict(train_data, roles=roles, verbose=4)
```

이게 되면 그 다음에 다시 `ReportDeco`를 씌우면 됩니다.

## 제가 보기엔 가장 가능성 높은 원인 3개

첫째, **타깃 매핑 후 `NaN` 또는 dtype 문제**입니다.  
둘째, **내부 CV에서 일부 fold/class 조합 문제**입니다.  
셋째, **특정 후보 모델 의존성/버전 문제**입니다. GitHub 이슈들에서도 “Probably one or more models failed”는 실제로 개별 모델 실패가 숨어 있는 경우가 많았습니다. citeturn120225search0turn120225search1turn120225search4
