## 💬 대화 내용 및 Q&A

### ❓ 질문 (User)
문제
BOJ의 인기스타, 방송인 권욱제는 통신 회사에 취업했다. 현재 이 통신 회사는 너무나 큰 통신망을 한 지사에서 관리하느라 큰 비용을 지불하고 있었다. 그래서 회사는 최근 IT의 트렌드 중 하나인 '탈중앙화'에 편승하여, 통신망을 분할하도록 결정했다. 그래서 욱제한테 통신망을 분할 할때 발생하는 비용을 분석하도록 지시했다.

현재 회사 망에는 1번부터 N번까지 총 N개의 통신 탑이 존재하며, 통신탑 간의 연결이 M개 존재한다. 이때 회사에서는 총 Q번 통신탑 간의 연결을 제거함으로써 하나의 통신망을 여러 개의 통신망으로 분리하려고 한다. 통신망이란, 통신탑의 연결을 통해 도달 가능한 통신탑들의 집합이다. 통신탑 간의 연결 관계를 제거할 때 드는 비용은 제거한 후 통신망이 두 개로 나누어진다면 나눠진 두 개의 통신망에 속한 통신탑들의 갯수의 곱이 되며, 나누어지지 않을 경우 0이다.



<그림 1>

그림 1을 예시로 할때, 연결 (3, 4)를 제거하면 {1, 2, 3}, {4, 5, 6}으로 분할 되며, 이때 발생하는 비용은 3 × 3 = 9가 된다. 대신 연결 (2, 3)을 제거하면, 망이 나눠지지 않았기에 비용은 0이 된다.

욱제는 회사의 요청에 따라 Q번의 제거를 통해 나오는 비용의 합을 구해야 한다. 하지만 욱제는 회사의 통신망을 이용해 방송하기 바쁘기 때문에 우리가 도와주자.

입력
첫 번째 줄에는 통신탑의 개수인 자연수 N, 통신탑 사이의 연결의 개수인 자연수 M, 통신망 연결 분할 횟수인 자연수 Q가 공백으로 구분되어 주어진다. (1 ≤ N ≤ 100,000, 1 ≤ M ≤ 100,000, 1 ≤ Q ≤ M)

두 번째 줄부터 M개의 줄에 걸쳐 두 개의 자연수 X, Y가 공백으로 구분되어 주어진다. 이는 X 통신탑과 Y 통신탑 사이에 연결이 있음을 뜻한다. (1 ≤ X, Y ≤ N, X ≠ Y)

중복된 연결은 주어지지 않으며, 모든 통신탑은 처음엔 하나의 통신망에 속한다. 조건에 의해 자기 자신과 연결이 있는 통신탑은 없다.

그 다음 줄부터 Q개의 줄에 걸쳐 제거될 연결의 번호인 자연수 A가 주어진다. 이는 A번째로 입력된 (X, Y)의 연결이 제거되었음을 의미한다. (1 ≤ A ≤ M)

이미 제거된 연결은 다시 제거되지 않으며, 제거는 입력 순서대로 진행된다.

출력
첫 번째 줄에 Q개의 연결을 순서대로 제거하는데 드는 비용의 합을 출력한다.

예제 입력 1 
4 4 3
1 2
2 3
3 4
1 4
4
2
3
예제 출력 1 
5
첫 번째로 제거되는 연결은 (1, 4)로, 통신망 {1, 2, 3, 4}가 분리되지 않아 비용이 0이다.

두 번째로 제거되는 연결은 (2, 3)으로, 통신망 {1, 2, 3, 4}가 {1, 2}와 {3, 4}로 분리되어 비용이 2 × 2 = 4이다.

세 번째로 제거되는 연결은 (3, 4)로, 통신망 {3, 4}가 {3}과 {4}로 분리되어 비용이 1 × 1 = 1이다.

결과적으로 총 비용은 0 + 4 + 1 = 5이다.

```

def find(a: int, parent:list[int]) -> int :
    if a != parent[a] :
        parent[a] = find(parent[a], parent)
    return parent[a]

def union(a:int, b:int, parent:list[int]) -> None :
    a = find(a, parent)
    b = find(b, parent)

    if a < b :
        parent[b] = a
        cost[a] += cost[b]
    elif a > b :
        parent[a] = b
        cost[b] += cost[a]

def main() :
    """
    N 개의 통신탑, M개의 연결, Q번 통신탑 간의 연결을 제거함으로써 여러 망으로 분리
    """
    global cost
    N, M, Q = map(int, input().split())
    edges = [list(map(int, input().split())) for _ in range(M)]

    tmp = [0] * M
    cut = []

    parent = [i for i in range(N+1)]
    cost = [1 for _ in range(N+1)]

    for _ in range(Q) :
        K = int(input()) - 1
        cut.append(K)
        tmp[K] = 1

    for i in range(M) :
        if not tmp[i] :
            x, y = edges[i]
            if find(x, parent) != find(y, parent) :
                union(x, y, parent)

    res = 0

    for i in range(Q-1, -1, -1) :
        x, y = edges[cut[i]]
        if find(x, parent) != find(y, parent) :
            res += cost[find(x, parent)] * cost[find(y, parent)]
            union(x, y, parent)

    return res

if __name__ == "__main__" :
    print(main())
```
상세하게 풀이와 분석을 해줘.

### 💡 답변 (Assistant)
먼저 결론부터 말하면,  
**이 문제는 “간선을 순서대로 삭제하면서 생기는 비용의 합”을,  
간선을 “역순으로 다시 붙이면서” DSU(Union-Find)로 계산하는 전형적인 오프라인 동적 연결 문제**야.  

네 코드가 딱 그 풀이를 잘 구현한 상태고, 변수 이름만 살짝 헷갈릴 뿐(특히 `cost`는 “컴포넌트 크기”) 로직은 깔끔해.

## 1. 문제를 DSU 관점에서 다시 보기

### 1) 비용의 정의

어떤 간선 (u, v)을 **제거**했을 때,

- 그 간선이 다리(bridge)라서  
  하나의 통신망이 두 통신망 A, B로 쪼개진다면  
  → 비용 = |A| × |B|

- 다리가 아니라서  
  통신망 개수가 그대로라면  
  → 비용 = 0

즉 “그 간선이 삭제 시점에 **서로 다른 두 컴포넌트를 연결하는 역할을 하고 있었냐**”가 포인트야.

---

### 2) 왜 정방향(삭제 순서대로)으로 풀기 힘든가?

삭제를 순서대로 시뮬레이션 하려면:

- 어떤 간선을 제거할 때마다
  - 그 간선이 다리인지 판별하고
  - 나뉘는 두 컴포넌트의 크기를 알아야 함

하지만 DSU는

- **간선을 “추가”하며** 컴포넌트들을 합치는 데 최적화되어 있고
- **간선을 “삭제”하면서”** 컴포넌트를 나누는 연산은 직접 지원하지 않아

그래서 보통 하는 트릭:

> “삭제를 거꾸로 보면, 간선 추가”가 된다.

---

## 2. 핵심 아이디어: 역순으로 간선 추가하기

문제에서 실제로 일어난 것은:

1. N개의 노드, M개의 간선으로 시작 (처음엔 모두 하나의 통신망이라고 했으니 사실상 연결 그래프)
2. Q개의 간선을 특정 순서로 하나씩 제거

우리가 할 일은:

- “모든 삭제가 끝난 **최종 상태**”에서 시작해서
- 삭제된 간선들을 **역순으로 다시 붙인다**

### 이렇게 보면:

- 어떤 간선 e를 “다시 붙일 때”  
  그 양 끝 정점이 **서로 다른 컴포넌트**에 속해있다면  
  → 그 컴포넌트 크기들의 곱만큼 “과거에 그 간선을 제거할 때” 비용이 발생했었다는 뜻.

- 만약 간선을 붙일 때 이미 같은 컴포넌트라면  
  → 과거에 그 간선을 제거해도 통신망이 안 나뉘었다 = 비용 0

왜냐하면,
- 정방향(삭제)에서 그 간선을 제거한 직후의 두 컴포넌트 구성이  
- 역방향(추가)에서 그 간선을 “붙이기 직전”의 두 컴포넌트 구성과 정확히 같기 때문이야.

그래서 역순 시뮬레이션에서

> 간선을 추가하는 순간, 그 간선의 비용 = 그 때의 두 컴포넌트 크기의 곱

을 그대로 더해주면 된다.

## 3. 코드 구조 한 줄씩 뜯어보기

### 3-1. DSU 기본 함수

```python
def find(a: int, parent:list[int]) -> int :
    if a != parent[a] :
        parent[a] = find(parent[a], parent)
    return parent[a]
```

- **경로 압축**이 들어간 `find` 함수.
- `parent[a]`가 자기 자신이 아니면 재귀로 최상위 루트를 찾고,  
  돌아오는 길에 부모를 바로 루트로 바꿔주는 방식 → 시간복잡도 거의 상수에 수렴.

```python
def union(a:int, b:int, parent:list[int]) -> None :
    a = find(a, parent)
    b = find(b, parent)

    if a < b :
        parent[b] = a
        cost[a] += cost[b]
    elif a > b :
        parent[a] = b
        cost[b] += cost[a]
```

- `a`, `b`를 각각 루트로 만든 뒤,
- 루트 번호가 작은 쪽으로 합치는 “임의의 규칙” 사용 (랭크 기반은 아니지만, 경로 압축 덕분에 괜찮음)
- **중요 포인트**:  
  `cost[root]` 배열이 “그 루트가 대표하는 컴포넌트의 크기(노드 수)”를 저장한다.
  - 두 컴포넌트를 합칠 때 `cost[새 루트] += cost[합쳐지는 루트]`로 크기를 갱신.

여기서 `cost`는 전역 변수로 잡혀 있어서, `union`에서 바로 사용 가능.

---

### 3-2. 입력 및 초기 세팅

```python
N, M, Q = map(int, input().split())
edges = [list(map(int, input().split())) for _ in range(M)]

tmp = [0] * M
cut = []

parent = [i for i in range(N+1)]
cost = [1 for _ in range(N+1)]
```

- `edges[i] = [x, y]` 는 `i`번째 간선 (0-based)
- `tmp[i]` :
  - 0 : 아직 삭제되지 않은 간선
  - 1 : 삭제될 간선
- `cut` : 실제로 삭제되는 간선들의 “인덱스 목록” (0-based로 저장)
- `parent[i] = i` : 각각이 자기 자신이 루트
- `cost[i] = 1` : 처음엔 각 노드가 크기 1짜리 컴포넌트

---

### 3-3. 삭제될 간선 정보 입력

```python
for _ in range(Q) :
    K = int(input()) - 1
    cut.append(K)
    tmp[K] = 1
```

- 입력에서 `K`는 1-based 간선 번호이므로 `-1` 해서 0-based로 맞춘다.
- `cut`에 삭제되는 순서대로 저장.
- 동시에 `tmp[K] = 1` 로 표시 → 이 간선은 “최종 상태에서 빠져 있는 간선”이라는 뜻.

---

### 3-4. “모든 삭제가 끝난 이후”의 그래프 구성

```python
for i in range(M) :
    if not tmp[i] :
        x, y = edges[i]
        if find(x, parent) != find(y, parent) :
            union(x, y, parent)
```

- `tmp[i] == 0` 인 간선만 사용 → **한 번도 삭제되지 않은 간선들**
- 이 간선들로 **최종 상태의 통신망**을 DSU로 구성한다.
- 동일한 컴포넌트에 속하지 않는 두 정점에 대해서만 Union 수행.

이 시점에서:

> parent / cost 배열은 “Q번의 간선 삭제가 모두 끝난 뒤”의 컴포넌트 구성과 크기를 반영.

---

### 3-5. 삭제를 역순으로 되돌리며 비용 계산

```python
res = 0

for i in range(Q-1, -1, -1) :
    x, y = edges[cut[i]]
    if find(x, parent) != find(y, parent) :
        res += cost[find(x, parent)] * cost[find(y, parent)]
        union(x, y, parent)
```

- `cut`에는 실제 삭제 순서대로 인덱스가 들어 있음.
- 우리는 이를 **역순으로** 순회:
  - `i = Q-1` → 마지막 삭제된 간선을 맨 처음 다시 붙임
  - `i = 0` → 처음 삭제된 간선을 맨 마지막에 붙임

#### 각 단계에서 하는 일

1. `edges[cut[i]]` : 지금 다시 붙일 간선 (x, y)

2. `if find(x) != find(y)`  
   - 두 정점이 다른 컴포넌트에 있다면,
     - 과거에 이 간선을 삭제했을 때 실제로 통신망이 둘로 나뉘었다는 뜻.
     - 따라서 그 때의 비용은
       ```python
       cost[find(x)] * cost[find(y)]
       ```
       이다. (각각이 현재 컴포넌트의 크기이므로)

   - 분해 시점 ↔ 합치는 시점의 컴포넌트 구성이 대응되므로,  
     이 값이 바로 “그 간선을 삭제했을 때의 비용”이 된다.

3. 비용 더하기
   ```python
   res += cost[find(x, parent)] * cost[find(y, parent)]
   ```

4. 두 컴포넌트를 실제로 합치기
   ```python
   union(x, y, parent)
   ```

- 만약 `find(x) == find(y)`라면
  - 이미 같은 컴포넌트 → 과거에 삭제해도 구조 변화 없음 → 비용 0
  - 따라서 그냥 넘김 (union도 안 함)

---

### 3-6. 최종 출력

```python
return res

if __name__ == "__main__" :
    print(main())
```

- 역순으로 모두 복원하면서 얻은 `res`가  
  정방향(삭제 순서대로) 진행했을 때 발생한 전체 비용의 합.

## 4. 예제 입력으로 직접 추적해 보기

예제:

```text
4 4 3
1 2
2 3
3 4
1 4
4
2
3
```

- N = 4, M = 4, Q = 3
- 간선 목록 (0-based 인덱스):
  - edges[0] = (1, 2)
  - edges[1] = (2, 3)
  - edges[2] = (3, 4)
  - edges[3] = (1, 4)
- 삭제되는 간선 번호 (1-based):
  - 4, 2, 3  → 0-based로 3, 1, 2

#### 1) tmp, cut 세팅

- cut = [3, 1, 2]
- tmp = [0, 1, 1, 1]  (1이면 삭제될 간선)

#### 2) 최종 상태 그래프 생성

- tmp[i] == 0인 간선은 i = 0 뿐 → edges[0] = (1, 2)만 남음

→ 최종 상태 컴포넌트:
- {1, 2}, {3}, {4}

각 컴포넌트 크기:
- cost[find(1)] = 2
- cost[find(3)] = 1
- cost[find(4)] = 1

#### 3) 역순으로 간선 복원

cut 역순: [2, 1, 3]

1. i = 2 → cut[2] = 2 → 간선 (3, 4)
   - find(3) = 3, find(4) = 4 (서로 다른 컴포넌트)
   - 비용 += 1 × 1 = 1
   - union(3, 4) → {3, 4} (size = 2)

2. i = 1 → cut[1] = 1 → 간선 (2, 3)
   - find(2) = 1 (1-2 묶여 있음)
   - find(3) = 3 (3-4 묶여 있음)
   - 비용 += 2 × 2 = 4 → 누적 비용 = 5
   - union(2, 3) → {1, 2, 3, 4} (size = 4)

3. i = 0 → cut[0] = 3 → 간선 (1, 4)
   - find(1) = 1, find(4) = 1 (이미 같은 컴포넌트)
   - 비용 += 0
   - union 안 함

최종 `res = 5`, 예제 출력과 일치.

- 이 5라는 값은 정방향에서의
  - (1,4) 제거 → 0
  - (2,3) 제거 → 2 × 2 = 4
  - (3,4) 제거 → 1 × 1 = 1  
  의 합 0 + 4 + 1 과 정확히 같다.

## 5. 시간 복잡도 & 구현 포인트

- `find` + `union`은 경로 압축 덕에 **거의 O(1)** (엄밀하게는 아커만 역함수 α(N))
- 전체 연산:
  - 초기 부모 설정: O(N)
  - 간선 M개 중 삭제 안 되는 것 union: O(M α(N))
  - 삭제되는 간선 Q개 역순 처리: O(Q α(N))
- 따라서 전체: **O((M + Q) α(N))**  
  (N, M, Q ≤ 100,000에 충분히 여유 있음)

구현상 포인트 몇 가지:

1. **배열 크기**
   - 노드 번호가 1부터 N이므로 `parent`와 `cost`를 `N+1` 크기로 선언한 것 ✔️

2. **정수 범위**
   - 최악의 경우 비용이 매우 커질 수 있으나, Python은 BigInt라 괜찮음.
   - C++라면 반드시 `long long` 사용해야 함.

3. **미세 최적화**
   - 이 부분에서 `find`를 두 번 호출하고 있는데:
     ```python
     if find(x, parent) != find(y, parent) :
         res += cost[find(x, parent)] * cost[find(y, parent)]
         union(x, y, parent)
     ```
   - 약간 더 깔끔하게 하려면:
     ```python
     rx = find(x, parent)
     ry = find(y, parent)
     if rx != ry:
         res += cost[rx] * cost[ry]
         union(rx, ry, parent)  # union이 루트를 받아도 되게 약간 수정
     ```
     이렇게 해서 `find` 호출 수를 줄일 수 있어.  
     하지만 현재 코드도 충분히 빠른 수준이야.

## 6. 요약

- **정방향(삭제 순서)**으로 풀기 어려운 이유:  
  DSU는 “삭제”를 직접 지원하지 않아서, 매 삭제마다 컴포넌트를 나누는 연산이 비싸다.
- 그래서 **역방향(삭제를 취소)**으로 시뮬레이션:
  - 최종 상태에서 **삭제되지 않은 간선만**으로 DSU 구성
  - 삭제된 간선을 **역순으로 하나씩 다시 붙이면서**,  
    - 두 컴포넌트의 루트가 다를 때만
      - 비용 += (각 컴포넌트 크기 곱)
      - 두 컴포넌트 union
- 이때 쓰인 `cost` 배열은 “각 컴포넌트(루트)의 노드 수”를 들고 있고,  
  union 할 때 두 컴포넌트의 크기를 합쳐서 관리.

전체적으로 **풀이 아이디어도 정확하고, 코드 구현도 올바른 DSU 역순 풀이**야.  
원하면 이걸 C++로 옮긴 버전이나, `union` 최적화 버전도 같이 만들어줄게.

## 1. 문제 시나리오 정리 (예제 기준)

### 1) 노드와 간선 번호

노드: `1, 2, 3, 4`

간선(입력 순서, 1-based 번호):

- **1번**: (1 — 2)
- **2번**: (2 — 3)
- **3번**: (3 — 4)
- **4번**: (1 — 4)

삭제 순서 (입력으로 주어짐):

- 4
- 2
- 3  

👉 0-based 기준으로는 `3, 1, 2`

---

## 2. 전체 알고리즘 흐름 “그림”

**큰 흐름을 그림처럼 그리면:**

```text
[초기 상태: 모든 간선 존재]   (문제 상으로는 이미 연결 그래프)

입력: 삭제될 간선들의 번호 Q개

1단계) 어떤 간선이 삭제될지 표시(tmp, cut)
        ↓
2단계) "이미 삭제된 간선"을 빼고
       나머지 간선들로만 DSU 구성
       → 이게 "모든 삭제가 끝난 후"의 최종 상태
        ↓
3단계) 삭제된 간선들을 '역순'으로 하나씩 다시 붙임
        ↓
      각 단계에서:
        - 이어지는 두 컴포넌트의 크기 × 크기를
          그 간선을 삭제했을 때의 비용으로 더함
        - 두 컴포넌트 union
        ↓
4단계) 누적된 비용(res)을 출력
```

---

## 3. 2단계: “모든 삭제가 끝난 후” 상태 도식화

### 3-1. 삭제될 간선 표시(tmp, cut)

| 간선 인덱스(i, 0-based) | 실제 간선(1-based) | 연결 (u, v) | 삭제 여부(tmp[i]) |
|-------------------------|--------------------|-------------|-------------------|
| 0                       | 1                  | (1, 2)      | 0 (삭제 안 됨)    |
| 1                       | 2                  | (2, 3)      | 1 (삭제됨)        |
| 2                       | 3                  | (3, 4)      | 1 (삭제됨)        |
| 3                       | 4                  | (1, 4)      | 1 (삭제됨)        |

- `cut = [3, 1, 2]`  (삭제 순서대로 간선 인덱스 저장)

### 3-2. 최종 상태에서 남는 간선만으로 DSU 구성

`tmp[i] == 0`인 간선:  
→ **i = 0** 하나뿐 → `(1, 2)`만 존재

초기:

```text
parent = [0, 1, 2, 3, 4]     # (0번은 버리는 자리)
cost   = [0, 1, 1, 1, 1]     # 각 노드는 크기 1짜리 컴포넌트
```

간선 (1, 2) 처리:

- find(1) = 1, find(2) = 2 → 서로 다른 컴포넌트
- union(1, 2) → (1이 루트가 된다고 가정)

```text
parent = [0, 1, 1, 3, 4]
cost   = [0, 2, 1, 1, 1]   # 루트 1의 컴포넌트 크기 = 2
```

**최종 상태(모든 삭제 후)**

컴포넌트 그림으로 그리면:

```text
{1, 2}      {3}      {4}

(1) - (2)   (3)      (4)
```

---

## 4. 3단계: 삭제를 역순으로 되돌리는 과정 도식화

이제 `cut`을 **역순**으로 돈다.

```text
cut = [3, 1, 2]  →  역순: [2, 1, 3]
```

| 역순 단계 | i 값 | cut[i] | 다시 붙일 간선 | 비고          |
|-----------|------|--------|----------------|---------------|
| 1         | 2    | 2      | (3, 4)         | 마지막에 삭제 |
| 2         | 1    | 1      | (2, 3)         | 두 번째 삭제  |
| 3         | 0    | 3      | (1, 4)         | 처음 삭제     |

이제 **각 단계마다 DSU 상태와 비용을 표로 그려볼게.**

---

### 🔵 Step 1: 간선 (3, 4) 복원

현재 컴포넌트:

```text
{1, 2}      {3}      {4}

parent = [0, 1, 1, 3, 4]
cost   = [0, 2, 1, 1, 1]
```

- 간선: `edges[cut[2]] = edges[2] = (3, 4)`

1. 루트 찾기

```text
rx = find(3) = 3   (size = cost[3] = 1)
ry = find(4) = 4   (size = cost[4] = 1)
```

2. 다른 컴포넌트이므로 → 과거에 삭제했을 때 분리되었음

> 이 간선을 삭제했을 때 비용 = 1 × 1 = 1

3. 누적 비용 `res += 1` → `res = 1`

4. union(3, 4)

```text
parent = [0, 1, 1, 3, 3]    # 3이 루트가 되었다고 가정
cost   = [0, 2, 1, 2, 1]    # 루트 3의 크기 = 2 (3, 4)
```

그림으로 보면:

```text
{1, 2}      {3, 4}

(1) - (2)   (3) - (4)
```

---

### 🟢 Step 2: 간선 (2, 3) 복원

현재 컴포넌트:

```text
{1, 2}      {3, 4}

parent = [0, 1, 1, 3, 3]
cost   = [0, 2, 1, 2, 1]
```

- 간선: `edges[cut[1]] = edges[1] = (2, 3)`

1. 루트 찾기

```text
rx = find(2) = find(1) = 1       (size = cost[1] = 2)
ry = find(3) = 3                 (size = cost[3] = 2)
```

2. 다른 컴포넌트 → 과거에 삭제했을 때 분리됨

> 이 간선을 삭제했을 때 비용 = 2 × 2 = 4

3. 누적 비용 `res += 4` → `res = 1 + 4 = 5`

4. union(2, 3)

```text
parent = [0, 1, 1, 1, 3]  → 경로 압축 후 보면 모두 루트 1로…
cost   = [0, 4, 1, 2, 1]  → 루트 1의 크기 = 4 (1,2,3,4 전체)
```

그림으로 보면:

```text
{1, 2, 3, 4}

(1) - (2) - (3) - (4)
```

(정확한 모양은 DSU 상관없이, “하나의 컴포넌트”라는 게 핵심)

---

### 🟣 Step 3: 간선 (1, 4) 복원

현재 컴포넌트:

```text
{1, 2, 3, 4}  전체 하나

parent = [0, 1, 1, 1, 1]
cost   = [0, 4, 1, 2, 1]
```

- 간선: `edges[cut[0]] = edges[3] = (1, 4)`

1. 루트 찾기

```text
rx = find(1) = 1
ry = find(4) = 1     # 이미 같은 루트
```

2. 같은 컴포넌트 → 과거에 이 간선을 삭제해도 통신망이 안 나뉨 → 비용 0

3. `res` 변화 없음 → 여전히 `res = 5`

4. union 수행 안 함

## 5. 전체 “역순 복원” 과정 요약 표

마지막으로, 위 내용을 한 번에 보이도록 테이블로 정리하면:

| 역순 단계 | 복원 간선 | rx = find(x) | size(rx) | ry = find(y) | size(ry) | 이 단계에서 더한 비용 | 누적 비용(res) | 복원 후 컴포넌트                  |
|----------|-----------|--------------|----------|--------------|----------|------------------------|----------------|------------------------------------|
| 1        | (3, 4)    | 3            | 1        | 4            | 1        | 1 × 1 = 1              | 1              | {1,2}, {3,4}                      |
| 2        | (2, 3)    | 1            | 2        | 3            | 2        | 2 × 2 = 4              | 5              | {1,2,3,4}                         |
| 3        | (1, 4)    | 1            | 4        | 1            | 4        | (같은 컴포넌트 → 0)    | 5              | {1,2,3,4} (변화 없음)             |

이렇게 보면 **각 간선이 “삭제될 당시”의 비용이, “역순으로 다시 붙일 때”의 컴포넌트 크기 곱으로 그대로 나타난다**는 게 한눈에 보일 거야.

- 이 과정을 **일반적인 N, M, Q에 대해 흐름도(Flowchart) 형태**로도 그려줄 수 있고,
- 아니면 **C++/Java 버전 코드**를 도식과 함께 맞춰서 정리해줄 수도 있어.

### 💡 답변 (Assistant)
아래처럼 **전체 알고리즘 흐름을 flowchart(순서도) 형태**로 그려볼게.  
Mermaid 문법이라, 지원되는 뷰어에서는 그림처럼 보이고, 아니어도 텍스트로 흐름은 읽을 수 있어.

```mermaid
flowchart TD

    %% 시작
    A[Start] --> B[입력 N, M, Q]
    B --> C[간선 M개 입력 → edges[0..M-1]]
    C --> D[Q개 삭제될 간선 번호 입력<br/>→ 1-based를 0-based로 바꿔 cut에 push]
    D --> E[tmp 배열에<br/>삭제될 간선 표시(tmp[idx] = 1)]

    %% DSU 초기화
    E --> F[parent[i] = i (i=1..N)]
    F --> G[cost[i] = 1 (각 노드 크기 1로 시작)]

    %% 최종 상태 그래프 구성
    G --> H[for i in 0..M-1<br/> if tmp[i] == 0 인 간선만 처리]
    H --> I[간선 (x, y) = edges[i]]
    I --> J{find(x) == find(y)?}
    J -- Yes --> H
    J -- No --> K[union(x, y)<br/>→ parent 갱신, cost[루트] += cost[다른 루트]]
    K --> H
    H --> L[모든 i 처리 완료<br/>→ 현재 DSU는<br/>“모든 삭제 후” 상태]

    %% 역순으로 삭제 복원
    L --> M[res = 0 초기화]
    M --> N[for i = Q-1 down to 0<br/>삭제된 간선을 역순 복원]

    N --> O[(x, y) = edges[cut[i]]]
    O --> P[rx = find(x), ry = find(y)]
    P --> Q{rx == ry?}
    Q -- Yes --> R[같은 컴포넌트 → 비용 0<br/>union 안 하고 다음 i로] --> N
    Q -- No --> S[비용 증가:<br/>res += cost[rx] * cost[ry]]
    S --> T[union(rx, ry)<br/>→ 두 컴포넌트 병합]
    T --> N

    N -->|모든 i 처리 완료| U[출력: res]
    U --> V[End]
```

---

### 간단 정리

- **윗부분**:  
  - 입력 → 삭제될 간선 표시(tmp, cut)  
  - 삭제되지 않은 간선들만으로 DSU 구성 → “모든 삭제가 끝난 상태” 만들기

- **아랫부분(핵심)**:  
  - `cut`을 **역순**으로 돌면서 간선을 하나씩 다시 붙임  
  - 이때 두 컴포넌트 루트가 다르면  
    - `res += (각 컴포넌트 크기 곱)`  
    - `union`으로 병합  
  - 같으면 아무 일도 안 하고 다음으로

- 마지막에 `res`가 곧 **정방향(삭제 순서대로)으로 진행했을 때의 총 비용 합**이 된다.

필요하면 이 flowchart를 기준으로 **주석 달린 의사코드/파이썬 재정리본**도 같이 만들어 줄게.
