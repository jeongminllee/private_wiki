좋다 👍 이 문제는 **CPU 스케줄링 핵심 개념 (SJF vs SRTF)**을 정확히 구분하는 문제야. 실기에서 굉장히 자주 나오는 유형이다.

# ✅ 문제 분석

제시된 설명의 핵심 포인트는 다음과 같습니다.

- CPU 실행 시간이 **짧은 프로세스 우선**
- **선점형 / 비선점형 모두 가능**
- 선점형에서는 **더 짧은 작업이 들어오면 기존 작업 중단**

→ 핵심 키워드:

- 실행 시간 기준
- 짧은 작업 우선
- 선점 / 비선점
- 도착 시 선점 발생

---

# 🎯 정답

👉 (1) SJF (Shortest Job First)  
👉 (2) SRT (Shortest Remaining Time First, SRTF)

---

# 📌 정답인 이유

## 1️⃣ SJF (Shortest Job First)

| 구분 | 설명 |
|------|------|
| 기준 | CPU 실행 시간 (Burst Time) |
| 특징 | 가장 짧은 작업을 먼저 실행 |
| 방식 | 비선점형 + 선점형 둘 다 존재 |

👉 문제에서  
"CPU 실행 시간이 짧은 프로세스를 우선 처리"  
→ **SJF 정의 그대로**

---

## 2️⃣ SRT (Shortest Remaining Time)

| 구분 | 설명 |
|------|------|
| 기준 | 남은 실행 시간 |
| 특징 | 더 짧은 작업이 오면 현재 작업 중단 |
| 방식 | 선점형 |

👉 문제에서  
"실행 중 더 짧은 프로세스가 오면 CPU 선점"  
→ **SRTF 특징 그대로**

---

# 🔎 헷갈릴 수 있는 오답

## ❌ FCFS (First Come First Served)
- 먼저 온 순서대로 처리
- 실행 시간 고려 X

## ❌ Priority Scheduling
- 우선순위 기준
- 실행 시간 기준 아님

## ❌ Round Robin
- 시간 할당량 기반
- 짧은 작업 우선 개념 없음

---

# 📚 추가로 공부해야 할 것 (중요)

## 1️⃣ SJF의 치명적 단점

👉 ⭐ 반드시 암기

- **기아 현상 (Starvation)**
  - 짧은 작업만 계속 실행됨
  - 긴 작업은 영원히 대기 가능

---

## 2️⃣ 해결 방법 → Aging

- 오래 기다린 프로세스의 우선순위 증가
- 기아 현상 방지

---

## 3️⃣ 평균 대기 시간 관점

👉 ⭐ 시험 포인트

- SJF / SRTF는  
👉 **평균 대기 시간 최소화 알고리즘**

---

## 4️⃣ 선점형 vs 비선점형 비교

| 구분 | 선점형 | 비선점형 |
|------|--------|----------|
| CPU 뺏기 | 가능 | 불가능 |
| 응답성 | 좋음 | 나쁨 |
| 오버헤드 | 큼 | 작음 |

---

## 5️⃣ SJF vs SRTF 핵심 차이 (시험 핵심)

| 구분 | SJF | SRTF |
|------|-----|------|
| 방식 | 비선점형 | 선점형 |
| 기준 | 전체 실행 시간 | 남은 실행 시간 |
| 중단 | 없음 | 있음 |

---

# 🧠 실기시험 포인트 정리

✔ "짧은 작업 우선" → SJF  
✔ "선점 발생" → SRTF  
✔ "남은 시간 기준" → SRTF  
✔ "평균 대기시간 최소" → SJF 계열  
✔ "기아 현상" → SJF 단점

### ❓ 질문 (User)
# 20. 호스트 주소가 223.13.234.132이고, 서브넷 마스크는 255.255.255.192일 때, 괄호( ) 안에 들어갈 값을 쓰시오.

- 이 호스트의 네트워크 주소는 223.13.234.( ① )이다.
- 이 네트워크 주소에서 사용 가능한 호스트 주소의 개수는 네트워크 주소와 브로드캐스트 주소를 뺀 ( ② )개이다.
---
이 문제는 나는 1. 호스트주소 and 서브넷마스크, 2. 호스트주소 or not(서브넷마스크) 로 해결을 했는데 풀이 보니까 2번이 서브넷의 0의 개수로 풀더라고. 관련된 공부를 알려줘

### 💡 답변 (Assistant)
좋다 👍 이 문제는 **IP 주소 + 서브넷 마스크 + 호스트 수 계산**을 정확히 이해했는지 묻는 전형적인 문제야.  
네가 푼 방식도 맞고, 풀이 방식도 맞기 때문에 **두 가지 접근을 연결해서 정리하는 게 핵심**이다.

---

# ✅ 문제 분석

주어진 정보:

- IP 주소: **223.13.234.132**
- 서브넷 마스크: **255.255.255.192**

→ 핵심 키워드:

- 네트워크 주소 계산
- 서브넷 마스크
- 호스트 수 계산
- AND 연산 / 비트 개수

---

# 🎯 정답

👉 ① **128**  
👉 ② **62**

---

# 📌 정답인 이유

## 1️⃣ 네트워크 주소 구하기 (AND 연산)

IP와 서브넷 마스크를 AND 연산

```
IP 주소        : 223.13.234.132 → 10000100
서브넷 마스크   : 255.255.255.192 → 11000000
-----------------------------------------
AND 결과        :                → 10000000 (128)
```

👉 네트워크 주소:  
**223.13.234.128**

---

## 2️⃣ 호스트 수 계산 (0의 개수 활용)

서브넷 마스크:

```
255.255.255.192 → 11111111.11111111.11111111.11000000
```

👉 마지막 옥텟에서 **0이 6개**

→ 호스트 비트 수 = 6

```
호스트 수 = 2^6 - 2 = 64 - 2 = 62
```

👉 정답: **62**

---

# 🔎 네가 푼 방식 vs 풀이 방식 (중요 비교)

## ✔ 네 방식

- 네트워크 주소 → AND
- 브로드캐스트 → OR + NOT

👉 **정석 네트워크 계산 방식 (실무/이론 둘 다 중요)**

---

## ✔ 풀이 방식

- 0의 개수 세기
- 2^n - 2

👉 **시험 최적화 방식 (빠르게 풀기)**

---

# 📚 추가로 공부해야 할 것 (핵심)

## 1️⃣ 서브넷 마스크 → 블록 크기 계산 ⭐

👉 매우 중요 (실기 단골)

```
블록 크기 = 256 - 서브넷 값
```

여기서는:

```
256 - 192 = 64
```

👉 네트워크 범위:

- 0 ~ 63
- 64 ~ 127
- 128 ~ 191 ← 포함됨
- 192 ~ 255

👉 132는 **128~191 구간**

→ 네트워크 주소 = **128**

---

## 2️⃣ 브로드캐스트 주소 구하기

👉 해당 블록의 마지막 값

```
128 ~ 191 → 브로드캐스트 = 191
```

---

## 3️⃣ 전체 구조 정리

| 구분 | 값 |
|------|----|
| 네트워크 주소 | 128 |
| 브로드캐스트 | 191 |
| 사용 가능 범위 | 129 ~ 190 |
| 호스트 수 | 62 |

---

## 4️⃣ 자주 출제되는 개념

### ✔ 서브넷 마스크 → CIDR 변환

```
255.255.255.192 → /26
```

👉 이유:
- 1의 개수 = 26개

---

### ✔ 호스트 수 공식

```
2^n - 2
```

👉 왜 -2?

- 네트워크 주소
- 브로드캐스트 주소

---

## 5️⃣ 빠르게 푸는 시험 스킬 ⭐

1️⃣ 마지막 옥텟만 본다  
2️⃣ 블록 크기 계산 (256 - 값)  
3️⃣ 해당 구간 찾기  
4️⃣ 호스트 수 = 2^n - 2  

---

# 🧠 실기시험 포인트 정리

✔ AND 연산 → 네트워크 주소  
✔ OR + NOT → 브로드캐스트  
✔ 0의 개수 → 호스트 수  
✔ 256 - 값 → 블록 크기  
✔ CIDR 변환 (/26) 자주 출제

# 📌 정답인 이유

## OAuth (Open Authorization)

| 구분 | 설명 |
|------|------|
| 개념 | 제3자에게 권한을 위임하는 기술 |
| 특징 | 비밀번호 공유 없이 접근 허용 |
| 방식 | 토큰 기반 인증 |
| 목적 | 인증(Authentication)이 아닌 **인가(Authorization)** |

---

👉 문제에서 말한

- "비밀번호를 제공하지 않고 접근 권한 부여"  
- "토큰을 이용"  
- "외부 계정 기반 로그인"  

→ **OAuth의 정의 그대로**

---

## ✔ 핵심 구조 이해 (시험 중요)

👉 예시: "구글로 로그인"

1️⃣ 사용자 → 서비스 (로그인 요청)  
2️⃣ 서비스 → 구글 (인증 요청)  
3️⃣ 사용자 → 구글 로그인  
4️⃣ 구글 → 서비스 (Access Token 전달)  
5️⃣ 서비스 → 사용자 로그인 처리  

👉 핵심:  
**비밀번호는 구글만 알고 있음**

# 🔎 헷갈릴 수 있는 오답

## ❌ SSO (Single Sign-On)

| 특징 |
|------|
| 한 번 로그인으로 여러 서비스 이용 |
| 인증(Authentication) 중심 |

👉 차이:
- SSO → "한 번 로그인"
- OAuth → "권한 위임"

---

## ❌ JWT (JSON Web Token)

| 특징 |
|------|
| 토큰 형식 (데이터 구조) |
| 인증 정보 저장 |

👉 차이:
- JWT = **토큰 자체**
- OAuth = **인증/인가 프로토콜**

---

## ❌ Kerberos

- 티켓 기반 인증
- 내부 네트워크 인증 (기업, 도메인 환경)

---

## ❌ OTP

- 1회용 비밀번호
- 2차 인증

---

# 📚 추가로 공부해야 할 것 (핵심)

## 1️⃣ 인증 vs 인가 (시험 초핵심) ⭐

| 구분 | 설명 |
|------|------|
| 인증 (Authentication) | “너 누구야?” |
| 인가 (Authorization) | “뭐 할 수 있어?” |

👉 OAuth = **인가 중심**

---

## 2️⃣ OAuth vs SSO vs JWT 정리 ⭐

| 구분 | OAuth | SSO | JWT |
|------|------|-----|-----|
| 역할 | 권한 위임 | 로그인 통합 | 토큰 |
| 목적 | 인가 | 인증 | 데이터 전달 |
| 특징 | 외부 계정 연동 | 한번 로그인 | JSON 기반 |

---

## 3️⃣ OAuth 2.0 구성 요소

| 요소 | 설명 |
|------|------|
| Resource Owner | 사용자 |
| Client | 서비스 |
| Authorization Server | 인증 서버 |
| Access Token | 접근 권한 |

👉 실기에서 자주 출제됨

---

## 4️⃣ 토큰 기반 인증 흐름 ⭐

- 세션 기반 vs 토큰 기반 차이

| 구분 | 세션 | 토큰 |
|------|------|------|
| 저장 위치 | 서버 | 클라이언트 |
| 확장성 | 낮음 | 높음 |
| 대표 | 로그인 세션 | JWT, OAuth |

---

✔ "토큰 기반" → OAuth

✔ "한 번 로그인" → SSO  
✔ "토큰 구조" → JWT  
✔ "인증 vs 인가" 반드시 구분
