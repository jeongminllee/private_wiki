# 폴더 간 모듈 임포트 문제

> **카테고리**: `Algorithms (알고리즘 & 자료구조)`  
> **원천**: ChatGPT 대화 아카이브 (`raw/notes/Chatgpt_2026-08-02-23-14-23`)  
> **작성일**: 2026-04-10

## 💬 대화 내용 및 Q&A

### 💡 답변 (Assistant)
이건 **Python import resolution (모듈 탐색 경로)** 문제야. 핵심은:

> `folder2/main.py`를 실행하면 **Python은 folder2 기준으로만 경로를 해석**한다는 점이다.

---

## 🔍 현재 구조
```
project_root/
│
├── folder1/
│     └── module1.py
│
└── folder2/
      └── main.py   ← 실행 중
```

---

## ❌ 왜 `import folder1.module1`이 안 되나?

`python folder2/main.py`로 실행하면:

- `sys.path[0]` = `folder2`
- Python은 `folder2` 기준으로만 module을 찾음
- 그런데 `folder1`은 **상위 디렉토리(project_root)에 있음**

👉 즉, Python 입장에서는 `folder1`이 안 보임

---

## ✅ 해결 방법 (실무적으로 중요한 순서대로)

### 1️⃣ 프로젝트 루트 기준으로 실행 (가장 정석)
```bash
cd project_root
python -m folder2.main
```

이렇게 하면:

- Python이 `project_root`를 기준으로 import 수행
- 아래 코드 정상 동작:

```python
import folder1.module1
```

👉 **이게 가장 권장되는 방식 (패키지 구조 유지)**

---

### 2️⃣ PYTHONPATH 설정

#### Linux / Mac
```bash
export PYTHONPATH=/path/to/project_root
python folder2/main.py
```

#### Windows (PowerShell)
```powershell
$env:PYTHONPATH="C:\path\to\project_root"
python folder2/main.py
```

---

### 3️⃣ 코드 내부에서 sys.path 수정 (비추천, but 빠른 해결)

```python
import sys
import os

sys.path.append(os.path.dirname(os.path.dirname(__file__)))

import folder1.module1
```

👉 즉:
- `folder2 → project_root`로 올라가서 path 추가

---

### 4️⃣ 패키지 구조로 만들기 (`__init__.py`)

```
project_root/
│
├── folder1/
│     ├── __init__.py
│     └── module1.py
│
└── folder2/
      ├── __init__.py
      └── main.py
```

👉 이 상태에서 반드시:

```bash
python -m folder2.main
```

---

## ⚠️ 흔한 실수

### ❌ 이렇게 실행하면 안 됨
```bash
cd folder2
python main.py
```

👉 이 경우 import 거의 다 깨짐

---

## 💡 한 줄 요약

> Python은 “현재 실행 위치” 기준이 아니라  
> **“어디서 실행했느냐 (working directory)” 기준으로 import 경로를 잡는다**

---

## 🔧 추천 워크플로우 (너한테 맞는 방식)

너 지금 ML 프로젝트 구조 쓰고 있고 (`src/` 구조도 경험 있음)  
👉 아래 방식이 가장 깔끔:

```bash
project_root 기준에서
python -m folder2.main
```

또는

```bash
uv run python -m folder2.main
```

---

필요하면  
👉 `src/` 기반 패키징 구조 (ml_starter 스타일)로 리팩토링도 같이 잡아줄게.

---

### ❓ 질문 (User)
main 
|
--- folder1
|      --- module1.py
|
--- folder2
        --- main.py
folder2에 있는 main.py를 실행시키고 있어. 모듈이 폴더 1에 있는데 
```
import folder1.module1 
```
로 됐던거 같은데 안되네. 방법을 알려줘.

### ❓ 질문 (User)
안되는데... sys.path.append('../folder1') 도 하고 하는데도 no module 오류가 나네

### 💡 답변 (Assistant)
`sys.path.append('../folder1')`를 넣고도 `import folder1.module1`이 안 되는 건, **추가한 경로가 잘못됐을 가능성**이 가장 커.

핵심은 이거야:

- `import folder1.module1` 을 하려면
- `sys.path` 안에는 **folder1 그 자체**가 아니라
- **folder1의 부모 디렉토리**가 들어 있어야 해

즉 현재 구조가:

```text
project_root/
├─ folder1/
│  └─ module1.py
└─ folder2/
   └─ main.py
```

이라면 `sys.path`에 들어가야 하는 건:

```text
project_root/
```

이지,

```text
project_root/folder1/
```

가 아니야.

---

## 왜 그런가

Python은 `import folder1.module1` 을 보면 이렇게 찾음:

1. `sys.path` 안의 각 경로를 하나씩 봄
2. 그 경로 아래에 `folder1` 폴더가 있는지 찾음
3. 그 안에 `module1.py`가 있는지 찾음

그런데 네가 `../folder1` 을 넣으면 Python은 그 안에서 다시 `folder1` 을 찾으려 해서 결국 이런 느낌이 돼:

```text
project_root/folder1/folder1/module1.py
```

그래서 실패해.

---

## 올바른 방법 1

`main.py` 안에 이렇게 넣어봐.

```python
import sys
import os

BASE_DIR = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
sys.path.append(BASE_DIR)

import folder1.module1
```

여기서 `BASE_DIR` 은 `project_root` 가 돼.

---

## 올바른 방법 2

아예 import를 바꿔서, `folder1` 자체를 path에 넣었으면 이렇게 해야 해:

```python
import sys
sys.path.append('../folder1')

import module1
```

즉,

- `sys.path.append('../folder1')` 이면 `import module1`
- `sys.path.append('..')` 이면 `import folder1.module1`

이 조합이어야 맞아.

---

## 네 경우에 가장 안전한 코드

`folder2/main.py`:

```python
import sys
import os

CURRENT_DIR = os.path.dirname(os.path.abspath(__file__))
PROJECT_ROOT = os.path.dirname(CURRENT_DIR)

if PROJECT_ROOT not in sys.path:
    sys.path.insert(0, PROJECT_ROOT)

import folder1.module1

print("import 성공")
```

---

## 추가로 꼭 확인할 것

### 1. 실제 실행 위치
`../folder1` 는 **파일 위치 기준이 아니라 현재 작업 디렉토리 기준**으로 해석될 수 있어서 헷갈려.

확인용으로 이것도 찍어봐:

```python
import os
print("cwd:", os.getcwd())
print("__file__:", __file__)
```

`sys.path.append('../folder1')` 같은 상대경로는 `cwd` 때문에 꼬이는 경우가 많아. 그래서 `__file__` 기준으로 절대경로 만드는 게 안전해.

---

### 2. 파일 이름 충돌
다음 같은 게 있으면 import 꼬일 수 있어:

- `folder2/folder1.py`
- `folder2/module1.py`
- `folder1.py`

---

### 3. 폴더 이름 오타
실제로 `folder1`, `module1.py` 가 맞는지 확인.

---

### 4. 에러 메시지 종류
에러가 둘 중 뭐냐에 따라 원인이 달라져.

- `No module named 'folder1'`
  - `sys.path` 문제
- `No module named 'folder1.module1'`
  - `folder1` 은 찾았는데 내부 모듈을 못 찾는 문제

---

## 가장 권장하는 실행 방식

`project_root` 에서 실행:

```bash
python -m folder2.main
```

그리고 `main.py` 에서는 그냥:

```python
import folder1.module1
```

이 방식이 제일 안 꼬여.

---

## 바로 점검할 수 있는 최소 예제

`folder2/main.py`

```python
import sys
import os

print("cwd =", os.getcwd())
print("__file__ =", __file__)
print("before =", sys.path[:3])

PROJECT_ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
sys.path.insert(0, PROJECT_ROOT)

print("after =", sys.path[:3])

import folder1.module1
print("성공")
```

이걸 돌렸는데도 안 되면, 그때는 거의 구조 문제야.

지금 뜨는 **정확한 에러 메시지 전체**를 붙여주면 어디서 막히는지 바로 짚어줄 수 있어.
