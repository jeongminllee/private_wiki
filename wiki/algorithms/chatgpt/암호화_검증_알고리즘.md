## 💬 대화 내용 및 Q&A

### 💡 답변 (Assistant)
이 문제는 원래 비밀번호에서 글자 몇 개를 재배열하고, 앞뒤에 임의의 문자들을 추가해서 암호화된 결과물을 만들 수 있는지를 확인하는 문제예요.

**좀 더 자세히 설명하면:**

1. **비밀번호는 알파벳 소문자로만 구성되어 있어요.**

2. **암호화 과정은 크게 세 단계로 이루어져 있어요.**
   - **단계 1: 두 글자끼리 위치를 바꿀 수 있어요.**  
     이 과정을 원하는 만큼 반복할 수 있기 때문에, 사실상 원래 비밀번호의 글자 순서를 아무렇게나 바꿀 수 있다는 뜻이에요.
   - **단계 2: 재배열한 결과물의 앞쪽에 임의의 문자들을 추가할 수 있어요.**  
     이 때 추가하는 문자의 개수는 0개 이상일 수 있어요.
   - **단계 3: 재배열한 결과물의 뒤쪽에 임의의 문자들을 추가할 수 있어요.**  
     역시 추가하는 문자의 개수는 0개 이상이에요.

3. **문제의 핵심은:**  
   주어진 암호화된 결과물 안에, 원래 비밀번호의 글자들을 어떤 순서(즉, 재배열)로 나열한 문자열이 **부분 문자열(subsequence)** 로 들어있는지를 확인하는 거예요.  
   - 다시 말해, 암호화된 결과물이 원래 비밀번호를 글자 순서를 재배열한 결과(=순열)를 **연속된 부분** 또는 **비연속적인 부분**(즉, 삽입된 문자들을 무시하고)으로 포함할 수 있으면 암호화가 올바른 것이에요.

**예시를 들어볼게요:**

- **예제 1:**  
  암호화된 결과물이 `abcdef`이고 원래 비밀번호가 `ecd`인 경우,  
  `ecd`의 재배열 중 하나인 `cde`가 `abcdef` 안에 들어있으므로 결과는 `YES`예요.

- **예제 2:**  
  암호화된 결과물이 `cde`이고 원래 비밀번호가 `ecd`인 경우,  
  여기서도 `ecd`의 재배열인 `cde`가 정확히 암호화된 결과물이므로 `YES`예요.

- **예제 3:**  
  암호화된 결과물이 `abcdef`이고 원래 비밀번호가 `fcd`인 경우,  
  `fcd`를 재배열해서 만들 수 있는 문자열들이 `abcdef` 안에 없으므로 결과는 `NO`예요.

**요약하자면:**  
암호화된 문자열 안에, 원래 비밀번호의 글자들을 임의의 순서로 재배열한 문자열이 **부분 문자열(subsequence)** 형태로 존재하면 "YES", 그렇지 않으면 "NO"라고 판단하면 되는 문제예요.

### ❓ 질문 (User)
문제
새로운 암호화 알고리즘이 개발되었다.

우선, 모든 비밀번호는 항상 알파벳 소문자로만 이루어진다고 가정하자.

암호화 알고리즘은 다음과 같이 진행된다.

비밀번호의 서로 다른 두 글자를 교환한다. 이 과정은 0번 또는 원하는 만큼 얼마든지 할 수 있다.
1번 과정의 결과물 앞부분에 0개 혹은 그 이상의 문자를 삽입한다.
2번 과정의 결과물 뒷부분에 0개 혹은 그 이상의 문자를 삽입한다.
3번 과정의 결과물이 암호화된 비밀번호이다.

청호는 사용하던 비밀번호들을 위 알고리즘대로 다 암호화했다.

하지만 수작업이었던 탓에 실수가 있을 지도 모르기 때문에 프로그램을 작성하여 제대로 암호화했는지 확인해보려 한다.

암호화된 비밀번호와 원래의 비밀번호가 주어지면, 암호화된 비밀번호가 원래의 비밀번호를 위의 알고리즘대로 암호화한 결과물일 수 있는지 혹은 없는지를 알아내 보자.

입력
첫 줄에 테스트 케이스의 수 T가 주어진다. ( 1 ≤ T ≤ 100 )

각 테스트 케이스는 두 줄로 구성된다.

첫 줄엔 암호화된 결과물이 주어진다.

두 번째 줄엔 원래의 비밀번호가 주어진다.

암호화된 비밀번호와 원래의 비밀번호는 1개 이상 10만개 이하의 문자로 이루어져 있으며, 항상 알파벳 소문자만을 포함한다.

암호화된 비밀번호의 길이는 항상 원래 비밀번호의 길이보다 크거나 같다.

출력
각 테스트 케이스마다, 원래의 비밀번호를 문제에서 설명한 알고리즘대로 암호화했을 때 주어진 결과물이 나올 수 있다면 YES를, 그렇지 않다면 NO를 출력한다.

예제 입력 1 
3
abcdef
ecd
cde
ecd
abcdef
fcd
예제 출력 1 
YES
YES
NO

### 💡 답변 (Assistant)
이 문제를 풀기 위한 핵심 아이디어는, 암호화된 문자열 내에 원래 비밀번호의 모든 글자들이 임의의 순서로 연속되어 있는 부분문자열(즉, 원래 비밀번호의 순열)이 존재하는지 확인하는 것입니다.

### 접근 방법

1. **문제 단순화:**  
   - 암호화 알고리즘에서 첫 번째 단계에서 원래 비밀번호의 글자 순서를 임의로 섞을 수 있으므로, 결국 우리가 찾아야 하는 것은 원래 비밀번호의 **순열**입니다.
   - 두 번째와 세 번째 단계에서는 암호화된 문자열의 앞과 뒤에 임의의 문자들이 추가되므로, 실제로는 암호화된 문자열 중 **연속된 한 구간**이 원래 비밀번호의 순열 형태여야 합니다.

2. **슬라이딩 윈도우 기법 사용:**  
   - 암호화된 문자열의 길이를 \( n \), 원래 비밀번호의 길이를 \( m \)라고 할 때, 암호화된 문자열에서 길이 \( m \)인 모든 연속 부분문자열을 살펴봅니다.
   - 각 부분문자열에 대해, 원래 비밀번호와 글자 빈도수가 동일한지 비교합니다. (예: 'abc'와 'cab'는 글자 빈도수가 동일하므로 서로 순열 관계입니다.)

3. **구체적인 단계:**  
   - **타겟 빈도수 계산:** 원래 비밀번호의 각 알파벳이 몇 번 등장하는지 배열이나 해시맵으로 계산합니다.
   - **윈도우 초기화:** 암호화된 문자열의 처음 \( m \)글자에 대해 빈도수를 계산합니다.
   - **윈도우 이동:**  
     - 윈도우를 오른쪽으로 한 칸씩 이동하면서, 새로 들어오는 문자에 대해 빈도수를 증가시키고, 윈도우에서 빠지는 문자에 대해 빈도수를 감소시킵니다.
     - 각 이동 시, 윈도우 내의 빈도수와 타겟 빈도수를 비교합니다.
     - 만약 두 빈도수가 일치하면, 암호화된 문자열 내에 원래 비밀번호의 순열이 존재하는 것이므로 "YES"를 반환할 수 있습니다.

4. **시간 복잡도:**  
   - 이 방법은 각 윈도우마다 \( O(1) \) (알파벳 26개이므로) 비교를 하므로 전체 시간 복잡도는 \( O(n) \)입니다.

### 요약

- **핵심 아이디어:** 암호화된 문자열 내에 원래 비밀번호의 순열(글자 빈도수가 같은 길이 \( m \)의 부분문자열)이 있는지 확인합니다.
- **알고리즘:** 슬라이딩 윈도우와 빈도수 비교를 사용하여 효율적으로 해결할 수 있습니다.

이런 식으로 접근하면 문제를 효율적으로 해결할 수 있습니다.

### 💡 답변 (Assistant)
다음은 파이썬으로 슬라이딩 윈도우 방식을 사용하여 문제를 해결하는 예시 코드입니다.

```python
from collections import Counter
import sys

def is_valid(encrypted, original):
    m = len(original)
    n = len(encrypted)
    
    # 원래 비밀번호의 글자 빈도수 계산
    target_counter = Counter(original)
    
    # 암호화된 문자열 처음 m 길이에 대해 빈도수 계산
    window_counter = Counter(encrypted[:m])
    
    # 첫 윈도우 체크
    if window_counter == target_counter:
        return True

    # 슬라이딩 윈도우: 오른쪽으로 한 칸씩 이동
    for i in range(m, n):
        # 새로 들어온 문자 추가
        window_counter[encrypted[i]] += 1
        # 윈도우에서 빠지는 문자 감소
        window_counter[encrypted[i-m]] -= 1
        
        # 빠진 문자가 0이면 딕셔너리에서 제거 (비교 간편화)
        if window_counter[encrypted[i-m]] == 0:
            del window_counter[encrypted[i-m]]
        
        # 현재 윈도우가 타겟과 동일하면 True 반환
        if window_counter == target_counter:
            return True
            
    return False

if __name__ == "__main__":
    input = sys.stdin.readline
    T = int(input().strip())
    for _ in range(T):
        encrypted = input().strip()
        original = input().strip()
        print("YES" if is_valid(encrypted, original) else "NO")
```

### 코드 설명
- **Counter 사용:** `collections.Counter`를 이용해 두 문자열의 문자 빈도를 비교합니다.
- **슬라이딩 윈도우:** 암호화된 문자열의 길이 \( m \)의 윈도우를 오른쪽으로 이동하면서 각 윈도우마다 빈도수를 업데이트하고, 타겟과 동일한지 확인합니다.
- **시간 복잡도:** 각 윈도우마다 비교하는 연산은 상수 시간(최대 26개 원소)이며, 전체 문자열을 한 번씩 훑으므로 \( O(n) \) 시간 내에 문제를 해결할 수 있습니다.

이 코드로 문제를 해결할 수 있습니다.

### 💡 답변 (Assistant)
다음은 `collections.Counter` 대신, 알파벳 26개에 대한 리스트(배열)를 사용하여 해결하는 방법입니다.

```python
import sys

def char_to_index(c):
    return ord(c) - ord('a')

def is_valid(encrypted, original):
    m = len(original)
    n = len(encrypted)
    
    # 두 문자열의 길이 비교: 암호화된 문자열이 짧으면 바로 False
    if m > n:
        return False
    
    # 원래 비밀번호와 첫 윈도우에 대한 빈도수를 저장할 배열 (알파벳 26개)
    target_freq = [0] * 26
    window_freq = [0] * 26
    
    for c in original:
        target_freq[char_to_index(c)] += 1
    
    # 첫 m개의 문자에 대한 윈도우 빈도수 계산
    for i in range(m):
        window_freq[char_to_index(encrypted[i])] += 1
        
    # 초기 윈도우 체크
    if window_freq == target_freq:
        return True
    
    # 슬라이딩 윈도우: 오른쪽으로 한 칸씩 이동하면서 빈도수 업데이트
    for i in range(m, n):
        # 새로 들어오는 문자 업데이트
        window_freq[char_to_index(encrypted[i])] += 1
        # 윈도우에서 벗어나는 문자 업데이트
        window_freq[char_to_index(encrypted[i - m])] -= 1
        
        if window_freq == target_freq:
            return True

    return False

if __name__ == "__main__":
    input = sys.stdin.readline
    T = int(input().strip())
    for _ in range(T):
        encrypted = input().strip()
        original = input().strip()
        print("YES" if is_valid(encrypted, original) else "NO")
```

### 코드 설명
- **빈도수 배열 사용:**  
  `target_freq` 배열은 원래 비밀번호의 각 문자의 빈도수를 저장하고, `window_freq` 배열은 암호화된 문자열의 현재 윈도우(길이 \( m \))의 빈도수를 저장합니다.
- **슬라이딩 윈도우 업데이트:**  
  암호화된 문자열을 오른쪽으로 이동하면서, 새로 들어온 문자의 빈도수를 증가시키고, 윈도우에서 벗어난 문자의 빈도수를 감소시킵니다.
- **비교:**  
  각 단계마다 두 배열이 동일하면, 원래 비밀번호의 순열이 해당 위치에 존재한다는 뜻이므로 `True`를 반환합니다.

이와 같이 구현하면 `Counter`를 사용하지 않고도 문제를 효율적으로 해결할 수 있습니다.

## 1. 문제의 핵심

문제에서는 원래 비밀번호의 글자들을 임의로 재배열한(순열) 문자열이 암호화된 문자열의 **어떤 연속 구간**에 나타날 수 있는지를 확인하는 것입니다.  
즉, 암호화된 문자열에서 길이가 원래 비밀번호와 같은 모든 연속 부분 문자열을 살펴보고, 이 부분 문자열이 원래 비밀번호와 **동일한 문자 빈도**를 가지고 있는지 확인하면 됩니다.

---

## 2. 접근 방법

### 2.1. 빈도수 배열 사용
알파벳은 소문자 26개로 한정되어 있으므로, 각 문자의 등장 횟수를 저장하는 배열을 26길이의 리스트로 관리할 수 있습니다.  
- `target_freq`: 원래 비밀번호의 각 문자가 몇 번 등장하는지를 저장합니다.
- `window_freq`: 암호화된 문자열에서 현재 슬라이딩 윈도우(길이 \( m \)) 내의 각 문자의 등장 횟수를 저장합니다.

문자 `'a'`부터 `'z'`까지 각 문자를 인덱스 0부터 25에 대응시킬 수 있으며, `ord(c) - ord('a')` 함수를 사용하면 해당 인덱스를 쉽게 구할 수 있습니다.

### 2.2. 슬라이딩 윈도우 기법

암호화된 문자열의 길이를 \( n \), 원래 비밀번호의 길이를 \( m \)이라고 할 때, 암호화된 문자열의 길이가 \( n \)인 상태에서 길이 \( m \)의 윈도우를 오른쪽으로 한 칸씩 이동하면서 각 구간의 문자 빈도 배열과 원래 비밀번호의 빈도 배열을 비교합니다.

1. **초기화 단계:**  
   - 원래 비밀번호의 빈도 배열 `target_freq`를 계산합니다.
   - 암호화된 문자열의 처음 \( m \)개의 문자에 대한 빈도 배열 `window_freq`를 계산합니다.
   - 초기 윈도우에서 두 배열이 일치하면, 바로 YES를 반환할 수 있습니다.

2. **윈도우 이동 단계:**  
   - 이후, 윈도우를 오른쪽으로 한 칸씩 이동시킵니다.
   - 이동할 때마다 새로 들어오는 문자는 `window_freq`에서 해당 인덱스의 값을 1 증가시키고, 윈도우에서 벗어나는 문자는 1 감소시킵니다.
   - 각 이동 후, 현재의 `window_freq`와 `target_freq` 배열을 비교합니다. 만약 두 배열이 같다면, 해당 위치에 원래 비밀번호의 순열이 존재한다는 뜻이므로 YES를 반환합니다.
   - 모든 윈도우를 확인한 후에도 조건을 만족하는 부분이 없으면 NO를 반환합니다.

## 3. 세부 구현 분석

### 3.1. 문자 -> 인덱스 변환 함수  
```python
def char_to_index(c):
    return ord(c) - ord('a')
```
- 이 함수는 문자를 0부터 25까지의 인덱스로 변환하여, 해당 문자의 빈도를 배열의 인덱스로 바로 저장할 수 있도록 도와줍니다.

### 3.2. 빈도 배열 초기화
```python
target_freq = [0] * 26
window_freq = [0] * 26
```
- 두 배열 모두 알파벳 소문자 26개에 대해 0으로 초기화합니다.
- 이후 원래 비밀번호의 각 문자에 대해 `target_freq`를 업데이트합니다.
- 암호화된 문자열의 처음 \( m \)개의 문자에 대해 `window_freq`를 업데이트합니다.

### 3.3. 초기 윈도우 체크
```python
if window_freq == target_freq:
    return True
```
- 첫 \( m \)글자에 대한 빈도 배열이 원래 비밀번호의 빈도 배열과 동일하면, 암호화된 문자열의 시작 부분에 올바른 순열이 존재하는 것입니다.

### 3.4. 슬라이딩 윈도우 이동 및 업데이트
```python
for i in range(m, n):
    # 새로 들어오는 문자 처리
    window_freq[char_to_index(encrypted[i])] += 1
    # 윈도우에서 벗어나는 문자 처리
    window_freq[char_to_index(encrypted[i - m])] -= 1

    if window_freq == target_freq:
        return True
```
- 반복문은 \( i = m \)부터 \( n - 1 \)까지 진행합니다.
- `encrypted[i]`는 윈도우에 새롭게 들어오는 문자입니다.
- `encrypted[i - m]`는 윈도우에서 빠지는 문자입니다.
- 윈도우가 한 칸씩 이동할 때마다 두 배열을 비교하여 조건이 맞으면 바로 결과를 반환합니다.

### 3.5. 시간 복잡도 분석
- **초기화:** 원래 비밀번호와 첫 윈도우의 계산은 각각 \( O(m) \)입니다.
- **슬라이딩 윈도우:** 암호화된 문자열 전체를 \( O(n - m) \)번 확인하며, 각 단계에서 배열 비교는 \( O(26) \)로 상수 시간입니다.
- **총 시간 복잡도:** \( O(m) + O(n-m) \times O(26) \) 즉, \( O(n) \)입니다.  
  \( n \)과 \( m \)의 최대 길이가 10만이므로 이 알고리즘은 충분히 효율적입니다.

## 4. 공간 복잡도 분석

- **빈도 배열:** 두 개의 배열을 사용하며, 각 배열의 크기는 26으로 상수 공간 \( O(1) \)입니다.
- **입력 저장:** 암호화된 문자열과 원래 비밀번호를 저장하는 데 \( O(n) \)과 \( O(m) \)의 공간이 필요합니다.
- **총 공간 복잡도:** \( O(n + m) \)으로 입력 크기에 비례합니다.

## 5. 엣지 케이스 고려

- **암호화된 문자열의 길이가 원래 비밀번호의 길이보다 작을 때:**  
  문제 조건에서 암호화된 문자열의 길이는 항상 원래 비밀번호의 길이 이상이라고 했으므로, 이 경우는 고려하지 않아도 되지만, 코드에서는 안전하게 `if m > n: return False`로 처리할 수 있습니다.

- **모든 문자가 같은 경우:**  
  예를 들어 원래 비밀번호가 "aaa"라면, 빈도 배열 비교 시 모든 위치에서 정확히 "aaa"의 빈도와 일치하는지만 확인하면 됩니다.

- **암호화된 문자열에 원래 비밀번호에 없는 문자가 포함된 경우:**  
  이 경우에도 빈도 배열 비교에서 정확히 0인 값과 다른 값으로 인해 조건을 만족하지 않으므로 문제가 없습니다.

## 6. 전체 파이썬 코드

아래는 위의 분석을 토대로 작성한 최종 코드입니다.

```python
import sys

def char_to_index(c):
    return ord(c) - ord('a')

def is_valid(encrypted, original):
    m = len(original)
    n = len(encrypted)
    
    if m > n:
        return False
    
    target_freq = [0] * 26
    window_freq = [0] * 26
    
    # 원래 비밀번호의 빈도수 계산
    for c in original:
        target_freq[char_to_index(c)] += 1
    
    # 암호화된 문자열의 첫 m개 문자에 대한 빈도수 계산
    for i in range(m):
        window_freq[char_to_index(encrypted[i])] += 1
    
    # 초기 윈도우 비교
    if window_freq == target_freq:
        return True
    
    # 슬라이딩 윈도우 적용: 오른쪽으로 한 칸씩 이동
    for i in range(m, n):
        window_freq[char_to_index(encrypted[i])] += 1
        window_freq[char_to_index(encrypted[i - m])] -= 1
        
        if window_freq == target_freq:
            return True

    return False

if __name__ == "__main__":
    input = sys.stdin.readline
    T = int(input().strip())
    for _ in range(T):
        encrypted = input().strip()
        original = input().strip()
        print("YES" if is_valid(encrypted, original) else "NO")
```

## 7. 요약

- **문제 핵심:** 암호화된 문자열 내에 원래 비밀번호의 임의 순열(동일한 문자 빈도 배열)이 존재하는지 확인하는 문제입니다.
- **접근 방법:**  
  - 알파벳 26개에 대한 빈도 배열을 사용하여 원래 비밀번호와 윈도우 부분 문자열의 빈도수를 비교합니다.
  - 슬라이딩 윈도우 기법을 이용해 효율적으로 모든 부분 문자열을 확인합니다.
- **시간/공간 복잡도:**  
  - 시간 복잡도는 \( O(n) \)
  - 공간 복잡도는 \( O(1) \) (상수 공간, 입력 제외)

이와 같이 분석하고 구현하면, Counter 라이브러리를 사용하지 않아도 문제를 효율적으로 해결할 수 있습니다.
