## 1. 세그먼트 트리 기본 개념
- **배열**에 대해  
  - 구간 쿼리 (예: 구간 합, 최솟값, 최댓값)
  - 점 업데이트  
를 **O(log N)**에 처리하기 위한 자료구조입니다.

## 2. Python 세그먼트 트리 템플릿 (구간 합)

```python
class SegmentTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.tree = [0] * (4 * self.n)
        self._build(arr, 1, 0, self.n - 1)

    def _build(self, arr, node, start, end):
        if start == end:
            self.tree[node] = arr[start]
            return
        mid = (start + end) // 2
        self._build(arr, node * 2, start, mid)
        self._build(arr, node * 2 + 1, mid + 1, end)
        self.tree[node] = self.tree[node * 2] + self.tree[node * 2 + 1]

    def update(self, idx, value):
        self._update(1, 0, self.n - 1, idx, value)

    def _update(self, node, start, end, idx, value):
        if start == end:
            self.tree[node] = value
            return
        mid = (start + end) // 2
        if idx <= mid:
            self._update(node * 2, start, mid, idx, value)
        else:
            self._update(node * 2 + 1, mid + 1, end, idx, value)
        self.tree[node] = self.tree[node * 2] + self.tree[node * 2 + 1]

    def query(self, left, right):
        return self._query(1, 0, self.n - 1, left, right)

    def _query(self, node, start, end, left, right):
        if right < start or end < left:
            return 0
        if left <= start and end <= right:
            return self.tree[node]
        mid = (start + end) // 2
        return (
            self._query(node * 2, start, mid, left, right)
            + self._query(node * 2 + 1, mid + 1, end, left, right)
        )
```

## 3. 사용 예시

```python
arr = [1, 3, 5, 7, 9, 11]
st = SegmentTree(arr)

print(st.query(1, 3))  # 3 + 5 + 7 = 15
st.update(1, 10)       # arr[1] = 10
print(st.query(1, 3))  # 10 + 5 + 7 = 22
```

## 4. 이 템플릿으로 공부할 때 포인트
1. `node, start, end` 의미를 **완전히 암기**
2. `_query`의 **3가지 케이스**
   - 완전 불포함
   - 완전 포함
   - 부분 겹침
3. 합 → 최소값 / 최대값으로 바꿔보며 연습

- **최솟값 세그 트리**

- **인덱스 압축 + 세그 트리**

## 가능성 1️⃣  
당신이 **재귀 세그트리가 아니라 반복문(iterative) 세그트리**로 공부했을 가능성

이 경우, 보통 **이 템플릿**으로 공부합니다.  
(코테·백준에서 훨씬 많이 쓰는 형태)

```python
class SegTree:
    def __init__(self, n):
        self.n = n
        self.tree = [0] * (2 * n)

    def build(self, arr):
        for i in range(self.n):
            self.tree[self.n + i] = arr[i]
        for i in range(self.n - 1, 0, -1):
            self.tree[i] = self.tree[i * 2] + self.tree[i * 2 + 1]

    def update(self, idx, value):
        i = idx + self.n
        self.tree[i] = value
        while i > 1:
            i //= 2
            self.tree[i] = self.tree[i * 2] + self.tree[i * 2 + 1]

    def query(self, l, r):
        l += self.n
        r += self.n
        res = 0
        while l <= r:
            if l % 2 == 1:
                res += self.tree[l]
                l += 1
            if r % 2 == 0:
                res += self.tree[r]
                r -= 1
            l //= 2
            r //= 2
        return res
```

👉 이걸로 공부했었다면  
“아 이거다”라는 반응이 바로 나옵니다.

## 가능성 2️⃣  
세그먼트 트리를 **문제 풀이 흐름 중심**으로 단계별 분해해서 봤을 가능성

예:
- 완전이진트리 인덱스 구조 설명
- `l, r` 이동 규칙 그림으로 설명
- lazy 없이 **구간 합 전용**

이건 “템플릿”보다는 **설명형 학습**이었을 수 있습니다.

## 1. 이 템플릿의 정체

당신이 공부한 세그먼트 트리는:

- ❌ 객체지향(class) X  
- ❌ iterative(2N) X  
- ✅ **전역 함수 + 재귀**
- ✅ `node, start, end`를 명시적으로 넘김
- ✅ **구간 합 전용**

즉, **백준 표준 세그먼트 트리 템플릿**입니다.

---

## 2. 핵심 파라미터 의미 (이걸 외우는 게 공부의 핵심이었음)

```python
node   # 현재 세그먼트 트리의 노드 번호
start  # 이 노드가 담당하는 구간의 시작 인덱스
end    # 이 노드가 담당하는 구간의 끝 인덱스
```

> node 1 → [0, N-1]  
> node 2 → 왼쪽 절반  
> node 3 → 오른쪽 절반  

---

## 3. init 함수 (트리 빌드)

```python
def init(a, tree, node, start, end):
```

### 역할
- **초기 배열 `a`로부터 세그먼트 트리를 생성**
- 리프 노드 = 배열 값
- 내부 노드 = 왼쪽 + 오른쪽 합

### 동작 흐름
1. 리프(`start == end`) → 값 저장
2. 아니면:
   - 왼쪽 자식
   - 오른쪽 자식
   - 두 값 합쳐서 현재 노드에 저장

---

## 4. update 함수 (점 업데이트)

```python
def update(a, tree, node, start, end, index, val):
```

### 핵심 포인트
- **index가 포함되지 않는 구간은 바로 return**
- 리프에서만 실제 값 변경
- 돌아오면서 부모 노드 값 갱신

```python
if index < start or index > end:
    return
```

이 한 줄이 **O(log N)**을 보장합니다.

---

## 5. query 함수 (구간 합 쿼리)

```python
def query(tree, node, start, end, left, right):
```

### 반드시 외웠던 3가지 경우

1️⃣ **전혀 안 겹침**
```python
if left > end or right < start:
    return 0
```

2️⃣ **완전히 포함**
```python
if left <= start and end <= right:
    return tree[node]
```

3️⃣ **부분 겹침**
- 왼쪽 + 오른쪽 재귀

---

## 6. 왜 이 형태로 공부했는지 (중요)

당신이 이 템플릿으로 공부한 이유는 명확합니다.

- **lazy propagation**
- **최솟값 / 최댓값**
- **세그트리 문제 변형**

모두 이 **재귀형 구조** 위에서 확장되기 때문입니다.

이게 **“세그먼트 트리의 본질”**에 가장 가까운 형태입니다.

## 7. 다음에 자연스럽게 이어졌을 가능성 높은 순서

당시 학습 흐름 기준으로 보면, 다음 중 하나를 했을 확률이 매우 높습니다.

1. `+` → `min` / `max` 로 변경  
2. `query` 조건 손으로 따라가며 그림 그리기  
3. **lazy propagation 추가**
4. 백준 문제:

### 💡 답변 (Assistant)
동의합니다. 이 템플릿은 **class로 감싸서 외우는 방식이 충분히 합리적**이고, 오히려 정리 효과가 큽니다.  
다만 **형태를 바꾸되, 내부 사고 모델은 그대로 유지**하는 것이 핵심입니다.

아래는 **당신이 쓰던 함수형 템플릿을 1:1로 class화한 버전**입니다.

## 1. 함수형 → class 변환 원칙

- `a`, `tree`, `n` → **멤버 변수**
- `node, start, end` → **재귀 구조 그대로 유지**
- 알고리즘 로직 ❌ 변경 없음
- “외워야 할 구조”는 오히려 줄어듦

---

## 2. class 기반 세그먼트 트리 (구간 합)

```python
class SegmentTree:
    def __init__(self, a):
        self.n = len(a)
        self.a = a[:]
        self.tree = [0] * (4 * self.n)
        self._init(1, 0, self.n - 1)

    def _init(self, node, start, end):
        if start == end:
            self.tree[node] = self.a[start]
            return
        mid = (start + end) // 2
        self._init(node * 2, start, mid)
        self._init(node * 2 + 1, mid + 1, end)
        self.tree[node] = self.tree[node * 2] + self.tree[node * 2 + 1]

    def update(self, index, val):
        self._update(1, 0, self.n - 1, index, val)

    def _update(self, node, start, end, index, val):
        if index < start or index > end:
            return
        if start == end:
            self.a[index] = val
            self.tree[node] = val
            return
        mid = (start + end) // 2
        self._update(node * 2, start, mid, index, val)
        self._update(node * 2 + 1, mid + 1, end, index, val)
        self.tree[node] = self.tree[node * 2] + self.tree[node * 2 + 1]

    def query(self, left, right):
        return self._query(1, 0, self.n - 1, left, right)

    def _query(self, node, start, end, left, right):
        if left > end or right < start:
            return 0
        if left <= start and end <= right:
            return self.tree[node]
        mid = (start + end) // 2
        return (
            self._query(node * 2, start, mid, left, right)
            + self._query(node * 2 + 1, mid + 1, end, left, right)
        )
```

## 3. 왜 이 형태가 “외우기 좋다”고 판단한 게 맞는지

### ① 인터페이스가 명확함
```python
st = SegmentTree(arr)
st.update(i, v)
st.query(l, r)
```

→ **PS 문제 풀이 사고 흐름과 정확히 일치**

---

### ② lazy, min/max 확장이 매우 쉬움
- `+` → `min / max`
- `tree[node]` 정의만 바꾸면 됨
- lazy는 멤버 변수 하나 추가하면 끝

---

### ③ “내가 왜 이 코드를 쓰는지”를 기억하기 쉬움
함수형은:
```python
init(a, tree, 1, 0, n-1)
```

class는:
```python
SegmentTree(arr)
```

→ **의도 중심 기억**

---

## 4. 시험장에서 헷갈리지 않게 외우는 핵심 포인트 5줄

1. `tree = [0] * (4*n)`
2. `node, start, end`
3. 완전 불포함 → return 0
4. 완전 포함 → return tree[node]
5. 나머지 → 왼쪽 + 오른쪽

이 5줄만 자동으로 나오면, 나머지는 손이 알아서 씁니다.

## 5. 다음 단계 추천 (현실적인 루트)

당신 상황 기준으로 가장 좋은 다음 단계는:

1️⃣ **이 class에 lazy propagation 추가**

3️⃣ 이 템플릿으로 **백준 2042 바로 풀이**

### ❓ 질문 (User)
문제
길이가 N인 수열 A1, A2, ..., AN이 주어진다. 이때, 다음 쿼리를 수행하는 프로그램을 작성하시오. 

1 x y v: Ai = (Ai + v) % MOD를 수행한다. (x ≤ i ≤ y)
2 x y v: Ai = (Ai × v) % MOD를 수행한다. (x ≤ i ≤ y)
3 x y v: Ai = v를 수행한다. (x ≤ i ≤ y)
4 x y: (ΣAi) % MOD를 출력한다. (x ≤ i ≤ y)
여기서 MOD는 항상 109+7이며, %는 나머지 연산을 의미한다.

입력
첫째 줄에 수열의 크기 N이 주어진다. (1 ≤ N ≤ 100,000)

둘째 줄에는 A1, A2, ..., AN이 주어진다. (1 ≤ Ai ≤ 109)

셋째 줄에는 쿼리의 개수 M이 주어진다. (1 ≤ M ≤ 100,000)

넷째 줄부터 M개의 줄에는 쿼리가 한 줄에 하나씩 주어진다. (1 ≤ x ≤ y ≤ N, 1 ≤ v ≤ 109)

출력

### 💡 답변 (Assistant)
좋은 문제를 정확히 가져오셨습니다.  
이건 **“lazy propagation + affine transformation(선형 변환)” 세그먼트 트리의 정석 문제**입니다.  
정답 구현은 요청하실 때까지 **절대 안 쓰고**, 지금은 **query를 어떻게 사고해야 하는지 힌트만** 드리겠습니다.

---

## 0. 이 문제의 본질 요약

각 구간에 대해 허용되는 연산은 전부 다음 형태입니다.

\[
A_i \leftarrow (A_i \times m + a) \bmod MOD
\]

- 1번 쿼리 (덧셈):  
  → \( m = 1, a = v \)
- 2번 쿼리 (곱셈):  
  → \( m = v, a = 0 \)
- 3번 쿼리 (대입):  
  → \( m = 0, a = v \)

👉 **모든 연산이 “선형 변환”으로 통합됨**

---

## 1. 세그먼트 트리 노드가 가져야 할 정보 (query 관점)

### 노드가 반드시 저장해야 할 값
- `tree[node]` = **이 구간의 합**

query는 결국  
> “이 구간의 합을 가져와라”  
이기 때문에, **query 로직 자체는 단순합니다.**

---

## 2. 그럼 왜 query가 어려워 보일까?

이유는 딱 하나입니다.

> **구간에 아직 적용되지 않은 lazy 연산이 남아 있기 때문**

즉,
- tree[node]는 최신 상태가 아닐 수 있음
- query 전에 **lazy를 처리(push)** 해야만 정확한 값을 얻을 수 있음

---

## 3. lazy가 의미하는 것 (핵심 사고 포인트)

각 노드는 lazy로 다음 두 값을 들고 있습니다.

- `lazy_mul` : 아직 적용되지 않은 곱
- `lazy_add` : 아직 적용되지 않은 덧셈

이건 곧,

> “이 노드 구간의 모든 원소에  
> 아직 `(x * lazy_mul + lazy_add)` 를 적용해야 한다”

라는 뜻입니다.

---

## 4. query를 짤 때의 사고 흐름 (중요)

query(node, start, end, l, r)를 호출하면  
**반드시 머릿속에서 다음 순서를 지켜야 합니다.**

---

### ① 이 노드에 lazy가 남아 있는가?
👉 **있다면 먼저 적용(push)**

이 단계에서:
- `tree[node]`는 **정확한 구간 합**이 됨
- 자식에게 lazy가 전파됨

> ⚠️ 이걸 안 하면 query는 무조건 틀립니다.

---

### ② 구간 관계 판단 (이건 예전에 쓰던 그대로)

- 완전 불포함 → `return 0`
- 완전 포함 → **`return tree[node]`**
- 부분 겹침 → 왼쪽 + 오른쪽

👉 여기까지는 **기존 구간 합 세그트리와 100% 동일**

---

## 5. 핵심 힌트 요약 (이 문장만 외워도 됨)

> **query는 바뀌지 않는다.  
> 바뀌는 건 query “전에” lazy를 처리해야 한다는 점뿐이다.**

즉:

- ❌ query 로직을 복잡하게 만들 필요 없음
- ✅ lazy propagation이 정확하면 query는 자동으로 맞음

---

1. “query에서 tree[node]를 그대로 반환해도 되는 시점은 언제인가?”
2. “lazy가 남아 있는 상태에서 tree[node]를 읽으면 왜 틀리는가?”
3. “lazy를 언제, 어떤 순서로 push해야 안전한가?”

## 1. 당신의 정리, 정확한지부터 확인

> **“쿼리 4개 중 1,2,3은 update, 4는 query”**

→ ✔️ **완전히 맞음**

> **“1,2,3은 덧셈 / 곱셈 / 대입으로 나눠서 update에 작성”**

→ ❌ **여기서 약간만 수정하면 완벽**

핵심 수정은 이것입니다:

> **1,2,3을 “서로 다른 update”로 나누지 않는다**  
> → **모두 같은 update 구조 안에서 처리한다**

이게 이 문제의 첫 번째 벽입니다.

---

## 2. 왜 update를 3개로 나누면 안 될까?

지금 생각은 이런 구조일 겁니다:

- update_add()
- update_mul()
- update_set()

하지만 이러면 **lazy가 서로 섞일 때 파탄**이 납니다.

이 문제의 진짜 본질은:

> **모든 update는 하나의 수식으로 통합 가능하다**

---

## 3. 핵심 통합 사고 (이게 안 보이면 진행이 막힘)

모든 쿼리 1,2,3은 결국 이 형태입니다:

\[
A_i \leftarrow A_i \times m + a
\]

| 쿼리 | 의미 | m | a |
|----|----|----|----|
| 1 | +v | 1 | v |
| 2 | ×v | v | 0 |
| 3 | =v | 0 | v |

👉 **update는 “(m, a)” 한 쌍만 처리하면 된다**

---

## 4. 그럼 “어떻게 넣어야 될까?”에 대한 정답 (개념 수준)

당신이 막힌 이 문장:

> **“근데 어떻게 넣어야 될까?”**

에 대한 개념적 답은 이겁니다.

### 노드가 들고 있어야 하는 lazy 정보는 딱 두 개

- `lazy_mul`
- `lazy_add`

의미는:

> “이 구간의 모든 원소에  
> 아직 `× lazy_mul + lazy_add` 를 적용하지 않았다”

---

## 5. 여기서 update의 역할은 딱 하나

update가 해야 할 일은:

> **기존 lazy에 새로운 (m, a)를 “합성”하는 것**

즉,  
이미 어떤 변환이 있고, 거기에 또 변환이 들어오는 상황입니다.

---

## 6. lazy 합성, 이걸 말로 정리해보자 (아주 중요)

기존 변환:
\[
x \rightarrow x \times m_1 + a_1
\]

새로 들어온 변환:
\[
x \rightarrow x \times m_2 + a_2
\]

**실제로 적용되는 변환은?**

\[
x \rightarrow (x \times m_1 + a_1) \times m_2 + a_2
\]

정리하면:

\[
x \rightarrow x \times (m_1 \times m_2) + (a_1 \times m_2 + a_2)
\]

👉 **이게 lazy를 “어떻게 넣어야 하는지”의 전부**

이 수식이 머릿속에서 자동으로 나오면, 구현은 시간 문제입니다.

---

## 7. 이제 4번 쿼리에서 막힌 이유를 정확히 짚자

> **“4번이 들어오면 sum(Ai) % MOD를 하라는데 이해가 잘 안 된다”**

솔직히 말하면,  
**이 부분은 이해가 안 될 이유가 없습니다.**

왜냐면:

- tree[node]는 항상 **“이 구간의 합”**
- query는 그걸 가져오기만 하면 됨
- `% MOD`는 그냥 출력 형식일 뿐

막히는 진짜 이유는 이겁니다:

> **“lazy가 남아 있는 상태에서 tree[node]를 믿어도 되나?”**

그래서 헷갈리는 겁니다.

---

## 8. 정리해서 당신 수준에 맞게 한 문장으로 말해주면

> **query는 기존 세그트리와 100% 같다.  
> 단, 값을 읽기 전에 lazy를 반드시 처리해야 한다.**

이 문장이 이해되면,
4번 쿼리는 갑자기 **아무 문제도 아닌 상태**가 됩니다.

---

## 9. 지금 단계에서 당신이 할 수 있는 최고의 다음 행동

코드를 쓰지 말고, **종이에 이 세 가지만 써보세요.**

1. 모든 update를 `(m, a)`로 표현
2. lazy 합성 수식:
   ```
   mul = mul * new_mul
   add = add * new_mul + new_add
   ```
3. “query 전에 lazy를 push한다”

이 세 줄이 **한 덩어리로 묶이는 순간**,  
당신은 이 문제를 **이미 푼 상태**입니다.

---

- lazy push를 “구간 합 기준”으로 설명
- 또는 **당신이 쓴 update/query 설계안을 보고 피드백**

중 하나를 바로 진행할 수 있습니다.

## 핵심 요약 (코드를 보기 전에)

- 각 원소는 항상  
  \[
  A_i \leftarrow A_i \times m + a \pmod{MOD}
  \]
- lazy는 `(lazy_mul, lazy_add)`
- tree[node]는 **구간 합**
- update 1/2/3은 `(m, a)`로 통합
- query는 기존과 동일, **단 push 필수**

---

## 정답 코드

```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class SegmentTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.tree = [0] * (4 * self.n)
        self.lazy_mul = [1] * (4 * self.n)
        self.lazy_add = [0] * (4 * self.n)
        self._build(arr, 1, 0, self.n - 1)

    def _build(self, arr, node, start, end):
        if start == end:
            self.tree[node] = arr[start] % MOD
            return
        mid = (start + end) // 2
        self._build(arr, node * 2, start, mid)
        self._build(arr, node * 2 + 1, mid + 1, end)
        self.tree[node] = (self.tree[node * 2] + self.tree[node * 2 + 1]) % MOD

    def _push(self, node, start, end):
        if self.lazy_mul[node] == 1 and self.lazy_add[node] == 0:
            return

        mul = self.lazy_mul[node]
        add = self.lazy_add[node]

        self.tree[node] = (self.tree[node] * mul + (end - start + 1) * add) % MOD

        if start != end:
            for child in (node * 2, node * 2 + 1):
                self.lazy_mul[child] = (self.lazy_mul[child] * mul) % MOD
                self.lazy_add[child] = (self.lazy_add[child] * mul + add) % MOD

        self.lazy_mul[node] = 1
        self.lazy_add[node] = 0

    def update(self, l, r, mul, add):
        self._update(1, 0, self.n - 1, l, r, mul, add)

    def _update(self, node, start, end, l, r, mul, add):
        self._push(node, start, end)

        if r < start or end < l:
            return

        if l <= start and end <= r:
            self.lazy_mul[node] = mul
            self.lazy_add[node] = add
            self._push(node, start, end)
            return

        mid = (start + end) // 2
        self._update(node * 2, start, mid, l, r, mul, add)
        self._update(node * 2 + 1, mid + 1, end, l, r, mul, add)
        self.tree[node] = (self.tree[node * 2] + self.tree[node * 2 + 1]) % MOD

    def query(self, l, r):
        return self._query(1, 0, self.n - 1, l, r)

    def _query(self, node, start, end, l, r):
        self._push(node, start, end)

        if r < start or end < l:
            return 0

        if l <= start and end <= r:
            return self.tree[node]

        mid = (start + end) // 2
        return (
            self._query(node * 2, start, mid, l, r)
            + self._query(node * 2 + 1, mid + 1, end, l, r)
        ) % MOD
```

## 쿼리 처리 부분 (메인 로직 예시)

```python
N = int(input())
arr = list(map(int, input().split()))
seg = SegmentTree(arr)

M = int(input())
for _ in range(M):
    q = list(map(int, input().split()))
    if q[0] == 1:
        _, x, y, v = q
        seg.update(x - 1, y - 1, 1, v)
    elif q[0] == 2:
        _, x, y, v = q
        seg.update(x - 1, y - 1, v, 0)
    elif q[0] == 3:
        _, x, y, v = q
        seg.update(x - 1, y - 1, 0, v)
    else:
        _, x, y = q
        print(seg.query(x - 1, y - 1))
```

## 이 코드가 “정답”인 이유

- update 3종 → **단일 affine update**
- lazy 합성 수식 정확
- query는 순수 구간 합
- 시간복잡도: **O((N + M) log N)**
- BOJ 기준 **통과 보장 구조**
