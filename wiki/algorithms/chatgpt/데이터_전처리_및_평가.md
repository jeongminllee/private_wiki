### 💡 답변 (Assistant)
원인은 **축이 뒤집혔기 때문**이야.

네 코드에서는 `precision`, `recall`을 직접 계산할 때도 그렇고, `sklearn.metrics.classification_report`를 쓸 때도 **`y_true`와 `y_pred`의 순서를 거꾸로 넣고 있어**.  
그래서 precision과 recall이 서로 바뀐 것처럼 보이는 거야.

## 핵심 원리

분류 평가 함수들은 기본적으로 이렇게 받는다.

```python
metric(y_true, y_pred)
```

즉,

- `y_true` : 실제 정답
- `y_pred` : 모델 예측값

이어야 해.

그런데 네 코드에서는:

```python
tp_1, fp_1, fn_1, tn_1 = confusionMatrix_1(y_pred_linear, y_test_arr)
```

이렇게 넣었지?

여기서 `arr1 = y_pred_linear`  
`arr2 = y_test_arr`

그리고 함수 내부를 보면:

```python
if arr1[i] == arr2[i]:
    if arr2[i] == 1:
        tp += 1
    else:
        tn += 1
else:
    if arr1[i] == 0:
        fp += 1
    else:
        fn += 1
```

이 로직은 주석상으로는 **정답 기준 confusion matrix**를 만들려고 했지만,  
실제로는 `arr1`, `arr2`를 다루는 방식이 깔끔하지 않아서 헷갈리기 쉬워.

특히 아래 부분이 문제를 만든다:

```python
if arr1[i] == 0:
    fp += 1
else:
    fn += 1
```

여기서는 **예측값(arr1)** 을 보고 FP/FN을 나누고 있어.  
그런데 FP/FN은 원래 **실제값과 예측값의 관계**로 정의해야 하거든.

정의는 이거야:

- **TP**: 실제 1, 예측 1
- **TN**: 실제 0, 예측 0
- **FP**: 실제 0, 예측 1
- **FN**: 실제 1, 예측 0

즉 FP/FN을 구분할 때는  
“실제값이 뭐냐, 예측값이 뭐냐”가 정확히 고정돼야 해.

---

## 왜 precision과 recall이 바뀌어 보이냐

precision과 recall 정의를 보면:

- **Precision** = `TP / (TP + FP)`
- **Recall** = `TP / (TP + FN)`

그런데 `y_true`, `y_pred`를 뒤집으면
FP와 FN의 의미가 서로 뒤바뀌는 효과가 생겨.

즉,

- 원래 precision에 들어가야 할 값이 recall 쪽으로 가고
- 원래 recall에 들어가야 할 값이 precision 쪽으로 감

그래서 둘이 바뀐 것처럼 보여.


즉:

- 첫 번째 인자 = 실제값
- 두 번째 인자 = 예측값

## 네 confusionMatrix 함수도 더 명확하게 고치는 게 좋아

지금처럼 `arr1`, `arr2`로 쓰면 헷갈리니까 아예 이름부터 바꾸는 게 좋아.

```python
def confusion_matrix_manual(y_true, y_pred):
    tp = tn = fp = fn = 0
    
    for i in range(len(y_true)):
        if y_true[i] == 1 and y_pred[i] == 1:
            tp += 1
        elif y_true[i] == 0 and y_pred[i] == 0:
            tn += 1
        elif y_true[i] == 0 and y_pred[i] == 1:
            fp += 1
        elif y_true[i] == 1 and y_pred[i] == 0:
            fn += 1

    return tp, fp, fn, tn
```

이렇게 쓰면 정의 자체가 명확해서 실수가 줄어들어.

사용은:

```python
tp_1, fp_1, fn_1, tn_1 = confusion_matrix_manual(y_test_arr, y_pred_linear)
precision_linear_1 = precision(tp_1, fp_1)
recall_linear_1 = recall(tp_1, fn_1)
```

## sklearn과 동일하게 맞추는 전체 수정 예시

```python
from sklearn.metrics import confusion_matrix, classification_report

def confusion_matrix_manual(y_true, y_pred):
    tp = tn = fp = fn = 0
    
    for i in range(len(y_true)):
        if y_true[i] == 1 and y_pred[i] == 1:
            tp += 1
        elif y_true[i] == 0 and y_pred[i] == 0:
            tn += 1
        elif y_true[i] == 0 and y_pred[i] == 1:
            fp += 1
        elif y_true[i] == 1 and y_pred[i] == 0:
            fn += 1

    return tp, fp, fn, tn

def precision(tp, fp):
    return tp / (tp + fp)

def recall(tp, fn):
    return tp / (tp + fn)

tp, fp, fn, tn = confusion_matrix_manual(y_test_arr, y_pred_linear)
print(f"tp={tp}, fp={fp}, fn={fn}, tn={tn}")
print("precision:", precision(tp, fp))
print("recall:", recall(tp, fn))

print(confusion_matrix(y_test_arr, y_pred_linear))
print(classification_report(y_test_arr, y_pred_linear))
```

## 추가로 하나 더

이 부분도 살짝 주의해야 해:

```python
df1.loc[[61, 829], 'embarked']='s'
```

원래 Titanic의 `embarked` 값은 보통 `'S'`, `'C'`, `'Q'` 대문자를 쓰는데  
여기서는 소문자 `'s'`를 넣었어. 그러면 one-hot encoding할 때 `'embarked_s'`라는 새 범주가 생길 수 있어.

그리고 더 큰 문제는 그 다음 줄이:

```python
embarked_one_hot = pd.get_dummies(t_data.embarked, prefix = 'embarked')
```

인데, 수정한 `df1['embarked']`가 아니라 **원본 `t_data.embarked`** 를 다시 one-hot 하고 있어.  
즉 네가 결측치 채운 수정이 반영되지 않고 있어.

아마 의도는 이거였을 거야:

```python
df1.loc[[61, 829], 'embarked'] = 'S'
embarked_one_hot = pd.get_dummies(df1.embarked, prefix='embarked')
```

이건 precision/recall 문제와는 별개지만, 데이터 전처리 쪽에서 꼭 고쳐야 해.

---

정리하면:

1. **precision과 recall이 바뀐 이유는 `y_true`, `y_pred` 순서를 뒤집어서 넣었기 때문**
2. `classification_report`, `confusion_matrix`는 반드시  
   **`(실제값, 예측값)`** 순서로 넣어야 함
3. 수동 confusion matrix 함수도 `y_true`, `y_pred`를 명확히 구분해서 다시 쓰는 게 좋음

원하면 내가 네 코드 전체를 **최소 수정 버전**으로 깔끔하게 다시 정리해줄게.
