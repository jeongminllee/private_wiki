### ❓ 질문 (User)
```
h_max = 10**6

class SegmentTree :
    def __init__(self, max_size):
        self.base = 1
        while self.base < max_size :
            self.base <<= 1

        self.tree = [(0, 0) for _ in range(self.base << 1)]

    def get(self, left, right) :
        res = (0, 0)
        left += self.base
        right += self.base

        while left <= right :
            if left & 1 :
                res = max(res, self.tree[left])
                left = (left + 1) >> 1
            else :
                left >>= 1

            if right & 1 :
                right >>= 1
            else :
                res = max(res, self.tree[right])
                right = (right - 1) >> 1

        return res
    
    def update(self, idx, value) :
        ti = idx + self.base
        self.tree[ti] = (value, idx)

        while (ti := ti >> 1) > 0 :
            self.tree[ti] = max(self.tree[ti * 2], self.tree[ti * 2 + 1])

def add_func(h) :
    dp, _ = seg.get(0, h - 1)
    dp += 1
    A.append(h)
    dp_idx.append(dp)
    dp_val[h].append(dp)
    seg.update(h, dp)

def remove_func() :
    h = A.pop()
    dp_idx.pop()
    dp_val[h].pop()
    dp = 0

    if dp_val[h] :
        dp = dp_val[h][-1]

    seg.update(h, dp)

def get_score(m_idx) :
    dp, idx = seg.get(0, h_max)
    return (dp_idx[m_idx] + dp - 1) * 10 ** 6 + idx

A = []
dp_idx = []
dp_val = [[] for _ in range(h_max + 1)]
seg = SegmentTree(h_max + 1)

if __name__ == "__main__" :
    Q = int(input())
    for _ in range(Q) :
        query = list(map(int, input().split()))
        cmd, *v = query

        if cmd == 100 :
            n, *mountain = v
            for h in mountain :
                add_func(h)

        elif cmd == 200 :
            add_func(v[0])

        elif cmd == 300 :
            remove_func() 

        elif cmd == 400 :
            print(get_score(v[0] - 1))
```
코드 분석하자.

### 💡 답변 (Assistant)
이 코드는 **수열의 뒤에 높이를 추가하거나 마지막 높이를 제거하면서, LIS(최장 증가 부분수열) 정보를 유지하는 구조**로 보입니다. 먼저 각 자료구조의 역할과 세그먼트 트리 동작을 분해한 뒤, `get_score()`가 무엇을 계산하는지까지 연결해보겠습니다.

---

### 💡 답변 (Assistant)
좋아. 이 코드는 핵심적으로 다음 문제를 처리합니다.

> 높이 수열의 뒤에 산을 추가하거나 마지막 산을 제거하면서, 현재 수열의 **LIS(Longest Increasing Subsequence, 최장 증가 부분수열)** 정보를 빠르게 관리한다.

높이의 최댓값이 `10^6`이므로, 높이를 인덱스로 사용하는 세그먼트 트리를 구성했습니다.

---

## 1. 코드 전체 구조

현재 산의 높이 수열을 다음처럼 관리합니다.

```python
A = []
```

예를 들어:

```text
A = [2, 5, 3, 6]
```

각 산마다 해당 위치에서 끝나는 LIS 길이를 저장합니다.

```python
dp_idx = []
```

위 수열의 경우:

```text
높이:    2  5  3  6
dp:      1  2  2  3
```

따라서:

```python
dp_idx = [1, 2, 2, 3]
```

DP 점화식은 다음과 같습니다.

\[
dp[i]
=
1+\max(dp[j])
\]

단,

\[
j<i,\quad A[j]<A[i]
\]

즉 현재 높이보다 작은 산에서 끝나는 LIS 중 가장 긴 것에 현재 산을 붙입니다.

---

# 2. 세그먼트 트리가 저장하는 값

```python
self.tree = [(0, 0) for _ in range(self.base << 1)]
```

각 노드는 다음 튜플을 저장합니다.

```python
(dp 길이, 마지막 산의 높이)
```

예를 들어:

```python
(4, 10)
```

은 높이 `10`에서 끝나는 LIS의 길이가 `4`라는 의미입니다.

파이썬의 튜플 비교는 사전식으로 이루어집니다.

```python
max((3, 100), (4, 20))
# (4, 20)
```

먼저 첫 번째 원소인 DP 길이를 비교합니다.

DP 길이가 같으면 두 번째 원소인 높이를 비교합니다.

```python
max((4, 100), (4, 200))
# (4, 200)
```

따라서 이 트리는 다음 우선순위로 최댓값을 선택합니다.

1. LIS 길이가 큰 것
2. 길이가 같으면 마지막 산의 높이가 큰 것

이 튜플 비교가 코드 전체에서 매우 중요한 역할을 합니다.

---

# 3. 세그먼트 트리 초기화

```python
def __init__(self, max_size):
    self.base = 1
    while self.base < max_size:
        self.base <<= 1
```

세그먼트 트리는 리프 노드 개수를 2의 거듭제곱으로 맞춥니다.

현재:

```python
max_size = 1_000_001
```

가장 가까운 2의 거듭제곱은:

```text
1,048,576 = 2^20
```

이므로:

```python
self.base = 1_048_576
```

전체 트리 크기는 대략:

```text
2 × 1,048,576 = 2,097,152
```

입니다.

리프 노드에서 높이 `h`는 다음 위치에 저장됩니다.

```python
self.tree[self.base + h]
```

---

# 4. 구간 최댓값 조회

```python
def get(self, left, right):
```

`left`부터 `right`까지 포함하는 구간에서 가장 큰 `(dp, 높이)`를 반환합니다.

즉:

```python
seg.get(0, h - 1)
```

은 다음 의미입니다.

> 높이가 `h`보다 작은 산에서 끝나는 LIS 중 가장 긴 것

LIS는 높이가 엄격하게 증가해야 하므로 `h`를 포함하지 않고 `h - 1`까지만 조회합니다.

---

## left 처리

```python
if left & 1:
    res = max(res, self.tree[left])
    left = (left + 1) >> 1
else:
    left >>= 1
```

`left`가 홀수라면 현재 노드는 부모의 오른쪽 자식입니다.

이 경우 현재 노드는 조회 범위에 완전히 들어가므로 결과에 포함합니다.

```python
res = max(res, self.tree[left])
```

그다음 오른쪽 구간으로 이동한 뒤 부모로 올라갑니다.

---

## right 처리

```python
if right & 1:
    right >>= 1
else:
    res = max(res, self.tree[right])
    right = (right - 1) >> 1
```

`right`가 짝수라면 현재 노드는 부모의 왼쪽 자식입니다.

현재 노드가 조회 범위에 완전히 포함되므로 결과에 반영합니다.

코드 형태가 일반적인 세그먼트 트리 구현보다 조금 압축되어 있지만, 포함 구간에 대한 최댓값을 정상적으로 계산합니다.

시간 복잡도는:

\[
O(\log H)
\]

입니다. 여기서 `H = 10^6`입니다.

---

# 5. 세그먼트 트리 갱신

```python
def update(self, idx, value):
    ti = idx + self.base
    self.tree[ti] = (value, idx)
```

높이 `idx`의 DP 값을 `value`로 변경합니다.

예를 들어:

```python
seg.update(10, 4)
```

이면 리프 노드에 다음 값이 들어갑니다.

```python
(4, 10)
```

그 후 부모 노드를 갱신합니다.

```python
while (ti := ti >> 1) > 0:
    self.tree[ti] = max(
        self.tree[ti * 2],
        self.tree[ti * 2 + 1],
    )
```

왼쪽 자식과 오른쪽 자식 중 큰 튜플을 부모에 저장합니다.

루트 노드인:

```python
self.tree[1]
```

에는 전체 높이 구간의 최댓값이 들어갑니다.

즉 현재 수열 전체의:

```text
(전체 LIS 길이, 그 LIS의 마지막 높이)
```

가 저장됩니다.

---

# 6. 산 추가: `add_func`

```python
def add_func(h):
    dp, _ = seg.get(0, h - 1)
    dp += 1
```

새로운 산의 높이가 `h`라고 하겠습니다.

먼저 높이가 `h`보다 작은 산에서 끝나는 LIS 중 최댓값을 구합니다.

```python
dp, _ = seg.get(0, h - 1)
```

그 뒤 현재 산을 추가합니다.

```python
dp += 1
```

이것이 정확히 LIS 점화식입니다.

\[
dp_{\text{new}}
=
1+\max_{x<h}dp[x]
\]

---

## 정보를 각 배열에 저장

```python
A.append(h)
dp_idx.append(dp)
dp_val[h].append(dp)
seg.update(h, dp)
```

각 자료구조의 상태는 다음과 같습니다.

| 자료구조 | 저장 내용 |
|---|---|
| `A` | 현재 산의 높이 수열 |
| `dp_idx[i]` | `i`번째 산에서 끝나는 LIS 길이 |
| `dp_val[h]` | 높이가 `h`인 산들이 가졌던 DP 값 스택 |
| 세그먼트 트리 | 높이별 현재 최적 DP 값 |

---

## 예시

다음 순서로 산을 추가한다고 하겠습니다.

```text
2 → 5 → 3 → 6
```

### 높이 2 추가

```python
seg.get(0, 1) == (0, 0)
```

따라서:

```text
dp = 1
```

### 높이 5 추가

높이 `0~4`의 최대 DP는 `1`입니다.

```text
dp = 1 + 1 = 2
```

### 높이 3 추가

높이 `0~2`의 최대 DP는 `1`입니다.

```text
dp = 2
```

### 높이 6 추가

높이 `0~5`의 최대 DP는 `2`입니다.

```text
dp = 3
```

결과:

```text
A       = [2, 5, 3, 6]
dp_idx  = [1, 2, 2, 3]
```

전체 LIS는 다음 중 하나입니다.

```text
2 → 5 → 6
2 → 3 → 6
```

길이는 `3`입니다.

---

# 7. `dp_val`이 필요한 이유

```python
dp_val = [[] for _ in range(h_max + 1)]
```

`dp_val[h]`는 높이가 `h`인 산들의 DP 값을 순서대로 저장하는 스택입니다.

예를 들어 높이 `5`인 산이 여러 번 추가됐다면:

```python
dp_val[5] = [2, 3, 4]
```

와 같은 상태가 될 수 있습니다.

현재 세그먼트 트리에는 가장 최근 값인:

```python
(4, 5)
```

가 저장됩니다.

마지막 높이 `5`를 제거하면 그 이전 상태인:

```python
(3, 5)
```

로 복구해야 합니다.

그래서 단순히 세그먼트 트리 값을 0으로 지울 수 없고, 높이별 DP 이력을 스택으로 관리합니다.

---

## 왜 마지막 DP 값이 최댓값인가?

같은 높이 `h`가 나중에 다시 등장하면, 그 시점에는 이전보다 더 많은 산이 앞에 존재합니다.

따라서:

```text
max DP among heights < h
```

는 감소하지 않습니다.

같은 높이에서 계산되는 DP는 추가 순서에 따라 단조 비감소합니다.

```text
dp_val[h] = [2, 2, 3, 4, ...]
```

그러므로 스택의 마지막 값이 현재 높이 `h`에서의 최적 DP가 됩니다.

이 성질 덕분에 별도의 최대 힙이나 멀티셋이 필요하지 않습니다.

---

# 8. 마지막 산 제거: `remove_func`

```python
def remove_func():
    h = A.pop()
    dp_idx.pop()
    dp_val[h].pop()
```

수열의 마지막 산을 제거합니다.

여기서 중요한 조건은 다음입니다.

> 임의 위치 삭제가 아니라 반드시 마지막 산만 제거한다.

그래서 스택 기반 롤백이 가능합니다.

---

## 이전 DP 값 복원

```python
dp = 0

if dp_val[h]:
    dp = dp_val[h][-1]

seg.update(h, dp)
```

같은 높이의 이전 산이 남아 있다면 그 DP 값을 복구합니다.

남아 있지 않으면 높이 `h`의 DP를 0으로 만듭니다.

예를 들어:

```python
dp_val[5] = [2, 3]
```

인 상태에서 마지막 높이 5를 제거하면:

```python
dp_val[5] = [2]
```

가 되고 세그먼트 트리는 다음으로 복원됩니다.

```python
seg.update(5, 2)
```

---

# 9. `dp_idx`는 삭제 후에도 유효한가?

유효합니다.

현재 구조에서는 마지막 원소만 제거할 수 있습니다.

어떤 인덱스 `i`가 수열에 남아 있다면, `i`보다 앞에 있던 산은 제거되지 않았습니다.

따라서 그 산이 추가됐을 때 계산된:

```python
dp_idx[i]
```

는 그대로 유효합니다.

중간 원소를 삭제할 수 있었다면 뒤쪽 모든 DP를 다시 계산해야 하지만, 이 문제는 스택 형태의 추가·삭제이기 때문에 롤백이 가능합니다.

---

# 10. 점수 계산: `get_score`

```python
def get_score(m_idx):
    dp, idx = seg.get(0, h_max)
    return (dp_idx[m_idx] + dp - 1) * 10 ** 6 + idx
```

여기서:

```python
dp_idx[m_idx]
```

는 지정된 `m_idx`번째 산에서 끝나는 LIS 길이입니다.

그리고:

```python
dp, idx = seg.get(0, h_max)
```

는 현재 전체 수열에서:

```text
dp  = 전체 LIS 길이
idx = 그 LIS가 끝나는 높이
```

를 의미합니다.

최종적으로:

```python
(dp_idx[m_idx] + dp - 1) * 10**6 + idx
```

를 반환합니다.

`-1`은 보통 두 경로나 두 수열을 결합할 때 공통으로 포함되는 기준 산 하나를 중복 계산하지 않기 위해 사용됩니다.

다만 이 함수가 문제에서 의미하는 정확한 경로를 계산하는지는 **문제의 점수 정의를 함께 봐야 확정할 수 있습니다.**

코드 자체가 계산하는 것은 정확히 다음입니다.

\[
\left(
m\_idx에서\ 끝나는\ LIS 길이
+
전체\ LIS 길이
-1
\right)
\times10^6
+
전체\ LIS의\ 마지막\ 높이
\]

---

## 입력 인덱스 처리

```python
print(get_score(v[0] - 1))
```

명령어에서 전달되는 인덱스는 1부터 시작하고, 파이썬 배열은 0부터 시작하므로 `1`을 뺍니다.

예를 들어 명령이:

```text
400 3
```

이라면:

```python
get_score(2)
```

가 호출됩니다.

# 12. 시간 복잡도

높이 범위를 `H`라고 하면:

```text
H = 1,000,001
```

각 연산의 시간 복잡도는 다음과 같습니다.

| 연산 | 시간 복잡도 |
|---|---:|
| 산 추가 `200` | `O(log H)` |
| 산 제거 `300` | `O(log H)` |
| 점수 조회 `400` | `O(log H)` |
| 초기 산맥 `100` | `O(N log H)` |

`log₂(1,000,001)`은 약 20이므로 연산 자체는 상당히 빠릅니다.

# 13. 현재 코드에서 확인해야 할 부분

## 13.1 전체 최댓값은 루트에서 바로 얻을 수 있음

현재:

```python
dp, idx = seg.get(0, h_max)
```

로 전체 범위를 조회합니다.

하지만 세그먼트 트리 루트에는 이미 전체 최댓값이 저장되어 있습니다.

따라서 다음처럼 바꿀 수 있습니다.

```python
dp, idx = seg.tree[1]
```

그러면 `get_score()`가 `O(log H)`에서 `O(1)`이 됩니다.

```python
def get_score(m_idx):
    dp, idx = seg.tree[1]
    return (dp_idx[m_idx] + dp - 1) * 10**6 + idx
```

패딩 구간에는 `(0, 0)`만 존재하므로 현재처럼 활성 산의 DP가 최소 1 이상이라면 루트 값을 사용해도 안전합니다.

---

## 13.2 값이 0일 때 `(0, h)`가 저장됨

```python
seg.update(h, 0)
```

을 실행하면 실제 리프에는:

```python
(0, h)
```

가 저장됩니다.

따라서 모든 산이 제거된 상황에서는 루트가 반드시 `(0, 0)`이 아니라:

```python
(0, 이전에 갱신했던 가장 큰 높이)
```

가 될 수 있습니다.

현재 코드에서는 산이 존재할 때 DP가 1 이상이므로 보통 문제가 되지 않습니다. 하지만 불변식을 명확하게 하려면 다음처럼 처리하는 것이 좋습니다.

```python
def update(self, idx, value):
    ti = idx + self.base

    if value == 0:
        self.tree[ti] = (0, 0)
    else:
        self.tree[ti] = (value, idx)

    while (ti := ti >> 1) > 0:
        self.tree[ti] = max(
            self.tree[ti * 2],
            self.tree[ti * 2 + 1],
        )
```

---

## 13.3 메모리 사용량이 큼

다음 배열은 빈 리스트를 백만 개 생성합니다.

```python
dp_val = [[] for _ in range(h_max + 1)]
```

파이썬의 빈 리스트 하나도 객체이므로 메모리 사용량이 상당합니다.

또한 세그먼트 트리에 튜플을 약 210만 개 생성합니다.

```python
self.tree = [(0, 0) for _ in range(self.base << 1)]
```

따라서 실행 직후에도 메모리가 대략 수백 MB에 가까워질 수 있습니다.

메모리 제한이 512MB라면 가능성이 있지만, 256MB라면 위험할 수 있습니다.

`dp_val`은 실제로 등장한 높이만 저장하도록 딕셔너리를 사용할 수 있습니다.

```python
from collections import defaultdict

dp_val = defaultdict(list)
```

이렇게 하면 사용하지 않는 높이에 대해 백만 개의 빈 리스트를 만들 필요가 없습니다.

---

## 13.4 `100` 명령은 초기화하지 않음

현재 `100` 명령은 기존 자료구조를 비우지 않고 산을 추가합니다.

```python
if cmd == 100:
    n, *mountain = v
    for h in mountain:
        add_func(h)
```

문제에서 `100` 명령이 정확히 한 번만 들어온다면 괜찮습니다.

여러 번 들어올 수 있다면 기존 상태를 초기화해야 합니다.

---

## 13.5 입력값 검증이 없음

다음 상황은 모두 오류를 발생시킬 수 있습니다.

```python
remove_func()           # A가 비어 있을 때
get_score(m_idx)        # m_idx가 범위를 벗어날 때
add_func(h)             # h가 0~1,000,000 범위를 벗어날 때
```

코딩 테스트에서는 입력 조건으로 보장되는 경우가 많으므로 반드시 문제는 아닙니다.

# 14. 핵심 불변식

이 코드를 이해할 때는 다음 네 가지 불변식을 기억하면 됩니다.

```text
A[i]
= i번째 산의 높이
```

```text
dp_idx[i]
= i번째 산에서 끝나는 LIS 길이
```

```text
dp_val[h][-1]
= 현재 높이 h에서 끝나는 LIS의 최댓값
```

```text
seg.tree[1]
= 현재 전체 수열의 (LIS 길이, 해당 LIS의 최대 마지막 높이)
```

특히 이 구조가 가능한 이유는:

> 산이 뒤에만 추가되고, 삭제도 마지막 산부터 이루어지기 때문이다.

즉 일반적인 동적 LIS가 아니라 **스택 롤백이 가능한 동적 LIS**입니다.

코드에서 가장 정교한 부분은 `dp_val[h]`를 높이별 스택으로 두어, 마지막 산을 삭제했을 때 세그먼트 트리를 이전 상태로 정확히 복원한다는 점입니다. 다음 단계에서는 문제 원문과 함께 `get_score()`의 수식이 왜 `dp_idx[m_idx] + dp - 1`인지 검증하는 것이 핵심입니다.
