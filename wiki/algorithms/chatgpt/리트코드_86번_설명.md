# LeetCode 86: Partition List — 개념과 구현 가이드

## 문제 요약
- 입력: 단일 연결 리스트 `head`, 정수 `x`.
- 목표: **값이 x보다 작은 노드들**을 앞쪽으로, **x 이상인 노드들**을 뒤쪽으로 재배치한 새 리스트를 만들되,  
  **각 그룹 내부에서는 기존 상대적 순서(안정성, stability)를 유지**해야 함.
- 출력: 재배치된 리스트의 `head`.

## 핵심 아이디어 (안정적 1-패스 분할)
가장 실용적인 방법은 **두 개의 보조 리스트**를 만드는 것입니다:
- `before` 리스트: 값 `< x` 인 노드들이 원래 순서를 유지한 채 연결됨
- `after` 리스트: 값 `>= x` 인 노드들이 원래 순서를 유지한 채 연결됨

실제 노드를 **새로 만들지 않고** 기존 노드 포인터만 재배치합니다.  
마지막에 `before`의 끝과 `after`의 시작을 연결하면 전체 결과가 됩니다.

복잡도: 시간 `O(n)`, 추가 공간 `O(1)` (더미 포인터만 사용, 노드 재활용)

---

## 동작별 구현 체크리스트

### 1) 초기화
- 목적: 분할을 간단히 하려고 두 개의 **더미(dummy) 노드**와 꼬리 포인터를 준비.
- 해야 할 일
  - `before_dummy`, `after_dummy` 두 개의 더미 노드를 만든다.
  - `before_tail = before_dummy`, `after_tail = after_dummy`.
  - 순회를 위한 `cur = head`.
- 실수 방지 포인트: 더미를 쓰면 “첫 노드를 어떻게 붙일지”에 대한 분기 로직이 사라져 코드가 단순해집니다.

### 2) 순회 준비 & 다음 포인터 백업
- 목적: 현재 노드를 분류해 다른 리스트로 이동해도 **순회가 끊기지 않게** 하기.
- 해야 할 일
  - 매 반복마다 `next_node = cur.next`를 **먼저** 백업합니다.
- 실수 방지 포인트: 백업 없이 포인터를 바꾸면 나머지 리스트를 잃어버리거나 사이클이 생길 수 있습니다.

### 3) 분류 & 붙이기 (핵심)
- 목적: 안정적 분할(원래 순서 유지).
- 해야 할 일
  - `cur.val < x` 이면: `before_tail.next = cur`, `before_tail = cur`
  - 아니면: `after_tail.next = cur`, `after_tail = cur`
  - 그 다음 `cur = next_node`로 진척.
- 실수 방지 포인트:
  - “값만 복사”가 아니라 **노드 자체를 이동**합니다(값 스왑 X).
  - 각 꼬리 포인터를 **이동 후 갱신**하는 것을 잊지 말기.

### 4) 마무리 연결 & 꼬리 끊기
- 목적: 두 리스트를 하나로 합치고, 끝을 정확히 닫기.
- 해야 할 일
  - **중요**: `after_tail.next = None` 로 **리스트의 꼬리를 끊기** (사이클 방지).
  - `before_tail.next = after_dummy.next` 로 두 리스트 연결.
- 실수 방지 포인트:
  - `after_tail.next = None` 를 빼먹으면 마지막 노드가 원래 리스트의 중간 어딘가를 계속 가리켜 **무한 루프**가 날 수 있습니다.

### 5) 반환 & 검증
- 목적: 완성된 리스트의 시작 지점 반환 및 엣지 케이스 점검.
- 해야 할 일
  - 결과 `head`는 `before_dummy.next`.
  - 만약 모든 노드가 `>= x` 였다면 `before_dummy.next`는 `None`이고, 이때도 `after_dummy.next`가 전체 결과이므로 연결 로직대로면 정상 반환됩니다.
- 실수 방지 포인트:
  - `None` 처리, 빈 리스트 처리, 단일 노드 처리 등을 간단 테스트로 확인하세요.

## 예시로 보는 흐름
입력: `1 → 4 → 3 → 2 → 5 → 2`, `x = 3`  
- `before`: 1, 2, 2 (등장 순서 유지)  
- `after`: 4, 3, 5 (등장 순서 유지)  
- 연결 결과: `1 → 2 → 2 → 4 → 3 → 5`

---

## 엣지 케이스 체크리스트
- 빈 리스트 (`head == None`)
- 모든 노드 `< x` → `after`가 비어 있음
- 모든 노드 `>= x` → `before`가 비어 있음
- 중복값이 많음 (예: 모두 3, `x=3`) → 전부 `after`로 가야 함
- 음수/양수 혼재, `x`가 매우 작거나 큼
- 하나의 노드만 존재

---

## 디버깅/검증 팁
- 순회가 끝나지 않거나 IDE가 멈춘다면 **사이클**을 의심 → `after_tail.next = None` 확인.
- 분할 후 **상대적 순서가 바뀌었다면**, 정렬이나 값 스왑을 했는지 확인(안 됨). 반드시 “붙이는 순서”만으로 처리해야 합니다.
- 유닛 테스트 예시(의사 테스트):
  - `[]`, `x=1` → `[]`
  - `[1]`, `x=1` → `[1]`이 `after`로 가야 함
  - `[2,1]`, `x=2` → `[1,2]`
  - `[3,3,3]`, `x=3` → `[3,3,3]` (전부 `after`)
  - `[1,4,3,0,2]`, `x=2` → `[1,0,4,3,2]`

```python
# LeetCode 86. Partition List

# 단일 연결 리스트 노드 정의 (LeetCode 기본 제공과 동일)
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

class Solution:
    def partition(self, head: ListNode, x: int) -> ListNode:
        # before: 값 < x 인 노드들
        # after : 값 >= x 인 노드들
        before_dummy = ListNode(0)
        after_dummy = ListNode(0)
        before_tail = before_dummy
        after_tail = after_dummy

        cur = head
        while cur:
            nxt = cur.next      # 다음 노드 백업
            cur.next = None     # 기존 링크 끊어 사이클/잔여 연결 방지
            if cur.val < x:
                before_tail.next = cur
                before_tail = cur
            else:
                after_tail.next = cur
                after_tail = cur
            cur = nxt

        # 두 리스트 연결 (before 뒤에 after를 붙임)
        before_tail.next = after_dummy.next

        # 결과 head 반환
        return before_dummy.next

# 복잡도: O(n) 시간, O(1) 추가 공간(더미/포인터만 사용)
```
