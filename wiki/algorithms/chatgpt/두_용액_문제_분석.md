# 두 용액 문제 분석

## 💬 대화 내용 및 Q&A

### ❓ 질문 (User)
```python
N = int(input())
lst = list(map(int, input().split()))

left, right = 0, N - 1

solution = abs(lst[left] + lst[right])
sol_left = left
sol_right = right

while left < right :
    tmp = lst[left] + lst[right]

    if abs(tmp) < solution :
        sol_left = left
        sol_right = right
        solution = abs(tmp)

        if solution == 0 :
            break

    if tmp > 0 :
        right -= 1
    else :
        left += 1

print(lst[sol_left], lst[sol_right])
```
이 코드를 분석해줘

### 💡 답변 (Assistant)
이 코드는 **두 용액 문제(또는 0에 가장 가까운 두 수의 합을 찾는 문제)**를 해결하는 알고리즘입니다. 입력 리스트는 오름차순으로 정렬된 상태라고 가정합니다. 아래는 코드의 분석입니다.

---

### 1. **입력 및 초기화**

```python
N = int(input())  
lst = list(map(int, input().split()))
```

- **`N`**: 리스트 `lst`의 크기 (양의 정수)
- **`lst`**: 정렬된 리스트. 예를 들어, `[-8, -4, -2, 0, 3, 5, 9]` 같은 형태.

```python
left, right = 0, N - 1
```

- **`left`**: 리스트의 시작 인덱스.
- **`right`**: 리스트의 끝 인덱스.

```python
solution = abs(lst[left] + lst[right])
sol_left = left
sol_right = right
```

- **`solution`**: 현재까지 발견한 두 수의 합의 절대값 중 최소값.
- **`sol_left`, `sol_right`**: 최소값을 만드는 두 수의 인덱스.

---

### 2. **투 포인터 알고리즘**

```python
while left < right:
```

- 두 포인터(`left`, `right`)를 사용해 리스트를 탐색합니다. `left`는 0에서 시작하고, `right`는 N-1에서 시작하여 점차 이동합니다.

#### 1. 현재 두 수의 합 계산

```python
tmp = lst[left] + lst[right]
```

- 현재 두 포인터가 가리키는 값의 합을 계산합니다.

#### 2. 절대값 비교 및 업데이트

```python
if abs(tmp) < solution:
    sol_left = left
    sol_right = right
    solution = abs(tmp)

    if solution == 0:
        break
```

- 현재 합의 절대값이 기존 최소값(`solution`)보다 작다면:
  - 최소값과 두 수의 인덱스를 업데이트합니다.
  - **합이 0이라면 완벽한 정답이므로 탐색을 중지합니다.**

#### 3. 포인터 이동

```python
if tmp > 0:
    right -= 1
else:
    left += 1
```

- 합(`tmp`)이 양수라면 **`right`를 왼쪽으로 한 칸 이동**.
  - 큰 값을 줄이기 위해.
- 합이 음수라면 **`left`를 오른쪽으로 한 칸 이동**.
  - 작은 값을 줄이기 위해.

---

### 3. **결과 출력**

```python
print(lst[sol_left], lst[sol_right])
```

- 두 포인터(`sol_left`, `sol_right`)가 가리키는 값을 출력합니다.
- 결과는 0에 가장 가까운 합을 만드는 두 수입니다.

---

### **알고리즘의 특징**

1. **시간 복잡도**
   - 리스트를 처음부터 끝까지 한 번 훑으므로 **O(N)**.
   - 정렬된 리스트를 입력받았다고 가정하기 때문에 정렬에 따른 추가 비용은 없습니다.

2. **공간 복잡도**
   - 입력 리스트를 그대로 사용하며, 추가 공간 사용은 상수 개수의 변수뿐이므로 **O(1)**.

---

### **예제**

#### 입력:
```
7
-8 -4 -2 0 3 5 9
```

#### 출력:
```
-4 3
```

#### 풀이 과정:
1. 초기값: `left = 0`, `right = 6` → 합 = `-8 + 9 = 1`.
2. 업데이트: 최소값 = 1, 두 수 = `-8, 9`.
3. `tmp > 0` → `right` 이동: `right = 5`.
4. `-8 + 5 = -3`. 최소값 업데이트: `-8, 5`.
5. 계속 탐색하여 `-4, 3`에서 절대값이 최소(`0`)로 발견 → 종료.

---

### ❓ 질문 (User)
이 문제는 이분 탐색 알고리즘으로도 해결 가능하다고 하는데, 이분 탐색 알고리즘을 사용해서 해결한 코드도 작성해줘. 그리고 분석해줘.

### 💡 답변 (Assistant)
이 문제를 **이분 탐색 알고리즘**으로 해결하려면 각 원소에 대해 그와 합이 0에 가까운 짝을 이분 탐색으로 찾는 방식으로 접근할 수 있습니다. 아래는 코드와 분석입니다.

---

### **코드**

```python
import bisect

# 입력 처리
N = int(input())
lst = list(map(int, input().split()))

# 오름차순으로 정렬된 상태라고 가정
lst.sort()

solution = float('inf')  # 최솟값을 무한대로 초기화
sol_left, sol_right = 0, 0  # 최종 결과 저장

for i in range(N):
    current = lst[i]
    # 이분 탐색으로 현재 원소의 반대 값을 찾음
    target = -current
    idx = bisect.bisect_left(lst, target, i + 1, N)  # 현재 원소 이후에서만 탐색

    # idx 및 idx-1의 값을 비교 (유효한 범위 내에서)
    if idx < N:  # idx가 리스트 범위를 벗어나지 않을 때
        tmp = abs(current + lst[idx])
        if tmp < solution:
            solution = tmp
            sol_left, sol_right = i, idx

    if idx - 1 > i:  # idx-1이 유효하고, 현재 원소 이후일 때
        tmp = abs(current + lst[idx - 1])
        if tmp < solution:
            solution = tmp
            sol_left, sol_right = i, idx - 1

print(lst[sol_left], lst[sol_right])
```

---

### **코드 분석**

#### **1. 입력 처리 및 초기화**

```python
N = int(input())
lst = list(map(int, input().split()))
lst.sort()
```

- 입력 리스트는 오름차순으로 정렬됩니다. 이 정렬은 이분 탐색을 적용하기 위한 전제 조건입니다.

```python
solution = float('inf')
sol_left, sol_right = 0, 0
```

- `solution`: 현재까지 발견된 두 수의 합의 절대값 중 최솟값.
- `sol_left`, `sol_right`: 최솟값을 만드는 두 수의 인덱스.

---

#### **2. 각 원소에 대해 이분 탐색**

```python
for i in range(N):
    current = lst[i]
    target = -current
    idx = bisect.bisect_left(lst, target, i + 1, N)
```

- **`current`**: 현재 기준이 되는 값.
- **`target`**: 현재 값의 음수 (`-current`). 이 값에 가까운 수를 찾으면 합이 0에 가까워집니다.
- **`idx`**: 이분 탐색으로 `target`보다 같거나 큰 값의 인덱스를 반환합니다. 범위는 `i+1`부터 `N`까지 제한합니다.

---

#### **3. 찾은 값과 비교**

```python
if idx < N:
    tmp = abs(current + lst[idx])
    if tmp < solution:
        solution = tmp
        sol_left, sol_right = i, idx
```

- `idx`가 리스트 범위 안에 있다면, `current`와 `lst[idx]`의 합의 절대값을 계산합니다.
- 절대값이 현재 최소값(`solution`)보다 작으면 최소값과 인덱스를 갱신합니다.

#### **4. 이전 값도 확인**

```python
if idx - 1 > i:
    tmp = abs(current + lst[idx - 1])
    if tmp < solution:
        solution = tmp
        sol_left, sol_right = i, idx - 1
```

- 이분 탐색으로 찾은 값의 바로 이전 값(`idx-1`)도 확인합니다.
- `idx-1`이 유효한 범위 내에 있으면 해당 합의 절대값을 계산하여 최소값과 비교합니다.

---

#### **5. 결과 출력**

```python
print(lst[sol_left], lst[sol_right])
```

- 최종적으로, 절대값이 최소인 두 값을 출력합니다.

---

### **알고리즘의 특징**

1. **시간 복잡도**
   - 외부 루프에서 각 원소에 대해 한 번씩 반복 → O(N).
   - 내부에서 이분 탐색을 수행 → O(log N).
   - 총 시간 복잡도는 **O(N log N)**.

2. **공간 복잡도**
   - 입력 리스트를 정렬된 상태로 유지하며, 상수 개수의 변수를 추가로 사용 → **O(1)**.

---

### **예제**

#### 입력:
```
7
-8 -4 -2 0 3 5 9
```

#### 출력:
```
-4 3
```

#### 풀이 과정:
1. `i = 0`, `current = -8`, `target = 8`. 이분 탐색으로 `idx = 6` (값 `9`).
   - `abs(-8 + 9) = 1`. 최소값 갱신: `solution = 1, sol_left = 0, sol_right = 6`.
2. `i = 1`, `current = -4`, `target = 4`. 이분 탐색으로 `idx = 4` (값 `5`).
   - `abs(-4 + 3) = 1`. 최소값 유지.
3. 나머지 값도 검토 후 최종 결과 `-4, 3`.

---

### ❓ 질문 (User)
```python
# 이분 탐색
N = int(input())
lst = list(map(int, input().split()))

solution = float('inf')
sol_left = sol_right = 0

for i in range(N - 1) :
    curr = lst[i]

    left, right = i + 1, N - 1

    while left < right :
        mid = (left + right) // 2
        tmp = curr + lst[mid]

        if abs(tmp) < solution :
            solution = abs(tmp)
            sol_left = i
            sol_right = mid

            if tmp == 0 :
                break

        if tmp < 0 :
            left = mid + 1
        else :
            right = mid - 1

print(lst[sol_left], lst[sol_right])
```
이 코드를 분석해줘

### 💡 답변 (Assistant)
이 코드는 **두 용액 문제**를 해결하기 위한 **이분 탐색 알고리즘**의 또 다른 구현입니다. 특정 원소를 기준으로 남은 부분에서 이분 탐색을 수행하여 합이 0에 가장 가까운 값을 찾는 방식으로 작동합니다. 아래는 코드의 분석입니다.

---

### **코드 분석**

#### **1. 입력 처리 및 초기화**

```python
N = int(input())
lst = list(map(int, input().split()))
```

- **`N`**: 리스트의 크기.
- **`lst`**: 정렬된 입력 리스트 (정렬된 상태라고 가정).
  - 예: `[-8, -4, -2, 0, 3, 5, 9]`.

```python
solution = float('inf')
sol_left = sol_right = 0
```

- **`solution`**: 현재까지 발견된 두 수의 합의 절대값 중 최솟값.
- **`sol_left`, `sol_right`**: 최솟값을 만드는 두 수의 인덱스.

---

#### **2. 각 원소에 대해 이분 탐색**

```python
for i in range(N - 1):
    curr = lst[i]
    left, right = i + 1, N - 1
```

- 외부 루프에서 각 원소 `lst[i]`를 기준으로 이분 탐색을 수행.
- **`curr`**: 기준이 되는 현재 원소.
- **`left, right`**: 기준 원소 다음 범위(`i+1`부터 `N-1`)에서 이분 탐색.

---

#### **3. 이분 탐색 구현**

```python
while left < right:
    mid = (left + right) // 2
    tmp = curr + lst[mid]
```

- **`mid`**: `left`와 `right`의 중간 지점.
- **`tmp`**: 기준 원소(`curr`)와 중간 원소(`lst[mid]`)의 합.

---

#### **4. 최솟값 갱신**

```python
if abs(tmp) < solution:
    solution = abs(tmp)
    sol_left = i
    sol_right = mid

    if tmp == 0:
        break
```

- 현재 합의 절대값이 기존 최솟값(`solution`)보다 작으면:
  - **`solution`**, **`sol_left`**, **`sol_right`**를 갱신.
- 합이 **0**이라면 최적의 정답이므로 즉시 탐색을 종료.

---

#### **5. 포인터 이동**

```python
if tmp < 0:
    left = mid + 1
else:
    right = mid - 1
```

- 합(`tmp`)이 음수면:
  - 왼쪽 포인터(`left`)를 오른쪽으로 이동 → 더 큰 값을 찾음.
- 합이 양수면:
  - 오른쪽 포인터(`right`)를 왼쪽으로 이동 → 더 작은 값을 찾음.

---

#### **6. 결과 출력**

```python
print(lst[sol_left], lst[sol_right])
```

- 최종적으로, 절대값이 최소인 두 값을 출력합니다.

---

### **알고리즘의 특징**

#### 시간 복잡도

1. 외부 루프: 각 원소에 대해 **O(N)**.
2. 내부 이분 탐색: 범위 `N`에서 절반씩 줄어듦 → **O(log N)**.
3. 전체 시간 복잡도: **O(N log N)**.

#### 공간 복잡도

- 추가적인 데이터 구조 없이 상수 개수의 변수만 사용 → **O(1)**.

---

### **예제 실행**

#### 입력
```
7
-8 -4 -2 0 3 5 9
```

#### 출력
```
-4 3
```

#### 풀이 과정

1. **`i = 0`, `curr = -8`**
   - 초기 탐색 범위: `left = 1`, `right = 6`.
   - `mid = 3`, `lst[mid] = 0`, `tmp = -8 + 0 = -8` → 절대값 8.
   - `left` 이동 후, `mid = 4`, `lst[mid] = 3`, `tmp = -8 + 3 = -5` → 절대값 5 (갱신).
   - 종료 시 최솟값은 `-8, 3`.

2. **`i = 1`, `curr = -4`**
   - 초기 탐색 범위: `left = 2`, `right = 6`.
   - `mid = 4`, `lst[mid] = 3`, `tmp = -4 + 3 = -1` → 절대값 1 (갱신).
   - `left` 이동 후, `mid = 5`, `lst[mid] = 5`, `tmp = -4 + 5 = 1` → 절대값 1 (유지).
   - 최솟값은 `-4, 3`.

3. 최종 결과: `-4`와 `3`의 합이 0에 가장 가까움.

---

### **코드 특징 및 장점**

- 이 코드는 **직접적인 이분 탐색**을 사용하여 모든 원소 쌍을 탐색하지 않고 효율적으로 최소값을 찾습니다.
- 투 포인터 방식보다 조금 더 직관적이지만, 이분 탐색 구현이 필요한 점에서 약간의 복잡성이 추가될 수 있습니다.
