### 💡 답변 (Assistant)

응집도는 그냥 정의만 외우면 안 되고, **“좋은 설계냐 나쁜 설계냐를 판단하는 기준”**으로 이해해야 해.

# ✅ 문제 분석

**응집도(Cohesion)** 는  
**하나의 모듈 내부 요소들이 서로 얼마나 밀접하게 관련되어 있는가**를 나타내는 개념이야.

즉,

- 한 모듈 안의 기능들이
- **하나의 목적을 위해**
- 얼마나 잘 모여 있는지를 보는 것

이라고 이해하면 돼.

### 핵심 키워드
- 모듈 내부
- 기능 간 관련성
- 하나의 목적
- 독립성
- 높을수록 좋음

---

# 🎯 응집도란?

👉 **모듈 내부의 구성 요소들이 서로 얼마나 강하게 연관되어 있는가를 나타내는 정도**

쉽게 말하면,

- **응집도가 높다**  
  → 모듈이 **딱 한 가지 일을 잘 한다**
- **응집도가 낮다**  
  → 모듈이 **이 일도 하고 저 일도 하고**, 서로 관련 없는 기능이 섞여 있다

---

# 📌 응집도가 왜 중요한가?

응집도가 높은 모듈은 좋은 모듈이야. 이유는 다음과 같아.

### 1. 이해하기 쉽다
모듈이 한 가지 책임만 가지므로 코드 해석이 쉬움

### 2. 수정이 쉽다
기능이 한곳에 모여 있어서 변경 범위가 명확함

### 3. 재사용이 쉽다
목적이 분명한 모듈은 다른 시스템에서도 가져다 쓰기 좋음

### 4. 오류가 적다
서로 관련 없는 기능이 섞이지 않으므로 부작용이 줄어듦

### 5. 유지보수가 좋다
정보처리기사에서 자주 연결되는 포인트:
**응집도는 높을수록, 결합도는 낮을수록 좋다**

---

# ✅ 응집도의 직관적 예시

## 예시 1) 응집도가 높은 경우
```python
def calculate_total_price(items):
    ...
```

이 함수는 “총 가격 계산”만 담당함.  
기능이 명확하지?  
→ **응집도 높음**

---

## 예시 2) 응집도가 낮은 경우
```python
def process_data():
    로그인 처리
    회원가입 처리
    주문 계산
    파일 저장
    이메일 발송
```

서로 관련 없는 기능이 한 함수에 다 들어있음  
→ **응집도 낮음**

---

# 📚 응집도의 종류

응집도는 보통 **낮은 것 → 높은 것** 순서로 외워.

## 1️⃣ 우연적 응집도 (Coincidental Cohesion)
가장 낮은 응집도

### 의미
모듈 내부의 요소들이 **아무 관련 없이 우연히** 모여 있는 상태

### 예시
- 잡다한 유틸 함수들을 한 파일에 마구 넣음
- 관련 없는 기능을 한 모듈에 넣음

### 특징
- 왜 같이 있는지 이유가 없음
- 유지보수 최악
- 재사용성 낮음

---

## 2️⃣ 논리적 응집도 (Logical Cohesion)

### 의미
비슷한 성격의 기능들을 논리적으로 묶었지만,  
실제로는 **하나의 기능 흐름**은 아님

### 예시
```python
입력 처리 모듈
```
이 안에
- 키보드 입력
- 마우스 입력
- 파일 입력
이 다 들어 있음

겉으로 보면 “입력”이라는 공통점은 있지만,  
실제로 수행되는 작업은 각각 다름.

### 특징
- 하나의 논리적 분류 기준으로 묶음
- 보통 제어 플래그나 조건문으로 동작이 갈림

---

## 3️⃣ 시간적 응집도 (Temporal Cohesion)

### 의미
특정한 **같은 시점**에 수행된다는 이유로 묶은 것

### 예시
- 시스템 시작 시 초기화 작업 모듈
- 종료 시 정리 작업 모듈

예:
- 로그 파일 열기
- 메모리 초기화
- 환경 설정 읽기

이 작업들은 기능적으로 완전히 같은 건 아니지만  
“프로그램 시작 시” 한꺼번에 수행됨.

### 특징
- 수행 시점이 같아서 묶임
- 기능 자체의 연관성은 강하지 않음

---

## 4️⃣ 절차적 응집도 (Procedural Cohesion)

### 의미
모듈 안의 요소들이 **특정한 순서**로 실행되어야 해서 묶인 경우

### 예시
1. 데이터 읽기
2. 데이터 검사
3. 결과 출력

이 작업들이 같은 자료를 다루지 않을 수도 있지만  
절차상 순서가 있어서 함께 묶임

### 특징
- 실행 순서가 중요
- 그러나 같은 데이터를 중심으로 묶인 것은 아닐 수 있음

---

## 5️⃣ 교환적 응집도 / 통신적 응집도 (Communicational Cohesion)

### 의미
모듈 내부 요소들이 **같은 입력 데이터 또는 같은 출력 데이터**를 사용해서 묶인 경우

### 예시
- 같은 고객 정보를 읽어서
- 주소 출력
- 연락처 출력
- 포인트 출력

이 기능들은 모두 **같은 데이터**를 사용함

### 특징
- 같은 데이터를 공유
- 절차적 응집도보다 더 강함

※ 책에 따라 **통신적 응집도**라고 많이 나와.

---

## 6️⃣ 순차적 응집도 (Sequential Cohesion)

### 의미
한 요소의 **출력이 다음 요소의 입력**이 되는 형태로 강하게 연결된 경우

### 예시
1. 데이터 읽기
2. 읽은 데이터를 정렬
3. 정렬한 데이터를 출력

앞 단계 결과가 바로 다음 단계 입력이 됨

### 특징
- 처리 흐름이 연속적임
- 기능 간 연관성이 강함

---

## 7️⃣ 기능적 응집도 (Functional Cohesion)
가장 높은 응집도

### 의미
모듈이 **오직 하나의 기능만 수행**하고,  
그 기능 수행에 필요한 모든 요소가 밀접하게 관련된 상태

### 예시
```python
def sort_scores(scores):
    ...
```

이 함수는 점수 정렬만 수행함.

### 특징
- 목적이 하나
- 가장 이상적인 형태
- 재사용성, 유지보수성 최고

---

# ✅ 응집도 순서 정리

낮음 → 높음 순서

**우연적 → 논리적 → 시간적 → 절차적 → 통신적(교환적) → 순차적 → 기능적**

이 순서는 시험에 매우 잘 나와.

---

# 📌 암기 포인트

### 가장 낮은 응집도
👉 **우연적 응집도**

### 가장 높은 응집도
👉 **기능적 응집도**

### 같은 시점
👉 **시간적 응집도**

### 같은 데이터 사용
👉 **통신적(교환적) 응집도**

### 출력이 다음 입력
👉 **순차적 응집도**

### 하나의 기능만 수행
👉 **기능적 응집도**

---

# 🔎 헷갈리기 쉬운 부분

## 1. 절차적 응집도 vs 순차적 응집도

둘 다 순서가 있어 보여서 많이 헷갈려.

### 절차적 응집도
- 단순히 실행 순서가 중요

### 순차적 응집도
- 앞의 결과가 뒤의 입력이 됨

즉,  
**데이터 흐름 연결까지 있으면 순차적 응집도**야.

---

## 2. 논리적 응집도 vs 기능적 응집도

### 논리적 응집도
- 비슷한 종류로 묶은 것
- 실제로는 여러 기능

### 기능적 응집도
- 한 가지 기능만 수행

예를 들어,

- “입력 관련 기능 모음” → 논리적 응집도
- “회원 정보 입력 처리” → 기능적 응집도

---

## 3. 시간적 응집도 vs 절차적 응집도

### 시간적 응집도
- 같은 시점에 실행

### 절차적 응집도
- 같은 순서로 실행

즉,
- “시작할 때 몰아서 실행” → 시간적
- “1번 후 2번 후 3번 절차” → 절차적

---

# 📚 결합도와 같이 보면 더 잘 이해됨

| 구분 | 의미 | 좋은 방향 |
|---|---|---|
| 응집도 | 모듈 내부 요소 간 관련성 | **높을수록 좋음** |
| 결합도 | 모듈 간 의존성 | **낮을수록 좋음** |

좋은 소프트웨어 구조는

👉 **응집도는 높고**  
👉 **결합도는 낮아야 한다**

---

# 🧠 실기시험 포인트 정리

✔ 응집도는 **모듈 내부의 관련성**  
✔ 응집도는 **높을수록 좋다**  
✔ 가장 낮은 응집도는 **우연적 응집도**  
✔ 가장 높은 응집도는 **기능적 응집도**  
✔ 순서만 중요하면 **절차적 응집도**  
✔ 앞 출력이 뒤 입력이면 **순차적 응집도**  
✔ 같은 시점 수행이면 **시간적 응집도**  
✔ 같은 데이터 사용이면 **통신적 응집도**

---

# ✅ 시험용 한 줄 암기

**“우논시절통순기”**  
→ **우연적, 논리적, 시간적, 절차적, 통신적, 순차적, 기능적**

낮음 → 높음 순서로 외우면 돼.

# ✅ 문제 분석

제시된 핵심 키워드를 먼저 잡자.

- VPN 기술
- 공중망 → 사설망
- IP 계층 (3계층)
- AH (Authentication Header)
- ESP (Encapsulating Security Payload)
- 무결성 / 인증 / 기밀성

👉 이건 거의 단서 수준이 아니라 **정답을 직접 말해주는 문제**

---

# 🎯 정답  
👉 **IPSec (IP Security)**

---

# 📌 정답인 이유

IPSec은 다음 특징을 가진다.

| 구분 | 설명 |
|------|------|
| 계층 | 네트워크 계층 (IP 계층, 3계층) |
| 목적 | VPN 구현 |
| 보안 기능 | 인증, 무결성, 기밀성 |
| 주요 프로토콜 | AH, ESP |

---

### 핵심 매칭

문제 요소 → IPSec 특징

- VPN 구현 → IPSec 대표 용도
- AH → 인증 + 무결성
- ESP → 암호화 + 기밀성
- IP 계층 → IPSec 동작 위치

👉 완벽하게 일치

---

# 🔎 IPSec 핵심 구조 (시험 핵심)

## 1️⃣ AH (Authentication Header)

- 데이터 **무결성 보장**
- 송신자 **인증**
- **암호화는 안 함**

👉 키워드: 인증, 무결성

---

## 2️⃣ ESP (Encapsulating Security Payload)

- 데이터 **암호화 (기밀성)**
- 인증 + 무결성도 가능

👉 키워드: 암호화, 기밀성

---

# ⚠️ 시험에서 자주 나오는 포인트

✔ AH는 **암호화 X**  
✔ ESP는 **암호화 O**

이거 한 번 틀리면 계속 틀린다.

---

# 🔥 여기서부터가 진짜 중요한 “연관 개념 묶기”

너가 물어본 핵심 포인트다.  
IPSec 하나만 보면 점수 안 올라간다.  
👉 **VPN + 보안 프로토콜 세트로 묶어서 봐야 한다**

---

# 📚 1️⃣ VPN 기술 묶음 비교 (핵심)

## 🔹 IPSec VPN
- 계층: 3계층 (Network)
- 특징: **가장 표준적 VPN**
- 사용: 기업 네트워크

---

## 🔹 SSL VPN
- 계층: 7계층 (Application)
- 특징: 웹 브라우저 기반
- 대표: HTTPS

👉 비교 핵심

| 구분 | IPSec | SSL |
|------|------|------|
| 계층 | 3계층 | 7계층 |
| 접근 | 네트워크 전체 | 특정 서비스 |
| 사용성 | 설정 필요 | 브라우저만 있으면 가능 |

---

# 📚 2️⃣ 보안 프로토콜 비교 (시험 단골)

## 🔹 IPSec vs SSL vs TLS

| 항목 | IPSec | SSL/TLS |
|------|------|--------|
| 계층 | 3계층 | 4~7계층 |
| 적용 범위 | 전체 IP 패킷 | 애플리케이션 |
| 대표 사용 | VPN | HTTPS |

---

# 📚 3️⃣ IPSec 동작 모드 (이거 시험 자주 나옴)

## 1. Transport Mode
- **IP 헤더 유지**
- 데이터 부분만 보호

👉 호스트 ↔ 호스트

---

## 2. Tunnel Mode
- **전체 IP 패킷 암호화**
- 새로운 IP 헤더 생성

👉 VPN에서 주로 사용

---

✔ 시험 포인트

- VPN = **Tunnel Mode**

---

# 📌 정답인 이유

Cursor 패턴은 자료구조를 순회할 때 사용하는 개념으로,  
디자인 패턴에서는 이를 **Iterator Pattern**이라고 부른다.

---

## Iterator Pattern 특징

| 구분 | 설명 |
|------|------|
| 목적 | 컬렉션 내부 구조를 노출하지 않고 순회 |
| 역할 | 반복자(Iterator)를 통해 접근 |
| 장점 | 내부 구현과 순회 로직 분리 |

---

### 핵심 개념

👉 “자료구조 내부를 직접 건드리지 않고 순차적으로 접근”

---

### 예시 (Python 개념)

```python
for item in collection:
    ...
```

→ 내부 구조 몰라도 순회 가능  
→ Iterator 패턴 적용

# 🔎 왜 Cursor라고 부르나?

- Cursor = “현재 위치를 가리키는 포인터”
- 데이터베이스에서도 “커서(cursor)” 사용

👉 즉,  
**데이터를 하나씩 이동하면서 접근하는 방식**

# 🎯 정답  
👉 **AES (Advanced Encryption Standard)**

# 📌 정답인 이유

AES는 다음 특징을 가진다.

| 구분 | 설명 |
|------|------|
| 개발 | NIST |
| 목적 | DES 대체 |
| 블록 크기 | 128bit |
| 키 길이 | 128 / 192 / 256bit |
| 방식 | 대칭키 |

👉 문제의 모든 조건과 정확히 일치

---

# 🔎 AES 핵심 구조 (시험 핵심)

AES는 **치환-치환 네트워크(SPN, Substitution-Permutation Network)** 구조

### 주요 연산 단계

1️⃣ SubBytes (치환)  
2️⃣ ShiftRows (행 이동)  
3️⃣ MixColumns (열 혼합)  
4️⃣ AddRoundKey (키 추가)

👉 이 4개는 시험에서 그대로 나옴

---

# 🔥 DES vs AES 비교 (매우 중요)

| 구분 | DES | AES |
|------|-----|-----|
| 블록 크기 | 64bit | 128bit |
| 키 길이 | 56bit | 128/192/256bit |
| 구조 | Feistel | SPN |
| 보안성 | 취약 | 매우 강력 |
| 현재 사용 | 거의 안 함 | 표준 |

👉 핵심 포인트

- DES는 **키 길이 짧아서 깨짐**
- AES는 **현대 표준**

---

# 📚 여기서부터 “연관 개념 묶기” (중요)

이 문제 하나로 아래 4개를 같이 묶어야 한다.

---

# 📚 1️⃣ 대칭키 vs 공개키 (무조건 같이 나옴)

## 🔹 대칭키 암호 (AES, DES)

- 같은 키로 암호화/복호화
- 빠름
- 키 관리 어려움

---

## 🔹 공개키 암호 (RSA)

- 공개키 / 개인키
- 느림
- 키 교환 문제 해결

---

👉 시험 핵심

| 구분 | 대칭키 | 공개키 |
|------|------|--------|
| 속도 | 빠름 | 느림 |
| 키 | 하나 | 두 개 |
| 대표 | AES | RSA |

---

# 📚 2️⃣ 블록암호 vs 스트림암호

## 🔹 블록 암호
👉 AES, DES

- 일정 크기 블록 단위 처리

---

## 🔹 스트림 암호
👉 RC4

- 1bit 또는 1byte 단위

---

👉 시험 포인트

- AES = 블록 암호

---

# 📚 3️⃣ 블록 암호 운영 모드 (진짜 중요)

AES는 단독이 아니라 **모드와 같이 출제됨**

## 대표 모드

| 모드 | 특징 |
|------|------|
| ECB | 단순, 보안 취약 |
| CBC | 이전 블록과 XOR |
| CFB | 스트림처럼 사용 |
| OFB | 오류 전파 없음 |
| CTR | 병렬 처리 가능 |

---

👉 핵심 암기

- ECB = 취약 (패턴 노출)
- CBC = 가장 기본
- CTR = 빠름 (병렬 처리)

---

# 📚 4️⃣ Triple DES (DES 보완)

DES의 약점 보완하려고 나온 것

👉 3번 암호화

- EDE 방식 (Encrypt-Decrypt-Encrypt)

---

👉 시험 포인트

- DES → 약함  
- 3DES → 개선  
- AES → 표준

---

| 경로 | 고정 | 매번 다름 |
| 순서 | 보장 | 보장 안됨 |
| 안정성 | 높음 | 낮음 |
| 속도 | 느림 | 빠름 |

---

# 📚 여기서부터 “연관 개념 묶기” (중요)

이 문제 하나로 최소 4개 같이 공부해야 한다.

---

# 📚 1️⃣ 회선교환 vs 패킷교환

## 🔹 회선교환 (Circuit Switching)

- 통신 전에 **물리적 회선 확보**
- 예: 전화

👉 특징
- 안정적
- 자원 낭비

---

## 🔹 패킷교환 (Packet Switching)

- 데이터를 패킷 단위로 분할
- 네트워크 자원 공유

👉 특징
- 효율적
- 지연 발생 가능

---

👉 핵심 비교

| 구분 | 회선교환 | 패킷교환 |
|------|----------|----------|
| 연결 | 고정 | 유동 |
| 효율 | 낮음 | 높음 |
| 예 | 전화 | 인터넷 |

---

# 📚 2️⃣ 패킷교환 내부 유형

👉 지금 문제 핵심

- 가상회선
- 데이터그램

---

# 📚 3️⃣ OSI 계층과 연결

## 🔹 데이터그램 방식
👉 **IP (3계층)**

- 대표 프로토콜: IP
- 인터넷 기본 구조

---

## 🔹 가상회선 방식
👉 과거 네트워크

- X.25
- Frame Relay

---

👉 시험 포인트

- IP = 데이터그램 방식

---

# 📚 4️⃣ TCP vs UDP (같이 나옴)

이거 무조건 연결된다.

## 🔹 TCP

- 연결형
- 순서 보장
- 신뢰성 있음

👉 가상회선 느낌

---

## 🔹 UDP

- 비연결형
- 순서 보장 없음
- 빠름

👉 데이터그램 느낌

---

👉 핵심 비교

| 구분 | TCP | UDP |
|------|-----|-----|
| 연결 | O | X |
| 신뢰성 | O | X |
| 속도 | 느림 | 빠름 |

---

# 🔎 헷갈릴 수 있는 포인트

## ❌ 회선교환 vs 가상회선

- 둘 다 “연결” 느낌이라 헷갈림

👉 차이

| 구분 | 회선교환 | 가상회선 |
|------|----------|----------|
| 경로 | 물리적 | 논리적 |
| 방식 | 전용 회선 | 패킷 기반 |

---

## ❌ 데이터그램 vs UDP

- 비슷하지만 다름

👉 데이터그램 = 네트워크 계층 개념  
👉 UDP = 전송 계층 프로토콜

---

# 🧠 실기시험 포인트 정리

✔ 가상회선 = 연결형  
✔ 데이터그램 = 비연결형  
✔ IP = 데이터그램  
✔ TCP = 연결형  
✔ UDP = 비연결형  

---

# 🎯 한 줄 암기

👉 **“연결하면 가상회선, 독립이면 데이터그램”**

---

# 📚 추가로 공부해야 할 것 (강력 추천)

이 문제 풀었으면 반드시 같이 보자:

---

## 1️⃣ 교환 방식 3가지

- 회선교환
- 패킷교환
- 메시지교환

---

## 2️⃣ 프로토콜 연결

- IP → 데이터그램
- TCP → 연결형
- UDP → 비연결형

---

## 3️⃣ OSI 계층별 역할

- 3계층 → IP
- 4계층 → TCP/UDP

---

## 4️⃣ 네트워크 성능 요소

- 지연 (Delay)
- 처리량 (Throughput)
- 패킷 손실

---

# 🚀 실전 대비 팁

시험에서 이렇게 바뀐다:

- “경로를 미리 설정” → 가상회선  
- “각 패킷 독립 전송” → 데이터그램  
- “IP 기반” → 데이터그램  
- “순서 보장 없음” → 데이터그램  

---

원하면 다음 단계로  
👉 **네트워크 핵심 개념 (OSI + TCP/IP + 프로토콜) 한 번에 정리**  
👉 또는 **기출 변형 문제 10개**로 실전 훈련시켜줄게.

---

### ❓ 질문 (User)
결합도 중 제어 요소가 전달되는 경우의 결합도를 영어로 (      ) Coupling이라고 한다.
---
이거 연관된 공부 알려줘.

### 💡 답변 (Assistant)
좋다. 이 문제는 **결합도 유형 암기 + 키워드 매칭 문제**다.  
특히 “무슨 데이터가 전달되느냐”로 구분하는 유형이라 실기에서 매우 자주 나온다.

---

# ✅ 문제 분석

핵심 키워드:

- 결합도
- 제어 요소 전달

👉 여기서 “제어 요소”는  
**if, switch, flag 같은 흐름 제어 값**을 의미한다.

---

# 🎯 정답  
👉 **Control Coupling**

---

# 📌 정답인 이유

## Control Coupling (제어 결합도)

- 한 모듈이 다른 모듈에게  
  **제어 정보(플래그, 조건값 등)**를 전달하여  
  **동작 방식을 결정**하게 하는 결합

---

### 예시

```python
def process(mode):
    if mode == 1:
        do_A()
    else:
        do_B()
```

👉 `mode` 값이 **제어 요소**  
👉 외부에서 내부 동작을 결정

→ **Control Coupling**

---

# 🔥 핵심 개념

👉 “데이터가 아니라 동작을 결정하는 값이 넘어오면”  
→ **Control Coupling**

---

# 📚 여기서부터 “연관 개념 묶기” (핵심)

이 문제 하나로 **결합도 전체 순서**를 같이 외워야 한다.

---

# 📚 1️⃣ 결합도 종류 (높음 → 낮음)

👉 시험은 이 순서 그대로 나온다

**Content → Common → External → Control → Stamp → Data**

---

## 1️⃣ 내용 결합도 (Content Coupling) ❌ 최악

- 다른 모듈 내부를 직접 접근

---

## 2️⃣ 공통 결합도 (Common Coupling)

- 전역 변수 공유

---

## 3️⃣ 외부 결합도 (External Coupling)

- 외부 시스템/포맷 의존

---

## 4️⃣ 제어 결합도 (Control Coupling) ⭐ 지금 문제

- 제어 값 전달

---

## 5️⃣ 스탬프 결합도 (Stamp Coupling)

- 구조체 일부 사용

---

## 6️⃣ 자료 결합도 (Data Coupling) ✅ 최고

- 필요한 데이터만 전달

---

# 📌 핵심 정리

| 결합도 | 특징 |
|------|------|
| Control | 제어 값 전달 |
| Stamp | 구조체 전달 |
| Data | 값만 전달 |

---

# 📚 2️⃣ 결합도 vs 응집도 (무조건 같이 나옴)

| 구분 | 의미 | 좋은 방향 |
|------|------|-----------|
| 결합도 | 모듈 간 의존성 | 낮을수록 좋다 |
| 응집도 | 모듈 내부 관련성 | 높을수록 좋다 |

---

👉 시험 핵심 문장

**“결합도는 낮고, 응집도는 높을수록 좋다”**

---

# 📚 3️⃣ 헷갈리는 유형 비교 (중요)

## 🔹 Control vs Data

| 구분 | Control | Data |
|------|--------|------|
| 전달 | 제어값 | 데이터 |
| 목적 | 동작 제어 | 값 전달 |

---

## 🔹 Control vs Stamp

| 구분 | Control | Stamp |
|------|--------|--------|
| 전달 | 제어 값 | 구조체 |
| 특징 | 흐름 제어 | 불필요 데이터 포함 |

---

# 📚 4️⃣ 시험에서 자주 나오는 키워드

이거 매칭 연습해야 한다.

| 키워드 | 결합도 |
|------|--------|
| 제어 플래그 | Control |
| 구조체 전달 | Stamp |
| 전역 변수 | Common |
| 내부 접근 | Content |
| 단순 데이터 | Data |

---

# 🔎 헷갈릴 수 있는 오답

## ❌ Data Coupling
- 단순 값 전달
- 제어 아님

---

## ❌ Stamp Coupling
- 구조체 전달
- 제어 아님

---

## ❌ Common Coupling
- 전역 변수 공유

---

# 🧠 실기시험 포인트 정리

✔ 제어 요소 전달 → Control Coupling  
✔ 결합도는 낮을수록 좋다  
✔ Control은 중간 정도 결합도  
✔ Data Coupling이 가장 좋다  

---

# 🎯 한 줄 암기

👉 **“제어 값 넘기면 Control Coupling”**

---

# 📚 추가로 공부해야 할 것 (강력 추천)

이 문제 풀었으면 반드시 같이 공부:

---

## 1️⃣ 결합도 순서 암기

👉 **Content → Common → External → Control → Stamp → Data**

---

## 2️⃣ 응집도 순서 (같이 묶기)

👉 **우논시절통순기**

---

## 3️⃣ 설계 품질 기준

- 결합도 ↓
- 응집도 ↑

---

## 4️⃣ 자주 나오는 비교 문제

- Control vs Data  
- Stamp vs Data  
- Content vs Common  

---

# 🚀 실전 대비 팁

시험에서 이렇게 바뀐다:

- “제어 플래그 전달” → Control  
- “구조체 전달” → Stamp  
- “전역 변수 공유” → Common  
- “내부 코드 접근” → Content  

---

원하면 다음 단계로  
👉 **결합도 + 응집도 혼합 문제 10개 (실전형)**  
👉 또는 **틀리기 쉬운 유형만 모아서 훈련** 시켜줄게.
