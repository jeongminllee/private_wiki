## 문제

다음 중 **운영체제의 성능 평가 기준**에 해당하지 않는 것은?

1. 사용 가능도  
2. 신뢰도  
3. 실행 시간  
4. 처리능력  

---

## 정답

👉 **2번 신뢰도**

---

## 1️⃣ 문제 해설 (출제 의도 & 풀이 전략)

출제자는 다음을 구분할 수 있는지를 확인합니다.

* **운영체제 성능 평가 기준**
  * 얼마나 빠르고 효율적으로 처리하는가?
  * 자원을 얼마나 잘 활용하는가?
* **시스템 품질/특성**
  * 안정적인가?
  * 고장이 잘 안 나는가?

👉 핵심 판별 기준  
**“성능(Performance) vs 품질(Quality Attribute)”**

---

## 2️⃣ 정답인 이유 (2번 신뢰도)

### ❌ 2번 신뢰도 (Reliability)

**신뢰도**란?

* 시스템이 **고장 없이 정상적으로 동작하는 정도**
* 오류 발생 빈도, 장애 가능성 등과 관련

👉 이는 **성능(Performance)** 이 아니라  
👉 **시스템의 품질 특성(Quality Attribute)** 에 해당합니다.

즉,

* 처리 속도 ❌
* 처리량 ❌
* 응답 시간 ❌  

→ **성능 평가 기준 아님**

따라서 **정답은 2번**

---

## 3️⃣ 나머지 선지 분석 (왜 옳은가)

### 1번 ✔ 사용 가능도 (Availability)

* 시스템이 **얼마나 자주 사용 가능한 상태인가**
* 장애 시간 대비 정상 운영 시간 비율

👉 운영체제의 **운영 효율 및 성능 평가 요소**

---

### 3번 ✔ 실행 시간 (Turnaround Time)

* 작업 제출 → 결과 완료까지 걸리는 시간
* 짧을수록 성능이 좋음

👉 **대표적인 OS 성능 지표**

---

### 4번 ✔ 처리능력 (Throughput)

* **단위 시간당 처리할 수 있는 작업량**
* 다중 프로그래밍 환경에서 중요

👉 운영체제 성능 평가의 핵심 요소

---

## 4️⃣ 틀렸다면 무엇을 추가로 공부해야 하나?

이 문제를 틀렸다면  
👉 **“성능 지표 vs 시스템 특성”이 섞여 있는 상태**입니다.

### 반드시 정리할 핵심 개념

#### 📌 운영체제 성능 평가 기준

| 구분 | 내용 |
|---|---|
| 처리능력 | 단위 시간당 처리량 |
| 응답 시간 | 요청 → 첫 반응까지 시간 |
| 실행 시간 | 작업 시작 → 종료 |
| 사용 가능도 | 시스템 가동 비율 |

#### 📌 성능 ❌ (품질 특성)

* 신뢰도(Reliability)
* 안정성(Stability)
* 보안성(Security)

---

## 5️⃣ 시험장에서 바로 쓰는 판별 요령

* **시간 / 처리량 / 자원 효율**
  → 성능 평가 ⭕
* **고장 / 오류 / 안정**
  → 성능 아님 ❌

**외부 인터럽트와 내부 인터럽트를 정확히 구분하는지**를 묻는 **대표적인 개념 구분 문제**입니다.

## 문제

인터럽트의 종류에서 **외부 인터럽트에 해당하지 않는 것**은?

1. program check  
2. machine check  
3. input/output  
4. power fail  

---

## 정답

👉 **1번 program check**

---

## 1️⃣ 문제 해설 (출제 의도 & 풀이 전략)

출제자는 다음 구분을 정확히 알고 있는지를 확인합니다.

* **외부 인터럽트 (External Interrupt)**
  * CPU 외부 하드웨어 요인
* **내부 인터럽트 (Internal Interrupt)**
  * 프로그램 실행 중 오류나 예외

👉 핵심 판별 기준  
**“원인이 CPU 외부인가, 프로그램 실행 내부인가?”**

---

## 2️⃣ 정답인 이유 (1번 program check)

### ❌ 1번 program check

**Program Check**란?

* 프로그램 실행 중 발생하는 오류
  * 0으로 나누기
  * 오버플로
  * 잘못된 명령어
  * 주소 오류 등

👉 이는 **CPU 내부에서 발생하는 인터럽트**
👉 즉, **내부 인터럽트(= 예외, Exception)**

따라서  
**외부 인터럽트에 해당하지 않음 → 정답**

---

## 3️⃣ 나머지 선지 분석 (왜 옳은가)

### 2번 ✔ machine check

* 하드웨어 이상
  * CPU 고장
  * 메모리 패리티 오류 등

👉 **CPU 외부 하드웨어 원인**
👉 외부 인터럽트

---

### 3번 ✔ input/output

* 입출력 장치의 작업 완료, 오류 발생 등
* 키보드, 디스크, 프린터 등

👉 대표적인 **외부 인터럽트**

---

### 4번 ✔ power fail

* 전원 이상, 정전 등
* 시스템 외부 환경 요인

👉 명백한 **외부 인터럽트**

---

## 4️⃣ 틀렸다면 무엇을 추가로 공부해야 하나?

이 문제를 틀렸다면  
👉 **인터럽트 분류 기준이 암기 수준에서 정리되지 않은 상태**입니다.

### 반드시 정리할 기출 핵심

#### 📌 인터럽트 분류 (정보처리기사 기준)

| 구분 | 종류 |
|---|---|
| 내부 인터럽트 | Program check |
| 외부 인터럽트 | I/O, Machine check, Power fail |
| 소프트웨어 인터럽트 | Supervisor call(SVC) |

---

## 5️⃣ 시험장에서 바로 쓰는 판별 요령

* **Program / Overflow / Divide by zero**
  → 내부 인터럽트 ❌
* **I/O / Power / Machine**
  → 외부 인터럽트 ⭕

👉 **“Program = 내부”**  
이 한 단어만 기억해도 실수 안 합니다.

---

**객체지향 설계 원칙과 일반 경영·통계 법칙을 구분할 수 있는지**를 묻는 **기본 개념 판별 문제**입니다.

## 문제

다음 중 **객체지향 설계 원칙**에 해당하지 않는 것은?

1. 파레토 법칙  
2. 개방 폐쇄  
3. 인터페이스 분리  
4. 의존성 뒤집기

## 정답

👉 **1번 파레토 법칙**

---

## 1️⃣ 문제 해설 (출제 의도 & 풀이 전략)

출제자는 다음을 정확히 알고 있는지를 봅니다.

* **객체지향 설계 원칙(SOLID)** 에 포함되는 개념
* 소프트웨어 공학 전반에서 쓰이지만  
  **객체지향 설계 원칙은 아닌 개념**

👉 핵심 전략  
**“SOLID 5대 원칙에 들어가는가?”** 로 빠르게 판별

---

## 2️⃣ 정답인 이유 (1번 파레토 법칙)

### ❌ 1번 파레토 법칙 (Pareto Principle)

* 전체 결과의 **80%는 20%의 원인에서 발생**
* 경영학, 경제학, 품질 관리 등에서 사용

👉 **객체지향 설계 원칙 아님**
👉 SOLID와 무관

따라서 **정답은 1번**

---

## 3️⃣ 나머지 선지 분석 (왜 옳은가)

### 2번 ✔ 개방-폐쇄 원칙 (OCP)

* **확장에는 열려 있고**
* **변경에는 닫혀 있어야 한다**

👉 SOLID의 **O (Open-Closed Principle)**

---

### 3번 ✔ 인터페이스 분리 원칙 (ISP)

* 사용하지 않는 인터페이스에 의존하지 말 것
* **작고 명확한 인터페이스로 분리**

👉 SOLID의 **I (Interface Segregation Principle)**

---

### 4번 ✔ 의존성 뒤집기 원칙 (DIP)

* 구체 클래스 ❌  
* 추상화(인터페이스)에 의존 ⭕

👉 SOLID의 **D (Dependency Inversion Principle)**

---

## 4️⃣ 틀렸다면 무엇을 추가로 공부해야 하나?

이 문제를 틀렸다면  
👉 **SOLID 원칙 5개가 머릿속에 한 세트로 정리되지 않은 상태**입니다.

### 반드시 암기해야 할 핵심 (시험용)

#### 📌 SOLID 5대 객체지향 설계 원칙

| 약자 | 원칙 |
|---|---|
| S | 단일 책임 원칙 |
| O | 개방-폐쇄 원칙 |
| L | 리스코프 치환 원칙 |
| I | 인터페이스 분리 원칙 |
| D | 의존성 역전(뒤집기) 원칙 |

---

## 5️⃣ 시험장에서 바로 쓰는 판별 요령

* **SOLID에 안 들어간다?**
  → 정답 후보
* **경영·통계·품질 관리 용어**
  → 객체지향 설계 원칙 ❌

👉 **“파레토 = 80:20 = 객체지향 아님”**

---

## 문제

다음 C 프로그램의 실행 결과는?

```c
int main()
{
    int a = 3, b = 1, c = 1;
    if(a = 5) b++;
    if(a == 5) c++;
    printf("%d %d\n", b, c);
    return 0;
}
```

1. 0 2  
2. 2 2  
3. 1 0  
4. 2 0  

---

## 정답

👉 **2번 (2 2)**

---

## 1️⃣ 문제 해설 (출제 의도 & 풀이 전략)

출제자는 다음 두 가지를 동시에 확인합니다.

* `=` (대입 연산자)
* `==` (비교 연산자)
* `if` 문에서 **조건식의 참/거짓 판단 기준**

👉 핵심 전략  
**“if문 안에서 = 이 나오면, 먼저 값 대입 → 그 결과로 참/거짓 판단”**

---

## 2️⃣ 코드 한 줄씩 해석

### 🔹 초기값

```c
int a = 3, b = 1, c = 1;
```

* a = 3
* b = 1
* c = 1

---

### 🔹 첫 번째 if문

```c
if(a = 5) b++;
```

#### 핵심 포인트

* `a = 5` → **비교 ❌ / 대입 ⭕**
* 대입 후 `a`의 값은 **5**
* C언어에서

  * 조건식 결과가 **0이면 false**
  * **0이 아니면 true**

👉 `a = 5` → 값은 5 → **true**

따라서,

* `b++` 실행
* b = 1 → **2**

---

### 🔹 두 번째 if문

```c
if(a == 5) c++;
```

* 현재 a는 이미 **5**
* `a == 5` → **true**

따라서,

* `c++` 실행
* c = 1 → **2**

---

### 🔹 최종 출력

```c
printf("%d %d\n", b, c);
```

👉 출력 결과  
**2 2**

---

## 3️⃣ 정답인 이유

| 변수 | 최종 값 |
|---|---|
| b | 2 |
| c | 2 |

따라서 정답은  
👉 **2번 (2 2)**

---

## 4️⃣ 나머지 선지가 틀린 이유 요약

* **1번 (0 2)**  
  → b 초기값부터 잘못 이해

* **3번 (1 0)**  
  → 첫 번째 if가 실행되지 않는다고 착각

* **4번 (2 0)**  
  → `==` 조건을 false로 잘못 판단

---

## 5️⃣ 틀렸다면 무엇을 추가로 공부해야 하나?

이 문제를 틀렸다면  
👉 **C언어 조건식 평가 규칙이 정리되지 않은 상태**입니다.

### 반드시 정리할 핵심

#### 📌 C언어 if 조건식 규칙

* `0` → false
* `0이 아닌 모든 값` → true
* `=` : 대입
* `==` : 비교

---

## 6️⃣ 시험장에서 바로 쓰는 판별 요령

* **if(a = 값)**  
  → 무조건 대입 먼저 ❗
* **if(a == 값)**  
  → 값 비교

👉 **“if 안의 = 는 거의 항상 함정”**

---

이 유형은 **정보처리기사 C언어 단골 1순위**입니다.  
다음으로 **증감 연산자 + 조건식 섞은 문제** 나오면  
실전 기준으로 바로 풀어드릴게요.

---

### 바이러스의 특징

* **자기 복제**는 가능
* **다른 프로그램이나 파일에 기생**
* 사용자의 실행 행위가 있어야 확산

👉 **스스로 이동 ❌**

따라서 **정답은 2번**

---

## 3️⃣ 나머지 선지 분석 (왜 옳은가)

### 1번 ✔ 복제

* 바이러스의 가장 기본적인 기능
* 자기 자신을 복사하여 확산

---

### 3번 ✔ 파괴

* 파일 삭제
* 시스템 장애 유발
* 데이터 변조

---

### 4번 ✔ 은폐 (잠복, 위장)

* 정상 프로그램처럼 위장
* 탐지 회피
* 일정 조건까지 잠복

---

## 4️⃣ 틀렸다면 무엇을 추가로 공부해야 하나?

이 문제를 틀렸다면  
👉 **바이러스 vs 웜 vs 트로이목마 차이가 정리되지 않은 상태**입니다.

### 반드시 정리할 기출 핵심

#### 📌 악성코드 비교

| 구분 | 특징 |
|---|---|
| 바이러스 | 숙주 필요, 사용자 실행 필요 |
| 웜 | 네트워크 통해 자가 이동 |
| 트로이목마 | 정상 프로그램 위장, 복제 ❌ |

---

## 5️⃣ 시험장에서 바로 쓰는 판별 요령

* **복제 / 파괴 / 은폐**
  → 바이러스 ⭕
* **스스로 이동 / 네트워크 전파**
  → 바이러스 ❌ (웜)

👉 **“이동 = 웜”**

한 번에 정리해 드릴게요.

### ❓ 질문 (User)
물리적 주소(MAC)를 논리적 주소(IP)로 변한해주는 프로토콜을 무엇이라 하는가?
1. RARP
2. ARP
3. ICMP
4. MtoI

### 💡 답변 (Assistant)
이 문제는 **정보처리기사 필기 – 네트워크 / 주소 변환 프로토콜**에서  
**ARP와 RARP의 방향을 정확히 구분하는지**를 묻는 **대표적인 개념 판별 문제**입니다.

## 문제

물리적 주소(MAC)를 **논리적 주소(IP)로 변환**해주는 프로토콜은 무엇인가?

1. RARP  
2. ARP  
3. ICMP  
4. MtoI  

---

## 정답

👉 **1번 RARP**

---

## 1️⃣ 문제 해설 (출제 의도 & 풀이 전략)

출제자는 다음을 헷갈리지 않는지를 봅니다.

* **ARP** : IP → MAC  
* **RARP** : MAC → IP  

👉 핵심 판별 공식  
**“앞에 있는 주소 → 뒤에 있는 주소”**

---

## 2️⃣ 정답인 이유 (1번 RARP)

### ✔ RARP (Reverse Address Resolution Protocol)

* **MAC 주소를 알고**
* **IP 주소를 알아내는 프로토콜**

즉,

```
MAC  →  IP
```

👉 문제의 조건과 정확히 일치

---

## 3️⃣ 나머지 선지 분석 (왜 틀렸는가)

### 2번 ❌ ARP

* IP 주소 → MAC 주소 변환
* LAN 통신 시 가장 많이 사용

👉 문제와 **방향이 반대**

---

### 3번 ❌ ICMP

* 오류 메시지 전달
* 네트워크 상태 제어 (ping 등)

👉 주소 변환 ❌

---

### 4번 ❌ MtoI

* 존재하지 않는 프로토콜
* 시험용 함정 보기

---

## 4️⃣ 틀렸다면 무엇을 추가로 공부해야 하나?

이 문제를 틀렸다면  
👉 **ARP ↔ RARP 방향 공식이 암기되지 않은 상태**입니다.

### 반드시 암기 (시험용 한 줄)

* **ARP = IP → MAC**
* **RARP = MAC → IP**

---

## 5️⃣ 시험장에서 바로 쓰는 판별 요령

* 문제에 **“물리적 주소 → 논리적 주소”**
  → RARP
* 문제에 **“논리적 주소 → 물리적 주소”**
  → ARP

👉 **“Reverse = 반대 방향”**

---

이 유형 다음에는  
**ARP 패킷 구조, 캐시, 프록시 ARP**까지 같이 묻는 문제가 나옵니다.  
다음 문제 주세요.

### ❓ 질문 (User)
암호 관련 용어에 해당하지 않는 것은?

4. Ciphertext

### 💡 답변 (Assistant)
이 문제는 **정보처리기사 필기 – 정보보안 / 암호 기초 용어**에서  
**암호 관련 기본 용어와 보안 취약점(사고)을 구분할 수 있는지**를 묻는 **개념 판별 문제**입니다.

## 문제

다음 중 **암호 관련 용어에 해당하지 않는 것**은?

1. Authorization  
2. Plaintext  
3. Heartbleed  
4. Ciphertext  

---

## 정답

👉 **3번 Heartbleed**

---

## 1️⃣ 문제 해설 (출제 의도 & 풀이 전략)

출제자는 다음을 구분할 수 있는지를 확인합니다.

* **암호화 과정에서 사용하는 용어**
* **보안 사고·취약점 이름**

👉 핵심 판별 기준  
**“암호의 구성 요소인가, 보안 사건/취약점인가?”**

---

## 2️⃣ 정답인 이유 (3번 Heartbleed)

### ❌ 3번 Heartbleed

* **Heartbleed**
  * OpenSSL의 **메모리 노출 취약점**
  * TLS/SSL 구현 오류
  * 암호 알고리즘이나 암호 용어 ❌

👉 즉,

* 평문 ❌
* 암호문 ❌
* 키 ❌

→ **암호 ‘용어’가 아님**

따라서 **정답은 3번**

---

## 3️⃣ 나머지 선지 분석 (왜 옳은가)

### 1번 ✔ Authorization

* 접근 권한 부여
* 인증(Authentication) 이후 단계
* 보안/암호 시스템에서 사용되는 용어

---

### 2번 ✔ Plaintext

* 암호화되기 전의 원문 데이터
* 암호 용어의 기본 중 기본

---

### 4번 ✔ Ciphertext

* 암호화된 데이터
* Plaintext의 반대 개념

---

## 4️⃣ 틀렸다면 무엇을 추가로 공부해야 하나?

이 문제를 틀렸다면  
👉 **암호 용어 vs 보안 사고 이름을 혼동하는 상태**입니다.

### 반드시 정리할 핵심

#### 📌 암호 관련 기본 용어

| 용어 | 의미 |
|---|---|
| Plaintext | 평문 |
| Ciphertext | 암호문 |
| Key | 암·복호화 키 |
| Authorization | 권한 부여 |

#### 📌 암호 ❌

* Heartbleed
* Shellshock
* Meltdown / Spectre

---

## 5️⃣ 시험장에서 바로 쓰는 판별 요령

* **~text**
  → 암호 용어 ⭕
* **취약점 이름(고유명사)**
  → 암호 용어 ❌

👉 **“Heartbleed = 사고 이름”**

### ❓ 질문 (User)
다중화기의 특징에 대한 설명과 거리가 먼 것은?
1. FDM, TDM, CDM, WDM 등이 있다.
2. 집중화기보다 기술이 정교하고 비용이 비싸다.
3. 전송 채널의 개수와 수신 채널의 개수가 동일하다.
4. 통신 회선의 채널을 정적, 규칙적으로 배분하고 공유한다.

### 💡 답변 (Assistant)
이 문제는 **정보처리기사 필기 – 데이터 통신 / 다중화기(Multiplexer)** 에서  
**다중화기의 개념·특징과 집중화기(Concentrator)와의 차이를 정확히 구분하는지**를 묻는 **대표적인 비교형 문제**입니다.

## 문제

다중화기의 특징에 대한 설명과 **거리가 먼 것**은?

1. FDM, TDM, CDM, WDM 등이 있다.  
2. 집중화기보다 기술이 정교하고 비용이 비싸다.  
3. 전송 채널의 개수와 수신 채널의 개수가 동일하다.  
4. 통신 회선의 채널을 정적, 규칙적으로 배분하고 공유한다.  

---

## 정답

👉 **3번**

---

## 1️⃣ 문제 해설 (출제 의도 & 풀이 전략)

출제자는 다음 두 개념을 비교할 수 있는지를 봅니다.

* **다중화기(Multiplexer)**
* **집중화기(Concentrator)**

👉 핵심 판별 기준  
**“입력 채널 수와 출력 채널 수의 관계”**

---

## 2️⃣ 정답인 이유 (3번)

### ❌ 3번  
> 전송 채널의 개수와 수신 채널의 개수가 동일하다.

이 설명은 **집중화기**의 특징이지,  
**다중화기의 특징이 아닙니다.**

### 왜 틀렸는가?

* **다중화기**
  * 여러 개의 입력 채널 → **하나의 고속 회선**
  * 입력 채널 수 ≠ 출력 채널 수

* **집중화기**
  * 다수의 저속 입력 → 소수의 출력
  * 경우에 따라 **입·출력 채널 수가 동일**

👉 따라서  
**“입력 채널 수 = 출력 채널 수”** 라는 설명은  
다중화기와 거리가 멂 → **정답**

---

## 3️⃣ 나머지 선지 분석 (왜 옳은가)

### 1번 ✔

> FDM, TDM, CDM, WDM 등이 있다.

* 다중화 방식의 대표적인 종류
  * FDM: 주파수 분할
  * TDM: 시간 분할
  * CDM: 코드 분할
  * WDM: 파장 분할

👉 정확한 설명

---

### 2번 ✔

> 집중화기보다 기술이 정교하고 비용이 비싸다.

* 다중화기는
  * 정해진 규칙
  * 정적 채널 분배
* 구현이 복잡 → 비용 상승

👉 맞는 설명

---

### 4번 ✔

> 통신 회선의 채널을 정적, 규칙적으로 배분하고 공유한다.

* 다중화기의 핵심 특징
  * 채널을 **고정적으로 분할**
  * 사전에 정해진 방식으로 공유

👉 교과서 문장

---

## 4️⃣ 틀렸다면 무엇을 추가로 공부해야 하나?

이 문제를 틀렸다면  
👉 **다중화기 vs 집중화기 비교가 정리되지 않은 상태**입니다.

### 반드시 정리할 비교표 (기출 핵심)

| 구분 | 다중화기 | 집중화기 |
|---|---|---|
| 채널 분배 | 정적, 규칙적 | 동적 |
| 입력/출력 채널 | 서로 다름 | 같거나 유사 |
| 비용 | 비쌈 | 저렴 |
| 기술 수준 | 높음 | 낮음 |

---

## 5️⃣ 시험장에서 바로 쓰는 판별 요령

* **FDM / TDM / 고정 분할**
  → 다중화기 ⭕
* **입력 = 출력**
  → 다중화기 ❌ (집중화기)

👉 **“다중화 = 여러 개 → 하나”**

---

👉 **다중화기·집중화기·스위칭 장비**를 섞어서 자주 출제됩니다.
