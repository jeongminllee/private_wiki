## 0. 전체 구조 한 번에 보기

구조는 **DB 2개 + 하루용 페이지 템플릿 1개**야.

1. **🕒 Time Log (원본 시간 기록 DB)**  
   - 모든 시간 기록이 다 여기로 들어감 (날짜, 한 일, 분류).
2. **📆 Daily Summary (일일 요약 DB)**  
   - 하루를 하나의 “페이지”로 보고, 그 안에 그날의 로그를 모으고 요약.
3. **📄 ‘오늘 페이지’ 템플릿 (Daily Summary용 템플릿)**  
   - 이 페이지 안에서만 오늘 시간을 기록.  
   - 페이지는 하루짜리지만, **기록은 Time Log DB에 계속 쌓이고, Daily Summary에 요약이 남음.**

---

## 1. 🕒 Time Log DB 만들기 (원장)

### 1-1. DB 생성
- 페이지 하나 만들고, 이름을 **`🕒 Time Log`** 로 설정
- 데이터베이스 타입: **Table (전체 페이지 DB)**

### 1-2. 속성 설정

필수 필드만 잡을게. (이미 쓰고 있는 DB가 있으면, 여기에 맞춰 이름만 조정해도 돼.)

1. **제목**  
   - 이름: `Task` (또는 `한 일`)
   - 타입: **Title**

2. **날짜**  
   - 이름: `Time`
   - 타입: **Date**  
   - **Start + End 시간 둘 다 쓰는 옵션** 켜기 (시작/끝 시간 입력).

3. **분류**  
   - 이름: `Category`  
   - 타입: **Select**  
   - 예: `Deep Work`, `관리/운영`, `커뮤니케이션`, `휴식`, `생활`, `콘텐츠 제작` 등

4. **소요시간 (시간)**  
   - 이름: `Duration (h)`  
   - 타입: **Formula**  
   - 식:

   ```text
   dateBetween(end(prop("Time")), start(prop("Time")), "minutes") / 60
   ```

5. **일자 키** (날짜별 묶기용 – 선택이지만 있으면 편함)  
   - 이름: `Day Key`  
   - 타입: **Formula**
   - 식:

   ```text
   formatDate(start(prop("Time")), "YYYY-MM-DD")
   ```

6. (선택) **타입/모드**  
   - 이름: `Mode`  
   - 타입: **Select**  
   - 예: `집중`, `표면 작업`, `회의`, `루틴`, `잡무`

7. (선택) **노트**  
   - 이름: `Note`  
   - 타입: Text

> 요약: **모든 시간 기록은 무조건 이 DB에 쌓인다.**  
> 하루용 페이지는 이 DB의 “필터된 뷰”일 뿐.

---

## 2. 📆 Daily Summary DB 만들기 (일별 요약용)

이 DB의 **각 페이지 = 하루**라고 생각하면 돼.

### 2-1. DB 생성
- 이름: **`📆 Daily Summary`**
- 타입: Table (전체 페이지 DB)

### 2-2. 속성 설정

1. **제목**
   - 이름: `Date`  
   - 타입: Title  
   - 예: `2025-12-04 (목)` 이런 식으로 적기

2. **실제 날짜**
   - 이름: `Date Real`  
   - 타입: **Date**  
   - (나중에 주/월 단위 필터할 때 유용함)

3. **Day Key (형식 통일용)**
   - 이름: `Day Key`  
   - 타입: **Formula**  

   ```text
   formatDate(prop("Date Real"), "YYYY-MM-DD")
   ```

4. **Relation – 로그 연결**
   - 이름: `Logs`  
   - 타입: **Relation**
   - 연결 대상: `🕒 Time Log`
   - 이 Relation은 **Time Log DB에도 자동으로 생성**됨 (이름은 보통 `Daily` 같은 식으로 생김. 필요하면 `Day`로 이름 변경).

5. **총 시간 (롤업)**  
   - 이름: `Total Hours`  
   - 타입: **Rollup**
   - `Logs` → `Duration (h)` → `Sum`

6. (선택) **Deep Work 시간**  
   - 이름: `Deep Work (h)`  
   - 타입: **Rollup**
   - `Logs` 뷰를 필터해서 `Category = Deep Work`인 뷰 따로 만들고 쓰는 방식이 조금 복잡하니,  
   처음엔 생략하고 나중에 확장해도 OK.

7. (선택) **오늘 한 줄 요약**
   - 이름: `Note`  
   - 타입: Text  
   - 예: `"콘텐츠 제작에 3시간, 커뮤니케이션에 1.5시간, 체력 떨어짐 느낌"`

## 3. 📄 “오늘만 쓰는 페이지” 템플릿 만들기

이제 핵심:  
**“하루만 쓰는 페이지인데, 기록은 다 남고 요약도 자동으로 쌓이는 구조”**를 템플릿으로 만든다.

### 3-1. Daily Summary에서 템플릿 만들기

1. `📆 Daily Summary` DB 들어가서
2. 우측 상단 `New` 버튼 옆의 `▼` 클릭 → **`+ New template`**

템플릿 이름 예: **`🧱 Daily Log – 템플릿`**

### 3-2. 템플릿 페이지 레이아웃

템플릿 안을 이렇게 구성해줘:

---

#### (1) 상단: 메타 정보

```text
H1: 오늘의 로그 🧱

- 오늘 날짜:  Date Real 속성에서 선택 (오늘로)
- 오늘 목표:  [텍스트 줄 하나]
```

> 실제로는 속성 바에서 `Date Real`을 오늘 날짜로 찍어두고 쓰면 됨.

---

#### (2) 섹션 1 – 오늘 시간 기록 (오늘만 쓰는 영역)

1. `/linked` → **Create linked view of database**
2. `🕒 Time Log` 선택
3. 이 뷰 이름을 **`오늘 로그`** 로 변경
4. 이 뷰에 **필터 2개** 걸기:

   1. `Daily (Relation)` → `Contains` → `Current page`  
      (이 Relation 이름은 `🕒 Time Log` 쪽에서 자동으로 생긴 일별 Relation 이름이야. 만약 `Daily Summary` 이런 이름이면 그걸로.)
   2. (선택) `Time` → `On or after` → `Date Real`  
      & `Time` → `On or before` → `Date Real`  
      → 날짜가 혼동되지 않도록.

> **포인트**:  
> 이 뷰 안에서 새 Row를 추가하면, Notion이 **`Daily` Relation을 자동으로 “현재 하루 페이지”에 연결**해 줘.  
> → 그래서 **“이 페이지 안에서만 오늘 기록을 쌓는 구조”**가 만들어짐.

5. 이 뷰의 **그룹핑**을 `Category`로 두면,  
   - 카테고리별로 기록이 묶이고
   - 각 그룹 하단에 `Duration (h)`를 `Sum`으로 설정하면  
     **카테고리별 시간 합계**가 바로 보인다.

---

#### (3) 섹션 2 – 오늘 요약 블록

템플릿 페이지에 아래처럼 Callout 또는 Toggle로 만들어두기:

```text
🧮 오늘 요약

- 총 시간:  →  상단 속성에서 `Total Hours` 확인
- 가장 많이 쓴 카테고리:  (눈으로 보고 적기)
- 에너지/컨디션:  (텍스트)
- 내일 바꾸고 싶은 것 1가지: (텍스트)
```

> `Total Hours`는 이미 Rollup이라 **오늘 기록만 해도 자동으로 쌓임.**

---

#### (4) 섹션 3 – 회고 메모

```text
📝 오늘 회고

- 오늘 시간을 제일 잘 쓴 구간:
- 시간을 버린 느낌이 든 구간:
- 내일 실험해볼 시간 배치:
```

## 4. 실제 사용 플로우 (하루 루틴)

이제 “어떻게 쓰면 되냐”가 중요하니까, **실제 하루 사용 시나리오**를 짧게 정리해볼게.

### 매일 아침

1. `📆 Daily Summary`에서 `New` 버튼 클릭 → `🧱 Daily Log – 템플릿` 선택
2. 상단 속성에서
   - `Date Real` → 오늘 날짜로 설정
3. 바로 아래 **`오늘 로그`** 뷰에서 시간 기록 시작:
   - Task, Time(시작/끝), Category만 계속 추가

> 이 페이지 = **오늘만 쓰는 작업실**  
> 근데 실제 데이터는 전부 `🕒 Time Log`에 들어가고,  
> 이 하루 페이지와 자동으로 연결되는 구조.

### 하루 중

- 작업할 때마다, 혹은 한 블럭이 끝날 때마다:
  - `오늘 로그`에 한 줄 추가
  - 시작/끝 시간과 카테고리만 잘 적어주면 됨.

### 하루 끝

1. 페이지 상단 `Total Hours` 값 확인
2. 카테고리별 시간 분포는 `오늘 로그` 뷰 하단 합계로 확인
3. 섹션 2 / 3의 회고 질문에 짧게 답 적기

> 이렇게 하면  
> - **원본 데이터**: `🕒 Time Log`에 모두 남아있고  
> - **일별 요약/메모**: `📆 Daily Summary`에 날짜별로 한 장씩 쌓여서  
> - 나중에 “내가 한 달 동안 어떻게 변했지?”를 쉽게 볼 수 있어.

## 5. 변화 추적: 주간/월간 관찰하기

이제 “변화”를 보는 뷰도 하나 만들어 두자.

### (1) Daily Summary에서 주간/월간 뷰 만들기

- `📆 Daily Summary`에 **새 View** 만들기:
  - 이름: `월간 요약`
  - View: Table 또는 Calendar

1. **Calendar 뷰**  
   - `Date Real` 기준으로 Calendar로 보기
   - 각 날짜에 `Total Hours`를 표시해서  
     “내가 어느 날 너무 갈려나갔는지 / 쉬었는지” 감각을 잡기 좋음.

2. **Table 뷰 (리스트)**  
   - 속성으로 `Date Real`, `Total Hours`, `Note`만 남기고 나머지 숨기기
   - 날짜별로 정렬해서, 한 줄 회고 + 총 시간 변화를 눈으로 보기.

---

## 6. 정리 – 이 시스템이 해주는 것

1. **하루 페이지는 딱 오늘만 보기 좋게**  
   - “오늘 로그”만 뜨는 필터 뷰라서, 계속 한 페이지에서 작성해도 정신 안 산만해짐.

2. **데이터는 전부 중앙 원장(Time Log)에 누적**  
   - 필요하면 나중에 카테고리별 합계, 클라이언트별 시간, 프로젝트별 시간 등으로 확장 가능.

3. **Daily Summary가 “날짜별 스냅샷 + 회고 노트” 역할**  
   - 나중에 “5월 둘째 주에 내가 뭘 바꾸려고 했지?”를  
     그대로 다시 읽어볼 수 있음.

---

원하면 다음 단계로,  
- 카테고리별 누적 시간 보는 `📊 Category Summary`까지 붙여서  
“나는 진짜 내가 중요하다고 믿는 일에 시간을 쓰고 있나?”까지 체크하는 구조도 만들어 줄 수 있어.

일단은 **오늘 바로 만들어서 써볼 수 있는 수준**으로만 설계해놨으니,  
실제로 만들어보면서 막히는 부분 생기면 스크린샷/설명 주면, 그 구조에 맞춰 더 미세 튜닝해줄게.

### ❓ 질문 (User)
아 다시 설명해줄게. 예시 사진은 내가 지금 가지고 있는 데일리로 활용할 수 있는 템플릿이야.
지금 데일리로 활용할 수 있는 템플릿을 하나 가지고 있어. 여기에서는 내가 직접 데이터를 입력할꺼야. 입력하는 데이터는 00시부터 24시까지 한 시간 단위로 내가 무엇을 했는지, 한 일을 어떻게 분류할 수 있을지에 대해서 작성할꺼야. 예시로 "|05:00-06:00 | 기상 및 런닝 | 루틴 |" 이런식으로 작성을 할거야.
여기에 옆에는 분류에 따라서 하루동안 얼마의 시간을 해당 분류에 소요하였는지 간략한 요약이 나타나있어. 그리고 하루 시간 자동 집계를 하여 사용시간이 어디에서 가장 많이 썼는지 보여주고 있어. 
여기서 내가 원하는 건 두번째 사진처럼 일일 리포트, 주간 리포트, 월간 리포트, 트래킹 캘린더를 보유한 데이터베이스를 데일리 시간 트래킹 페이지와 연동하여 내가 과거에 작성했던 시간 관리를 보고 반성 및 개선하고, 어떻게 변화하는지 체크하고 싶어. 이런 노션 데이터베이스 페이지를 만들어줘.

### 💡 답변 (Assistant)
좋아, 이제 무슨 그림을 그리고 싶은지 딱 보인다 😊  
“**지금 쓰는 데일리 시간 트래킹 페이지**”는 그대로 쓰면서,  
그 데이터를 **일일 / 주간 / 월간 / 캘린더**로 쌓아두는 구조로 설계해볼게.

아래 순서대로 만들면, 지금 스샷이 **완전한 시간 다이어리 시스템**이 돼.

## 1. 전체 구조 한 번에 정리

### 이미 있는 것 (1일용 템플릿)

- DB `타임 트래킹 / 시간 관리`
  - 시작, 종료, 하는 일, 분류
- 오른쪽에
  - `내 시간 리포트` (텍스트 요약 영역)
  - `하루 시간 자동 집계` (카테고리별 사용시간 막대 그래프)

### 앞으로 만들 것

1. **마스터 로그 DB** : 지금 쓰는 `타임 트래킹`을 “모든 날”의 원장으로 사용  
2. **일일 리포트 DB** : 하루에 1개씩 생기는 “일 단위 요약 페이지”
3. **상위 허브 페이지** :  
   - 토글 안에
     - 일일 리포트 뷰
     - 주간 리포트 뷰
     - 월간 리포트 뷰
     - 트래킹 캘린더 뷰

---

## 2. `타임 트래킹 / 시간 관리`를 “마스터 로그 DB”로 세팅

지금 왼쪽 표를 이렇게 살짝만 손보면 돼.

### 2-1. 필드 구성

기존 컬럼은 유지하고, 몇 개만 추가해줘.

1. **`시작`** – 지금 그대로 (텍스트/선택/시각 어떤 형식이든 OK)
2. **`종료`** – 그대로
3. **`하는 일`** – Text
4. **`분류`** – Select (루틴 / 기본일상 / 자기계발 / 일 / 휴식 …)

여기에 아래 3개를 **추가**:

5. **`날짜`** (Date)
   - 타입: Date (날짜만)
   - 오늘 페이지에서 00~24시 라인 전부 `"오늘 날짜"`로 통일해서 입력

6. **`Duration (h)`** (Formula)
   - 한 줄이 항상 1시간이라면, 그냥 **상수 1** 로 써도 됨:

   ```text
   1
   ```

   (나중에 시작/종료를 이용해서 자동 계산하고 싶으면 바꿔도 됨)

7. **`일일 리포트`** (Relation)
   - 타입: Relation
   - 연결 대상 DB: **(곧 만들) `일일 리포트` DB**
   - 일단 지금은 Relation만 만들어 두고, 나중에 연결할 거야.

> 이렇게 하면 **모든 날짜의 시간 기록은 이 한 DB에 계속 누적**되고,  
> 날짜/분류/주차 등은 뷰와 리포트 DB에서 꺼내 쓰게 돼.

---

## 3. `일일 리포트` DB 만들기

이 DB의 **각 페이지 = 하루 요약 페이지** (두 번째 스샷의 “일일 리포트” 영역).

### 3-1. DB 생성

- 새 페이지 → `데이터베이스 – 전체 페이지`
- 이름: **`일일 리포트`**

### 3-2. 속성 설정

1. **Title**  
   - 이름: `제목`
   - 예: `2025-12-04(목)` 이런 식으로 적게 쓰면 됨

2. **`날짜`** (Date)
   - 타입: Date

3. **`주차`** (Formula)

   ```text
   formatDate(prop("날짜"), "YYYY-ww")
   ```

   → `2025-49` 이런 식으로 주차 키 생성

4. **`월`** (Formula)

   ```text
   formatDate(prop("날짜"), "YYYY-MM")
   ```

   → `2025-12` 이런 식으로 월 키

5. **`일일 트래킹`** (Relation)
   - 타입: Relation
   - 연결 대상: **`타임 트래킹 / 시간 관리` DB**
   - 이 Relation이 바로 앞에서 만든 `일일 리포트` <-> `일일 트래킹` 연결 고리야
   - 반대편(타임 트래킹 DB)에는 자동으로 **`일일 리포트`** 라는 Relation 컬럼이 생길 것

6. **`총 시간`** (Rollup)
   - 타입: Rollup
   - `일일 트래킹` → `Duration (h)` → `Sum`

7. (선택) **`오늘 한 줄 요약`** (Text)
   - 하루 끝에 적는 회고 문장

8. (선택) 나중에 추가할 것들  
   - `컨디션`, `만족도`, `Deep Work 비율` 등은 나중에 확장 가능

---

## 4. “데일리 시간 트래킹 템플릿” 만들기

이제 **`일일 리포트` DB의 한 페이지 안**에  
지금 쓰는 레이아웃(타임 트래킹 + 내 시간 리포트 + 자동 집계)을 넣을 거야.

### 4-1. 템플릿 생성

1. `일일 리포트` DB 열기
2. 우측 상단 `새로 만들기` 옆 `▼` → `+ 새 템플릿`
3. 템플릿 이름: 예) **`🧱 데일리 시간 트래킹`**

템플릿 페이지 안을 아래처럼 구성해줘.

---

### 4-2. 섹션 1 – 헤더 / 메타

페이지 맨 위에 간단히:

```text
H1: 오늘의 시간 트래킹

- 날짜:  (상단 속성에서 `날짜` 선택 → 오늘 날짜)
- 오늘 한 줄 목표:  (텍스트)
```

※ 매일 새로 만들 때 `날짜`만 오늘로 바꾸면 됨.

---

### 4-3. 섹션 2 – “타임 트래킹 / 시간 관리” 연결하기

1. 템플릿 안에서 `/linked` →  
   **“Create linked view of database”** 선택
2. DB로 **`타임 트래킹 / 시간 관리`** 선택
3. 뷰 이름을 `시간 관리 (오늘)` 정도로 바꿔줘

#### ⬇️ 이 뷰에 **필터 2개** 걸기

- 필터 1  
  - `일일 리포트` (Relation 컬럼) → `contains` → `현재 페이지`
- 필터 2 (선택)  
  - `날짜` → `is` → `현재 페이지의 날짜`는 직접 못 걸지만,  
    어차피 위 Relation으로 이미 “이 페이지에 연결된 기록만” 보기 때문에  
    두 번째 필터는 생략해도 됨.

> 💡 **포인트**  
> 이 뷰 안에서 **새 행을 추가**하면,  
> `일일 리포트` Relation이 **자동으로 “현재 페이지”로 들어간다.**  
> → 즉, 이 페이지에서 입력하는 모든 "|05:00-06:00 | 런닝 | 루틴|"이  
> 전부 `타임 트래킹` 마스터 DB에 쌓이면서, **오늘 리포트랑도 연결**되는 구조.

지금 쓰는 형식대로 컬럼 맞춰놓고,  
0~24시까지 라인만 쭉 복사해서 템플릿에 깔아줘도 좋아.  
(날짜만 그날그날 다르고, 나머진 동일한 1시간 블록이니까.)

---

### 4-4. 섹션 3 – “하루 시간 자동 집계” (막대 그래프)

이제 스샷에 있는 막대 그래프를  
“오늘 페이지 전용 뷰”로 만들어주자.

1. 다시 `/linked` → 같은 DB **`타임 트래킹 / 시간 관리`** 선택
2. 이 뷰 이름: **`하루 시간 자동 집계`**
3. 뷰 타입을 **차트(Bar)** 로 변경
4. 필터는 아까와 완전히 동일하게:

   - `일일 리포트` → `contains` → `현재 페이지`

5. 그룹/축 설정:

   - X축: `Duration (h)` → **Sum**
   - 그룹: `분류` (루틴 / 기본일상 / 휴식 …)

그러면 스샷처럼

- 쉼 : 4  
- 기본일상 : 3  
- 루틴 : 2  

이런 식으로 **카테고리별 사용시간**이 자동 집계된다.

---

### 4-5. 섹션 4 – `내 시간 리포트` 박스

지금 스샷처럼 “기본일상 3시간 잡은 평균…” 이런 텍스트 리포트는  
굳이 DB로 안 만들어도 되고, 그냥 텍스트 블록/콜아웃으로 둬도 돼.

예:

```text
📌 나의 일상 리포트

- 기본일상 3시간: ~~ (느낌/평가)
- 루틴 2시간: ~~ 
- 휴식 4시간: ~~ 
- 한 줄 총평:  오늘 하루는 __ 이런 하루였다.
```

필요하면 나중에 이 부분을  
`AI에게 요약 요청 → 텍스트 붙여넣기` 루틴으로 쓰면 된다.

---

## 5. 상위 허브 페이지 만들기 (일/주/월/캘린더)

이제 두 번째 스샷처럼,  
위에서 만든 **`일일 리포트` DB**를 다양한 뷰로 보여주는 “허브”를 만들자.

### 5-1. 새 페이지 생성

- 이름 예: **`Time Diary`** 또는 **`타임 트래킹 허브`**

여기 안에 아래 4개 블록(토글)을 만든다.

---

### 5-2. 일일 리포트 뷰

1. 토글 블록 만들기 → 제목: **`📅 일일 리포트`**
2. 토글 안에서 `/linked` → `일일 리포트` 선택
3. 뷰 이름: `트래킹`
4. 뷰 타입: **Table**

표에 보여줄 컬럼 추천:

- `날짜`
- `총 시간`
- `오늘 한 줄 요약`
- (원하면 `기분`, `만족도` 등도 추가)

정렬: `날짜` 기준 내림차순.

---

### 5-3. 주간 리포트 뷰

1. 토글 블록: **`📆 주간 리포트`**
2. 토글 안에서 `/linked` → `일일 리포트`
3. 새 뷰 만들기:
   - 이름: `주간`
   - 뷰 타입: **Board**
   - 그룹 기준: `주차` (formula)

이렇게 하면:

- 왼쪽 칼럼: `2025-48`
- 다음 칼럼: `2025-49` …

각 칼럼 안에는 그 주에 해당하는 날짜들이 카드로 쌓이고,  
각 카드에 `총 시간`, `오늘 한 줄 요약`이 보이게 설정하면  
**주차별 패턴**이 한눈에 보인다.

---

### 5-4. 월간 리포트 뷰

1. 토글 블록: **`📊 월간 리포트`**
2. `/linked` → `일일 리포트`
3. 새 뷰:
   - 이름: `이번달`
   - 뷰 타입: **Table**
   - 필터:
     - `월` → `contains` → `올해 + 현재 월` (예: `2025-12`)
   - 보여줄 필드: `날짜`, `총 시간`, `오늘 한 줄 요약`

또는

- 뷰 타입을 **Board**
- 그룹 기준: `월`

로 해서, 칼럼 하나가 한 달이 되도록 만들어도 좋다.

---

### 5-5. 트래킹 캘린더 뷰

1. 섹션 제목: **`🗓 트래킹 캘린더`**
2. `/linked` → `일일 리포트`
3. 뷰 타입: **Calendar**
4. 날짜 기준: `날짜` 속성

→ 이 캘린더에서 **날짜를 클릭하고 “새 페이지”를 만들면서  
`🧱 데일리 시간 트래킹` 템플릿을 선택**하면,  
그 날의 일일 리포트 + 시간 트래킹 페이지가 자동으로 생성된다.

## 6. 실제 사용 흐름 정리

### 1) 하루를 시작할 때

1. `Time Diary` (허브 페이지) → 맨 아래 **트래킹 캘린더**로 이동
2. 오늘 날짜 클릭 → “새 페이지” →  
   템플릿 `🧱 데일리 시간 트래킹` 선택
3. 상단 속성에서 `날짜`를 오늘로 세팅

### 2) 하루 동안

- 페이지 안 `시간 관리 (오늘)` 표에서
  - 05:00–06:00 런닝 루틴  
  - 06:00–07:00 런닝 루틴  
  - … 이런 식으로 입력  
- 이때마다 Row들이 **`타임 트래킹` DB에 쌓이고**,  
  Relation 덕분에 이 일일 리포트 페이지와 자동 연결됨

### 3) 하루 마무리

- 같은 페이지에서 `하루 시간 자동 집계` 막대 그래프 확인
- `총 시간`(rollup) 확인
- 아래 텍스트 리포트/회고 작성
- 끝.

그 순간 이미:

- 허브 페이지의 **일일/주간/월간/캘린더 뷰가 전부 자동으로 업데이트**됨  
- 과거 날짜 페이지를 열어보면서  
  - “그때는 루틴이 몇 시간, 휴식이 몇 시간 있었지?”
  - “지난달보다 이번달 Deep Work 비율이 늘었나?”  
  이런 식으로 비교 가능.

---

일단 여기까지 세팅하면,  
**“오늘 쓴 트래킹이 자동으로 과거/주간/월간 히스토리로 축적되는 시스템”**은 완성돼.

다음 단계로,
- 카테고리별 합계를 일일 리포트 DB로 올리거나
- Deep Work 비율, 휴식 비율 같은 지표까지 만들고 싶으면

지금 구조 기준으로 **공식/롤업 예시**까지 더 짜서 보내줄게.
