## 2️⃣ 알고리즘 테스트 케이스 생성 프로젝트 – 기본 프롬프트 템플릿

아래는 **문제 하나당 항상 적용할 “공통 프롬프트/규칙”**으로 쓰기 좋은 형태야.

---

### 📌 테스트 케이스 설계 프롬프트

> 주어진 알고리즘 문제에 대해,  
> **정답 검증 능력을 최대화할 수 있는 테스트 케이스를 체계적으로 설계하라.**  
> 단, 단순 예제 중심이 아닌 **실패 가능성이 높은 입력**을 우선적으로 고려한다.

### 📌 필수 테스트 케이스 분류

아래 유형을 **모두 포함하도록 테스트 케이스를 설계**한다:

1. **최소 입력 (Minimum Case)**
   - 입력 크기, 값의 최솟값
2. **최대 입력 (Maximum Case)**
   - 입력 크기, 값의 최댓값
3. **경계값 (Boundary Case)**
   - 조건 분기 바로 전/후 값
4. **비정형 케이스 (Edge / Corner Case)**
   - 정렬 안 된 입력  
   - 중복 값  
   - 특수 패턴 (모두 같은 값, 단조 증가/감소 등)
5. **시간 복잡도 최악 케이스**
   - O(N²), O(N log N) 알고리즘이 가장 느려지는 입력
6. **공간 복잡도 압박 케이스**
   - 메모리 사용량이 커지는 입력 구조
7. **잘못된 접근을 유도하는 반례**
   - 흔히 떠올리는 naive 풀이가 실패하는 케이스

---

## 3️⃣ 제약사항(Constraints) 작성 템플릿

문제 분석 능력을 키우기 위해 **항상 제약사항을 명시적으로 재작성**하는 걸 추천해.

### 📌 제약사항 작성 규칙

- 입력 크기(N, M 등)
- 값의 범위
- 시간 제한 / 메모리 제한 (플랫폼 기준 추정 가능)
- 허용되는 알고리즘 복잡도 추정

#### 예시
```text
- 1 ≤ N ≤ 100,000
- 각 원소 값은 -10⁹ ≤ A[i] ≤ 10⁹
- 시간 제한: 1초
- 메모리 제한: 512MB
- 예상 허용 복잡도: O(N log N) 이하
```
