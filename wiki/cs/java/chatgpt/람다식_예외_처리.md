## 💬 대화 내용 및 Q&A

### ❓ 질문 (User)
```
public class Main {
 
    static interface F {
        int apply(int x) throws Exception;
    }
 
    public static int run(F f) {
        try {
            return f.apply(3);
        } catch (Exception e) {
            return 7;
        }
    }
 
    public static void main(String[] args) {
 
        F f = (x) -> {
            if (x > 2) {
                throw new Exception();
            }
            return x * 2;
        };
 
        System.out.print(run(f) + run((int n) -> n + 9));
    }
 
}
```
이 코드를 설명해줘.

## ✅ 문제 분석

제시된 코드의 핵심 포인트는 다음과 같습니다.

- **함수형 인터페이스 (Functional Interface)** 사용
- **람다식 (Lambda Expression)** 적용
- **예외 처리 (try-catch)** 흐름
- **throw → catch → 반환값 변경 구조**

→ 핵심 키워드  
람다식, 예외 발생, catch 처리, 반환값 변화

## 🎯 실행 흐름 분석

### 1️⃣ 인터페이스 정의

```java
static interface F {
    int apply(int x) throws Exception;
}
```

- `apply()` 메서드는 **예외를 던질 수 있음 (throws Exception)**
- → 람다식에서 `throw new Exception()` 사용 가능

---

### 2️⃣ run 메서드

```java
public static int run(F f) {
    try {
        return f.apply(3);
    } catch (Exception e) {
        return 7;
    }
}
```

✔ 핵심 구조

| 상황 | 결과 |
|------|------|
| 정상 실행 | f.apply(3) 반환값 |
| 예외 발생 | 7 반환 |

---

### 3️⃣ 첫 번째 실행: `run(f)`

```java
F f = (x) -> {
    if (x > 2) {
        throw new Exception();
    }
    return x * 2;
};
```

- `run(f)` → `f.apply(3)` 호출
- x = 3

✔ 조건 확인

```java
if (x > 2) → true
```

→ **Exception 발생**

✔ 결과 흐름

```
throw → catch → return 7
```

👉 첫 번째 결과 = **7**

---

### 4️⃣ 두 번째 실행: `run((int n) -> n + 9)`

```java
run((int n) -> n + 9)
```

- `f.apply(3)` → 3 + 9 = 12
- 예외 없음

👉 두 번째 결과 = **12**

---

### 5️⃣ 최종 출력

```java
System.out.print(run(f) + run((int n) -> n + 9));
```

👉 계산

```
7 + 12 = 19
```

### ❓ 질문 (User)
```
public class Main{
 
    public static class Parent {
 
        public int x(int i) { return i + 2; }
        public static String id() { return "P";}
        
    }
 
    public static class Child extends Parent {
        
        public int x(int i) { return i + 3; }
        public String x(String s) { return s + "R"; }
        public static String id() { return "C"; }
        
    }
 
    public static void main(String[] args) {
 
        Parent ref = new Child();
        System.out.println(ref.x(2) + ref.id());
        
    }
    
}
```

### 💡 답변 (Assistant)
좋습니다. 이 문제는 **오버라이딩(Overriding)** 과 **정적 메서드(static method)** 의 동작 차이를 묻는 아주 중요한 문제입니다.

---

## ✅ 문제 분석

제시된 코드의 핵심 포인트는 다음과 같습니다.

- `Parent ref = new Child();`
- **인스턴스 메서드** `x(int)` 는 **오버라이딩**
- **정적 메서드** `id()` 는 **오버라이딩이 아니라 숨김(Hiding)**
- 참조변수 타입이 `Parent`

→ 핵심 키워드:  
다형성, 오버라이딩, 정적 메서드, 참조변수 타입 기준

---

## 🎯 정답

👉 **5P**

---

## 📌 실행 흐름 분석

### 1️⃣ 객체 생성

```java
Parent ref = new Child();
```

의미:

- 참조변수 타입: `Parent`
- 실제 객체 타입: `Child`

즉, **부모 타입으로 자식을 참조**하는 **다형성** 상황입니다.

---

### 2️⃣ `ref.x(2)` 실행

`x(int)` 메서드는 **인스턴스 메서드**입니다.

`Parent` 에도 있고 `Child` 에도 같은 형태로 존재하므로  
이것은 **오버라이딩**입니다.

#### Parent

```java
public int x(int i) { return i + 2; }
```

#### Child

```java
public int x(int i) { return i + 3; }
```

실제 객체가 `Child` 이므로, 실행되는 것은 **Child의 x(int)** 입니다.

```java
ref.x(2) = 2 + 3 = 5
```

👉 결과: **5**

---

### 3️⃣ `ref.id()` 실행

```java
public static String id() { return "P"; }
```

```java
public static String id() { return "C"; }
```

여기서 `id()` 는 **static 메서드**입니다.

중요:

- static 메서드는 **오버라이딩되지 않음**
- 참조변수의 **타입 기준으로 호출됨**

즉,

```java
ref.id()
```

는 실제 객체가 `Child` 여도  
참조변수 타입이 `Parent` 이므로

```java
Parent.id()
```

처럼 동작합니다.

👉 결과: **"P"**

---

### 4️⃣ 최종 출력

```java
System.out.println(ref.x(2) + ref.id());
```

앞에서 구한 값:

- `ref.x(2)` → `5`
- `ref.id()` → `"P"`

따라서

```java
5 + "P" = "5P"
```

👉 최종 출력: **5P**

---

## 🔎 헷갈릴 수 있는 오답

### ❌ `5C` 라고 생각하는 경우

많이 틀리는 이유:

- 실제 객체가 `Child` 니까 `id()` 도 `"C"` 라고 착각

하지만 `id()` 는 **static 메서드**라서  
**객체 기준이 아니라 참조변수 타입 기준**입니다.

즉, `Child` 객체여도 `ref` 타입이 `Parent` 이므로 `"P"` 가 나옵니다.

---

## 📚 추가로 공부해야 할 것 (만약 틀렸다면)

이 문제에서 반드시 정리해야 할 것은 다음 2가지입니다.

### 1️⃣ 오버라이딩 vs 오버로딩

#### 오버라이딩
부모 메서드를 자식이 **같은 형태로 재정의**

```java
public int x(int i) { ... }
```

→ 실행 시 **실제 객체 타입 기준**

#### 오버로딩
이름은 같고 매개변수가 다름

```java
public int x(int i) { ... }
public String x(String s) { ... }
```

→ 컴파일 시 **매개변수 형태로 결정**

이 코드의 `x(String s)` 는 오버라이딩이 아니라 **오버로딩**입니다.  
왜냐하면 부모에 없는 새로운 형태이기 때문입니다.

---

### 2️⃣ static 메서드와 일반 메서드 차이

| 구분 | 일반 메서드 | static 메서드 |
|------|-------------|----------------|
| 소속 | 객체 | 클래스 |
| 오버라이딩 | 가능 | 불가(숨김) |
| 결정 기준 | 실제 객체 타입 | 참조변수 타입 |

이 표는 실기에서 매우 중요합니다.

---

## 🧠 실기시험 포인트 정리

✔ `Parent ref = new Child();` → 다형성  
✔ 일반 메서드 호출 → 실제 객체 타입 기준  
✔ static 메서드 호출 → 참조변수 타입 기준  
✔ `x(int)` 는 오버라이딩  
✔ `x(String)` 는 오버로딩  
✔ 정답: **5P**

## 한 줄 핵심 정리

👉 **인스턴스 메서드는 실제 객체를 따르고, static 메서드는 참조변수 타입을 따른다.**

원하시면 제가 이 문제를 바탕으로  
**오버라이딩 / 오버로딩 / static / 다형성** 한 번에 구분하는 표까지 만들어드리겠습니다.

## 4️⃣ 각 프로세스의 대기시간 계산

공식:

**대기시간 = 종료시간 - 도착시간 - 실행시간**

---

### P1
- 종료시간: 20
- 도착시간: 0
- 실행시간: 8

```text
대기시간 = 20 - 0 - 8 = 12
```

---

### P2
- 종료시간: 8
- 도착시간: 1
- 실행시간: 4

```text
대기시간 = 8 - 1 - 4 = 3
```

---

### P3
- 종료시간: 26
- 도착시간: 2
- 실행시간: 9

```text
대기시간 = 26 - 2 - 9 = 15
```

---

### P4
- 종료시간: 25
- 도착시간: 3
- 실행시간: 5

```text
대기시간 = 25 - 3 - 5 = 17
```

## 5️⃣ 평균 대기시간 계산

```text
(12 + 3 + 15 + 17) / 4
= 47 / 4
= 11.75
```

잠깐, 여기서 한 번 더 점검해야 합니다.

---

## ✅ 재검산

RR에서는 **타임슬라이스 종료 시점에 새로 도착한 프로세스와 기존 재삽입 프로세스의 순서**를 정확히 봐야 합니다.

시간 0~4 동안 P2, P3, P4가 이미 도착했으므로  
4ms 시점 큐는:

```text
P2, P3, P4, P1
```

이후 진행은 맞습니다.

간트 차트도 맞습니다.

각 종료시간도 맞습니다.

따라서 대기시간:

- P1 = 20 - 0 - 8 = 12
- P2 = 8 - 1 - 4 = 3
- P3 = 26 - 2 - 9 = 15
- P4 = 25 - 3 - 5 = 17

합계:

```text
12 + 3 + 15 + 17 = 47
```

평균:

```text
47 / 4 = 11.75ms
```

👉 **11.75ms**

## 📌 정답인 이유

라운드로빈은 **선입선출 큐 기반으로 타임 퀀텀만큼 순환 실행**합니다.  
도착시간을 고려하여 큐를 구성하고, 각 프로세스의 종료 시각을 구한 뒤

**대기시간 = 종료시간 - 도착시간 - 실행시간**

공식으로 계산하면 됩니다.

---

## 🔎 헷갈릴 수 있는 오답

### ❌ 실행 시작 전까지 기다린 시간만 계산하는 경우
대기시간은 한 번만 기다린 시간이 아닙니다.

RR에서는 프로세스가 **여러 번 CPU를 양보하고 다시 대기**하므로  
전체 대기시간을 모두 포함해야 합니다.

---

### ❌ 반환시간(Turnaround Time)과 혼동
- 반환시간 = 종료시간 - 도착시간
- 대기시간 = 반환시간 - 실행시간

둘을 헷갈리면 오답이 나옵니다.
