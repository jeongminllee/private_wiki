## ✅ 문제 분석

핵심 포인트를 먼저 뽑자.

- 구조체 배열 선언
- 포인터로 특정 요소 접근
- 문자열 포인터 (`char *`)
- 포인터 연산 (`+`)
- 문자열 일부 출력

👉 핵심 키워드  
**구조체 배열 / 포인터 / 문자열 / 포인터 이동**

---

## 🔍 코드 흐름 분석

### 1️⃣ 구조체 배열 선언
```c
struct Test test[] = {{1, "AB"}, {2, "DC"}, {3, "EB"}};
```

배열 상태:

| 인덱스 | i | g   |
|--------|---|-----|
| 0      | 1 | "AB"|
| 1      | 2 | "DC"|
| 2      | 3 | "EB"|

---

### 2️⃣ 포인터 설정
```c
struct Test *p = &test[1];
```

👉 `p`는 `test[1]`을 가리킴

즉,

- `p->i = 2`
- `p->g = "DC"`

---

### 3️⃣ 핵심 출력문
```c
printf("%s", p->g + (p->i - 1));
```

#### (1) `p->i - 1`
```
2 - 1 = 1
```

#### (2) `p->g + 1`
```
"DC" + 1
```

👉 문자열 `"DC"`에서 **1칸 이동**

```
"D"  "C"
 ↑    ↑
 0    1
```

👉 `+1` → `"C"`를 가리킴

---

### 4️⃣ 최종 출력

```c
printf("%s", "C");
```

👉 결과:

```
C
```

---

## 🎯 정답
👉 **C**

---

## 📌 정답인 이유

- `p->g`는 문자열의 시작 주소
- `(p->i - 1)` 만큼 이동하면 **문자열 중간부터 출력**
- `%s`는 해당 위치부터 **끝까지 출력**

👉 즉,  
**"DC" → "C"만 출력됨**

---

## 🔎 헷갈릴 수 있는 포인트

❌ `p->g[1]`로 착각  
→ 이건 문자 하나 (`'C'`) 반환

❌ `"C"`가 아니라 `"C\0"`까지 고려 안함  
→ `%s`는 널 문자까지 출력

---

## 📚 추가로 공부해야 할 것 (틀렸다면 반드시)

### 1️⃣ 문자열 포인터 연산 (⭐ 중요)
```c
char *str = "ABCDE";

str + 2 → "CDE"
str + 3 → "DE"
```

👉 실기 단골 출제

### 2️⃣ 구조체 포인터 접근
```c
p->g == (*p).g
```

👉 둘 다 동일

---

### 3️⃣ %s vs %c 차이
| 형식 | 의미 |
|------|------|
| %s | 문자열 |
| %c | 문자 하나 |

---

## 🧠 실기시험 포인트 정리

✔ `문자열 + n` → n번째부터 출력  
✔ `%s` → 끝까지 출력  
✔ 구조체 포인터 → `p->멤버`  
✔ 배열 + 포인터 조합 → 출제 빈도 매우 높음

---

필요하면 이 유형 **난이도 높인 문제 (포인터 2중, 문자열 배열, 역참조)**도 만들어줄게.

class Rectangle {

### 💡 답변 (Assistant)
✅ 문제 분석

이 문제의 핵심은 **자바 상속에서 부모 생성자 호출 방법**이다.

제시된 코드의 핵심 포인트는 다음과 같습니다.

- `Square` 클래스가 `Rectangle`을 상속함
- `Rectangle`에는 기본 생성자(`Rectangle()`)가 없음
- 부모 클래스에는 `Rectangle(int width, int height)` 생성자만 존재
- 따라서 자식 클래스 `Square`에서 **부모 생성자를 직접 호출**해야 함

→ 핵심 키워드:  
**상속, 생성자, 부모 생성자 호출, super()**

---

🎯 정답  
👉 `super`

즉, 빈칸은 다음과 같습니다.

```java
super(a, a);
```

---

📌 정답인 이유

`Square`는 `Rectangle`을 상속받고 있다.

```java
class Square extends Rectangle
```

그런데 부모 클래스 `Rectangle`의 생성자는 다음 하나만 있다.

```java
Rectangle(int width, int height) {
    this.width = width;
    this.height = height;
}
```

즉, **기본 생성자 `Rectangle()`가 없다.**

자바에서는 자식 클래스 생성자가 실행될 때, 먼저 부모 생성자가 호출되어야 한다.  
이때 부모의 기본 생성자가 없으면, 자식에서 반드시 `super(인자)`로 직접 호출해야 한다.

따라서

```java
Square(int a) {
    super(a, a);
}
```

로 작성해야 한다.

정사각형은 가로와 세로가 같으므로 `a, a`를 전달하는 것도 자연스럽다.

---

🔍 코드 실행 흐름

### 1️⃣ 객체 생성
```java
Square sq = new Square(10);
```

### 2️⃣ 자식 생성자 호출
```java
Square(int a) {
    super(a, a);
}
```

→ `super(10, 10)` 실행

### 3️⃣ 부모 생성자 실행
```java
Rectangle(int width, int height) {
    this.width = width;
    this.height = height;
}
```

→ `width = 10`, `height = 10`

### 4️⃣ 넓이 계산
```java
return width * height;
```

→ `10 * 10 = 100`

### 5️⃣ 출력 결과
```java
100
```

---

🔎 헷갈릴 수 있는 오답

❌ `this(a, a);`  
→ `this()`는 같은 클래스의 다른 생성자를 호출할 때 사용한다.  
여기서는 부모 클래스 생성자를 불러야 하므로 틀림.

❌ `Rectangle(a, a);`  
→ 자바에서 생성자를 함수처럼 직접 호출할 수 없다.  
반드시 `super(...)` 또는 `this(...)` 형태여야 한다.

❌ 아무것도 안 쓰는 경우  
→ 컴파일러가 자동으로 `super()`를 넣으려 하는데, 부모에 기본 생성자가 없으므로 오류 발생

---

📚 추가로 공부해야 할 것 (만약 틀렸다면)

### 1️⃣ `super()`와 `this()` 차이

| 구분 | 의미 |
|------|------|
| `super(...)` | 부모 클래스 생성자 호출 |
| `this(...)` | 같은 클래스의 다른 생성자 호출 |

---

### 2️⃣ 생성자 호출 규칙

- 생성자의 첫 줄에만 올 수 있음
- `super(...)`와 `this(...)`를 동시에 쓸 수 없음
- 부모 기본 생성자가 없으면 자식에서 반드시 명시해야 함

---

### 3️⃣ 상속에서 자주 나오는 포인트

- `extends` : 상속
- `super` : 부모 멤버/생성자 접근
- `this` : 현재 객체 참조
- 오버라이딩 / 오버로딩 차이

---

🧠 실기시험 포인트 정리

✔ 부모 생성자 호출 → `super()`  
✔ 같은 클래스 다른 생성자 호출 → `this()`  
✔ 부모에 기본 생성자 없으면 `super(인자)` 필수  
✔ 정사각형은 가로, 세로 같으므로 `super(a, a)`

---

최종 정답:

```java
super(a, a);
```

출력 결과:

```java
100
```

원하면 내가 이 문제를 이어서  
**“왜 width, height가 private이면 안 되는지”**,  
**“super와 this의 차이”**,  
**“생성자 문제 5문제 세트”**로 확장해서 같이 풀어줄게.

### 💡 답변 (Assistant)
좋은 질문이다. 이건 **자바 vs 파이썬 생성자 호출 방식의 핵심 차이**라서 실기뿐 아니라 실무에서도 중요하다.

## ✅ 문제 분석

핵심 포인트는 다음이다.

- 자바: `super(...)`
- 파이썬: `super().__init__(...)`
- 왜 문법이 다른가?
- `self`는 왜 붙거나 안 붙는가?

→ 핵심 키워드:  
**생성자 호출 방식, 객체 모델 차이, self, super**

---

## 🎯 핵심 결론 (먼저 정리)

| 언어 | 부모 생성자 호출 |
|------|----------------|
| 자바 | `super(인자)` |
| 파이썬 | `super().__init__(인자)` |

👉 **완전히 다른 개념이다 (문법만 다른 게 아니라 구조가 다름)**

---

## 📌 자바 방식 (컴파일 언어, 정적 구조)

```java
Square(int a) {
    super(a, a);
}
```

### 특징

- `super` = **부모 클래스 생성자 직접 호출**
- 컴파일 시점에 결정됨
- `this`를 자동으로 넘김 (명시 안함)

👉 내부적으로는 이런 느낌
```
Rectangle.__init__(this, a, a)
```
하지만 자바는 `this`를 자동 처리함

---

## 📌 파이썬 방식 (동적 언어, 객체 기반)

```python
class Square(Rectangle):
    def __init__(self, a):
        super().__init__(a, a)
```

### 특징

- `super()` = **부모 객체를 반환**
- 그 뒤에 `. __init__()`를 호출
- **메서드 호출 방식**

👉 구조적으로 이렇게 동작
```
super() → 부모 객체
.__init__(a, a) → 부모 생성자 호출
```

---

## 🔥 핵심 차이 (시험 핵심 포인트)

### 1️⃣ super의 의미 차이

| 구분 | 자바 | 파이썬 |
|------|------|--------|
| super 의미 | 부모 생성자 호출 키워드 | 부모 객체 반환 |
| 동작 방식 | 직접 호출 | 객체 → 메서드 호출 |

---

### 2️⃣ self 차이

#### 자바
```java
super(a, a);
```
👉 `this` 자동 전달

#### 파이썬
```python
super().__init__(a, a)
```
👉 `self`를 안 쓰는 이유  
→ `super()`가 이미 바인딩된 객체 반환

---

### ❗ 잘못된 파이썬 코드 (네가 쓴 형태)

```python
super.__init__(self)
```

👉 ❌ 틀림 이유

- `super`는 함수인데 호출 안함
- `super()`가 되어야 함
- `self`를 직접 넘길 필요 없음

👉 올바른 형태
```python
super().__init__(...)
```

---

## 🔎 더 깊은 차이 (중요)

### 자바
- 단일 상속
- 호출 경로 단순

### 파이썬
- 다중 상속 지원
- **MRO (Method Resolution Order)** 기반

```python
super()
```
👉 단순 부모가 아니라  
👉 **다음 순서의 클래스** 호출

---

## 📚 추가로 공부해야 할 것 (틀렸다면 필수)

### 1️⃣ 파이썬 MRO (★★★★★)
```python
Class.__mro__
```

👉 다중 상속에서 super()가 왜 필요한지 핵심

---

### 2️⃣ 자바 vs 파이썬 객체 모델 차이

| 항목 | 자바 | 파이썬 |
|------|------|--------|
| 타입 | 정적 | 동적 |
| 메서드 호출 | 컴파일 기반 | 런타임 기반 |
| self | 없음 (자동) | 명시 필요 |

---

## 🧠 실기시험 포인트 정리

✔ 자바 → `super()` = 부모 생성자 직접 호출  
✔ 파이썬 → `super()` = 부모 객체 반환 후 메서드 호출  
✔ 파이썬은 반드시 `super()` 형태로 호출  
✔ `super.__init__` ❌ (괄호 없음 → 오류)  
✔ 다중 상속 → 파이썬에서 super 매우 중요

---

## 🔥 한 줄 정리

👉 자바: **"부모 생성자 바로 호출"**  
👉 파이썬: **"부모 객체 가져와서 메서드 호출"**

---

원하면  
👉 **super 없이 부모 호출하는 방식 (`Rectangle.__init__(self, ...)`) 차이**  
👉 **다중 상속에서 super 안 쓰면 터지는 사례**  
까지 실전 문제로 만들어줄게.

---

### 💡 답변 (Assistant)

실기에서 **거의 그대로 출제되는 핵심 유형**이다.

## ✅ 문제 분석

각 보기의 핵심 키워드를 먼저 뽑아보자.

### ㄱ
- 중앙에서 정책 통제
- 사용자 임의 변경 불가
- 군사 / 국가 보안
- 보안 등급 기반

👉 핵심 키워드:  
**중앙 통제 / 등급 기반 / 강제적**

---

### ㄴ
- 역할(Role) 기반
- 사용자 직접 권한 X
- 역할 변경으로 권한 관리

👉 핵심 키워드:  
**Role / 직무 / 권한 묶음**

---

### ㄷ
- 자원 소유자가 권한 설정
- 사용자 마음대로 변경 가능
- 보안성 낮음

👉 핵심 키워드:  
**Owner / 자유 설정 / 유연성 높음**

---

## 🎯 정답

👉 ㄱ: **MAC**  
👉 ㄴ: **RBAC**  
👉 ㄷ: **DAC**

---

## 📌 정답인 이유

### 🔴 ㄱ → MAC (Mandatory Access Control)

| 특징 | 설명 |
|------|------|
| 통제 주체 | 중앙 관리자 |
| 사용자 권한 변경 | 불가능 |
| 기준 | 보안 등급 (Top Secret 등) |
| 사용 환경 | 군대, 정부 |

👉 문제의  
"중앙에서 설정, 변경 불가, 보안 등급"  
→ MAC의 정의 그대로

---

### 🔵 ㄴ → RBAC (Role-Based Access Control)

| 특징 | 설명 |
|------|------|
| 기준 | 역할(Role) |
| 권한 부여 | 역할에 부여 |
| 장점 | 관리 용이 |

👉 문제의  
"직무/역할 기반, 역할만 변경"  
→ RBAC 핵심 특징

---

### 🟢 ㄷ → DAC (Discretionary Access Control)

| 특징 | 설명 |
|------|------|
| 통제 주체 | 자원 소유자 |
| 권한 설정 | 자유롭게 가능 |
| 단점 | 보안 취약 |

👉 문제의  
"소유자가 자유롭게 설정"  
→ DAC 정의 그대로

## 🔎 헷갈릴 수 있는 오답 포인트

❌ MAC vs DAC 헷갈림

| 구분 | MAC | DAC |
|------|-----|-----|
| 권한 결정 | 시스템 | 사용자 |
| 변경 가능 | ❌ | ⭕ |
| 보안 수준 | 높음 | 낮음 |

---

## 📚 추가로 공부해야 할 것 (틀렸다면 필수)

### 1️⃣ 접근통제 3대장 완벽 암기 (★★★★★)

| 모델 | 키워드 |
|------|--------|
| MAC | 강제, 등급 |
| DAC | 소유자 |
| RBAC | 역할 |

---

### 2️⃣ 실무 예시

- MAC → 군사 기밀 시스템
- DAC → 윈도우 파일 권한
- RBAC → 회사 권한 관리 (사원, 관리자 등)

---

## 🧠 실기시험 포인트 정리

✔ "등급 / 중앙 통제" → MAC  
✔ "역할 / 직무" → RBAC  
✔ "소유자 / 자유 설정" → DAC  

👉 이 3개는 **그대로 외우면 점수 먹는 문제**

설명에 해당하는 접근통제 모델을 <보기>에서 골라 빈칸에 작성하시오.

 

ㄱ	중앙에서 보안 정책을 일괄적으로 설정하며, 주체(사용자)가 임의로 수정하거나 변경할 수 없다. 주로 군사 기밀, 국가 보안과 같은 높은 보안 수준이 요구되는 환경에서 사용된다. 보안 등급(Top Secret / Secret / Confidential 등)에 따라 접근 여부가 결정된다.
ㄴ	조직 내에서 부여된 직무나 역할(Role)에 따라 접근 권한을 부여하는 방식이다. 개별 사용자에게 직접 권한을 설정하지 않고, 역할에 권한을 묶어 부여하기 때문에 관리가 용이하며 직무 변경 시 역할만 변경하면 된다.
ㄷ	자원의 소유자(Owner)가 해당 자원에 대한 접근 권한을 자유롭게 부여하거나 회수할 수 있는 방식이다. 파일이나 폴더의 소유자가 읽기/쓰기/실행 권한을 설정하는 것이 대표적인 예로 사용자의 임의 설정이 가능해 보안성이 상대적으로 낮다.
