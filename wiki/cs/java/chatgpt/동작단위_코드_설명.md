### 💡 답변 (Assistant)
좋아. 이 코드는 **필드 `n`**, **매개변수 `n`**, 그리고 **`this.n`** 이 서로 다르다는 점이 핵심이야.  
동작 단위로 아주 잘게 끊어서 볼게.

---

## 1. 클래스 구조 먼저 보기

### Base
```java
class Base {
	int n = 10;
	void display(int n) {
		System.out.print("B" + (n + this.n));
	}
}
```

- `Base` 객체 안에는 필드 `n = 10` 이 있음
- `display(int n)`의 `n`은 **매개변수**
- `this.n`은 **객체 자신의 필드 n**

즉 여기서
```java
(n + this.n)
```
은  
**매개변수 n + 객체의 필드 n**

---

### Derived
```java
class Derived extends Base {
	int n = 20;
	void display(int n) {
		this.n += n;
		System.out.print("D" + this.n);
	}
}
```

- `Derived`는 `Base`를 상속
- 그런데 `Derived` 안에도 `int n = 20;` 이 따로 있음
- 그래서 `Derived` 객체에는 사실상
  - `Base`의 `n = 10`
  - `Derived`의 `n = 20`
  둘 다 존재함
- 다만 `Derived` 클래스 내부에서 `this.n`이라고 하면 **가까운 쪽인 Derived의 n** 을 가리킴

즉
```java
this.n += n;
```
은  
**Derived의 필드 n = Derived의 필드 n + 매개변수 n**

# 특히 헷갈리기 쉬운 포인트

## 1. `display(int n)`의 `n`과 필드 `n`은 다름
예를 들어
```java
void display(int n)
```
여기서 `n`은 **매개변수**

반면
```java
this.n
```
은 **객체의 필드**

---

## 2. `Derived`에는 `n`이 2개처럼 존재
`Derived`는 `Base`를 상속받았기 때문에

- `Base`의 `n`
- `Derived`의 `n`

둘 다 가짐.

하지만 `Derived` 안에서 `this.n`은 기본적으로 **Derived의 n** 을 의미함.

---

## 3. `b.display(n)`은 `Base` 객체로 호출
```java
Base b = new Base();
```
이므로 `b.display(...)`는 무조건 `Base.display(...)`

### ❓ 질문 (User)
• 클래스 (Radar):
• limit라는 정수형 변수를 가지며 초기값은 60이다.
• check(int s) 메서드는 매개변수 s가 limit보다 크면 과속 상태 코드인 "1"을, 그렇지
않으면 안전 상태 코드인 "0"을 반환한다.
클래스 (HighwayRadar):
• Radar 클래스를 상속받는다.
생성자를 통해 부모로부터 물려받은 limit 값을 100으로 변경한다.
check(int s) 메서드를 오버라이딩한다.
• 내부에서 부모의 check(s)를 호출하여 그 결과가 과속 상태 코드인 "1"이라면 벌금을
"1,000,000"를 반환하고, 안전 상태 코드인 "0"라면 "0"를 반환한다.
메인 함수 (Main):
HighwayRadar 객체를 생성한다.
• 속도 값으로 110을 인자로 주어 check 메서드를 호출하고 그 결과를 출력한다.

이 조건대로 자바 프로그래밍을 보여줘.

### 💡 답변 (Assistant)
요구사항을 정확히 반영해서 **상속 + 오버라이딩 + 생성자 초기화 흐름**이 명확하게 드러나도록 구현해볼게.

---

## ✔️ 핵심 설계 포인트
- `Radar`
  - `limit = 60`
  - `check(int s)` → `"1"` 또는 `"0"` 반환

- `HighwayRadar`
  - `Radar` 상속
  - 생성자에서 `limit = 100`으로 변경
  - `check(int s)` 오버라이딩
  - `super.check(s)` 결과 기반으로 벌금 반환

---

## ✔️ 코드

```java
class Radar {
    int limit = 60;

    String check(int s) {
        if (s > limit) {
            return "1";  // 과속
        } else {
            return "0";  // 안전
        }
    }
}

class HighwayRadar extends Radar {

    // 생성자에서 limit 변경
    HighwayRadar() {
        this.limit = 100;
    }

    // 메서드 오버라이딩
    @Override
    String check(int s) {
        String result = super.check(s);  // 부모 메서드 호출

        if (result.equals("1")) {
            return "1000000";  // 벌금
        } else {
            return "0";        // 안전
        }
    }
}

public class Main {
    public static void main(String[] args) {
        HighwayRadar radar = new HighwayRadar();

        String result = radar.check(110);
        System.out.println(result);
    }
}
```

---

## ✔️ 실행 흐름 (중요 포인트만 정확히 짚기)

1. `HighwayRadar` 객체 생성
   - 부모 `limit = 60` → 생성자에서 `100`으로 변경

2. `radar.check(110)` 호출
   - 오버라이딩된 `HighwayRadar.check()` 실행

3. 내부에서
   ```java
   super.check(110)
   ```
   호출됨

4. 부모 기준 판단
   ```java
   110 > 100 → "1"
   ```

5. 결과 처리
   ```java
   "1" → "1000000"
   ```

## ✔️ 시험에서 자주 틀리는 포인트

- `"1"` vs `1` (문자열 vs 정수) 헷갈림 ❌
