# 사용법

이 노트는 새 개념을 넓히는 자료가 아니다. 200문제 진단에서 틀렸거나, 정답이어도 유사 개념과 바꾸어 쓸 위험이 있었던 내용을 **정식 답안 형태로 고정**하는 자료다.

1. 왼쪽의 `단서`만 보고 답을 소리 내어 말한다.
2. 오른쪽 `정답`을 확인한다.
3. 틀린 항목에는 체크하고 10분 뒤 다시 답한다.
4. 영어 철자보다 한국어 정식 명칭을 우선 고정한다. 약어는 한글 명칭과 함께 쓴다.

# 1. 60점 방어 즉시 회상 카드

## 1.1 네트워크·운영체제

| 단서 | 정답 | 혼동 방지 |
|---|---|---|
| 송수신 처리 속도 차이 조절 | **흐름 제어 (Flow Control)** | 오류를 고치는 기능이 아님 |
| 재전송 없이 수신 측이 오류 수정 | **FEC (전진 오류 수정)** | 수신 측이 직접 수정 |
| 재전송을 요구하는 오류 제어 대분류 | **BEC (후진 오류 수정)** | 대표 방식이 ARQ |
| 재전송 요구 방식 | **ARQ** | Stop-and-Wait, Go-Back-N은 ARQ의 하위 방식 |
| 한 프레임 전송 후 ACK 대기 | **Stop-and-Wait ARQ** | 다음 프레임을 보내지 않음 |
| 오류 프레임 이후를 되돌아가 재전송 | **Go-Back-N ARQ** | ARQ의 세부 방식 |
| 네트워크 장비 관리·감시 | **SNMP** | IP 자동 할당은 DHCP |
| IP 주소 자동 할당 | **DHCP** | 장비 관리는 SNMP |
| 메일 전송 | **SMTP** | `SMTP` 철자를 정확히 씀 |
| 서버에 메일을 남기며 여러 기기 동기화 | **IMAP** | POP3는 내려받기 중심 |
| 메일을 내려받고 보통 서버에서 삭제 | **POP3** | 동기화 중심은 IMAP |
| 유선 이더넷 충돌 감지 | **CSMA/CD** | CD = Collision Detection |
| 무선 LAN 충돌 회피 | **CSMA/CA** | CA = Collision Avoidance |
| 실행 중인 프로그램 / 내부 최소 실행 단위 | **프로세스 / 스레드** | 괄호 순서를 바꾸지 않음 |
| 사용자 명령 해석기 / OS 핵심 | **셸 / 커널** | 셸은 인터페이스, 커널은 자원 관리 |
| RR 시간 할당량이 너무 큼 | **FCFS와 유사** | HRN이 아님 |
| RR 시간 할당량이 너무 작음 | **문맥 교환 오버헤드 증가** | Context Switching |

## 1.2 참조 지역성과 REST

| 단서 | 정답 | 한 줄 암기 |
|---|---|---|
| 같은 데이터를 곧 다시 접근 | **시간 지역성** | 같은 것 = 시간 |
| 인접한 메모리 주소 접근 | **공간 지역성** | 옆 주소 = 공간 |
| 다음 명령어를 실행 순서대로 접근 | **순차 지역성** | 다음 순서 = 순차 |
| REST에서 자원 식별 | **URI** | URI는 이름표 |
| REST에서 자원 조회 | **GET** | GET은 동작 |
| 자원을 URI로 식별하고 HTTP 메서드로 조작 | **REST** | 로이 필딩 |

# 2. 보안 정식 용어 카드

## 2.1 보안 솔루션·모델·인증정보 공격

| 단서 | 정답 | 혼동 방지 |
|---|---|---|
| 기업 중요 정보의 외부 유출 탐지·차단 | **DLP (Data Loss Prevention)** | 공격 기법이 아니라 방지 솔루션 |
| 사람의 심리·신뢰 이용 | **사회공학** | 피싱은 사회공학의 하위 공격 |
| 가짜 이메일·웹사이트로 계정 탈취 | **피싱** | 상위 개념은 사회공학 |
| 정상 Wi-Fi와 비슷한 가짜 AP | **이블 트윈 (Evil Twin)** | “가짜 AP = 악성 쌍둥이” |
| 유출 ID·비밀번호 자동 대입 | **크리덴셜 스터핑** | 여러 서비스 로그인을 자동 시도 |
| 기밀성 중심 보안 모델 | **벨-라파듈라 (BLP)** | BLP = 기밀성 |
| 낮은 등급이 높은 등급을 읽지 못함 | **No Read Up** | BLP와 한 묶음 |

## 2.2 공격 기법 구분

| 단서 | 정답 | 혼동 방지 |
|---|---|---|
| 업데이트 서버·배포 파일 변조 | **공급망 공격 (Supply Chain Attack)** | 웜이 아님 |
| 반사 서버 + 출발지 IP 위조 + 증폭 | **DRDoS** | 일반 DDoS보다 반사체가 핵심 |
| `target="_blank"` 뒤 기존 탭 피싱 변조 | **탭내빙 (Tabnabbing)** | 표기를 `탭내빙`으로 고정 |
| 정상 광고를 이용한 악성코드 유포 | **말버타이징 (Malvertising)** | Malicious + Advertising |
| 희생자 IP 위조 + ICMP 브로드캐스트 | **스머핑 (Smurfing)** | ICMP 응답 집중 |
| 출발지·목적지 IP 모두 피해자 IP | **랜드 어택 (Land Attack)** | 단순 스푸핑보다 구체적 명칭 |
| 허용 크기 초과 ICMP 패킷 | **핑 오브 데스 (Ping of Death)** | 큰 Ping |
| 단편화 Offset 조작 | **티어드롭 (Teardrop)** | Fragment 재조합 오류 |
| 특정 표적에 정교한 악성 메일 | **스피어 피싱 (Spear Phishing)** | SMS 피싱은 스미싱 |
| 장기간 은밀한 표적 공격 | **APT** | Advanced Persistent Threat |
| 패치 전 취약점 공백 공격 | **제로데이 공격** | Zero-Day |
| 표적이 자주 가는 사이트를 감염 | **워터링 홀** | 방문을 기다림 |

# 3. 데이터베이스·소프트웨어 공학 비교 학습

## 3.1 정규화와 관계 대수

| 단서 | 정답 |
|---|---|
| 속성값이 원자값 | **1NF** |
| 부분 함수 종속 제거 | **2NF** |
| 이행 함수 종속 제거 | **3NF** |
| 모든 결정자가 후보키 | **BCNF** |
| 다치 종속 제거 | **4NF** |
| 조인 종속 제거 | **5NF** |
| R과 S에 동시에 속하는 튜플 | **교집합 (∩, Intersection)** |
| 후보키의 두 성질 | **유일성, 최소성** |

암기: **도부이결다조** = 도메인 원자값 / 부분 종속 / 이행 종속 / 결정자 / 다치 종속 / 조인 종속.

## 3.2 요구사항·테스트·UML

| 단서 | 정답 | 혼동 방지 |
|---|---|---|
| 제품을 올바르게 만들고 있는가? | **검증 (Verification)** | Product right |
| 올바른 제품을 만들고 있는가? | **확인 (Validation)** | Right product |
| 역할을 직접 연기·시연 | **롤플레잉** | 흐름을 글로 쓰는 것은 시나리오 |
| 사용자·시스템 상호작용 흐름을 이야기로 기술 | **시나리오** | 애자일이 아님 |
| 실행 없이 문서·설계·코드 검토 | **정적 테스트** | 정적 분석은 세부 기법 |
| 입력을 같은 성격의 그룹으로 분할 | **동등 분할** | 대표값 선택 |
| `-1, 0, 50, 51` 같은 경계 선택 | **경계값 분석** | 범위 경계 안팎 |
| 코드 내부의 조건·분기·반복 기준 | **화이트박스 테스트** | 조건 테스트는 세부 기법 |
| 인터페이스 구현 관계 | **실현 관계 (Realization)** | 실체화도 인정 |
| 상속 관계 | **일반화 관계 (Generalization)** | 실선 + 빈 삼각형 |
| 일시 참조·점선 화살표 | **의존 관계 (Dependency)** | 변경 영향 |
| 전체와 부분이 함께 소멸 | **합성 (Composition)** | 강한 전체-부분 |
| 부분이 독립 생존 | **집합 (Aggregation)** | 약한 전체-부분 |

## 3.3 아키텍처·디자인 패턴

| 단서 | 정답 | 혼동 방지 |
|---|---|---|
| 표준 인터페이스 버스에 앱 연결 | **메시지 버스 (EAI)** | 토큰 버스가 아님 |
| 앱끼리 직접 1:1 연결 | **Point-to-Point** | EAI 구축 유형 |
| 중앙 허브가 연계 중개 | **Hub-and-Spoke** | EAI 구축 유형 |
| 데이터가 필터를 순차 통과 | **파이프-필터** | 데이터 스트림 처리 |
| 분산 통신 중개·위치 투명성 | **브로커** | 인터페이스 변환은 어댑터 |
| 단 하나의 인스턴스 | **싱글톤** | 생성 패턴 |
| 호환되지 않는 인터페이스 변환 | **어댑터** | 브리지는 추상화·구현 분리 |
| 객체에 동적으로 기능 추가 | **데코레이터** | 상속 없이 책임 추가 |
| 상태 변화 시 여러 객체에 알림 | **옵저버** | 1:N 알림 |
| 서브클래스가 객체 생성을 결정 | **팩토리 메서드** | 생성 패턴 |
| 연관 객체군 생성 | **추상 팩토리** | 플라이웨이트가 아님 |
| 객체 공유로 메모리 절약 | **플라이웨이트** | 구조 패턴 |
| 알고리즘 골격, 세부 단계는 서브클래스 | **템플릿 메서드** | 빌더가 아님 |
| 생성 과정을 단계별로 분리 | **빌더** | 생성 패턴 |

# 4. 코드·SQL 실수 방지 규칙

## Python

```python
def f(a, b=2, c=3):
    return a + b * c

f(10, 4)     # b=4, c=3 -> 22
f(10, c=4)   # b=2, c=4 -> 18
```

- 위치 인수는 **왼쪽부터 매개변수 칸에 순서대로** 들어간다.
- `max(r, key=r.get)`은 값으로 비교하지만, **키**를 반환한다.
- 가변 기본 인자 `items=[]`는 호출마다 새로 생성되지 않고 공유될 수 있다.

## C

```c
x *= a + b;      // x = x * (a + b)
data[pos++];     // data[pos]를 먼저 사용한 뒤 pos 증가
!(!a);           // a가 0이면 0, 0이 아니면 1
```

- 복합 대입 연산자는 일반 대입식으로 한 번 풀어 쓴다.
- 후위 증감은 **현재 값 사용 후 증가**다.
- 문자열 전체 글자 수에는 공백도 포함한다. `"hello soojebi world"`는 **19자**, 단어는 **3개**다.

## Java

```java
try {
    return value;
} finally {
    // return 전에 반드시 실행
}
```

- `return`을 만나도 `finally`는 먼저 실행된다.
- `static` 변수·초기화 블록은 **클래스 단위로 공유**되며 클래스 로딩 시 한 번 실행된다.

## SQL

```sql
CREATE INDEX idx_학번 ON 학생(학번);
SELECT * FROM 교수 ORDER BY 강의실 DESC, 이름 ASC;
```

- `AVG()`와 `SUM()`은 `NULL`을 제외하고 계산한다.
- `ORDER BY`는 앞 컬럼이 1차, 뒤 컬럼이 동률일 때의 2차 기준이다.

# 5. 재해 복구와 응집도

## 재해 복구 센터

```text
미러 → 핫 → 웜 → 콜드
```

- **미러**: 실시간 복제, 가장 빠른 복구
- **핫**: 시스템·데이터 준비
- **웜**: 장비·기본 환경 준비, 복구 작업 추가 필요
- **콜드**: 건물·전력 등 기본 시설만 준비

## 모듈 응집도

```text
우 < 논 < 시 < 절 < 통 < 순 < 기
```

- 유사한 성격·특정 형태로 분류 → **논리적 응집도**
- 초기화·종료처럼 같은 시간대 처리 → **시간적 응집도**
- 동일 입출력 데이터를 사용 → **통신적 응집도**
- 이전 출력이 다음 입력 → **순차적 응집도**
- 단일 목적 수행 → **기능적 응집도**

원칙: **응집도는 높게, 결합도는 낮게.**
