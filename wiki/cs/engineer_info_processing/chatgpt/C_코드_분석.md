# 📌 정답인 이유

## 1️⃣ dec 함수 분석

```c
int dec(int enc) {
    return enc & 0xA5;
}
```

👉 **비트 AND 연산 수행**

- 0xA5 = `1010 0101` (2진수)

---

## 2️⃣ 각 값 계산

### 🔹 첫 번째 학생 (Kim)

```c
{0xA0, 0xA5, 0xDB}
```

| 값 | 2진수 | AND 0xA5 | 결과 |
|----|------|---------|------|
| 0xA0 | 1010 0000 | 1010 0000 & 1010 0101 | 1010 0000 = 0xA0 (160) |
| 0xA5 | 1010 0101 | 그대로 | 0xA5 (165) |
| 0xDB | 1101 1011 | 1000 0001 | 0x81 (129) |

👉 합:
```
160 + 165 + 129 = 454
```

---

### 🔹 두 번째 학생 (Lee)

```c
{0xA0, 0xED, 0x81}
```

| 값 | 2진수 | AND 0xA5 | 결과 |
|----|------|---------|------|
| 0xA0 | 1010 0000 | → 0xA0 | 160 |
| 0xED | 1110 1101 | 1010 0101 | 0xA5 (165) |
| 0x81 | 1000 0001 | 그대로 | 0x81 (129) |

👉 합:
```
160 + 165 + 129 = 454
```

---

## 3️⃣ 최종 결과

```c
result = 454 + 454 = 908
```

### 🔥 핵심: `0xDB & 0xA5`

# 🚨 그런데 문제의 진짜 포인트

```c
Student s[2] = { "Kim", {0xA0, 0xA5, 0xDB}, "Lee", {0xA0, 0xED, 0x81} };

👉 이건 **구조체 초기화 순서 문제**

s[1] → "Lee", {0xA0, 0xED, 0x81}
```

👉 정상적으로 2개 생성됨

# 🧠 실기시험 포인트 정리

✔ `&` → AND 연산  
✔ 0x → 16진수  
✔ 구조체 배열 초기화 순서 중요  
✔ 비트 연산 결과는 2진수로 직접 계산  

---

필요하면 **비트 연산 빠르게 푸는 꿀팁 (시험용 스킬)**도 따로 정리해줄게.

---

### ❓ 질문 (User)
```
#include <stdio.h>
 
typedef struct student {
    char* name;
    int score[3];
} Student;
 
int dec(int enc) {
    return enc & 0xA5;
}
 
int sum(Student* p) {
    return dec(p->score[0]) + dec(p->score[1]) + dec(p->score[2]);
}
 
int main() {
    Student s[2] = { "Kim", {0xA0, 0xA5, 0xDB}, "Lee", {0xA0, 0xED, 0x81} };
    Student* p = s;
    int result = 0;
 
    for (int i = 0; i < 2; i++) {
        result += sum(&s[i]);
    }
    printf("%d", result);
    return 0;
}
```

# ✅ 문제 분석

제시된 설명의 핵심 포인트는 다음과 같습니다.

- 검사 비트를 추가하여 **오류 검출 + 수정 가능**
- 재전송 없이 **수신 측에서 자체 수정**
- 재전송을 요구하는 방식 존재
- 패리티 / CRC 특징 설명 포함

👉 핵심 키워드:

오류 검출 + 수정, 재전송 없음, 재전송 요구, 1비트 검사, 다항식

---

👉  
① **㉧ Hamming**

④ **㉤ Parity**  
⑤ **㉠ CRC**

# 📌 정답인 이유

## ① Hamming 코드

- 오류 **검출 + 수정 가능**
- 검사 비트를 여러 개 추가
- 대표적인 오류 정정 코드

👉 문제의  
"검사 비트를 추가하여 오류를 검출하고 수정까지 가능"  
→ **해밍 코드 특징 그대로**

---

## ② FEC (Forward Error Correction)

- 수신 측에서 **재전송 없이 자체 수정**
- 오류 정정 코드 방식

👉 문제의  
"재전송 없이 수신 측에서 자체 수정"  
→ **FEC 정의**

---

## ③ BEC (Backward Error Correction)

- 오류 발생 시 **송신 측에 재전송 요구**
- ARQ 방식 포함

👉 문제의  
"재전송 요구"  
→ **BEC**

---

## ④ Parity 검사

- 데이터 끝에 **1비트 추가**
- 가장 단순한 오류 검출 방식

👉 문제의  
"1비트 검사 비트 추가"  
→ **Parity**

---

## ⑤ CRC 검사

- **다항식 기반 오류 검출**
- 네트워크에서 매우 중요

👉 문제의  
"특정 다항식을 사용"  
→ **CRC**

---

# 🔎 헷갈릴 수 있는 오답

## ❌ NAK (㉣)

- 재전송 요청 신호
- 방식 자체가 아님

👉 BEC와 혼동 주의

---

## ❌ MD5 (㉥)

- 해시 함수 (무결성 확인)
- 오류 검출 코드 아님

---

## ❌ BCD (㉦)

- 이진화 10진 코드
- 데이터 표현 방식

---

# 📚 추가로 공부해야 할 것 (틀렸다면)

## 1️⃣ 오류 제어 방식 (핵심)

| 구분 | 설명 |
|------|------|
| FEC | 수신 측에서 오류 수정 |
| BEC | 재전송 요청 |

👉 시험 단골 비교 문제

---

## 2️⃣ 오류 검출 vs 정정

| 구분 | 예시 |
|------|------|
| 검출 | Parity, CRC |
| 정정 | Hamming |

---

## 3️⃣ CRC 핵심 포인트

- 다항식 기반
- 네트워크 계층(L2)에서 사용

---

# 🧠 실기시험 포인트 정리

✔ "수정까지 가능" → Hamming  
✔ "재전송 없음" → FEC  
✔ "재전송 요구" → BEC  
✔ "1비트 추가" → Parity  
✔ "다항식" → CRC  

---

필요하면 **해밍코드 계산 문제 (비트 위치 구하는 문제)**도 시험 대비용으로 풀어줄게.
