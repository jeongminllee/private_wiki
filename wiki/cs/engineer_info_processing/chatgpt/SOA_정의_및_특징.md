### 💡 답변 (Assistant)
✅ 문제 분석

제시된 설명의 핵심 포인트는 다음과 같습니다.

- 프로세스 수행을 지원하는 정보 시스템 구현
- 서비스라고 정의되는 분할된 애플리케이션 조각
- **Loosely-Coupled**, 즉 느슨하게 결합
- 여러 서비스를 연결하여 하나의 완성된 애플리케이션 구현

→ 핵심 키워드:  
**서비스, 느슨한 결합, 분할된 애플리케이션, 아키텍처**

---

🎯 정답

👉 **SOA**  
👉 **서비스 지향 아키텍처**  
👉 **Service Oriented Architecture**

---

📌 정답인 이유

SOA는 애플리케이션의 기능을 **서비스 단위로 분리**하고, 이 서비스들을 **느슨하게 연결**하여 전체 시스템을 구성하는 소프트웨어 아키텍처입니다.

| 구분 | 설명 |
|---|---|
| 정식 명칭 | Service Oriented Architecture |
| 한글명 | 서비스 지향 아키텍처 |
| 핵심 단위 | 서비스 |
| 결합 방식 | 느슨한 결합, Loosely-Coupled |
| 목적 | 재사용성, 유연성, 확장성 향상 |
| 구현 방식 | 독립적인 서비스들을 조합하여 애플리케이션 구성 |

문제에서 말한

> “서비스라고 정의되는 분할된 애플리케이션 조각들을 Loosely-Coupled하게 연결”

이 부분이 SOA의 대표적인 정의입니다.

---

🔎 헷갈릴 수 있는 오답

❌ **MSA, Microservice Architecture**

MSA도 서비스를 작게 나누고 느슨하게 결합한다는 점에서 비슷합니다.  
하지만 정보처리기사 실기에서 이 문장처럼

> “서비스라고 정의되는 분할된 애플리케이션 조각”  
> “Loosely-Coupled하게 연결”  
> “하나의 Application 구현”

이라고 나오면 전통적으로 **SOA**를 묻는 문제입니다.

MSA는 SOA보다 더 작고 독립적인 배포 단위, DevOps, 컨테이너, API Gateway 등과 함께 출제되는 경우가 많습니다.

---

📚 추가로 공부해야 할 것

만약 틀렸다면 다음 개념을 같이 정리하세요.

| 개념 | 핵심 |
|---|---|
| SOA | 서비스 단위로 시스템 구성 |
| 느슨한 결합 | 서비스 간 의존도를 낮춤 |
| 재사용성 | 기존 서비스를 다른 업무에서도 활용 |
| ESB | 서비스 간 연계와 메시지 중계 담당 |
| Web Service | SOAP, WSDL, UDDI 등과 관련 |

✔ **서비스 단위** → SOA  
✔ **Loosely-Coupled** → SOA 핵심 키워드  
✔ **분할된 애플리케이션 조각** → 서비스

### 💡 답변 (Assistant)
✅ 문제 분석

이 문제는 **C언어 2차원 배열과 포인터 연산**을 묻는 문제입니다.

핵심 포인트는 다음과 같습니다.

- 2차원 배열은 메모리에 **행 우선 순서(Row-major order)** 로 저장됨
- `a[1]`은 2차원 배열의 **두 번째 행의 시작 주소**
- `p[1]`, `q[2]`는 포인터 기준으로 떨어진 위치의 값을 의미함

---

🎯 정답

👉 출력 결과는

```text
74
```

---

📌 정답인 이유

배열은 다음과 같이 저장됩니다.

| 배열 위치 | 값 |
|---|---:|
| `a[0][0]` | 1 |
| `a[0][1]` | 2 |
| `a[0][2]` | 3 |
| `a[1][0]` | 4 |
| `a[1][1]` | 5 |
| `a[1][2]` | 6 |
| `a[2][0]` | 7 |
| `a[2][1]` | 8 |
| `a[2][2]` | 9 |

즉 메모리상으로는 다음과 같이 연속 저장됩니다.

```text
1  2  3  4  5  6  7  8  9
```

---

### 1️⃣ `int *p = a[1] + 2;`

`a[1]`은 두 번째 행의 시작 주소입니다.

```c
a[1] == &a[1][0]
```

따라서

```c
a[1] + 2 == &a[1][2]
```

즉 `p`는 `a[1][2]`를 가리킵니다.

```text
a[1][2] = 6
```

그런데 출력은 `p[1]`입니다.

```c
p[1] == *(p + 1)
```

`p`가 `a[1][2]`를 가리키고 있으므로, 그 다음 위치는 `a[2][0]`입니다.

```text
p[1] = a[2][0] = 7
```

따라서 첫 번째 출력은

```text
7
```

---

### 2️⃣ `int *q = &a[0][1];`

`q`는 `a[0][1]`의 주소를 가리킵니다.

```text
a[0][1] = 2
```

출력은 `q[2]`입니다.

```c
q[2] == *(q + 2)
```

`q` 기준으로 보면 다음과 같습니다.

| 포인터 표현 | 배열 위치 | 값 |
|---|---|---:|
| `q[0]` | `a[0][1]` | 2 |
| `q[1]` | `a[0][2]` | 3 |
| `q[2]` | `a[1][0]` | 4 |

따라서 두 번째 출력은

```text
4
```

---

📌 최종 출력

`printf` 사이에 공백이나 줄바꿈이 없으므로 그대로 붙어서 출력됩니다.

```text
74
```

---

🔎 헷갈릴 수 있는 부분

❌ `p[1]`을 `a[1][1]`로 착각하면 안 됩니다.

`p`는 이미 `a[1][2]`를 가리키고 있습니다.

```c
p[0] == a[1][2] == 6
p[1] == a[2][0] == 7
```

❌ `q[2]`를 `a[0][3]`처럼 생각하면 안 됩니다.

C언어에서 2차원 배열은 메모리에 연속적으로 저장되므로 `a[0][2]` 다음은 `a[1][0]`입니다.

---

📚 추가로 공부해야 할 것

이 문제를 틀렸다면 다음 내용을 꼭 복습하세요.

| 개념 | 설명 |
|---|---|
| 2차원 배열 저장 방식 | C언어는 행 우선 저장 |
| 배열명과 주소 | `a[1]`은 `&a[1][0]`과 같음 |
| 포인터 인덱싱 | `p[i] == *(p+i)` |
| 2차원 배열 포인터 연산 | 행 경계를 넘어도 메모리상 다음 원소 접근 가능 |

---

🧠 실기시험 포인트 정리

✔ `a[1]` → 두 번째 행 시작 주소  
✔ `a[1] + 2` → `&a[1][2]`  
✔ `p[1]` → `a[2][0]` → `7`  
✔ `q = &a[0][1]`  
✔ `q[2]` → `a[1][0]` → `4`  
✔ 최종 출력 → **74**

### 💡 답변 (Assistant)
✅ 문제 분석

문제의 핵심은 다음 조건입니다.

- 문자열 **`symmetry` 앞에**
- **정확히 한 글자만 추가된 문자열**을 조회
- `symmetry`는 앞에 글자가 없으므로 제외
- `anti-symmetry`는 앞에 여러 글자가 있으므로 제외
- `asymmetry`, `Rsymmetry`, `Tsymmetry`는 앞에 한 글자만 있으므로 조회

→ 핵심 키워드:  
**LIKE, `_`, 한 글자 매칭**

---

🎯 정답

```sql
SELECT 단어, 뜻
FROM 사전
WHERE 단어 LIKE '_symmetry';
```

---

📌 정답인 이유

SQL의 `LIKE`에서 사용하는 와일드카드는 다음과 같습니다.

| 와일드카드 | 의미 |
|---|---|
| `%` | 0개 이상의 문자 |
| `_` | 정확히 1개의 문자 |

따라서

```sql
LIKE '_symmetry'
```

는 다음 의미입니다.

```text
앞에 아무 문자 1개 + symmetry
```

즉, 전체 문자열 길이는 반드시

```text
1글자 + symmetry
```

형태여야 합니다.

---

✅ 조회되는 값

| 단어 | 이유 |
|---|---|
| `asymmetry` | `a` + `symmetry` |
| `Rsymmetry` | `R` + `symmetry` |
| `Tsymmetry` | `T` + `symmetry` |

---

🔎 조회되지 않는 값

| 단어 | 제외 이유 |
|---|---|
| `symmetry` | 앞에 추가된 글자가 없음 |
| `anti-symmetry` | `symmetry` 앞에 한 글자가 아니라 여러 글자가 있음 |

---

📚 추가로 공부해야 할 것

SQL `LIKE` 문제에서는 `%`와 `_`의 차이를 반드시 구분해야 합니다.

| 조건 | SQL |
|---|---|
| `symmetry`로 끝나는 모든 문자열 | `LIKE '%symmetry'` |
| `symmetry` 앞에 정확히 한 글자 | `LIKE '_symmetry'` |
| `symmetry` 앞에 한 글자 이상 | `LIKE '_%symmetry'` |
| `symmetry`로 시작하는 문자열 | `LIKE 'symmetry%'` |

---

🧠 실기시험 포인트 정리

✔ `%` → 0개 이상의 문자  
✔ `_` → 정확히 1개의 문자  
✔ “한 글자 추가” → `_` 사용  
✔ “앞에 한 글자가 추가된 symmetry” → **`LIKE '_symmetry'`**

### 💡 답변 (Assistant)
✅ 문제 분석

이 문제는 **C언어 함수 포인터(Function Pointer)** 를 묻는 문제입니다.

핵심 포인트는 다음과 같습니다.

```c
int (*pf)(int, int);
```

이 선언은 다음 의미입니다.

> 정수형 매개변수 2개를 받고, 정수형 값을 반환하는 함수를 가리키는 포인터 `pf`

즉, `pf`는 다음 함수들을 가리킬 수 있습니다.

```c
int add(int i, int j)
int sub(int i, int j)
```

---

🎯 정답

빈칸은 다음과 같이 작성하면 됩니다.

```c
① pf = add;
② pf = sub;
```

또는 주소 연산자를 붙여도 됩니다.

```c
① pf = &add;
② pf = &sub;
```

둘 다 정답으로 볼 수 있습니다.

---

📌 완성 코드

```c
#include <stdio.h>

int add(int i, int j){
    return i + j;
}

int sub(int i, int j){
    return i - j;
}

int main(){
    int (*pf)(int, int);

    pf = add;
    printf("%d", pf(5, 4));

    pf = sub;
    printf("%d", pf(5, 4));

    return 0;
}
```

---

📌 정답인 이유

### 1️⃣ `pf = add;`

`pf`가 `add` 함수를 가리키게 됩니다.

```c
pf(5, 4)
```

는 실제로 다음과 같습니다.

```c
add(5, 4)
```

따라서 결과는

```text
5 + 4 = 9
```

첫 번째 출력은 `9`입니다.

---

### 2️⃣ `pf = sub;`

이제 `pf`가 `sub` 함수를 가리키게 됩니다.

```c
pf(5, 4)
```

는 실제로 다음과 같습니다.

```c
sub(5, 4)
```

따라서 결과는

```text
5 - 4 = 1
```

두 번째 출력은 `1`입니다.

---

🎯 최종 출력 결과

두 `printf` 사이에 공백이나 줄바꿈이 없으므로 붙어서 출력됩니다.

```text
91
```

---

🔎 헷갈릴 수 있는 부분

❌ `pf = add(5, 4);` 는 틀립니다.

이렇게 쓰면 `add` 함수의 **실행 결과값 9**를 `pf`에 넣으려는 의미가 됩니다.  
하지만 `pf`는 정수가 아니라 **함수의 주소를 저장하는 포인터**입니다.

정확히는 함수 이름만 써야 합니다.

```c
pf = add;
```

또는

```c
pf = &add;
```

---

📚 추가로 공부해야 할 것

함수 포인터 문제에서는 선언 해석이 중요합니다.

| 코드 | 의미 |
|---|---|
| `int (*pf)(int, int);` | int 2개를 받아 int를 반환하는 함수 포인터 |
| `pf = add;` | `pf`가 `add` 함수 주소를 가리킴 |
| `pf(5, 4)` | `pf`가 가리키는 함수 호출 |
| `(*pf)(5, 4)` | 위와 같은 의미 |

---

🧠 실기시험 포인트 정리

✔ `int (*pf)(int, int)` → 함수 포인터  
✔ `pf = add;` → add 함수 연결  
✔ `pf = sub;` → sub 함수 연결  
✔ `pf(5, 4)` → 가리키는 함수 실행  
✔ 최종 출력 → **91**
