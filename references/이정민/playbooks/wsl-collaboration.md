# Playbook · WSL 팀 작업

개인 하네스는 `references/이정민/`의 문서만으로 유지한다. 팀원의 작업 환경이나 하네스는 변경하지 않는다.
개인 폴더가 나뉘었다고 소스 편집·공유 자원 충돌까지 해결된 것으로 간주하지 않는다.

## 기존 작업 사본 유지

실제 작업 경로, 현재 branch, 기존 사용자 변경, 다른 작업자의 수정 범위를 먼저 확인한다.
이 하네스를 적용하려고 저장소를 옮기거나 새 개발 환경·worktree·branch를 만드는 작업을 시작하지 않는다.
팀에서 이미 사용하는 방식으로 진행한다. 분리가 실제 필요한 경우에만 이유를 제안하고 승인받는다.

같은 작업 사본의 writer는 하나다. Sol이 직접 수정하는 동안에도 다른 writer를 병행하지 않는다.
다른 작성자의 상태를 알 수 없으면 추정하지 말고 쓰기를 보류한다.
서로 다른 사본이라도 같은 파일·lockfile·생성물의 통합 충돌을 확인한다.

## 실행 부작용

검증 전에 공유 DB·서비스 포트·GPU·캐시·출력 경로의 소유권과 충돌을 확인한다.
모델 서빙/학습 작업과 테스트가 같은 GPU를 사용하면 필요한 자원과 실행 승인을 먼저 확인한다.
팀원의 프로세스를 종료하거나 방화벽·운영 설정을 바꾸어 문제를 해결하지 않는다.

## 통합과 검증

검증 대상 후보와 실행 환경을 기록한다. 검사 중인 소스를 변경하지 않는다.
같은 경로의 파일이 바뀌었거나 통합으로 새 후보가 만들어지면 영향 범위 검증·리뷰를 다시 한다.
기존 팀의 CI와 릴리스 절차를 사용한다. 하네스의 ACCEPT는 자동 push·merge·배포 허가가 아니다.

## 개인 문서 공유

폴더 경로는 `references/이정민/` 그대로 사용한다.
해당 경로는 사용자가 지정한 개인 문서 위치이지 계정 이름이나 CLI 프로필 식별자 규칙이 아니다.
다른 도구 연결용 경로로 임의 변환하지 않는다.
문서를 다른 위치에 복사할 때는 링크와 진입 경로만 확인하고 프로젝트 설정을 바꾸지 않는다.
키·토큰·원시 민감 로그는 문서와 인수인계에 넣지 않는다.
