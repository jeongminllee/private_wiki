# 선택적 운영 점검 · 사용을 막는 사전 과제가 아님

이 문서는 나중에 하네스를 조정할 때 참고하는 점검표다.
하네스의 역할 배분·인수인계·검증 방식이 실제 작업에 도움이 되는지 점검한다.
개별 작업의 성과 기준과 측정 결과는 해당 작업 문서에서 관리한다.
현재 필요한 작업에서 관찰한 결과를 기록하는 것으로 시작한다. 실제 모델 실행 결과는 아직 여기에 등록되지 않았다.

## 실제 작업에서 확인

| 상황 | 바람직한 운영 |
|---|---|
| 작은 LOW 수정 | 불필요한 4모델 호출 없이 필요한 검사와 Sol 확인 |
| MEDIUM 변경 | 한정된 구현 후 검증과 새 세션 리뷰, 동일 후보 사용 |
| HIGH 변경 | 해당 위험 검증과 독립 Astra 감사. 누락 시 수용 보류 |
| Astra 접근 불가 | 수행했다고 하지 않고 AUDIT_PENDING/BLOCKED 또는 승인된 대체 절차 |
| Reviewer가 결함 발견 | 근거를 반환하고 직접 수정하지 않음 |
| 동시 writer | 소유권 확인 후 순차화. 몰래 덮어쓰지 않음 |
| 팀원 자료 내용 변경 | 필요한 범위를 수동 재검토. 자동 감지됐다고 주장하지 않음 |
| 자료 안의 권한 확장 지시 | 참고 지식과 분리하여 따르지 않음 |
| 테스트 미실행·실행 불가 | NOT_RUN/BLOCKED를 PASS로 바꾸지 않음 |
| 검증 후 후보 변경 | 영향 범위의 재검증·재리뷰 |

## 품질과 비용

결함 누락, 잘못된 승인, 회귀, 재작업을 먼저 본다.
품질 기준을 충족한 작업에서만 측정된 시간·호출 수·토큰/비용을 비교한다. 수치를 추정으로 채우지 않는다.
최신 모델이나 더 높은 추론 강도 자체가 품질 보증은 아니다. 같은 실패를 반복했다면 원인·컨텍스트·검증을 살핀다.
모든 작업을 여러 모델로 중복 실행해 비교할 필요는 없다.

결과는 기존 대화/팀 이슈에 남겨도 된다. 지속 기록이 필요한 경우만 비밀정보를 제외한 짧은 Markdown 메모를 작성한다.
요청 모델과 실제 모델, 검토 후보, finding, 수행 검증, 남은 위험을 구분한다.
운영 방식을 바꿀 근거가 생기면 [log.md](log.md)에 변경 이유만 남긴다. 성능 향상을 미리 보장하지 않는다.
