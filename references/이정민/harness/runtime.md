# 세션 운영 · 기존 도구에서 문서만 읽기

## 시작

사용자가 이번 세션에서 `references/이정민/index.md`를 진입점으로 지정한다.
[시작 문구](../templates/session-start.md)를 작업 요청과 함께 전달하면 된다.
설치·초기화·프로필 생성·네이티브 설정 파일 생성은 필요하지 않다.

이 문서를 읽었다는 사실과 실제 모델이 배정됐다는 사실을 구분한다.
폴더를 복사한 사실만으로 도구가 자동으로 읽었거나 설정을 적용했다고 간주하지 않는다.
지정한 문서가 보이지 않으면 접근 문제를 보고한다. 내용을 읽은 것처럼 추정하지 않는다.

## 첫 확인은 짧게

현재 작업 경로, 적용 팀 규칙, 읽기/쓰기 범위, 실제 모델·권한을 필요한 만큼 확인한다.
모델 요청값은 [모델 운영표](../config/models.md)에 있다. 도구 버전 확인이나 전체 모델 호출을 매 작업의 의식처럼 반복하지 않는다.
실제 모델/추론 강도는 현재 도구의 상태·메타데이터로 확인 가능한 경우만 확정한다.
확인되지 않은 값은 unknown으로 남기고, 필수 독립 검토를 충족할 수 있는지 별도로 판단한다.

## 사용 가능한 실행 방식

| 방식 | 사용 방법 | 반드시 구분할 점 |
|---|---|---|
| 기존 native 위임 | 현재 도구에서 이미 지원·설정된 모델/하위 세션 기능 사용 | 역할 파일을 읽히고 실제 배정 모델을 확인. 별도 설정 설치를 전제하지 않음 |
| 수동 다중 세션 | 사람이 각 모델 세션에 같은 후보와 필요한 역할·task를 전달 | 결과를 Sol에 돌려준다. 외부 반출·비밀정보 정책 준수 |
| 단일 세션 | 현재 모델이 요구 분석·자체 점검 수행 | 실제 4모델 협업이나 독립 리뷰라고 부르지 않음 |

한 모델에게 Luna·Terra·Sol·Astra 이름을 붙여 말하게 한 것은 실제 모델 전환이 아니다.
별도 검토 세션을 확보하지 못한 단일 세션의 자체 점검은 필수 독립 리뷰를 충족하지 않는다.
확인 가능한 기능만 사용하며 지원되지 않는 위임 호출이나 모델 선택을 꾸며내지 않는다.

## 기능이 없을 때

모델/위임 기능이 없다는 이유로 사용자가 요청하지 않은 환경 구축부터 시작하지 않는다.
수행 가능한 조사·자체 검토는 범위와 한계를 명시해 진행한다.
필수 독립 리뷰/감사는 `BLOCKED` 또는 `AUDIT_PENDING`으로 남기고 필요한 추가 검토만 알린다.
권한 있는 사람이 대체 전문 검토를 승인하면 실제 검토자와 이유를 기록한다.
조용한 하향 대체, 계정 제한 우회, 모델 사용을 위한 비밀정보 전송은 하지 않는다.

## 파일·권한

기본 하네스 적용만을 이유로 루트 `README.md`, `AGENTS.md`, `.gitignore`, 기존 도구 설정을
변경하지 않는다. 사용자가 명시적으로 승인한 한정된 governance upgrade는 예외이며, 그때도
정확한 WRITE SCOPE 안의 문서만 바꾸고 native `.codex` 설정은 변경하지 않는다.
개인 폴더에 어떤 파일을 두더라도 그것만으로 팀 규칙을 덮어쓰는 권한이 생기지 않는다.
기존 지시와 충돌하면 개인 지시를 중단하고 필요한 충돌만 보고한다.

이 '개인 폴더 안에만 배치' 원칙은 하네스의 설치 범위다.
실제 개발 요청의 코드 수정은 별도로 지정된 WRITE SCOPE 안에서만 가능하다.
읽기 전용 역할의 검사에도 임시 파일·네트워크·공유 DB 부작용이 있을 수 있으므로 실제 권한을 확인한다.
문서만으로 sandbox·동시 실행 제한이 강제된다고 믿지 않는다.

## 첫 사용

프로젝트를 일부러 바꾸는 smoke test를 새로 만들지 않는다.
현재 필요한 작은 실제 작업에서 역할·인계·검증이 되는지 확인하고, 미확인 항목은 그대로 기록한다.
결과는 대화에 남기는 것이 기본이다. 별도 저장은 필요한 경우에만 승인된 위치의 Markdown으로 한다.
