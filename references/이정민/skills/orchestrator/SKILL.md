# V3.1.1 Orchestrator · 비단순 작업의 조율 절차

이 파일은 기존 폴더 구성을 유지한 **일반 Markdown 운영 문서**다.
별도 skill 설치·등록·자동 탐색을 전제하지 않는다. [index](../../index.md)에서 필요할 때 직접 읽는다.
팀 규칙과 실제 도구 권한을 우회하지 않는다.

## 절차

1. 최신 사용자 요청과 관련 작업 문서에서 목표·변경 대상·제약을 확인한다.
   적용 팀 규칙을 확인하고, 이전 작업의 상태를 현재 작업의 기본값으로 두지 않는다.
2. [모델 운영표](../../config/models.md)를 읽고 실제 가능한 역할 배정과 확인되지 않은 부분을 구분한다.
   연결이 불명확할 때만 [세션 운영](../../harness/runtime.md)을 읽는다.
3. [routing](../../harness/routing.md)으로 위험과 직접 수행 여부를 결정한다. 작은 LOW 작업에는 위임을 늘리지 않는다.
4. 필요한 조사만 Luna에 맡긴다. Sol이 이미 아는 조사 결과를 다시 수집시키지 않는다.
5. 위임할 작업은 [handoff](../../harness/handoff.md)로 목표·read/write scope·후보·검증·완료 조건을 명시한다.
6. 구현이 요청되면 Terra에 한정된 변경을 맡긴다. 검토만 요청됐으면 구현을 시작하지 않는다.
7. 기본 동시 하위 작업은 최대 2개, 같은 작업 사본의 writer는 1개다. 하위 작업자의 재위임은 금지한다.
8. Sol은 위임된 일을 중복 수행하지 않는다. 필요한 독립적 계약·영향 검토와 통합 준비를 한다.
9. 반환된 증거·변경 범위·실제 모델·명령 실행 여부를 확인한다. 필요한 결과만 짧게 통합한다.
10. 후보를 고정하고 [review](../../harness/review.md)의 위험별 검증·독립 리뷰를 수행한다.
11. HIGH 또는 [승격 조건](../../harness/escalation.md)에 해당하면 Astra 전문 검토/감사를 확보한다.
12. 실패는 원인·가설·쓰기 범위를 수정한 새 작업으로 처리한다. 근거 없이 같은 재시도를 반복하지 않는다.
13. 필수 단계와 finding 처리를 확인한 뒤 Sol이 수용·재작업·보류를 판단한다. 팀 병합·배포 권한과 구별한다.
14. 기존 도구가 지원하는 경우 완료된 하위 세션을 종료한다. 전체 대화 대신 필요한 결과와 증거만 인계한다.

## 문서와 결과

동료 자료는 [references](../../references.md)와 [참조 규칙](../../harness/team-references.md)을 따른다.
결과는 대화에 남기는 것이 기본이며 자동 파일 생성은 요구하지 않는다.
필요한 경우에만 [result](../../templates/result.md), [review](../../templates/review.md),
[decision](../../templates/decision.md) 양식을 사용한다.
모든 모델·양식을 반드시 참여시키는 절차가 아니라, 같은 품질 기준을 지키는 최소 절차다.
