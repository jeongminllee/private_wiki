# V2 / 도구 포함 V3 → Markdown 전용 V3

## 유지한 구조

Sol의 조율·설계·통합, Terra의 구현/독립 리뷰, Luna의 조사/검증, Astra의 전문 검토/독립 감사를 유지했다.
역할 우선 배정, 제한된 쓰기 범위, 필수 검증, 구조화된 인수인계, 필요한 참고자료만 읽는 원칙도 그대로다.
프로젝트 루트 README는 계속 프로젝트 소개로 유지한다.

## 이번 전환

| 이전 구성 | Markdown 전용 구성 |
|---|---|

| 프로필 선택 파일·루트 연결 블록·전역 설정 변경 | 필요 없음. 세션에서 개인 진입점 지정 |

원본 문서를 기계적으로 남기지 않고 제거된 도구를 호출하던 지시·경로도 바꿨다.
사용자가 마지막으로 지정한 추론 강도 Sol high / Terra high / Luna low / Astra high를 적용했다.

## 배치

압축을 별도 위치에 풀고 `references/이정민/` 폴더를 프로젝트의 같은 위치에 둔다.
이미 같은 폴더에 개인 자료가 있으면 먼저 비교하고 필요한 문서만 교체한다. 통째로 덮어쓰거나 지우지 않는다.
[시작 문구](templates/session-start.md)와 실제 작업을 에이전트에 전달한다.
이 버전의 파일은 모두 개인 폴더 안의 Markdown이다. 루트·전역 설정을 건드릴 필요가 없다.

## 이전 설치본이 있는 경우

새 문서 묶음은 이전에 사용자가 설치한 파일을 자동 제거하지 않는다.
예전에 별도로 연결한 자동 진입 규칙이나 도구 설정이 있다면 두 하네스가 동시에 적용되는지 확인한다.
이전 개인 연결만 정리할 수 있지만 팀이 쓰는 기존 규칙이나 설정을 함께 삭제하지 않는다.
충돌을 발견해도 이번 개인 하네스가 팀 정책을 덮어쓰지 않는다. 필요한 충돌만 보고한다.

기존 설계·구현을 완료한 프로젝트를 하네스 전환 때문에 처음부터 다시 검사·재설계할 필요는 없다.
현재 요청한 작업과 직접 관련된 범위에서만 적용한다.
